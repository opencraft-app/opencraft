# 本地完整开发栈规格审查

## 结论

规格保持 API 与静态前端的生产边界，同时为开发提供一条命令的完整栈。选择依赖无关的 shell supervisor，适合当前 macOS 开发环境，也不把开发编排逻辑带入 Go 业务进程。

## 已审查风险

- **密钥泄漏**：真实密钥只存在于被忽略且权限受限的文件，不进入参数、环境值和日志。
- **误杀进程**：停止前校验 PID 对应命令，不只依赖 PID 文件。
- **端口冲突**：启动前检查并输出明确占用信息。
- **半启动状态**：API 健康后才启动 Web；启动失败清理本轮进程。
- **路径耦合**：当前拓扑有安全默认值，同时允许 `VELA_WEB_DIR` 覆盖。
- **循环成本**：支持单侧重启、统一状态和合并日志，不要求重跑生产构建。

## 不在范围

- Docker Compose、Kubernetes、Ingress 和生产发布。
- 自动创建或修改腾讯云 IM 应用。
- 在 Go API 中重新加入静态文件服务。
- iOS/Android 原生构建；首版完整栈的 UI 入口为 Expo Web。
