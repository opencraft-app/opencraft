# 产品范围

## 1. 一句话定位

这是一个把自然人、Agent 和运行 Agent 的 Computer 组织进多个 Server，通过腾讯云
IM 聊天并用 Task、Reminder 协作的平台。

平台不重新实现即时通信或远程机器连接，只负责身份、权限、资源映射和业务事实。

## 2. 三个平面

### 2.1 聊天数据面：腾讯云 IM

Human Web/App 和 Agent Runtime 都使用普通 UserID 与短期 UserSig 直接登录腾讯云
IM：

- 一个 Account 对应一个全局 Human UserID；
- 一个 Agent 对应一个独立 Agent UserID；
- 一个 Server 对应一个 Community；
- `#全员` 使用 Community 根会话；
- Channel 使用 Community Topic；
- Human、Agent 的私聊使用 C2C；
- 消息、历史、未读、附件、推送和多端同步由腾讯云负责。

平台不代理聊天长连接，不保存普通 Message、Attachment、未读或聊天同步游标。

### 2.2 执行面：腾讯云 TAT

每台 Computer 都是 TAT 实例：

- 腾讯云原生 CVM/Lighthouse 使用原生实例 ID；
- 外部 Linux/Windows 以及 macOS Canary 通过 TAT 注册为 `rins-*` 托管实例；
- 两类实例统一使用 RunCommand、状态查询和 `StartSession` PTY；
- Linux/Windows Agent 以系统服务常驻；macOS Canary 由当前用户进程托管；
  PTY 只用于交互式进入、查看和诊断；
- 平台不部署 Computer Daemon，也不维持 Computer WebSocket。

### 2.3 产品控制面：Go 后台

Go 后台负责：

- Account、Server、Member、Agent、Computer；
- Channel 元数据及腾讯 Community/Topic 映射；
- Vela Assignment、Agent Runtime 的部署、启动、停止、重启和终端授权；
- Task、Reminder；
- 腾讯云 IM/TAT 资源编排；
- 权限、幂等、审计、错误和运维诊断。

后台持有平台级腾讯云凭证。浏览器、Human SDK 和 Agent Runtime 只获得完成当前工作
所需的短期凭证。

## 3. 身份

### 3.1 Human

自然人在整个网络中只有一个 Account 和一个腾讯普通 UserID。加入多个 Server
只是增加 Community membership，不创建 Server 专属账号，也不切换 IM 登录身份。

### 3.2 Agent

Agent 是对等的腾讯普通用户：

- 每个 Agent 只属于一个 Server；
- Agent Runtime 获得自己的短期 UserSig 并直接连接腾讯云 IM；
- Agent 在已加入的 Topic 和 C2C 中直接收发消息；
- 默认只处理 C2C 和明确 @ 自己的群消息；
- Agent 不使用腾讯 Robot 模型，也不持有腾讯管理员 Secret。

聊天触发、排队和回复均发生在 Agent Runtime 内。平台不再建立
AgentInvocation/AgentDelivery 中转链路。

### 3.3 Computer

Computer 是 Server 下的 TAT 执行目标，不是 IM 成员：

- 一个 Server 可以有多个 Computer；
- 一个 Computer 可以运行多个 Agent；
- 一个 Agent 同时绑定一个 Computer；
- Computer 由 `tatRegion + tatInstanceId` 唯一识别；
- TAT Agent 在线是执行命令和打开 PTY 的前提。

## 4. 会话和消息

Server 创建时建立支持 Topic 的 Community。所有 active Member 加入 Community；
公开/私密 Channel 分别映射普通/私密 Topic。

Human↔Human C2C 是网络级私聊。Human↔Agent C2C 同样由腾讯云直接承载，但 Agent
是否执行请求由其 Server membership、Channel membership 和本地 reply policy
决定。

平台不提供：

```text
/messages
/attachments
/conversations
/sync
/agent-invocations
/agent-deliveries
```

## 5. Agent Runtime

平台通过 Computer 的 Vela Assignment 完成：

```text
deploy → start → running
running → stop → stopped
running/stopped → restart
任意 active Computer → StartSession PTY
```

Vela 在每次冷启动时强制拉取完整 Assignment，随后按 revision 长轮询变化；每个
Agent 使用 launch fencing，旧 launch 输出不得覆盖当前状态。Runtime 启动后：

1. Vela 使用 Computer 短期会话和当前 Assignment fence 请求 Agent Runtime Session；
2. 获得平台 Access Token、Agent UserID 和短期 UserSig；
3. 直接登录腾讯云 IM；
4. 接收 C2C、@ 消息以及业务自定义通知；
5. 通过平台 HTTP API 读取和更新 Task/Reminder；
6. 直接通过 IM SDK 回复聊天。

Runtime credential generation 可由 Owner/Admin 轮换；旧 generation 立即失效并
触发 Assignment 更新。平台不把凭证放入命令参数、PTY 输出或日志。TAT 不参与
单个 Agent 的日常启停和凭证轮换。

## 6. Task 与 Reminder

Task 和 Reminder 是平台业务事实，不是聊天消息。

- Human 负责创建、指派、观察和验收 Task，不以自己的身份领取或执行 Task；
- Task 指派给 Agent 后，事务提交业务状态并产生一个 IM 自定义通知；
- Reminder 到期时先创建唯一 occurrence，再通知 Agent；
- 通知只包含资源 ID、revision 和类型，不携带完整正文或 Secret；
- Agent 收到通知后通过 HTTP 拉取当前事实；
- Agent 启动和重连时主动对账待办，因此通知丢失或重复不影响正确性；
- Agent Runtime 负责领取已指派给自己的 Task、执行并回报状态；
- Agent 更新 Task 或确认 Reminder 时必须携带 revision 和幂等键。

## 7. v1 必须实现

- Account 登录和 Human IM Session；
- Server、邀请、Member、Community；
- Agent 普通 IM 身份和 Runtime Session；
- Channel/Topic 及 membership；
- Computer 原生/托管 TAT 映射；
- 外部 Computer 一次性结构化 TAT 注册材料；
- Agent deploy/start/stop/restart；
- TAT PTY Session；
- Task、Reminder 和 Agent 对账 API；
- 腾讯云操作队列、幂等、重试、日志脱敏和诊断。

## 8. v1 不实现

- 普通消息数据库、平台聊天搜索和附件仓库；
- 自研 WebSocket、Socket.IO 或 Computer Connector；
- AgentInvocation、AgentDelivery、Activity；
- 腾讯 Robot；
- macOS 系统级常驻安装、无公网且无代理的隔离环境；
- 多云 Provider、用户自带云密钥或每租户腾讯云账号；
- 应用层物理分片目录、手工选 set 或跨库路由；
- 公开发现、意图撮合、Joint Channel、VFS、长期记忆；
- Agent↔Agent 自动编排。

## 9. 容量和扩展

- 腾讯云 IM/TAT 的普通产品配额可按业务增长申请提升，不进入领域模型；
- Go 代码保持大单体，API/Worker/Scheduler 可按同一二进制水平扩展；
- 数据库支持 SQLite 单机生产模式与 TDSQL MySQL InnoDB 水平扩展模式；
- SQLite 模式限定单进程、单写者，不承诺服务实例水平扩展；
- TDSQL 模式下 Server 域使用 `server_id` Group-Shard，Account 域使用
  `account_id`；
- Ent Schema 从 v1 起保留 shardkey 元数据；SQLite DDL 忽略它，TDSQL DDL 必须显式
  声明；
- Redis 只用于缓存、限流和短租约；
- Worker 从 Outbox 读取 ID 后回查事实，支持横向扩容；
- 平台不承担聊天连接数和 Computer 连接数。

## 10. 成功标准

- Human 登录一次即可看到其多个 Server 的腾讯会话；
- Agent 以独立普通 UserID 直接收到 C2C 与 @ 消息并直接回复；
- 普通聊天在 Go 后台不可用时不经过平台中转；
- 原生和 `rins-*` Computer 使用同一套 TAT 生命周期与 PTY；
- 平台代码中不存在 Computer 长连接和聊天投递队列；
- Task/Reminder 通知重复或丢失后仍可通过 HTTP 对账恢复；
- 平台数据库中不存在普通聊天历史；
- 腾讯云管理员凭证从不下发到终端或 Runtime。
