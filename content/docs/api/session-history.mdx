# Diagnostics History API

Diagnostics history endpoints 返回 session 的综合历史、审计和调试视图。它们不是 source of truth，也不是普通 UI surface 的主输入。

普通 UI 应该优先使用 [UI Read Model API](/docs/api/ui-read-models)：`ConversationView`、`PendingRequestsView`、`DiffReviewView` 等投影。

OpenAPI 是唯一 client-facing wire contract。`timeline` 和 `trace` 只存在于 diagnostics namespace；旧的 main-session timeline/trace path 不属于契约。

## Endpoints

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/sessions/{session_id}/diagnostics/timeline` | 获取 CloudAgent-style diagnostics timeline |
| `GET` | `/sessions/{session_id}/diagnostics/timeline/{item_id}` | 获取单个 diagnostics timeline item |
| `GET` | `/sessions/{session_id}/diagnostics/trace` | 获取 command、raw backend output、normalization、projection trace |

## Timeline 和 Trace

`SessionTimeline` 适合：

- DevTools
- audit
- replay
- debugging
- export
- full historical inspection

`SessionTrace` 适合检查：

- command acceptance / rejection
- idempotency decision
- backend raw event
- raw-to-canonical normalization
- projection invalidation
- warning / error diagnostics

它们都不能替代普通 UI read model。

## Projection 区分

UI read models 是展示面：

- `/sessions/{id}/views/conversation`：chat 主列表，包含 message、turn meta、agent work、status
- `/sessions/{id}/views/requests`：permission/request dock
- `/sessions/{id}/views/diffs`：review panel

Timeline 和 trace 都是 diagnostics resource。普通客户端不应该通过它们拼 UI。

## Requirements

### Requirement: Timeline 是 diagnostics API，不是 UI read model

Session timeline MUST 挂在 diagnostics namespace 下面，而不是 `/views/*` 或 session 主资源下面。

#### Scenario: client 读取综合历史

- **WHEN** client 请求 `/sessions/{session_id}/diagnostics/timeline`
- **THEN** daemon 返回 session 的综合 timeline
- **AND** 这个请求不改变任何 canonical event

### Requirement: History 视图是派生视图

Session timeline 和 trace MUST 从 canonical events、raw retention、normalization records 或安全 daemon state 派生，不能成为事实源。

#### Scenario: timeline cache 被清空

- **WHEN** session timeline projection 被清空
- **THEN** daemon 可以 replay canonical events 重建
- **AND** 不改变任何 canonical event

### Requirement: Conversation 必须是普通 UI 主输入

Chat conversation MUST 使用 `ConversationView`，不直接渲染 session timeline。

#### Scenario: tool command 完成

- **WHEN** backend 完成一个 command
- **THEN** daemon 可以在 timeline 中保留完整历史
- **AND** projector 输出相应 `agent_work` item
- **AND**普通 UI 从 `ConversationView` 渲染这个 work item
