# Events API

Events 是同步主干。Client 用 stream 获取 live updates，用 fetch endpoints 做 reconnect 和 audit。

它不是 UI read model，但它会告诉 UI **哪些 read model 需要刷新**。例如权限请求出现时，stream 不要求 UI 自己拼 permission dock；stream 只发布 canonical request event，UI 随后读取 `/sessions/{session_id}/views/requests`。

事件类型必须来自 [事件词表](/docs/api/event-vocabulary)。Backend adapter 负责把 Codex、CloudAgent、ACP、Qoder 等后端原始事件映射到这组 canonical 类型。

## Endpoints

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/sessions/{session_id}/events` | 拉取 event history |
| `GET` | `/sessions/{session_id}/events/stream` | 订阅 session events |
| `GET` | `/events/stream` | 订阅 workbench-wide events |

## SSE 示例

```txt
id: evt_0004
event: diff.updated
data: {"event_id":"evt_0004","epoch":1,"seq":4,"session_id":"ses_123","type":"diff.updated","affected_views":["diffs","activity"],"payload":{"files_changed":2}}
```

## 权限请求订阅示例

Agent 需要用户授权时，daemon 把后端 raw event 归一成 canonical request event：

```txt
id: evt_0042
event: request.opened
data: {"event_id":"evt_0042","epoch":1,"seq":42,"session_id":"ses_123","type":"request.opened","affected_views":["requests","activity"],"payload":{"request_id":"req_abc","request_type":"tool_confirmation","title":"Allow shell command?"}}
```

Client 收到 `request.opened` 后：

1. 刷新 `/sessions/{session_id}/views/requests`。
2. 在 permission dock / mobile approval surface 展示 `PendingRequestsView`。
3. 用户点击 approve / deny / answer 后调用 `POST /sessions/{session_id}/events`，投递 `user.tool_confirmation` / `user.request_answer` 等 input event。
4. Daemon 校验 request 状态并 append `request.response.accepted`、`request.resolved` 或 `input.rejected`。

Chat transcript 不直接消费 `request.opened`。如果正文需要提示，只能通过 `ChatTranscriptView` 里明确的 `activity_marker` 或 `working` row 出现。

## Reset 示例

```txt
event: sync.reset
data: {"reason":"stale_cursor","views":["session","timeline","requests"],"latest_event_id":"evt_1200"}
```

## Requirements

### Requirement: SSE id 等于 canonical event_id

每条 SSE message MUST 使用 canonical `event_id` 作为 SSE `id`。

#### Scenario: 浏览器自动重连

- **WHEN** 浏览器用 `Last-Event-ID` 重连
- **THEN** server 可以从同一个 canonical cursor 继续发送

### Requirement: stale cursor 必须 reset

Server MUST 在 cursor 不可恢复时返回或发送 reset instruction。

#### Scenario: cursor epoch 过旧

- **WHEN** client 请求旧 epoch 的事件
- **THEN** server 告诉 client 需要刷新哪些 read models
- **AND** 返回最新可用 cursor

### Requirement: request event 必须触发 request view 刷新

Request lifecycle event MUST declare that request-related UI read models are stale.

#### Scenario: backend 请求工具确认

- **WHEN** backend emits a pending tool confirmation
- **THEN** daemon emits `request.opened`
- **AND** event `affected_views` marks `requests` view as affected
- **AND** clients refresh `PendingRequestsView`
- **AND** transcript renderer does not render the raw request event as assistant text
