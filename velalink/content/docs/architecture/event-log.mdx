# 事件账本

Event log 是所有 read models 的事实来源。v1 可以是本地 SQLite；未来可以镜像到 Pulsar，或由 Pulsar-derived ledger 提供同等语义。

## Event Envelope

```ts
export type VelaEventEnvelope = {
  event_id: string;
  epoch: number;
  seq: number;
  session_id: string;
  thread_id?: string;
  type: string;
  created_at: string;
  source: EventSourceRef;
  payload: unknown;
  raw?: RawProviderEvent;
};
```

## 排序模型

- `epoch` 表示 session event stream 的 generation。
- `seq` 是 epoch 内单调递增序号。
- `event_id` 是对外 opaque cursor。
- `type` 是 canonical event name。
- `raw` 保存 provider 原始数据，便于调试 provider quirks。

## Requirements

### Requirement: 明确排序

Daemon MUST 给每个 canonical event 分配 `event_id`、`epoch`、`seq`。

#### Scenario: 正常追加事件

- **WHEN** backend 输出一个 runtime event
- **THEN** daemon 在当前 epoch 下追加事件
- **AND** 分配下一个 seq

### Requirement: Epoch reset

当旧 cursor 不再能安全表示当前事件流时，daemon MUST 增加 epoch。

#### Scenario: 历史被压缩

- **WHEN** client cursor 所需的旧事件已被 compact 或替换
- **THEN** daemon 增加 epoch
- **AND** 要求 stale client 刷新 read models

### Requirement: Raw event 可保留但不可依赖

Daemon SHOULD 在安全时保留 raw provider payload；客户端 MUST NOT 依赖 raw payload 渲染主 UI。

#### Scenario: provider 行为异常

- **WHEN** canonical event 渲染不符合预期
- **THEN** 工程师可以检查 raw provider payload
- **AND** 无需改变 client API contract
