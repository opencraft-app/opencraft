# Agent Tool Streams

Tool stream 是 managed agent runtime 的核心协议面。它让 Codex、Vela Engine、ACP、Qoder-style managed agents 都能被投影成同一种 ChatUI agent work。

## 目标

- 工具调用是一等实体。
- 工具输出是一等流。
- Runtime event log 可以完整回放。
- ConversationView 可以展示 compact row、expanded terminal、chunk viewer。
- Provider raw event 只作为 adapter 输入和 diagnostics evidence，不进入普通 UI contract。

## Runtime Event Contract

### tool.started

建立工具调用实体。

```json
{
  "type": "tool.started",
  "payload": {
    "tool_id": "cmd_abc",
    "turn_id": "turn_123",
    "kind": "shell",
    "name": "shell",
    "title": "Running command",
    "detail": {
      "type": "shell",
      "command": "cargo test",
      "cwd": "/repo"
    }
  }
}
```

### tool.output.delta

追加工具输出分片。

```json
{
  "type": "tool.output.delta",
  "payload": {
    "tool_id": "cmd_abc",
    "turn_id": "turn_123",
    "stream_id": "stdout",
    "chunk_id": "cmd_abc:stdout:42",
    "sequence": 42,
    "delta": "test result: ok\n",
    "encoding": "utf8"
  }
}
```

Rules:

- `tool_id` is required.
- `stream_id` defaults to `stdout` only at adapter normalization time; projected events should carry it explicitly.
- `sequence` is per `tool_id + stream_id`.
- `chunk_id` is opaque and stable when the provider gives enough identity; otherwise runtime can derive it from tool/stream/sequence.
- `delta` is text after adapter decoding. Binary/artifact streams should use a separate artifact reference, not base64 text in `delta`.

### tool.completed / tool.failed

Terminate the tool call.

```json
{
  "type": "tool.completed",
  "payload": {
    "tool_id": "cmd_abc",
    "turn_id": "turn_123",
    "status": "completed",
    "exit_code": 0,
    "summary": "42 tests passed",
    "detail": {
      "type": "shell",
      "exit_code": 0
    }
  }
}
```

Completion events may repeat durable summary or structured result fields, but they should not be the only source of stream chunks.

## Projection Contract

ConversationView projects tool events into `agent_work`.

```json
{
  "kind": "agent_work",
  "id": "work:cmd_abc",
  "status": "running",
  "title": "Running command",
  "summary": "cargo test",
  "detail": {
    "type": "shell",
    "command": "cargo test",
    "cwd": "/repo",
    "streams": [
      {
        "id": "stdout",
        "label": "stdout",
        "kind": "terminal",
        "preview": "running tests...\nok\n",
        "bytes": 2048,
        "line_count": 80,
        "chunk_count": 42,
        "truncated": false,
        "latest_sequence": 42
      },
      {
        "id": "stderr",
        "label": "stderr",
        "kind": "terminal",
        "preview": "",
        "bytes": 0,
        "line_count": 0,
        "chunk_count": 0,
        "truncated": false
      }
    ],
    "view": {
      "default": "compact",
      "expanded": "terminal",
      "supports_chunk_view": true
    }
  }
}
```

Projection may provide preview strings and counts. Full chunk retrieval can be added as a narrow endpoint later, for example:

```txt
GET /sessions/{session_id}/views/agent-work/{agent_work_id}/streams/{stream_id}/chunks
```

That endpoint would still be a read model endpoint, not diagnostics.

## UI State Boundary

Renderer-owned state:

- whether a tool row is expanded;
- selected stream tab;
- terminal scroll position;
- selected chunk range;
- copied text selection.

Server-owned projection:

- whether a tool supports terminal/chunk view;
- stream IDs and labels;
- preview, counts, truncation;
- source event ranges.

## Provider Mapping

| Provider signal | Runtime mapping |
| --- | --- |
| Codex `item/started` with `commandExecution` | `tool.started` |
| Codex `item/commandExecution/outputDelta` | `tool.output.delta` |
| Codex legacy `codex/event/exec_command_output_delta` | `tool.output.delta` |
| Codex `item/completed` with `commandExecution` | `tool.completed` / `tool.failed` |
| Qoder `agent.tool_use` | `tool.started` or `request.opened` when confirmation is required |
| Qoder `agent.tool_result` | `tool.completed` / `tool.failed` |
| ACP tool call lifecycle | `tool.started` / `tool.updated` / `tool.completed` |

Provider method names stay inside adapter folders. The rest of the system consumes only canonical event types.

## OpenAPI Shape

First schema slice should add reusable components rather than broad endpoint changes:

- `ToolKind`
- `ToolOutputStreamId`
- `ToolStartedPayload`
- `ToolOutputDeltaPayload`
- `ToolCompletedPayload`
- `AgentWorkViewHint`
- `AgentWorkStreamSummary`

Then wire them into:

- `VelaEvent.payload` documentation and examples for `tool.*`;
- `AgentWorkShellDetail.streams`;
- future stream chunk read endpoint when UI needs lazy full-output loading.

## Requirements

### Requirement: tool_id is stable

All `tool.*` events for the same provider tool invocation MUST share the same `tool_id`.

#### Scenario: command emits output before completion

- **WHEN** adapter receives command output delta
- **THEN** it emits `tool.output.delta` with the same `tool_id` as the command started/completed events

### Requirement: output delta is append-only

Projection MUST append tool output deltas by `tool_id + stream_id + sequence`.

#### Scenario: command emits multiple stdout chunks

- **WHEN** runtime stores three `tool.output.delta` events
- **THEN** ConversationView stream preview reflects all chunks in sequence
- **AND** later chunks do not overwrite earlier chunks

### Requirement: tool stream does not become assistant text

Tool output MUST NOT be appended to assistant message text.

#### Scenario: shell command prints markdown

- **WHEN** shell stdout contains markdown-looking text
- **THEN** ChatUI renders it inside the tool terminal view
- **AND** assistant markdown row is unchanged

### Requirement: long output supports partial viewing

Projection SHOULD expose enough metadata for chunk/paged views without loading unbounded text into the main conversation window.

#### Scenario: command prints megabytes

- **WHEN** tool output exceeds projection preview limits
- **THEN** AgentWork stream summary marks `truncated: true`
- **AND** UI can request a chunk view endpoint once implemented
