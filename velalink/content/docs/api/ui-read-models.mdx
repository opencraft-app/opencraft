# UI Read Model API

velaChat 的 API 分成两层：

- **Agent 基础 API**：事实和控制面，例如 input events、canonical events、backend capability。
- **Diagnostics API**：审计和调试面，例如 diagnostics timeline、trace。
- **UI Read Model API**：由 projector 派生的展示面，例如 conversation、requests、diffs、sessions。

OpenAPI 是唯一 client-facing wire contract。MDX 只解释行为边界；字段名、required 规则、枚举和 endpoint 以 `public/openapi/velachat.v1.yaml` 为准。

```txt
Canonical event log
  -> ConversationView      # chat main list: messages, turn meta, agent work, status
  -> PendingRequestsView   # permission / question dock
  -> DiffReviewView        # file review lane
  -> SessionView           # current session metadata and operations
Diagnostics projections
  -> DiagnosticsTimeline   # audit/history, not normal UI input
  -> DiagnosticsTrace      # diagnostics/debug
```

## ConversationView

`GET /sessions/{session_id}/views/conversation` 是普通 Chat UI 主列表的唯一 read model。

它不是 raw timeline，也不是前端把多个窄 view 拼出来的临时模型。Daemon/projector 已经把 provider 差异归一化成一个稳定的 `items[]` window：

| Item kind | 语义 | 典型渲染 |
| --- | --- | --- |
| `user_message` | daemon 接受的用户输入 | user bubble、附件/图片 |
| `assistant_message` | assistant 正文，可 streaming | markdown response |
| `turn_meta` | turn 生命周期和计时 | `处理中` / `已处理 Xs` header |
| `agent_work` | 工具、命令、搜索、读写文件、warning 等 agent work | Synara/Codex 风格 work rows |
| `status` | 用户可理解的状态或错误摘要 | inline status row |

`agent_work.detail` 是 normalized UI-safe union，例如 `shell`、`read`、`write`、`edit`、`search`、`fetch`、`generic`。完整 provider raw payload 属于 diagnostics timeline 或 trace，不能塞进普通 UI read model。

Turn header 只来自 `turn_meta`。Client 不能从 assistant streaming 状态、tool 数量、activity summary 或 provider raw event 反推 `Worked for` / `处理中`。

## Windowing

Conversation window 是 item window，不是 event window：

```txt
GET /sessions/{session_id}/views/conversation?direction=tail&limit=80
GET /sessions/{session_id}/views/conversation?direction=before&anchor_item_id=item_x&limit=80
GET /sessions/{session_id}/views/conversation?direction=after&anchor_item_id=item_x&limit=80
GET /sessions/{session_id}/views/conversation?direction=around&anchor_item_id=item_x&limit=80
```

规则：

- `direction=tail` 拉尾部，不带 anchor。
- `before` / `after` / `around` 必须带 `anchor_item_id`。
- `item_id` 是 opaque view anchor，client 只能原样传回。
- 未知 anchor 返回 `409 stale_cursor`，client 丢弃本地 window 并重新拉 tail。
- `limit` 以 OpenAPI 的 `Limit` 参数为准。
- Response 的 `window` 用于列表分页和滚动恢复。
- Response 的 `cursor` 是 canonical event cursor，用于 SSE reconnect、stale detection 和 reset。

这条边界给 Web、桌面、移动端同一套列表协议：少消息时直接渲染，多消息时前端可以做 Paseo-style head/tail、partial virtualization 和 bottom anchor；服务端不要求客户端自己 replay raw events。

## Live Updates

推荐流程：

1. Fetch `SessionView`。
2. Fetch `ConversationView` tail window。
3. Fetch `PendingRequestsView` 和其他辅助 views。
4. Subscribe `/sessions/{session_id}/events/stream`。
5. 根据 SSE 事件的 `affected_views` 局部刷新或应用隔离的 live overlay。

Day 0 前端可以对 `assistant.message.delta` 做本地 overlay，以改善流式体感；overlay 必须隔离在 client adapter，不能让 React 组件重新实现 projector。更省流的终局可以增加 projected read-model patch stream，但这不是普通 UI 组件的职责。

## Timeline And Trace

`GET /sessions/{session_id}/diagnostics/timeline` 和 `GET /sessions/{session_id}/diagnostics/trace` 是 diagnostics API：

- timeline 适合 audit、replay、debug、export。
- trace 适合 provider raw event、normalization、command/idempotency 链路排查。
- 普通 ChatUI 不用它们拼消息、工具或 turn header。

## Requirements

### Requirement: UI API 不写事实

- **WHEN** client 请求 `/sessions/{id}/views/conversation`
- **THEN** daemon 返回 projected `ConversationView`
- **AND** 不追加 canonical event

### Requirement: Conversation window 使用 item anchor

- **WHEN** client 上拉旧内容
- **THEN** client 使用 `direction=before&anchor_item_id=<first_item_id>`
- **AND** daemon 返回该 item 之前的 projected items
- **AND** client 不需要使用 canonical event cursor 拼 UI window

### Requirement: agent work 归一化后进入 conversation

- **WHEN** backend 输出 tool、command、search、read/write、warning
- **THEN** adapter/runtime 先映射成 canonical events
- **AND** projector 再输出 `agent_work` item
- **AND** UI 不读取 provider raw payload 补工具展示

### Requirement: Mobile 使用同一 read model

- **WHEN** mobile 或远程 WebView 打开 session
- **THEN** 它读取同一个 `ConversationView`
- **AND** 可以只拉小 window
- **AND** 不需要一套单独的 mobile transcript 协议
