# 浏览器注解 V2：选择、设计意图、复杂页面

状态：A/B/C 与受控 B2 已实现并在本地验收，尚未部署；具体覆盖和限制见 `browser-annotation-v2-acceptance.md`。下文保留原设计与分期依据。

复核补充：见第 9–14 节。原方案覆盖选择与证据协议，但不等于达到 Codex 的完整体验。
第 9–14 节修正生命周期、编号和区域策略的粗粒度表述，并将实时试改作为需要单独排期的 B2 阶段，不暗中扩大首版实现承诺。

## 1. 目标与明确不做

让用户准确表达“改哪里、几处有什么关系、希望怎么改”，让 Agent 收到可解释、可校验的证据。

- 保持现有主题、共享控件、手机底部编辑面板、桌面侧面板；不复刻 Codex 的独立窗口体系。
- 保留页内叠层，远程标记随页面一起合成；客户端只画尚未确认的拖拽预览，不画持久定位框。
- 不承诺历史视频帧精确拾取、不强行穿透跨域/closed Shadow DOM、不从 DOM 猜源码行号。
- 样式编辑第一版只表达意图，不修改网页、不自动改源码；实时试改属于独立后续项目。

## 2. 核心模型：一条批注，多种目标

```ts
type Selection = ElementSelection | RegionSelection | TextSelection;
type AnnotationV2 = {
  schemaVersion: 2;
  id: string;
  number: number;
  surfaceId: string;
  selections: Selection[];
  comment: string;
  styleIntents: StyleIntent[];
  evidence: EvidenceAttachment[];
};
```

每个 Selection 有独立 selectionId、文档身份、frame 路径、证据采集时间和生命周期状态。
状态为 live / stale / unsupported；“旧证据仍可阅读”和“标记仍可定位”必须分开。
主文档/子 frame 导航、控制权丢失、草稿切换后，旧响应不得写入新会话。
文档身份用宿主维护的 generation，不以 URL 相同或页面声称的 revision 证明同一文档。

编号：批注 1 内的目标显示 1A、1B、1C。编号在提交前允许整理，已提交证据保持原编号。
默认一条批注最多 8 个目标，一个草稿最多 8 条批注、32 个目标；超限显式提示，不静默截断。

### 2.1 元素选择

保留现有点选、选父级、bindingKey 和敏感文本处理。加入“添加目标”，不会因下一次点击丢掉前一次选择。
同一活文档内重复选择同一 bindingKey 默认去重；点击目标列表项定位已有项。

### 2.2 区域框选

- 桌面：显式进入区域模式后拖出矩形；鼠标滚轮仍可滚动。
- 手机：进入区域模式后单指拖框，松手出现四角手柄；用显式“移动页面”切换回单指滚动，不抢浏览器双指缩放。
- 拖拽期间不自动滚屏；拖拽被取消、页面几何改变或越过可支持坐标边界时，取消本次框选，不提交旧矩形。
- 提交前页端确认实际区域并回显“已选区域”。客户端拖拽框是暂态反馈，不是 Agent 证据。
- 第一版是特定页面状态下的视觉区域，不伪装成随内容移动的元素。滚动、缩放、布局失效后停止显示原框，保留已确认的历史证据。
- 允许区域横跨多个元素，但不跨 frame 拼一个逻辑 DOM 目标。
- 对 canvas、图表、空白和图片优先用区域截图；没有截图能力时说明限制，不生成“看不到的区域”假证据。
- 截图沿用显式预览确认。拒绝图片时仍可提交文字和区域位置，但提示缺少视觉证据；绝不自动附整页截图。

### 2.3 文本选择

- 使用独立的只读文本 Range 模型，不把“点到段落”伪装成选中了用户指定的句子。
- 桌面拖选；手机拖动选区端点，提供选中内容预览。页面输入控件不进入文本选择，不更改 selection/value/focus。
- 本地预览由页端绘制并拦截选取手势；远程视频表面无法直接依赖客户端原生 Selection，需要宿主将起终点转为页端 Range。
- 证据保存精确引文、有限前后文、起终节点路径与偏移；长引文显式限制（默认 2,000 字符），敏感范围拒绝采集。
- 同文档内用 Range 计算多行 rect，禁止用一个大矩形跨过无关文字；文本变动先校验原文，失配标记过期，不悄悄绑到同名文本。
- 第一版只允许一个 frame、一个可访问树范围内的选区；跨 frame/Shadow 边界提示分开选择。

### 2.4 多选与关系

一条批注可混合元素、区域、文本；第一版限定同一 surface、同一主文档生命周期，允许其已授权子 frame。
不同标签页用不同批注，避免当前页面、截图与目标混淆。
交互不强迫依赖 Shift：桌面可快捷多选，手机始终有“添加目标”和逐项删除。
“对齐”“统一间距”首先作为用户评论关联 1A/1B，不引入第二套自动执行命令系统。

## 3. 设计意图：观察值与要求分开

### 第一版：读取当前样式，填写目标值，生成差异

元素选中后提供折叠的“样式”区，只按需读取白名单：文字颜色/背景色、字号/字重/行高、padding/gap、圆角、宽高。
白名单禁止 URL、任意 CSS 文本、自定义脚本、全量 computed style 导出。

```ts
type StyleIntent = {
  selectionId: string;
  property: AllowedProperty;
  observedComputedValue: string;
  requestedValue: string;
  observedAt: string;
  documentGeneration: string;
};
```

- 使用共享颜色/尺寸控件，允许合法单位和 auto 等明确支持的值；不能把所有属性都当作 px。
- computed 值不代表源码声明：例如 gap 当前 16px，源码可能是 token 或 rem。Agent 文本明确写“观察到的计算值”，不声称找到了 CSS 原始声明。
- 提交时重读活目标；值已变化则要求重新确认观察值或移除该条样式要求，不能静默更新用户认可的前后差异。
- 多元素批量设置会为每个目标保留各自原值，混合值展示“多个值”，不拿第一个值代表全部。
- 区域不能读取样式；文本首版只承载引文及修改说明，不虚构统一的文本样式来源。
- 第一版不做页面实时试改，因此没有隐藏的 inline style 修改，也不承担网页 React 状态和撤销冲突。
- 如后续增加试改，必须单独设计所有权、站点并发写入检测、撤销和控制权要求；不能简单保存/恢复整条 style 属性。

## 4. frame 与 Shadow DOM：能力驱动，不降低隔离

### 4.1 表面能力协商

每个 surface 返回 element / region / text / multiSelect / styles / capture，以及可达 frame 范围。
菜单只展示支持能力，受限入口解释原因。自有 HTML 注解能力不自动意味着有截图能力或 browser_use 工具访问权。

第一阶段支持主 frame、可访问的同源子 frame、open Shadow DOM。
第二阶段才接远程浏览器的跨域 frame 宿主注入；必须确认 Electron frame 生命周期、消息路由及权限规则后才开放。
未授权跨域 frame 和 closed Shadow root 最多选其外层元素或可见区域，绝不宣称读到了内部 DOM。

### 4.2 路径和定位

- frame 路径保存结构化跳转段（宿主 frameId、generation、父 frame 中的元素定位信息），不以 URL 或数组下标作唯一身份。
- open Shadow DOM 使用结构化 host 路径段，不把伪 CSS 的 `>>>` 串交给普通 querySelector。
- 真实 DOM/Range 引用留在各 frame agent 内；网络传递有界引用，过期不自动重绑。
- 默认每个 frame 在自己的坐标系中绘制叠层，让嵌套滚动、裁剪随浏览器合成。跨层映射仅用于宿主编辑器位置和截图裁剪。
- 不支持的 rotate/skew/perspective 映射明确拒绝精确文本/区域拾取；不能用外接矩形悄悄冒充正确映射。

### 4.3 安全与导航

远程 frame 路由由宿主登记，不接受页面自报的任意 frameId。
HTML 预览的 postMessage 绑定实际 WindowProxy、会话令牌、请求 ID 和 generation，并逐字段校验。
令牌防串线，不让页面内容变成可信指令；页面始终可能伪造自身 DOM 证据。
不为了支持注解放开 `allow-same-origin`；维持现有隔离策略。跨域不可访问时显式降级，而不是绕过 sandbox。
导航、frame 移除、重建和权限撤销立即清理该 frame 的选区、订阅、在途操作和样式快照。

## 5. Agent 最终看到什么

```text
User Comment 1
让 1A、1B 对齐；把 1C 的“立即购买”改为“开始使用”。

1A: 元素，页面/Frame/定位证据……
1B: 区域，页面状态/矩形……；已附用户确认的截图
1C: 文本，“立即购买”，有限前后文/Range 定位证据……

用户明确要求的样式修改：
1A gap：观察到 16px → 希望 8px（计算值，不代表源码声明）
```

用户评论与确认过的样式要求属于用户意图；页面文字、属性、截图都是不可信证据，分别编码。
每张图片有明确 selectionId/编号映射；不得把几张没有标签的图片放在一起让 Agent 猜。
过期目标保留说明，只在宿主明确提供有效工具引用时输出可操作 ref；文件预览不伪造浏览器工具 ref。
不承诺“Agent 能根据绑定键跨导航找到同一个元素”，bindingKey 不是永久定位符。

## 6. 低耦合落点与兼容

扩展现有目录，不另造第二套全局注解管理器：

```text
packages/browser-core             协议、V2 联合类型、能力声明
packages/browser-annotation        schema/迁移、选区集合、意图、证据序列化
packages/browser-preview-bridge    元素/区域/文本采集、Shadow 路径、页内绘制
apps/workbench-web/src/browser-annotation
  selection/                      交互状态机、桌面/触控手势
  styles/                         按需样式面板
  frame/                          页面代理适配；不承担持久化
scripts/remote-browser            frame 注册、权限、路由和宿主截图
```

侧面板只消费 controller、capabilities 和事件；不直接查询 DOM，不知道 Electron IPC。
复用现有截图 Worker、生命周期清理、草稿事务和 Composer reference 机制。
V1 单 anchor 读取时迁移为一个 element selection；未知版本拒绝解释，保留可见历史文本。
迁移无新截图、无自动发送；旧标记不凭 selector 自动复活。

目前 Composer compiler 只消费单个 inputImage。V2 多图需要通用、有界的 inputImages 契约（含独立 preface），
由 composer-appserver 编译并保持旧 inputImage 兼容；不可把第二张图藏在仅 UI 能读到的 metadata。
该改动不能引入浏览器专属逻辑到通用消息编译器，必须测试不同消费端的有序多图传递。
图片建议最多 4 张/批注、8 张/草稿，每张沿用 300 KiB data URL 上限；另设总草稿序列化预算，包含 metadata，防止突破现有 4 MiB 存储边界。

## 7. 手机呈现

```text
┌───────────────────────────┐
│ 浏览器页面       [完成选择] │
│       ①A      ①B           │
├───────────────────────────┤
│ 元素   区域   文字          │
│ [1A 按钮 ×] [1B 区域 ×] [+]│
│ 说说这些地方要怎么改…       │

```

选择时收起键盘，编辑时保留目标清单；键盘出现通过 visualViewport 避让，不把网页强制滚到另一处。
区域模式显式提供“移动页面”，避免单指拖框与页面滚动互相争抢。
无悬停必需操作、无右键必需操作，删除/撤销/切换目标都有可触控入口，复用主题触控尺寸。

## 8. 顺序、风险与验收

### A：共同底座 + 区域/多选
先落 V2 schema、文档身份、能力协商、多图编译与预算，再做区域及多选。
验收：鼠标/手机模式切换不误点页面；图片编号严格对应；过期、取消和草稿切换无残留发送。

### B：文本 + 只读样式意图
先验证远程 Range 拾取原型，再做端点手柄；样式面板不试改网页。
验收：中文/英文/多行/双向文字、嵌套标签、滚动、重排；输入/密码控件排除；观察值与要求值清晰区分。

### C：同源 frame + open Shadow DOM
跨域宿主注入作为单独可开关实验，不计入 C 的完成条件。
验收：同 URL 导航、frame 重建、跨层滚动、不同缩放、坐标拒绝降级、伪造消息和权限撤销。

### 全程性能与安全门槛
- 关闭注解后无注解 RAF/观察器/Worker；被隐藏的远程页面显式暂停。
- 单个 surface 最多一个拾取在途，仅保留最新意图；文本拖选合并中间位置，pointerup 的最终位置必须确认。
- 不在每帧遍历整页 DOM，不常驻监听全站 subtree；样式仅按需读取，图片继续离主线程处理。
- 活跃状态在相同页面/视口/标记数量下对比已发布版本的 CPU、长任务、内存；没有实测前不写性能承诺。
- 测试 32 目标、反复开关和多标签切换；销毁后对象/消息/图像不持续增长。
- 单测、实际组件、生产压缩产物、安装后的 Electron、真实登录 Shell、手机真机分别记录，不能用模拟器覆盖所有验收名义。

### 实施前先验证的三个原型
1. 远程视频表面的文本端点拖动：真实手机是否足够可控，弱网如何反馈待确认位置。
2. 区域采集能否用宿主 frame/viewport 元数据可靠拒绝过期状态；不能仅凭客户端尺寸声称对齐历史帧。
3. 同源 frame/open shadow 的拾取与页内绘制，以及受限 frame 的降级是否一致。

这些不确定性应在扩大 UI 前用独立场景验证，不先承诺全站全浏览器支持。

## 9. 再对标：实现 A/B/C 后仍差在哪里

### 证据边界

本次静态复核的是本地已解包 Codex 26.831.21537，不是对最新版、所有账号或手机支持的声明。
参考文件摘要与搜索锚点保存在本地调研记录，不随源码分发。以下区分“看到实现”和“产品运行已验证”。

| 项目 | 本地 Codex 代码证据 | 原方案完成后的状态 | 结论 |
|---|---|---|---|
| 元素/区域/文本 | 存在三种 anchor、文本 locator、多行 selectionRects | 有三类目标，手机交互尚需实测 | 数据类别可补齐，不能据此声称体验追平 |
| 同一批注多个目标 | additionalSelections；element/region 分支携带附加目标，text 分支独立处理 | 原方案允许三类任意混合 | 我们的混合文本多选是额外设计，不是已证实的 Codex 行为 |
| 页面设计试改 | 设计草稿生成样式、更新页面文字；original view 切换移除设计效果 | B 只采样式、写目标值，不试改 | 实现后最大的明确产品差距 |
| 文本内容改前/改后 | 设计草稿包含文字原值与新值，页面文字预览有恢复逻辑 | 普通评论描述换字 | 需要独立 replacement intent，不应只有选中文字 |
| 页面语义 | elementName/elementMetadata；显式页面 annotation API/事件；字段有数量和大小限制 | 主要是 DOM、路径、短文本 | 有接入的页面中，业务语义仍会更丰富 |
| 特定文档 | 有 Google Docs documentContext，包含文档和页签身份等 | 通用 DOM，无文档适配 | 不能因三种选区完成就声称所有文档能力接近 |
| frame/Shadow | framePath/frameUrl、shadow 路径及重定位逻辑 | C 支持同源/open；跨域另行验证 | 需要按能力范围对比，不能宣称 Codex 跨域全覆盖 |
| 截图策略 | 有 always/necessary 设置，以及图片关联数据 | 每次显式预览确认，图片数量有界 | 有意选择隐私与成本边界，不是必须照抄 |
| 可操作工具引用 | 已检查的批注文本主要是 URL/selector/path | 我们可提供受文档身份约束的 ref | 尚未证明 Codex 有永久可操作引用；不可编造该差距 |
| 源码行号 | 这里没有足够证据证明普遍自动映射 | 只接受可验证的项目来源提示 | 不算已确认的落后项 |

Codex 的设计预览实现使用页面 MutationObserver、样式节点和临时属性，并带文字恢复逻辑。
这证明它具备试改机制，不证明在所有站点都无副作用，更不意味着应复制它的观察范围和写入方式。

## 10. 交互规格补全：一条批注从选择到发送

### 10.1 状态机与草稿所有权

`browse → selecting → resolving → reviewing → composing → ready → submitting → attached`

- browse：页面正常交互；selecting：只拦截当前选择手势；resolving：等待页端确认，不假装已选中。
- reviewing：确认目标、图片和编号；composing：写评论/修改意图；ready：准备加入当前对话草稿。
- submitting/attached 指“加入 Composer 草稿”，不是“消息已经发送”，也不是“Agent 已处理”。
- 页面侧编辑器拥有未提交的暂存事务；加入成功后 Composer 成为草稿唯一持久化 owner。
- 再编辑 Composer 批注时以副本开始；保存原子替换，取消不改变原引用。禁止面板和 Composer 各自自动保存一份。
- 短请求不闪提示；超过约 300ms 展示“正在确认选区”，超过 3s 给重试/取消，不无限 spinner。阈值是初始产品预算，需实测调整。

### 10.2 区分两种失效

原来的 live/stale/unsupported 不足以表示移动到屏幕外。改成两个维度：

- targetState：bound / detached / document-replaced / unsupported。
- evidenceState：current / snapshot / needs-review；另外独立记录 inViewport。

滚动出屏不等于目标失效；同文档元素还在就保留绑定，显示“当前不在画面内”，可显式定位。
文档替换、节点替换则停止活标记。历史引文、已确认图片仍可阅读，标记“采集于此前页面”，不能冒充当前状态。
不因普通 mutation 全部标过期；优先验证所选目标的身份、文本和几何，避免高度动态页面不可用。

### 10.3 多选操作细节

- 区分“添加目标”和“替换当前目标”；默认点下一处不覆盖前一个已确认目标。
- 主目标始终明确；选父级只调整当前目标，不改动其余目标。
- 点已有标记打开对应目标，不新增重复目标；标记重叠时先显示目标列表，不让最后绘制者永远抢点击。
- 第一个版本不自动合并重叠区域；目标列表显示各自缩略图/引文，用户决定保留哪一处。
- 文字/评论不为空时取消整条批注需要确认；撤销最后一次选择独立于撤销评论输入。
- selectionId 永久不复用。出现文字引用或确认截图后，1A/1B 等可见标签也冻结；删除 1B 后允许留下 1A/1C，不能把原 1C 悄悄改成 1B。
- `Escape` 优先取消当前拖拽，再退出当前编辑；只有无未保存内容时才直接退出注解。手机有等价按钮，不依赖快捷键。

### 10.4 文本修改应是显式意图

新增可选 TextReplacementIntent：selectionId、用户确认的 beforeText、afterText。
UI 提供“替换为…”输入，不让 Agent 从一大段评论猜哪部分是新文案；空字符串表示明确删除，不等于未填写。
保存空白、换行、emoji 和 Unicode 原样；用于展示的折叠空白文本不能作为实际替换依据。
beforeText 来自页面并保持证据属性；只有 afterText/用户确认动作表达修改意图。仍由 Agent 检查具体源码，不直接全局字符串替换。
首版排除输入框是有意的能力差异：Codex 已看到 form-control locator 分支；如以后开放，只允许非敏感控件，不能读取密码或页面隐藏值。

### 10.5 发送与失败

- 加入对话失败时保留评论、目标及已确认图片；重试同一事务不会生成重复批注。
- 用户发送聊天消息时固定一份不可变证据快照；随后页面变化不重写已经发送的内容。
- 多图编译失败必须报告具体目标，禁止悄悄丢图后仍显示“图文已发送”。用户可明确移除失败图片再发。
- 网络不确定沿用现有消息投递/确认机制，不因浏览器恢复自动重发批注。
- 不新增“已修复”假状态。只有 Agent 的回复或后续验证结果才能描述处理情况，附加到 Composer 不代表执行完成。

## 11. 视觉证据：不只是一张裁剪图

### 11.1 目标和周边关系

紧贴目标的裁剪适合看按钮，却可能解释不了“对齐”“这块太空”。为此增加两档明确选择：

- 目标图：当前默认，尽量少带无关内容。
- 周边图：用户显式开启并预览，包含所选目标之间的空间关系；不自动扩大到整个页面。

同一画面中的 1A/1B 可共享一张关系图，但图片记录关联的 selectionIds、裁剪坐标、采集文档身份。
不同 frame/不同采集时刻的目标不能伪装成同一时刻的合成现场。
截图中的编号必须和文本对应；颜色只作辅助，不能靠蓝/绿区分所有目标。
用户可选择重新采集，但重新采集后必须再次确认，不能把旧预览换成新图片静默发送。

### 11.2 区域随滚动的修订

原稿“滚动就停止原框”太保守。按事实拆开：

1. 普通文档区域可保存采集时的 document CSS rect；同文档单纯窗口滚动可投影这个矩形，但要保持“区域快照”语义。
2. 嵌套滚动、sticky/fixed、变换或布局发生无法确定的变化时，不能声称矩形仍对应原内容；收起活框，保留缩略图和“重新圈选”。
3. 区域不自动变成其中心点下的 DOM 元素；历史区域截图不因活框隐藏而被删除。

远程拖拽始终是“客户端预览 → 服务端确认”。未实现帧身份校验前，不能把两次几何一致当成与用户看到的历史视频帧一致。
需要宿主暴露 frame/document/viewport 关联信息；遇到明显变化要求重选。协议细节先通过原型验证，不只给现有 point 增加一个无校验的 frameId 字段。

### 11.3 预算与隐私

截图预算按编码后的真实字节和最终序列化大小双重检查，不按图片分辨率估计存储大小。
整个草稿仍遵守总预算；超预算提示选择压缩、移除哪张图片或拆分消息，不能自动丢掉最后几个目标。
周边图的隐私提醒更强；文本脱敏不等于图像脱敏。后续像素遮罩必须是独立、可验证的功能。

## 12. B2：真正缩小设计体验差距的可选阶段

B 阶段的只读样式意图仍保留为安全起点。但如果目标是接近 Codex 的设计体验，应明确增加 B2，而不是称 B 已对齐。

### 12.1 用户流程

选元素 → 调整少量属性/简单文案 → 页面临时显示效果 → 按住/切换“看原样” → 加入修改请求。
按钮明确区分“预览效果”和“请求 Agent 修改”。前者不保存源码，不代表最终修改完成。
保留独立清单列出改了哪些属性、哪些目标，支持逐项恢复原值；“恢复全部”只撤销当前预览会话拥有的修改。

### 12.2 受控预览的技术门槛

- 先限定受控自有页面/明确可试改的 surface；任意外部网站默认只读。是否开放范围需要单独评审。
- 用 scoped 属性规则/隔离样式表表达允许的属性，不直接重写元素整个 style；按文档、frame 和会话持有 ownership。
- CSS 继承、布局、副作用和 !important 无法靠 scoped 规则完全消除；若 CSP 或页面样式使试改失败，明确显示“未应用”，不能伪造成功。
- 样式变更要求宿主确认目标身份和当前控制权；无控制权仍允许写修改意图，不允许页面试改。
- 文字试改第一版只支持可安全处理的简单文本节点；不对带复杂子元素/事件绑定的容器覆盖 textContent。
- 进入原样视图只暂时撤销本会话试改，离开后恢复待确认试改；文档重建后不自动重放。
- 并发页面修改时停止并提示冲突，不以保存的原值覆盖站点的新状态。文本恢复需比较当前值是否仍是本会话最后写入值。
- 导航、失去控制权、关闭面板、取消和会话销毁都要释放临时属性/规则；不能留下后台持续观察器。
- 截图区分“原页面”和“临时试改预览”；发送后若移除试改，证据仍保留其采集状态，不让 Agent 以为源文件已变。

### 12.3 绝不许混淆的三种值

1. 观察值：页面当时的 computed style/文字。
2. 预览值：本次临时应用的效果，可能因层叠/布局没有实际生效。
3. 用户要求值：确认要交给 Agent 的修改目标。

“16px → 8px”仍不代表发现了项目中的 spacing token 或 CSS 源文件。源码定位另行验证，不能用字段名称 provenance 暗示已经拿到来源文件。

## 13. 页面语义与 Agent 可读结果

### 13.1 一个后续小模块，比堆更多 selector 更有价值

可以增加独立、按需的 annotation context provider：自有页面显式声明元素业务名称和少量元数据。
例如“结算页主按钮 / variant=primary / component=CheckoutAction”，比 `div > div > button` 更容易解释。

- 采用我们自己的 API/属性命名，不照搬第三方品牌接口。
- 默认仅显式接入页面；有限标量、键数量和字节预算；拒绝 getter、原型污染键及函数等数据。
- 页面请求打开编辑器只能作为建议，必须经过宿主策略和可见 UI；不可自动发送、抢焦点或覆盖当前草稿。
- 页面提供的 initialComment 不直接成为可信用户指令，显示为待确认建议；metadata 永远是页面证据。
- 元数据中的 source 只能是提示，不能触发任意文件读取。项目路径必须在已授权工作区解析验证。
- 特定文档适配器独立于通用 picker；先不承诺支持 Google Docs/Office，按用户需求和可测试场景接入。

### 13.2 Agent 消息顺序

一条批注的消息必须能独立理解：用户要求 → 目标列表 → 页面证据 → 明确编号图片 → 必要的限制说明。
样式/文案意图逐个引用 selectionId 和可见标签；一张图片覆盖多目标时列全关联编号。
frame URL 可辅助识别，但不输出凭据、敏感 query/fragment；显示 URL 和真实导航身份是不同字段，不能把凭据放进截图说明。
带有效工具 ref 时输出绑定的工具能力；没有 frame 级工具支持时只给证据，不能因为采集支持子 frame 就伪造可点击 ref。
格式测试必须检查最终 provider input，而不只检查 UI chip 或 reference.metadata 中“看起来有数据”。

### 13.3 准确操作与安全重定位

过期后可以发起重新定位建议，但不能静默替换原目标。
同文档中的活引用优先；若需 selector/文字恢复，候选必须唯一且满足原证据约束，用户确认后产生新的绑定。
失败时保留旧证据，向 Agent 说明目标无法实时定位。多候选绝不随机取第一个。
该策略比仅按 URL/selector 恢复更保守，是有意选择，不为了“看起来一直能用”牺牲目标准确性。

## 14. 完成标准：不再只数功能和单测

| 用户任务 | 必须通过的端到端行为 | 失败时应看到什么 |
|---|---|---|
| 两按钮对齐 | 选择 1A/1B，写关系要求，必要时预览同一张周边图，最终 input 能辨认双方 | 哪个目标/哪张图失效，保留另一方和评论 |
| 修改一段文案 | 中文多行选区与 replacement intent 原样进入消息；取消不改变网页 | 文字已变化，请重新确认；不替换错句 |
| 调间距 | B 给清晰计算值差异；B2 能看原样/预览并恢复 | 试改未生效或站点已变化，不显示假成功 |
| iframe 内控件 | 目标属于正确 frame，父/子滚动后仍正确，导航后旧引用失效 | 无权访问或已换文档；外层区域降级明确 |
| 多目标回改 | 删除中间目标、重开编辑、取消、再次保存，标签/图片/意图不串位 | 不可保存时不损坏原草稿 |
| 手机完整使用 | 选区手柄不误滚动；评论输入避开键盘；横竖屏后不误选；无需鼠标专属操作 | 未确认位置与已确认目标视觉不同 |
| 断网/接管 | 断线保留草稿；Agent 接管后停止试改；恢复不自动重发 | 只读/待重连状态，用户文字仍在 |
| 发送后回看 | 已发送证据是原快照；图文顺序正确，页面后续变化不改历史消息 | 历史证据标识，不承诺仍能实时定位 |

### 执行顺序调整

1. A0：schema/状态所有权/最终 input 多图测试/预算/编号冻结。
2. A1：区域 + 元素多选 + 编辑删除 + 截图关系图；先做最常见的“这几处一起改”。
3. B1：文本选取 + replacement intent + 只读样式意图；先验证手机远程端点体验。
4. C1：同源 iframe/open Shadow 和工具能力边界；复杂变换/跨域保持显式限制。
5. B2：受控实时试改/原样对比，这是追近 Codex 设计体验的单独里程碑。
6. D：自有页面语义 provider；文档专用适配按真实需求增加。

结论：A0–C1 完成后，可明显补齐通用批注的表达能力；B2 未做前，不能称设计体验对齐。
手机远程链路、站点兼容和长期性能必须靠实测，不用对方的桌面源码替我们背书，也不给未经测量的“达到百分之多少”评价。
