# 腾讯云 IM 适配

## 1. 使用方式

一个生产环境使用一个腾讯云 IM SDKAppID。所有 Server 共用该应用，Server 级授权
由平台 Member/Channel 事实与 Community/Topic membership 共同保证。

开发、测试、生产使用不同 SDKAppID。v1 不实现多 SDKAppID 分片、用户自带 IM
应用或每租户独立腾讯云账号。

后台持有部署级 IM 管理员密钥，用于导入账号、管理 Community/Topic、发送业务通知
和签发 UserSig。管理员密钥永不下发。

## 2. 对象映射

| 平台 | 腾讯云 IM |
|---|---|
| Account | 一个普通 Human UserID |
| Human Member | 同一 Human UserID 的 Community membership |
| Agent | 一个普通 Agent UserID |
| Agent Runtime | 使用 Agent UserID/UserSig 登录的无 UI 客户端 |
| Server | 一个启用 Topic 的 Community |
| `#全员` | Community 根会话 |
| 普通 Public Channel | Private Topic（平台公开发现、独立成员） |
| Private Channel | Private Topic（平台私密发现、独立成员） |
| Human↔Human DM | 网络级 C2C |
| Human↔Agent DM | C2C |
| Task/Reminder 通知 | 平台通知账号发给 Agent 的 CustomElem |
| Computer | 无 IM 映射 |

v1 不使用 Robot/Chatbot、`@RBT#` 身份或 Robot 专属回调。

## 3. UserID

Human：

```text
u_<29-char-base32-suffix>
```

Agent：

```text
a_<29-char-base32-suffix>
```

稳定算法：

```text
input  = uint32be(len(utf8(opaqueId))) || utf8(opaqueId)
digest = HMAC-SHA256(kindSubkey, input)
suffix = BASE32-NO-PADDING(digest)[0:29]
```

规则：

- SDKAppID 内全局唯一；
- 不包含邮箱、Server slug 或个人信息；
- Human/Agent 使用不同派生子键和前缀；
- 创建后持久化，不因密钥轮换重新计算；
- root key 只存在 Secret Manager。

## 4. Human 直连

Human 调用 `/v1/me/im/session` 获得短期 UserSig，然后登录一次腾讯 SDK：

- 腾讯 SDK 提供会话列表、历史、未读、附件和推送；
- 一个 UserID 自动聚合其加入的多个 Community；
- Server 切换只是客户端视图过滤；
- 平台 logout 时客户端同步调用 IM SDK logout；
- Human↔Human C2C 是网络级私聊。

平台不提供消息代理、消息表或 C2C ACL 镜像。

## 5. Agent 直连

Computer 为当前 launch 调用 `/v1/computer/agents/{agentId}/launches` 或 session 刷新端点，取得：

- Agent UserID；
- 短期 UserSig；
- 短期平台 Access Token；
- Server/Channel 初始化数据；
- replyPolicy。

Runtime 使用腾讯云 IM 无 UI SDK 或兼容长连接客户端直接登录。UserSig 到期前重新
换取；登录断线、历史补偿和消息顺序由 SDK 负责。

Agent 可以看到其腾讯 membership 授予的消息，但默认执行规则为：

```text
C2C 发给自己                      → 处理
Group/Topic 明确 @ 自己           → 处理
Group/Topic 未 @ 自己             → 忽略
平台 CustomElem 指向自己的业务资源 → 拉取并处理
```

replyPolicy 可以收窄或扩展群消息处理，但不能越过 Channel membership。

Agent 使用自己的 IM SDK 直接回复，平台不代发聊天消息，也不推导回复目标。

## 6. Server 和 Channel 资源

Community GroupId 与 TopicId 由平台稳定派生并持久化。标准算法：

```text
LP(x)       = uint32be(len(utf8(x))) || utf8(x)
groupDigest = HMAC-SHA256(resourceSubkey, LP("community") || LP(serverId))
topicDigest = HMAC-SHA256(resourceSubkey, LP("topic") || LP(serverId) || LP(channelId))
groupPart   = BASE32-NO-PADDING(groupDigest)[0:26]
topicPart   = BASE32-NO-PADDING(topicDigest)[0:26]

GroupId   = "@TGS#_C_" + groupPart
TopicId   = GroupId + "@TOPIC#_T_" + topicPart
TopicName = "C-" + topicPart[0:20]
```

`community`、`topic` 是固定 ASCII 域标签；算法输入使用平台 UUIDv7 逻辑 ID。
资源创建后以数据库映射为准，不因密钥轮换重新派生。GroupId、TopicId 和
TopicName 分别固定为 34、70、22 个 ASCII 字节。测试向量见
`fixtures/internal/im-resource-identifiers.v1.json`。

可靠资源操作：

```text
im.identity.ensure
im.community.ensure
im.community.member.add/remove
im.topic.ensure/update
im.topic.member.add/remove
```

每个操作使用稳定 resource ID、desiredRevision 和 idempotencyKey。Worker 发送前
回读当前业务事实；旧 revision superseded。

Server 创建 Community 时：

- 使用稳定自定义 GroupId；
- 启用 Topic；
- join/invite 权限由平台管理；
- 创建 `#全员` 根 Channel。

普通 Channel 创建 Topic 时始终设置 `TopicType=Private`。平台 `visibility` 只决定发现与
主动加入策略，不映射腾讯 TopicType；visibility v1 不支持修改。

## 7. 普通消息路径

```text
Human SDK ───────────────┐
                         ▼
                    腾讯云 IM
                         ▲
Agent Runtime IM SDK ────┘
```

平台不参与：

- 消息发送与 ACK；
- 离线消息；
- 历史、未读和同步游标；
- 附件上传下载；
- 群消息扇出；
- Agent 聊天 Invocation/Delivery；
- Agent 聊天回复。

因此普通聊天不依赖 Go 后台在线。Agent 若需要在收到消息后读取 Task 等平台资源，
该业务动作才依赖平台 HTTP API。

### 7.1 Thread 引用索引

Thread 不创建第二个腾讯会话，也不建立平台消息库。根消息和回复仍发送到同一个
Topic；回复通过 Web 已识别的 `raft.message/v1` 信封携带，并附加 `thread` 扩展：

```json
{
  "schema": "raft.message/v1",
  "serverId": "0198f4c2-...",
  "conversationId": "0198f4c2-...",
  "clientRequestId": "client-generated-id",
  "parentMessageId": "tencent-root-message-id",
  "rootMessageId": "tencent-root-message-id",
  "mentionedMemberIds": [],
  "attachmentIds": [],
  "thread": {
    "role": "reply",
    "threadId": "0198f4c2-7a39-7af3-a01e-0fcb31e9d851",
    "rootMessageRef": {
      "kind": "group",
      "messageId": "tencent-root-message-id",
      "sequence": 100,
      "timestamp": 1785484800
    }
  }
}
```

旧的 `schema=raft.thread-reply/v1` 与早期扁平 `type=raft.thread-reply/v1` 仅用于
历史消息读取兼容，不再作为新消息发送格式。

客户端先把回复发送给腾讯 IM；收到腾讯 ACK 后，再把
`messageId/sequence/timestamp/groupId/topicId` 登记到平台。平台失败不能把腾讯
已发送消息标成失败，也不能重发腾讯消息，只能单独重试引用登记。

打开右侧 Thread 时：

1. 平台返回分页引用，不返回正文；
2. 客户端调用腾讯 SDK 的跳转拉取能力按 sequence 找回消息；
3. 主 Channel 列表过滤 `role=reply` 的消息；
4. 平台只推进 Thread 自己的成员读位置，腾讯 Topic 的会话已读仍由 SDK 管理。

这两张轻量表使用 `server_id` 分片，因此热门 Thread 不产生跨分片事务。

## 8. Task/Reminder 通知

平台维护一个普通但仅用于机器通信的通知 UserID。Worker 使用腾讯 REST 向 Agent
发送 CustomElem：

```json
{
  "schema": "chatserver.agent-notification/v1",
  "type": "task.assigned",
  "serverId": "0198f4c2-7a31-7c91-a6d2-7d76f9188c38",
  "resourceId": "0198f4c2-7a32-7d02-b8c1-3f6e15aa91b4",
  "revision": 3,
  "eventId": "0198f4c2-7a34-7af3-a01e-0fcb31e9d84a"
}
```

Reminder 使用 `type=reminder.due`，resourceId 指向 occurrence。

规则：

- 不携带完整 Task/Reminder 正文；
- 不携带 Secret、UserSig、云凭证或任意 URL；
- Runtime 只接受通知账号发出的、serverId/agentId 当前匹配的消息；
- 收到后通过平台 HTTP 拉取业务事实；
- `eventId` 只用于去重优化，资源 ID+revision 才决定当前性；
- Agent 启动、IM 重连和周期检查都会主动对账；
- 通知允许重复，通知丢失不影响业务正确性。

CustomElem 是唤醒机制，不是第二套 Task 数据库。

## 9. Callback

v1 不依赖普通消息 Before/After callback：

```text
C2C.CallbackBeforeSendMsg
C2C.CallbackAfterSendMsg
Group.CallbackAfterSendMsg
```

未来 callback 只能用于风控、审计或对账加速，不能成为 Agent 收件队列，也不能让
平台复制全部聊天内容。

v1 只接入 `State.StateChange` 登录状态回调。平台按腾讯签名规范校验独立 Token、
RequestTime、Sign、SDKAppID 和命令字，再通过 `agent_im_routes.im_user_id` 定位
Agent 分片。该回调只更新当前状态和时间，不保存在线历史。

## 10. 在线状态

Agent 在线投影组合三类事实：

- 腾讯 IM `State.StateChange` 表示 Agent UserID 的连接状态；
- `/computer/heartbeat` 与当前 launch observation 表示 Vela Host 最近仍健康；
- TAT probe 负责纠正已经陈旧的 `observedState=running`。

IM online 不单独保证 Runtime 业务逻辑健康，offline 也不删除 Task/Reminder。平台
只保存当前投影与最近观测时间，不建立永久在线历史。完整阈值、fencing 和回调安全
规则见 `22-Agent在线投影.md`。

## 11. 安全

- SDKAppID 可公开，IM 管理员密钥只在服务端；
- Human/Agent UserSig 短期签发且不写日志；
- Runtime credential 不能换取其他 Agent 的 UserSig；
- Agent 不持有腾讯管理员密钥；
- IM UserID、GroupId、TopicId 必须从平台映射读取；
- 通知账号不能加入普通 Human 会话；
- 生产、测试 SDKAppID 和密钥完全分离；
- 密钥泄露后立即轮换，既有 UserID 不改变。

## 12. 容量

腾讯云高级套餐和可申请提升的配额属于部署能力，不进入领域模型。平台保留基础
监控：

- IM 登录和发送错误率；
- Community/Topic 创建失败；
- REST 限流；
- UserSig 签发失败；
- Agent online 观测。

当真实容量接近部署边界时通过腾讯云侧扩容处理，v1 不为假设性配额设计多 App
分片。

## 13. 上线门禁

- Community、Topic、Private Topic 已启用；
- Human/Agent 普通 UserID 均可登录；
- Agent Runtime 能收到 C2C、群 @ 和 CustomElem；
- Agent 能直接回复 C2C/Topic；
- UserSig 可在不中断进程的情况下续期；
- Agent 重连后可以恢复腾讯离线消息；
- Task/Reminder 通知丢失后可以由 HTTP 对账发现；
- 一个 Human 登录后能同时看到至少两个 Server；
- 平台数据库抽查确认没有普通消息正文。
