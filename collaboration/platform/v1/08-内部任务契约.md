# 内部任务契约

## 1. 边界

v1 只有三类后台任务：

1. `TencentOperation`：调用腾讯云 IM 或 TAT；
2. `OutboxEvent`：业务事务提交后的可靠唤醒；
3. Reminder Scheduler：创建到期 occurrence。

不存在 AgentDelivery、Computer 帧、聊天 ingest、Activity 投影或消息 fanout Worker。

## 2. 通用规则

- 业务事务只写事实与 Outbox；
- Worker 按 aggregateId 回读当前事实；
- Server 事件 partitionKey=serverId，Account 事件 partitionKey=accountId；
- Event 不复制消息正文、Task 正文、Secret 或腾讯响应原文；
- Worker 使用短租约、指数退避和稳定 idempotencyKey；
- 每次外部调用前比较 desiredRevision；
- 旧 revision 进入 superseded；
- failed/uncertain 可由运维查询；
- reconciliation scanner 可以从事实表补建遗漏 Outbox。

除低频恢复扫描外，所有 Worker 查询必须携带 partitionKey，禁止用
`state+availableAt` 在 TDSQL 上做持续广播扫描。

## 3. TencentOperation

### 3.1 IM 操作

```text
im.identity.ensure
im.community.ensure
im.community.member.add
im.community.member.remove
im.topic.ensure
im.topic.update
im.topic.member.add
im.topic.member.remove
im.agent.notify
```

资源类操作以业务对象 ID+revision 为幂等边界。`im.agent.notify` 使用 eventId
作为发送幂等键，但通知不是业务事实，发送长期失败不会回滚 Task/Reminder。

### 3.2 TAT 操作

```text
tat.computer.registration.reconcile
tat.computer.refresh
```

TAT operation 的资源类型固定为 `computer`。Agent 配置、生命周期和 credential
轮换通过 Computer Assignment 收敛，不创建任何逐 Agent 的 TAT operation。

### 3.3 状态

```text
pending → running → succeeded
                 ↘ retry_wait
                 ↘ failed
                 ↘ uncertain
pending/running/retry_wait → superseded
```

- 可确认未执行或模板幂等：允许 retry；
- 腾讯明确业务失败：failed；
- 超时且无法查询确定：uncertain；
- 业务 revision 已变化：superseded。

## 4. Outbox

建议 eventType：

```text
tencent.operation.ready
task.agent-notification.requested
reminder.agent-notification.requested
computer.registration.reconcile
reconciliation.requested
```

Outbox `dead` 后保留稳定 errorCode。人工 requeue 只恢复唤醒，不能跳过权限、revision
和资源当前性检查。

正常投递：

```text
TDSQL 本地事务写 Outbox
→ 提交后 Redis Stream 写 {partitionKey,eventId}
→ Worker 按 partitionKey 点查
```

提交后进程崩溃导致 Redis 唤醒丢失时，低频恢复扫描广播各 set 并重新入队。Redis
不是事实源。

## 5. Task 通知

Task owner 变成 Agent 的事务写：

```text
Task(ownerMemberId=agentId, assignmentRevision=N, revision=M)
Outbox(task.agent-notification.requested, aggregateId=taskId)
```

Worker 回读 Task：

- owner 已不是 Agent：事件完成，不发送；
- assignmentRevision 已变化：旧事件完成，由新 revision 负责；
- Agent/Member removed：记录失败，不恢复旧 owner；
- 当前有效：创建或复用 `im.agent.notify` TencentOperation。

Agent Runtime 无论是否收到通知，都通过：

```text
GET /v1/servers/{serverId}/tasks?owner=me&updatedAfter=<cursor>
```

对账当前 Task。

## 6. Reminder

正常 Scheduler 使用 Redis 时间轮携带 serverId/reminderId 唤醒，再在 serverId
分片使用数据库锁领取 due Reminder：

```text
Reminder(active, nextFireAt <= now)
  → ReminderOccurrence(due)
  → Outbox(reminder.agent-notification.requested)
  → 推进 nextFireAt 或 once=completed
```

幂等键为 `(reminderId, scheduledFireAt)`。Agent Runtime 查询自己的 due occurrence
并使用稳定 Idempotency-Key ACK。

IM 通知失败可重试，但 occurrence 永远是平台事实。Agent removed 时将相关 Reminder
和未处理 occurrence 置 canceled。

时间轮丢失由低频全 set 恢复扫描补建；禁止把无 shardkey 的 due 查询作为常规轮询。

## 7. Computer 注册对账

外部纳管 Computer 生成一次性注册码后，Worker：

1. `raft-computer-go` 通过 Rust C ABI 注册时写入
   `agent-network-computer-id:<computerId>`；
2. 按该标签查询唯一的新注册 `rins-*`；
3. 计算 region+instance bindingHash；
4. 使用 TDSQL 2PC 预留 TATInstanceBinding 并绑定 Computer；
5. 校验注册窗口、地域、系统和平台内唯一性；
6. 查询 TAT Agent online；
7. Computer 进入 active；
8. 不保存 CodeID/CodeValue，等待本次注册码按一小时有效期自然失效。

结构化注册材料和注册码不进入 Outbox payload、TencentOperation snapshot 或日志。

## 8. PTY

`StartSession` 不走 Outbox：

- 它是用户在线等待的短期授权；
- 失败直接返回；
- 成功连接信息只返回一次；
- 平台只写安全审计日志；
- 不保存终端数据。

## 9. 无需建立的流

v1 不建立：

- Tencent IM 普通消息 ingest；
- message→mention→Agent fanout；
- Agent Invocation/Delivery；
- Computer ready/ping/ack；
- Runtime streaming/activity；
- C2C BeforeSend 权限缓存；
- Provider App 迁移；
- 聊天同步游标；
- PTY 录制队列。

## 10. TDSQL 事务边界

内部任务默认只访问一个 partitionKey。只有 Account 登录身份、Server slug 和
Computer TAT 绑定三个 registry 生命周期允许进入分布式事务白名单。2PC 内不得
调用腾讯云、Redis 或其他外部服务。

Worker 消息必须同时携带：

```json
{"partitionKey":"0198f4c2-7a31-7c91-a6d2-7d76f9188c38","eventId":"0198f4c2-7a34-7af3-a01e-0fcb31e9d84a"}
```

只有 eventId 没有 partitionKey 的消息视为协议错误，不允许通过全库搜索兜底。
