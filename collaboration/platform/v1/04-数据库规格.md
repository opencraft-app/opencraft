# 数据库规格

## 1. 边界

v1 正式支持两种部署等级：

- SQLite：单进程、单写者的单机生产模式；
- TDSQL MySQL InnoDB 分布式版：多实例水平扩展生产模式。

两种模式提供相同的产品语义。Go 应用保持大单体；TDSQL 从第一版 DDL 开始显式
分表，不经历“先单机、以后再补 shardkey”的迁移阶段。

业务事实写入部署所选择的 SQLite 或 TDSQL 主数据库；Redis 只用于缓存、限流、
短租约和 Outbox 唤醒，不是权限、Task 或 Reminder 的事实源。

平台不保存普通聊天消息正文、腾讯会话未读、附件、DM、聊天同步游标或 PTY
输入输出。Thread 是产品级派生视图，因此平台只保存腾讯消息引用和 Thread 内的
轻量已读位置，不复制正文。

## 2. TDSQL 通用约定

- 所有表都是 HASH 分表，不使用持续增长的 Noshard 单表；
- 当前没有广播表；
- `server_id`、`account_id`、`partition_key` 使用相同的
  `varchar(64) character set ascii collate ascii_bin`；
- ID 使用应用实例本地生成的 RFC 9562 UUIDv7，不依赖 Sequence 或中心 ID 服务；
- UUIDv7 对外使用标准小写字符串；数据库仍统一使用
  `varchar(64) character set ascii collate ascii_bin`，并由应用校验 UUID 格式；
- UUIDv7 只提供大致时间有序性，业务排序使用 `created_at,id`；
- 时间使用 UTC `datetime(3)`；
- JSON 只存版本化配置或脱敏结果，不用于核心关系查询；
- Secret 只保存强哈希；
- INSERT 必须显式包含 shardkey；
- shardkey 不可修改；
- 主键和所有唯一索引必须包含 shardkey；
- TDSQL 不支持外键，归属约束由事务和一致性扫描保证；
- 腾讯云 Secret、IM 管理员密钥只存在 Secret Manager。

完整路由规则见 `10-TDSQL分区与路由.md`。

## 2.1 数据访问与迁移

数据访问固定采用 `Ent + Atlas 版本化迁移`：

- Ent Schema 是 Go 实体、字段、边和通用约束的唯一结构来源；
- SQLite 使用 Ent SQLite 方言；
- TDSQL 复用 Ent MySQL 方言，不维护独立方言分支；
- 两种数据库分别保存版本化迁移目录，并在 CI 中实际执行；
- 生产环境禁止调用运行时 `Schema.Create` 或 AutoMigrate；
- TDSQL shardkey 通过自定义 Schema Annotation 表达；
- 迁移生成扩展把 Annotation 转换为 TDSQL DDL，并静态校验所有主键和唯一索引
  包含 shardkey；
- `id` 是应用生成的全局唯一逻辑 ID，`server_id/account_id` 是独立路由键；
- SQLite 首版以 `id` 为物理主键；未来 TDSQL 迁移将其转换为
  `(shardkey,id)` 物理主键，但 Go 领域层不暴露复合 ID；
- Ent Client 只允许在 Repository 内使用；Server/Account 域查询、更新和删除必须
  同时带逻辑 ID 与路由键，不允许业务代码调用无范围的 `Get(id)` 等方法；
- 不在 Ent 中声明数据库外键；关联完整性由应用事务和一致性检查维护；
- 必须精确控制路由、锁或批处理执行计划时，允许在 Repository 内使用 Ent SQL
  Modifier 或局部原生 SQL。

Ent Schema 不能替代数据库迁移审查。每次变更必须同时得到可重放的 SQLite 迁移和
TDSQL 迁移；两者都通过后才能合并。

## 4. Account 域

### 4.1 account_login_identities

```text
login_hash char(64)                  SHARDKEY
id
kind = email | phone | oauth
normalized_login
account_id
state = active | retired
created_at
retired_at NULL
```

DDL 约束：

```text
PRIMARY KEY(login_hash, id)
UNIQUE(login_hash, kind)
INDEX(login_hash, account_id)
shardkey=login_hash
```

`login_hash=SHA-256(kind + 0x00 + normalizedLogin)` 的小写十六进制。登录先点查本表，
再按 account_id 点查 accounts。normalized_login 用于哈希碰撞复核和展示，必须按

## 10. 逻辑归属与一致性

TDSQL 不支持外键。Repository 和事务层必须保证：

- Server 子表的 server_id 与父对象一致；
- Agent.id 对应同 Server 的 Agent Member；
- Agent.computer_id 指向同 Server active Computer；
- Channel member 指向同 Server Channel/Member；
- Task owner/creator/updater 都属于同 Server；
- Reminder/Occurrence 的 Agent 和 Reminder 属于同 Server；
- partition_key 与 aggregate 所属 Account/Server 一致。

一致性扫描按 shardkey 分批运行，发现跨租户 ID 组合时告警并阻止继续执行，不自动
猜测修复。

## 11. 事务白名单

常规业务事务只能访问一个 shardkey。仅以下低频流程允许 TDSQL 2PC：

| 流程 | 分片 |
|---|---|
| Account 登录身份创建/替换/退役 | login_hash + account_id |
| Server slug 创建/退役 | slug + server_id |
| Computer TAT 绑定/解绑 | binding_hash + server_id |

2PC 事务内禁止腾讯云 API、HTTP、Redis 或文件操作。

`account_server_memberships` 是异步可重建投影，不参加 Member 权威事务。

## 12. 数据保留

| 数据 | 保留 |
|---|---|
| Account、Server、Member、Agent、Computer、Channel、Task、Reminder | 产品生命周期 |
| 登录/slug/TAT registry retired 行 | 1 年 |
| Account Server 投影 | 随权威 Member 重建 |
| Runtime credential 历史 | revoked 后 30 天只保留哈希和审计 |
| Reminder occurrence | 1 年 |
| TencentOperation | 90 天；结果 JSON 30 天清空 |
| Idempotency | 24 小时至 7 天 |
| processed Outbox | 7 天 |
| 普通聊天、DM、附件 | 不进入平台数据库 |
| PTY 输入输出 | 不保存 |

清理任务必须按 partition_key 执行。全局保留扫描仅做低频运维批次。

## 13. Schema 迁移

- SQLite 与 TDSQL 分别使用 Atlas 版本化 SQL migration，不使用生产
  AutoMigrate；
- TDSQL 的所有 CREATE TABLE 显式声明 shardkey；
- 在线 DDL 前在 TDSQL 测试实例验证；
- 不修改既有 shardkey；
- 新唯一索引必须包含 shardkey；
- 不创建外键、触发器、存储过程或自建分区；
- 枚举先扩读后扩写；
- 删除列分两次发布；
- SQLite migration 必须在全新库和上一稳定版本升级路径上验证；
- CI 在至少 4 个 set 验证点查路由、Group-Shard JOIN、2PC 白名单和恢复扫描；
- 全局报表通过 CDC 进入分析库，不在 OLTP 上做跨 Server 聚合。
