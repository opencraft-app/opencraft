# 2026-08-06 BrainStorm：云端部署热点宣发与技术方案

> 来源：2026-08-06 LightVela 脑暴会逐字稿。本文用于沉淀围绕“AI 工作台 / 云端应用部署”热点场景的技术选型、产品入口、运营宣发与资源保障，不直接等同于已排期需求。

## 总览

本次讨论围绕 LightVela 正在推进的“云端应用部署”能力展开，重点不是重新评审能力本身，而是基于近期社区里的“用 WorkBuddy 搭建个人工作台”热点，判断 LightVela 是否可以把该能力包装成一个场景化增长动作。

会议形成的阶段判断：

1. “AI 生成个人工作台并分享给别人访问”是一个正在发酵的内容热点，和 LightVela 云端部署能力高度相关。
2. 该场景如果只做静态网页还不够，个人工作台往往需要数据存储、文件/对象存储或持久化能力。
3. TCB、COS 静态托管、用户实例端口反代等方案均有可行性，但在成本、隔离、合规和域名管理上各有代价。
4. 国内站公开托管面临更高合规风险，短期更倾向优先在国际站上线和宣发。
5. 技术方案未定前，周五或下周一上线存在不确定性，需要尽快拉 TCB 团队专项确认。
6. 国际站资源库存和计费链路仍是场景上线的基础前提。

## 背景：从社区热点切入云端部署

近期社区中出现了一个较热的教程：基于 WorkBuddy 搭建个人工作台。该教程在自媒体圈传播后，不少用户开始模仿搭建自己的工作台。

用户遇到的典型问题是：

- 工作台只能自己访问，无法分享给别人。
- 用户缺少公网访问、部署、域名和存储配置能力。
- 低技术用户甚至在 WorkBuddy 积分用完、模型配置、账号注册等环节就容易卡住。

LightVela 当前正在建设的云端应用部署能力，正好可以承接这一类需求：让用户通过 Agent 生成工作台，再由 Agent 帮忙部署到云端并返回可访问地址。

## 方向一：技术选型仍需确认

### TCB 方案

原始方案以 TCB 静态网站托管为基础，优点是云开发链路成熟，能快速承接静态站点部署。

当前发现的问题：

- 个人工作台场景可能需要持久化待办、文件或对象存储，不只是静态页面。
- TCB 多环境可实现用户间数据隔离，但每个环境有成本。
- 当前个人版 TCB 环境成本约 26 元，可能占掉套餐成本的大部分。
- 如果每个用户创建独立环境，需要重新评估成本和可持续性。

待确认问题：

- TCB 是否有更适合大账号多用户隔离的合作方案。
- 多环境成本是否可通过合作折扣或资源包降低。
- TCB 数据库能力是否支持更低成本的按量或存算分离模式。

### COS 静态托管方案

另一个方案是使用对象存储承接静态站点：

- 静态文件可放在 COS。
- 域名需要 LightVela 自己配置和管理。
- 文件或对象级别的数据存储也可能放在 COS 中实现。

当前判断：

- 技术上静态托管可行。
- 域名配置链路仍在验证中。
- 如果涉及更复杂的应用持久化，COS 方案需要额外设计数据读写方式。

### 用户实例端口反代方案

会议中也讨论了通过网关把用户自己机器里的端口转发出来：

- 用户应用运行在自己的 LightVela 实例里。
- LightVela 提供网关和域名，把端口代理出去。
- 可加登录态或鉴权，只允许用户自己访问。

当前判断：

- 技术上可能更贴近“部署到自己的云端 Agent 环境”。
- 但国内站如果暴露公网访问，合规风险较高。
- 国内站短期不建议做公开分享；即使只做自用，也需要谨慎评估。

## 方向二：产品入口与用户路径

当前设想的用户路径：

1. 用户先创建一个 Agent。
2. 进入“网站/作品”相关页面。
3. 选择一个模板，例如 AI 工作台模板。
4. Agent 基于模板生成应用。
5. Agent 调用部署能力，把应用发布到云端。
6. 用户获得可访问链接，并可在后台查看。

需要优化的产品细节：

- 页面入口名称需要从“网站”进一步抽象，避免限制未来扩展。
- 模板需要突出 AI 工作台，但也可搭配其他轻量模板支撑能力展示。
- 模板中应预置基础技术栈和代码框架，让用户更快生成可用工作台。
- 用户免费体验只有 100 积分，模型配置和部署过程可能消耗较多，需要在教程和模型配置页加强引导。
- 创建路径较深，后续传播内容要用清晰步骤降低上手门槛。
- 命名规则、生成物管理、部署记录等细节需继续整理。

## 方向三：国内站与国际站落点

短期倾向：

- 云端部署的公开访问能力优先放在国际站。
- 国内站暂不优先做公开分享能力，避免合规风险。
- 国内内容可用于借势热点和教育用户，但最终跳转和承接锚点更可能是国际站。

原因：

- 国内公开托管需要处理更多合规、内容、安全和域名风险。
- 目标热点用户中不少人愿意使用海外账号或英文站点。
- 国际站更适合承接“可分享、可访问、可传播”的网站部署能力。

仍需注意：

- 国内用户注册 Google 账号可能有门槛，教程中需要给出合理提示。
- 如果国际站账号、模型配置或积分不足导致体验断点，会削弱热点转化。

## 方向四：运营宣发策略

### 目标用户画像

本次热点对应的用户大致是：

- 自媒体博主。
- 想起号或做个人 IP 的创作者。
- 关注 AI 工作台、个人效率工具的人群。
- 技术水平偏低，可能无法独立完成部署、域名、模型配置等步骤。

### 内容策略

短期需要优先准备教程：

- 如何用 LightVela 创建 AI 工作台。
- 如何让 Agent 帮你部署到云端。
- 如何把工作台链接分享给别人。
- 如何配置模型、补足积分、处理生成失败。

传播渠道：

- 国内侧优先使用个人账号在小红书、知乎等平台传播。
- 国际站可使用现有 X 矩阵，也可以尝试发布中文和英文版本。
- 内容可以先围绕中文热点快速切入，再逐步补英文版本。

需要产出的内容形态：

- 操作教程。
- 场景短帖。
- 热点借势内容。
- 中英文版本的轻量介绍。
- 后续可补视频或图文教程。
