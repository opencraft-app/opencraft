# Hermes Agent 与 OpenClaw 有什么不同？

如果你最近关注 AI Agent 领域，一定听过两个名字：**Hermes Agent** 和 **OpenClaw**。它们经常被放在一起比较，但很多人其实并不清楚——这俩到底是不是一个赛道的东西？

先给一个不严谨但足够直观的类比：

- **OpenClaw** 更像一台"开箱即用的工作站"：给你一个能读代码、写代码、执行命令的通用 Agent，它擅长在**单次任务**里把事情做完。
- **Hermes Agent** 更像一位"会成长的搭档"：它不仅能干活，还会**记住你是谁、你在做什么、你偏好什么**，跨越会话持续演化。

下面我们从四个维度把这层直觉拆细。

## 一、架构定位：任务型 vs 陪伴型

OpenClaw 的核心叙事是"**通用编码 Agent**"：给它一个仓库、一个目标，它会自己规划、调用工具、写文件、跑测试，直到任务完成。它的上下文以"当前任务"为中心，任务结束基本就 reset。

Hermes Agent 的核心叙事，按官方文档的说法，是构建一个"**具备长期记忆和人格的通用 Agent**"。它在 CLI 和调度层之上，专门做了两件 OpenClaw 没有强调的事：

1. **稳定的自我描述**（SOUL.md）——Agent 有明确的"我是谁、我怎么工作"。
2. **稳定的用户建模**（USER.md）——Agent 明确地"记住你是谁"。

一句话：OpenClaw 优化的是"**这次任务能不能做好**"，Hermes 优化的是"**这个 Agent 能不能长期陪你把事做好**"。

## 二、记忆机制：短上下文 vs 持久记忆

这是两者最本质的差别。

OpenClaw 走的是当下主流的路线：**大上下文 + RAG**。当前任务需要什么，就把什么塞进 context window；跨任务的东西大多要用户自己粘贴，或者靠外部的知识库/记忆插件。

Hermes Agent 把**长期记忆**做成一等公民：

- 记忆被拆成**多种类型**（事实性记忆、用户画像、程序性技能等），分别落到不同的文件与索引里。
- 记忆写入不是"随手记"，而是由 Agent 在 compression / checkpoint / 用户显式指令 等时机**主动整理**。
- 检索时同时结合**结构化文件（USER.md / MEMORY.md）+ 全文索引（FTS5）+ LLM 摘要**，而不是简单的向量召回。
- 还引入了 **Honcho** 这类"关系型用户建模"组件，专门用来抽取"用户是一个什么样的人"。

如果说 OpenClaw 是"每次都从零开始的实习生"，Hermes 就是"你带过几个月、已经知道你脾气的同事"。

## 三、可扩展性：工具 vs 技能

OpenClaw 的扩展模型主要围绕**工具（Tools）**：加一个 MCP、加一个命令、加一个内置能力。

Hermes Agent 在工具之外，还有一层非常关键的抽象——**Skills（技能）**。Skill 是一段 **程序性记忆**（procedural memory）：它不是"我记住了这个事实"，而是"我记住了做这件事的标准流程"。当 Agent 遇到匹配的场景，Skill 会被自动装载为高优先级 prompt。

这带来一个很实际的差异：

- 在 OpenClaw 里，让 Agent"下次记得这样做"，你通常要**改 prompt、改工具、改 config**。
- 在 Hermes 里，你可以直接对它说"以后这类需求这么处理"，它会把这段流程沉淀成一个 Skill，下次自动生效。

## 四、工程落地：单机 CLI vs Agent 平台雏形

在工程形态上，两者也在逐步分化：

| 维度 | OpenClaw | Hermes Agent |
| --- | --- | --- |
| 主要形态 | 通用编码 CLI | 通用 Agent 运行时（CLI + 长期记忆 + 技能） |
| 上下文单位 | 单次任务 | 跨会话的用户 & Agent |
| 记忆 | 短上下文 + 外挂 | 内建的多层记忆系统 |
| 扩展方式 | Tools / MCP | Tools + Skills（程序性记忆） |
| 用户建模 | 弱 | 强（USER.md + Honcho） |

一句话总结：**OpenClaw 让 AI 会干活，Hermes Agent 让 AI 会成长。**

## 从 Hermes 反观：LightVela 在做什么？

看到这里，你可能会问：这些"长期记忆 + 技能沉淀"的能力，只有 Hermes 才有吗？

其实并不是。**LightVela** 内部构建的 Agent 体系，走的也是"能成长的搭档"这条路线：

- 我们同样把**用户画像**和**事实性记忆**分层管理，一方沉淀"你是谁"，一方沉淀"我们一起做过什么"。
- 我们同样区分**知识**（memory）和**流程**（skill）：知识可查可引用，流程可复用可版本化。
- 在此之上，LightVela 更侧重把这些能力**产品化**——让个人和团队都能低门槛地训练自己的 Agent，而不是只停留在开发者 CLI。

Hermes Agent 给了我们一个非常好的参考：**一个真正好用的 Agent，不能只有"聪明的当下"，还必须有"稳定的长期"**。LightVela 想做的，正是把这份"长期"，做成每个人都用得起来的产品体验。

## 小结

- OpenClaw：任务型编码 Agent，强在"当下能把事做好"。
- Hermes Agent：陪伴型通用 Agent，强在"长期能陪你把事做得越来越好"。
- 二者不冲突，甚至可以配合：OpenClaw 做执行层，Hermes 做记忆与人格层。
- 如果你在寻找一个**能落地到产品**的"能成长的 Agent"方案，LightVela 值得一试。
