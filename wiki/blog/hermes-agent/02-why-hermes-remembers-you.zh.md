# Hermes Agent 为什么能"记住你"？拆解长期记忆系统的工作原理

大部分 AI 助手让人失望的第一个瞬间，往往不是它答错了什么，而是——**"你上次不是刚跟我说过吗？"**

上下文窗口越来越大，但"记住你"这件事，从来不是靠塞更多 token 能解决的。**Hermes Agent 的长期记忆系统**，正是围绕这个问题设计的。这篇文章，我们把它拆开来看。

## 一、先问一个问题：什么叫"记住"？

在人类语境里，"记住你"至少包含三层意思：

1. **知道你是谁**——名字、职业、偏好、常用工具链。
2. **知道我们一起做过什么**——之前聊过的项目、给过的结论、踩过的坑。
3. **知道该怎么和你打交道**——你喜欢简短还是详细？喜欢先结论还是先过程？

一个只有大上下文窗口的模型，能在**一次对话内**同时做到这三点；但只要会话一断，第 1、3 点就重置了。Hermes 的思路是：**把这三层分别落到不同的持久层里，各自用最合适的方式维护。**

## 二、写入：记忆不是"随手记"，而是"主动整理"

Hermes 的长期记忆不是"每说一句话就记一条"，而是由 Agent 在几个明确时机**主动组织并落盘**：

- **Compression（压缩）**：上下文接近上限时，Agent 会先把当前会话里"值得长期保留"的信息抽出来，再压缩当前 context。
- **Checkpoint（检查点）**：会话进行到某些里程碑（比如完成一个子任务、切换话题），Agent 会主动记一次。
- **Nudges（周期性提示）**：系统会周期性地"戳"一下 Agent："看看有没有值得写入长期记忆的内容？"这避免了信息在一次长会话里悄悄丢失。
- **用户显式指令**：用户直接说"以后记住我在 X 项目里用的是 Y"，会被识别为高优先级记忆写入。

关键在于：**决定是否写入长期记忆的是 Agent 自己**，而不是全量落盘。这一步过滤，正是"记忆质量"的第一道闸门。

## 三、存储：多种记忆，分层落地

Hermes 把长期记忆拆成几种，分别放在不同的位置：

- **USER.md**：结构化的**用户画像**——你是谁、你的角色、偏好、常用栈、沟通风格。它是一份"越用越准"的活文档。
- **MEMORY.md / memories/**：**事实性记忆**——具体的事件、决定、结论、跨会话要复用的知识点。
- **skills/**：**程序性记忆**——"遇到这种情况我该怎么做"的流程模板（我们下一篇会专门讲）。
- **SOUL.md**：Agent 自己的"人格描述"——它是谁、如何思考、如何回应，属于 Agent 的自我模型，不属于用户记忆，但会和用户记忆共同构成上下文底座。

在这些"结构化文件"之外，Hermes 还维护了**全文索引（FTS5）**，让所有历史记忆可以按关键词精确召回。

值得注意的是，Hermes 还引入了一个叫 **Honcho** 的组件，用来做**dialectic user modeling**——通俗讲，就是不断从对话里抽取"关于用户的可复用陈述"，反哺 USER.md 的维护。这一层是纯 LLM 驱动的用户理解，弥补了结构化文件不擅长的"隐性偏好"。

## 四、召回：结构化 + 全文 + 语义，三条腿走路

传统 RAG 方案的召回，很依赖向量相似度。但只用向量，会遇到两个老大难问题：**"你重要不代表你和 query 相似"**、**"细节被稀释在整段里"**。

Hermes 的召回策略更像"混合检索"：

1. **结构化载入**：每次对话启动时，USER.md、SOUL.md 等**默认整份加载**——因为这些内容本身就是被精挑细选过的高价值信息。
2. **全文检索（FTS5）**：面对具体问题（"上次那个报错是啥来着？"），走精确关键词命中。
3. **LLM 摘要 & 语义匹配**：对于需要跨条目整合的问题，让模型基于压缩后的摘要做二次组织。

这三层配合，才让"记住你"不只停留在"我们向量相似"，而是"我真的知道你说过什么"。

## 五、更新：记忆是活的，不是流水账

一个常被忽视的点：**记忆不仅要能写入，还要能被修改和淘汰**。

Hermes 在这点上有几个明确的策略（后续文章会展开）：

- 新的事实和旧的事实冲突时，**优先更新而不是并列写入**，避免"分裂人格"。
- 长期没被引用的记忆条目，会被判定为"低价值"逐步降权。
- 用户明确否认的信息，会被立刻**删除**，而不是"记录一条相反的"。

也就是说，Hermes 更接近"编辑一份活的档案"，而不是"追加一份日记"。

## 六、把这些能力放到产品里：LightVela 的实践视角

Hermes Agent 是一个非常好的**"记忆系统参考实现"**，但要把这份能力真正带到普通用户和团队面前，还需要几件事：

- **可视化的记忆管理**：普通用户不该去改 Markdown 文件，而应该在界面上看到"Agent 记得关于我的哪些事"，并能一键更正。
- **多端一致的记忆**：Web、移动端、IDE 内的 Agent，应该共享同一份"你是谁"。
- **团队维度的记忆**：不只是"Agent 记得我"，还要"Agent 记得我们团队的规矩"。

这正是 **LightVela** 在构建的方向：把 Hermes 这类研究级别的记忆系统，抽象成**用户画像 + 事实记忆 + 团队上下文**三层，做成人人可用的能力。你不需要理解 FTS5、不需要写 SOUL.md，也能拥有一个"越用越懂你"的 Agent。

## 小结

- Hermes 的"记住你"不是靠更大的窗口，而是靠**主动整理 + 分层存储 + 混合召回 + 持续更新**。
- 记忆按类型分层落地：USER.md 管画像，MEMORY.md 管事实，Skills 管流程，SOUL.md 管 Agent 自己。
- 好的 Agent 记忆系统，一定是"编辑档案"而不是"追加日记"。
- LightVela 想做的，是把这份能力从命令行带到产品里，让"被记住"成为默认体验。
