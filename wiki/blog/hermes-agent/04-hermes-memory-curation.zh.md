# 记忆不是越多越好：Hermes Agent 如何筛选、整理和更新长期记忆

有一个常见的误解：**"AI 助手记得越多越聪明。"**

事实恰恰相反。**记得多而杂，会让 Agent 变笨**——它开始把你临时的、错误的、过时的信息，当成关于你的稳定事实。真正好用的长期记忆系统，一定是"**少而准**"的。

Hermes Agent 在这件事上有一整套很值得研究的做法，我们分四步拆开来看。

## 一、写入：不是所有信息都值得进入长期记忆

Hermes 的第一道门是**写入过滤**。它不会把每一句话都存下来，而是在几种明确的时机由 Agent **自己判断**要不要写：

- **Compression（压缩时）**：上下文接近上限时，Agent 会 review 当前会话，把"值得跨会话保留"的信息抽出来。
- **Checkpoint（关键节点）**：任务闭环、话题切换等时刻，做一次记忆盘点。
- **Nudges（周期性提醒）**：系统会周期性地问 Agent："这一段有什么值得写进长期记忆的吗？"避免忘掉重要片段。
- **用户显式指令**："请记住 X" 会被优先写入。

判断标准通常包括：

1. **可复用性**：这条信息在未来其他任务里可能还会用到吗？
2. **稳定性**：它是暂时的（"今天头有点疼"）还是长期的（"我常年戴隐形眼镜"）？
3. **具体性**：它是模糊的态度，还是可以被后续动作复用的事实？

一个训练良好的 Hermes Agent，宁可**少记**，也不乱记。

## 二、整理：把碎片写成条目，把条目组织成结构

即便通过了写入过滤，进来的信息也往往是"碎片"。Hermes 的第二道处理，是**把碎片重写成规范条目**。

举个例子。原始对话可能是：

> "哦对了，我们那个 API 后来改成走 gateway 了，不再直连服务了，是上个礼拜的事。"

Hermes 不会原样保存这句话，它更倾向于写成：

```md
- [~2026-07-24] Project X 的 API 已从直连改为经由 gateway 路由。
```

这里发生了几件事：

- **抽事实**：去掉"哦对了"这类语气词。
- **补主语**：把"我们那个"补成"Project X"。
- **加时间**：把"上个礼拜"锚定成大致时间。
- **可检索**：写成结构化条目，方便日后 FTS5 命中。

结构化整理之后，记忆条目才具备"**几个月后被再次召回**"的可能。

## 三、更新：优先"修改"，而不是"追加相反"

这是很多简单记忆系统会翻车的地方：**信息变化了怎么办？**

朴素做法是"再记一条"，结果 Agent 里同时存在：

- "用户偏好 Vue"
- "用户后来换成了 React"
- "用户又回到了 Vue"

三条并列，模型自己都不知道该信谁。

Hermes 的做法是**优先更新，而不是追加相反**：

- 用户画像（USER.md）里的偏好类字段，倾向于"**覆盖旧值**"。
- 事实记忆（MEMORY.md）里，历史事件保留，但**当前状态字段被更新**，并保留一个简短的"版本迁移"痕迹。
- 用户明确否认的内容（"我从来不是那样"），会被**删除**而不是记录成"用户否认了 X"。

这样做的核心目的，是让 Agent 的世界模型**保持自洽**，避免"分裂人格"。

## 四、淘汰：让"低价值记忆"自然衰减

即使写入很克制、整理很规范，长期下来记忆也会膨胀。Hermes 用几种机制让**低价值记忆自然衰减**：

- **访问频率降权**：长期没被召回的条目，会被判定为低价值，在后续检索里排名下降。
- **主题聚合**：一堆相似条目会被 LLM 摘要合并成一条更概括的记忆。
- **过期标记**：某些绑定时间语义的条目（"本周 sprint 的目标是…"）会在时间点之后被标记过时。

这些机制加在一起的效果是：**你几个月前的碎碎念不会一直污染 Agent 对你的判断**，但真正长期重要的信息会被反复强化。

## 五、这里藏着一个反直觉的结论

很多产品在宣传"AI 记忆能力"时，会强调"记住的条目数量"、"支持多大记忆库"。

但站在 Agent 使用者的角度，你真正关心的其实是三件事：

1. **它有没有记住真正重要的东西？**
2. **它有没有把已经不成立的信息及时更新掉？**
3. **它会不会因为记了一堆无关的东西，反而变得更啰嗦、更容易搞错？**

**能回答"什么不该记"的记忆系统，才是好的记忆系统。**

## 六、从 Hermes 到 LightVela：把"记忆治理"变成产品能力

Hermes 的这一整套筛选 / 整理 / 更新 / 淘汰机制，对开发者而言是清晰的，但对普通用户还是"黑盒"。**LightVela** 想做的一件事，就是把这层"记忆治理"变成用户可感知、可控制的产品能力：

- **可见的记忆列表**：Agent 关于你的每一条记忆都可以被查看、编辑、删除，不用去改 Markdown。
- **可信度可视化**：每条记忆背后关联的对话来源和更新时间，都清晰可查——不会有"Agent 无端捏造关于你的事实"这种事。
- **主动的记忆审阅**：LightVela 会周期性地把"新记住的画像/事实"整理成一份小报告，让你花一分钟确认或修正。这一步，正是把 Hermes 内部的 "nudge + compression" 流程，产品化成人类看得懂的动作。

一句话：**Hermes 让 Agent 学会"少而准地记住"，LightVela 让用户学会"轻松地治理这份记忆"。**

## 小结

- 好记忆系统 = 严格写入 + 规范整理 + 主动更新 + 自然淘汰。
- 记得多不等于聪明，能识别"什么不该记"更重要。
- Hermes 给出了工程实现的参考，LightVela 想把它做成用户能触达的产品体验。
