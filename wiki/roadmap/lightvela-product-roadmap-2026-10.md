# LightVela 产品 Roadmap（讨论稿）

> 更新时间：2026-10-12  
> 本文先整理产品方向与阶段框架。具体功能范围、优先级与交付节奏，待后续继续讨论。

## 第一部分：产品方向与阶段判断

### 1. 整体方向

LightVela 面向个人云端 Agent 助手：以云端运行环境为基础，逐步增加用户上下文的接入与积累，进一步支持 Agent 主动形成与用户有关的洞察。

这里的核心演进路径是：

1. 先让 Agent 稳定地运行在可持续的环境中；
2. 再让 Agent 获得更多与用户相关的上下文；
3. 最终让 Agent 基于持续运行和上下文积累，主动形成洞察并向用户提供帮助。

### 2. 三个阶段及能力要求

以下阶段划分来自本次讨论，具体能力是供后续展开的建议，不代表已交付状态。

#### 阶段一：基本的 Agent 运行以及它的环境

解决 Agent 能否被创建、启动、持续运行，以及运行所需环境是否可靠的问题。

这一阶段关注：

- Agent 的创建、配置与启动；
- Agent 运行所需的云端环境；
- Agent 与模型、工具、Skill 等基础能力的连接；
- Agent 任务的执行过程与基本结果反馈；
- Agent 在用户不在线时仍能继续运行的基础。

阶段目标：用户能够可靠地使用 Agent，Agent 能在云端持续执行任务。

#### 阶段二：Agent 上下文如何更多地接入

在 Agent 能够稳定运行之后，让它接触更多与用户有关的信息、资料、任务和历史结果，使 Agent 不再只依赖当前对话中的临时输入。

这一阶段关注：

- 用户主动提供的资料、任务目标与参考来源；
- Agent 执行过程中产生的历史记录与结果；
- 云端文件、产物及其他可持续沉淀的数据；
- 外部服务、消息与事件等上下文来源；
- 上下文在后续任务中的引用、复用与持续积累。

阶段目标：Agent 在执行任务时能够获取相关上下文，积累的信息和结果也能服务于后续任务。

#### 阶段三：基于稳定运行和充足上下文，主动对用户进行上下文洞察

当 Agent 能够稳定运行，并且已经拥有足够持续的用户上下文后，进一步让它主动识别变化、发现机会或风险，并向用户提供有依据的洞察与行动建议。

这一阶段关注：

- 从持续积累的上下文中发现变化与关联；
- 识别可能需要用户关注的问题、机会或风险；
- 主动生成提醒、总结、建议或下一步行动；
- 让洞察能够指向值得用户关注或处理的具体事项；
- 让 Agent 的主动行为建立在可追溯的上下文和结果之上。

阶段目标：Agent 能够基于持续积累的上下文，主动提供有依据、与用户相关的洞察。

### 3. LightVela 所处阶段判断

LightVela 当前整体处在：

> **阶段一的末尾，阶段二的起始。**

这是对产品整体发展阶段的方向性判断，不代表阶段一或阶段二的能力已经完善，也不代表具体功能已经完成交付。

## 第二部分：产品规划

### 阶段一：Agent 运行稳定性与运行架构

当前阶段需要优先解决用户环境下 Hermes Agent 的运行稳定性问题。

#### 自动化、常态化验证机制

围绕用户的核心使用场景，建立自动化、常态化验证机制，持续发现产品运行中的可靠性问题。

#### 运行稳定性优化实施路径

基于当前 VM + Hermes Agent 架构推进短期优化，与自动化、常态化验证机制并行建设。

1. **观测**：只观测、不执行修复动作。结合实例状态、TAT 在线状态、Hermes 健康接口和网关请求结果，判断存活、故障或未知，在控制台展示并提示；不发起合成请求，同时确定基线指标。
2. **快照与手动入口**：系统盘定期创建快照并保留多份，支持在控制台选择快照回滚，并增加“重启机器”按钮；所有操作按钮执行前先创建保护点。存量机器在原形态下只实施前两步。
3. **新镜像**：Agent 进入 Sandbox，程序只读，用户数据放在数据盘；提供“重置 Agent”，从镜像重建容器并原样挂回数据，对用户自装软件记账并在重建时重放；一键更新改为替换制品，先灰度再全量。
4. **配置移出 Sandbox**：平台配置在启动时注入，重置即可恢复；用户配置提供“上次正常配置”和“恢复默认”两个按钮；之后将渠道连接器移到宿主层。
5. **换机**：VM 层发生故障时，从资源池更换一台机器并挂上数据盘。
6. **存量迁移**：仅在修复失败或用户要求时，按需迁移到新形态，不进行批量迁移。

#### 长期规划：整体优化 Agent 运行架构

- 对 Agent 的运行架构进行整体优化；
- 具体方案与实施路径待进一步讨论。

### 阶段二：Agent 上下文相关工作

#### 1. Agent 表现层提升

- **用户侧输出优化**：减少或去除系统级提示，让 Agent 的反馈更符合用户理解习惯。
- **Hermes Agent 系统提示词定制**：基于 LightVela 的产品特性，定制 Hermes Agent 的系统提示词。

#### 2. Agent 基础能力提升

- **云电脑能力**。
- **连接器能力**：提供 Agent 与第三方应用对接的标准入口。
- **海外通道配置体验优化**。
- **邮箱接入**：为 Agent 接入邮箱能力。
- **钱包接入**：为 Agent 接入钱包能力。
- **场景化模型能力**：为 Agent 提供语言模型以外的能力支持，例如图片模型、视频模型、联网搜索等。
- **Agent 产物与云存储体验提升**：支持产物预览，并提供可在产物界面中与 Agent 交互的体验。

#### 3. Agent 运行环境扩展

- **公网访问能力**：为 Agent 运行环境配置公网 IP，国内站使用 IPv4，国际站使用 IPv6。
- **云存储空间扩展**：扩展 Agent 的云存储空间。
- **Agent 记忆增强**：支持外接 Agent Memory。

#### 4. 上手体验与信任建立（并行支线）

在用户开始向 Agent 提供上下文的阶段，通过上手期间的产品设计，降低用户建立 Agent 信任感的门槛。

- **Agent 创建体验优化**：进一步优化创建流程，将连接能力纳入用户上手过程。
- **Agent 迁移能力**：支持用户将已有 Agent 迁移到 LightVela，第一波优先支持来自 OpenClaw 类型产品的 Agent 迁移。
- **品牌新形象的视觉应用**：将最新的产品品牌形象应用到产品交互中。

#### 5. 用户成长与激励机制设计

- **亲密度设计**：按亲密度组织用户与 Agent 可完成的任务，让用户直观看到使用深度的持续提升，并基于使用深度提供产品激励。
- **用户留存与促活策略设计**：设计用户留存与促活策略，促进持续使用。

#### 6. Agent 协作能力提升（长期规划）

- **多 Bot 协作**：支持 Hermes Agent 的多个 Bot 在同一协作空间中协作，例如看板或群聊。
- **跨 Agent Runtime 协作**：支持 Hermes Agent 调度其他 Agent Runtime 或与其协作，例如 DeepSeek Harness，以及更多本地 Agent。

#### 7. 硬件生态接入（纯探索支线）

探索硬件生态的接入，进入手机和 Web 覆盖范围之外的场景，为 Agent 获取更多用户上下文。

### 阶段二向阶段三演进：APP 主端建设

**APP 后续将成为 LightVela 产品的主端。** 围绕个人用户的体验要求，逐步建设以下能力。

#### 1. 入口层：Agent 优先的 APP

扩展 APP 入口，以 Agent 为核心重新设计交互体验，发挥第一方产品的能力，为个人用户提供比 IM 更好的 Agent 交互体验。

#### 2. 连接层：个人上下文接入

通过 APP 通道接入更多用户的个人上下文，包括手机操作系统内的数据，扩展 Agent 获取上下文的能力。

#### 3. 主动性：机制探索与用户感知

探索 Agent 主动行为的机制，通过 APP 接入手机通知等能力，让用户能够感知 Agent 的主动洞察、提醒等行为。

### Chat

持续优化自建 Chat，将其建设为所有能力分发的枢纽。

### 云端 Agent 特性功能建设

帮助用户通过 Agent 在云端构建并部署自己的应用，目前已建成基于底层 COS 静态资源的网页部署能力，并正在初步测试基于中间件、带数据库的应用部署能力。

- **连接器数据源接入**：将连接器作为数据源，接入云端应用部署能力。
- **身份与数据源访问控制**：参考 ChatGPT Side 的方向，探索按访问者身份控制数据源访问权限，让每位用户访问云端网页时，看到与自身身份权限对应的数据。
- **自定义域名与部署基础设施**：支持用户自定义域名配置，并完善底层域名解析与证书配置能力。

### 独立站基础能力

#### 1. 支付能力

- 国际站接入微信支付。
- 国内站与国际站均支持微信签约。

#### 2. 订单、发票与退款能力

在 LightVela 中接入腾讯云的订单与发票机制，支持退款机制与腾讯云代金券体系。

#### 3. 账号能力

支持账号注销与冷静期机制。

#### 4. 安全与合规

- Chat 层面接入内容安全与风控能力。
- 整个站点支持防薅机制。

#### 5. 开放能力建设

LightVela 逐步开放 API、SDK 或 MCP 的接入能力。

### 数据体系建设

- **用户场景挖掘**：建立用户场景的持续挖掘机制。
- **产品使用与经营数据**：建立产品使用规模、经营与成本的数据体系。
- **独立站访问数据**：建立覆盖独立站访问信息的完整数据体系。

### 安全性建设

接入代码安全与漏洞扫描的公共机制。
