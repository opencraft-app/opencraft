# 国际站繁体中文支持（P1：官网）

## 基本信息
- 当前产品：LightVela（国际站 lightvela.ai）
- 需求单状态：草稿
- 创建人：jasminzhao
- 创建日期 / 最后更新时间：2026-07-27 / 2026-07-27
- 所属父需求：国际站繁体中文（zh-Hant）支持（分三阶段：P1 官网 → P2 文档站 → P3 控制台）

## 需求背景
- 为什么要做：国际站 lightvela.ai 目前仅提供 English 与 简体中文（zh-SG）两种语言。中国台湾、香港、澳门及部分东南亚华人用户习惯使用繁体中文，缺失繁体会造成阅读门槛与品牌本地化不足。
- 不做会怎么样：繁体地区用户只能看到简体或英文，转化与信任度受损；后续文档站、控制台繁体化也缺少统一的语言基础设施。
- 用户价值：繁体地区用户在官网获得母语一致的浏览体验。
- 业务价值：提升繁体市场的落地页转化与专业形象；一次性搭好"新增第三语言"的地基，为 P2 文档站、P3 控制台复用。

## 目标用户与场景
- 目标用户画像：使用繁体中文的海外/港澳台华语用户，通过搜索或分享链接访问 lightvela.ai 官网页面的潜在用户。
- 典型场景：
  - 用户首次访问 lightvela.ai，在语言切换器中选择「繁體中文」，官网落地页文案切换为繁体。
  - 用户通过繁体地区搜索引擎命中 `/zh-hant/...` 页面，直接看到繁体内容且 SEO/hreflang 正确。

## 目标
- 产品结果：国际站官网新增并列的第三种语言「繁體中文（zh-Hant）」，语言菜单为 `English / 简体中文 / 繁體中文`，官网可见文案完整呈现繁体。
- 业务目标（定性为主）：为繁体地区提供母语官网体验；不引入定量转化承诺，作为本地化基础能力建设。

## 范围
- 本次包含（P1）：
  - 在国际站（global）新增 locale `zh-Hant`，作为与 `en-US`、`zh-SG` 并列的第三种语言，`zh-SG` 保留不变。
  - URL 前缀 `zh-hant`（BCP-47），繁体官网页面走 `/zh-hant/...`。
  - 语言切换组件加入「繁體中文」选项，切换后写入 localStorage 并改写 URL 前缀。
  - 官网公开页面（首页、about、changelog、订阅页、隐私政策、Cookie 政策、开源许可等落地/法律页）UI 文案的繁体呈现。
  - 繁体文案由现有 zh-SG 简体做**简→繁转换**（如 OpenCC）+ 维护一份**术语校正表**（港台常用词，如 軟體/影片/網路 等）。
  - 语言相关基础设施：SEO/hreflang/canonical、sitemap.xml、静态产物 `<html lang>` 修正、SEO 构建校验脚本、繁体字体子集。
- 本次不包含：
  - P2 文档站（`/docs` 帮助文档繁体）与 P3 登录后控制台应用（含 tea-app SDK 面板）繁体。
  - 简繁词汇全量精校（本次仅覆盖官网可见文案的术语校正）。
  - 国内站 lightvela.com 的任何改动。
  - 繁体地区专属的营销活动、图片重做（除非文案图有硬编码文字）。
- 优先级：P1
- 已知依赖：
  - 现有 zh-SG 简体文案为繁体转换的源。
  - 简→繁转换工具与术语校正表。
  - 繁体字体子集（避免缺字）。

## 功能详细描述
- 功能点拆解：
  1. **Locale 注册**：新增 `zh-Hant` 到国际站可选语言集合（当前单一真相源集中在 `next-site/seo.tsx` 的语言常量与 `[lang]/docs` 的 region locale；本次以官网为主，涉及公开站 locale 类型与映射表）。建议在改动中顺带将分散的 locale 二/三元判断向数据驱动的 locale 注册表收敛（非强制，避免范围膨胀）。
  2. **URL 路由**：`/zh-hant/...` 前缀可被语言前缀匹配识别（扩展 `matchPublicLangPrefix` 等正则与映射），并纳入初始语言优先级（URL 前缀 > localStorage > 默认）。
  3. **语言切换**：切换器新增「繁體中文」项；国际站中文不再只映射 zh-SG，需区分 简体（zh-SG）与 繁体（zh-Hant）两项并存。
  4. **文案繁体化**：以 zh-SG 简体为源，简→繁转换生成官网 UI 繁体文案，叠加术语校正表覆盖机转用词差异。
  5. **SEO**：hreflang/alternates 增加 `zh-Hant`（BCP-47 输出，如 `zh-Hant`），sitemap 增加繁体 URL，静态产物 `<html lang="zh-Hant">` 正确写入，SEO 构建校验通过。
  6. **字体**：扩大/新增繁体字体子集，覆盖官网繁体文案字符，避免缺字。
- Demo / 页面结构说明：本次不新增页面结构，仅在既有官网页面上新增一种语言呈现，复用现有页面布局；默认输出以现有页面 + 语言切换器的实际运行效果作为 Demo（本地 `pnpm dev:global` 切换到繁体验证）。
- 交互说明：用户在语言切换器选择「繁體中文」→ URL 前缀切到 `/zh-hant`，页面文案切换为繁体，选择被持久化。
- 边界条件与异常处理：
  - 某文案缺少繁体（转换/校正未覆盖）时，回退到 zh-SG 简体或默认语言，不得出现空白或报错。
  - 直接访问 `/zh-hant/<未本地化页面>` 时按既有回退策略处理，页面可正常渲染。
- 数据埋点需求：沿用现有语言切换埋点，新增语言值 `zh-Hant`（如现有切换有埋点则补充枚举值）。

## 发布站点与同步策略
- 发布范围：国际站 lightvela.ai（global）
- 国际站是否同步：是（本需求即国际站）
- 国内站是否同步：否（国内站单语言中文，无繁体需求，本次不改动）
- 差异化原因：语言/本地化差异，仅国际站涉及多语言与繁体受众
- 路由与内容影响：新增 `/zh-hant` 路由前缀；影响语言切换组件、公开站 i18n 文案、SEO/hreflang/canonical、sitemap、`<html lang>`、字体子集
- 上线顺序：国际站单独上线；作为父需求三阶段中的第一阶段，先官网灰度/上线，再推进 P2 文档站、P3 控制台

## LightVela 影响面

- SkillHub/MCP/工具：无

## 非功能性需求
- 性能指标：新增语言不显著增加首屏体积；繁体字体走子集化，避免全量繁体字体拖慢加载
- 兼容性：沿用现有兼容性要求（现代浏览器）
- 安全与权限：无新增权限或安全要求
- 国际化 / 无障碍：`<html lang="zh-Hant">` 正确标注；繁体文案避免机转导致的语义错误（术语校正表兜底）

## 方案决策
- 采用方案：方案 A —— 并列新增 `zh-Hant`（URL 前缀 `zh-hant`），官网繁体文案由 zh-SG 简→繁转换 + 术语校正表，`zh-SG` 保留
- 选择理由：`zh-Hant` 与 `zh-SG` 并存满足繁简双受众；`zh-hant` 前缀符合 BCP-47 与 SEO 规范；从简体转换成本最低、上线快，术语校正表兼顾质量
- 备选方案与取舍：
  - 方案 B（只加繁体入口、文案暂复用简体不转换）：上线最快但切繁体仍显示简体字，体验割裂，不采用
  - 全人工翻译：质量最高但需翻译资源与排期，官网文案量小，收益不划算，暂不采用
- 延后或不做：P2 文档站、P3 控制台繁体；简繁全量精校

## 验收标准
- 验收 1：国际站语言切换器出现三项 `English / 简体中文 / 繁體中文`，选择繁体后官网落地/法律页面文案为繁体，且 `zh-SG` 仍可正常使用
- 验收 2：繁体页面 URL 为 `/zh-hant/...`；`<html lang>` 为 `zh-Hant`；hreflang/canonical/sitemap 包含繁体，SEO 构建校验（check-next-seo 等）通过
- 验收 3：官网繁体文案无明显机转错词（术语校正表覆盖高频词）、无缺字（字体子集覆盖）；文案缺失时回退到简体/默认语言且不报错
- 验收 4：`pnpm build:global` 构建通过，相关单测（seo、html lang、language-switcher 等）补充 zh-Hant 用例并通过

## 发布与观测
- 灰度/开关：作为新增语言项上线；如需可先内部/灰度验证 `/zh-hant` 再对外露出切换入口
- 日志/埋点/指标：语言切换埋点新增 `zh-Hant` 枚举；观测繁体页面访问量与切换占比
- 回滚：如异常，隐藏繁体切换入口 / 移除 `zh-Hant` locale 注册即可回退，不影响 en-US、zh-SG
