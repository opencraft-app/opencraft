## 背景与问题

LightVela 当前的自动任务彼此独立。用户可以创建周期任务、配置任务说明、Skill 和通知渠道，但不能在页面中让一个任务直接复用另一个任务的执行结果。

资讯整理、内容生产、项目巡检和周期分析等场景通常包含多个可以独立执行的阶段：

```text
A：收集原始信息
        ↓ 最近一次完成输出
B：筛选、分析或加工
        ↓ 最近一次完成输出
C：生成最终内容或发送简报
```

Hermes Agent Cron 已通过 `context_from` 支持定时任务之间的结果传递：下游任务按自己的计划启动，在启动时读取上游任务最近一次已完成的非空输出，并把输出注入本次任务上下文。当前原生调度器按输出文件时间选择最新结果，不额外按执行成功或失败筛选。

`context_from` 不等同于完成事件触发。下游任务不会等待同一时刻仍在运行的上游任务，也不会在上游完成后立即接手；它只在下游自己的计划时间读取当时可用的最近结果。本需求首期严格采用这一定时串联语义，不扩展为工作流调度引擎。

### 当前用户怎么做

- 把收集、分析和生成全部塞入一个长任务，任务说明复杂且难以复用。
- 手工复制上游结果到下游任务或普通对话。
- 绕过 LightVela 页面直接管理 Hermes Cron 配置。
- 通过错峰定时模拟多阶段流程，但无法在页面中建立和识别任务关系。

### 当前卡点

- 创建或编辑自动任务时不能选择上游任务。
- 任务卡片和详情无法展示来源关系。
- 执行记录无法说明本次是否拿到上游上下文、使用的是哪次输出。
- 上游暂停或删除后，下游任务的行为对用户不可见。
- 页面能力与 Hermes Cron 已有的 `context_from` 能力不一致。

### 为什么现在要做

- Hermes 已具备基础的上下文传递能力，不需要首期新增完成触发调度器。
- LightVela 已有完整的自动任务创建、编辑、详情、删除和执行历史入口，具备补齐配置面的产品基础。
- 单上游定时串联可以覆盖“收集 → 分析 → 生成”类核心场景，同时避免首期引入分支、汇聚和事件触发的复杂度。

## 目标用户与场景

### 目标用户

- 使用 LightVela 自动任务处理周期性工作的个人用户。
- 需要拆分“收集—分析—生成—发送”等多阶段流程的内容创作者、运营人员和知识工作者。
- 国内站中具备 Agent 和自动任务使用权限的用户。

### 典型场景

#### 每日新闻简报

- A 每天 07:00 收集过去 24 小时的行业新闻。
- B 每天 07:30 使用 A 最近一次完成输出完成筛选和排序。
- C 每天 08:00 使用 B 最近一次完成输出生成最终简报并投递。

#### 项目风险分析

- A 周期性汇总项目状态和异常。
- B 在稍后的固定时间读取 A 最近一次完成输出，分析风险并发送提醒。

#### 内容生产流水线

- A 抓取候选内容。
- B 筛选并提炼观点。
- C 生成最终发布稿。

### 频率和重要性

- 自动任务会周期性重复执行，错误关系可能持续产生过期或偏离预期的结果。
- 用户必须能看懂串联是“读取最近结果”，而不是“等待上游完成”。
- 上游输出时间、暂停状态和缺失状态需要清晰可见，避免用户误把旧数据当成最新数据。

## 目标

### 用户结果

- 创建或编辑自动任务时，可以显式选择一个当前 Agent 中正常运行的任务作为上游。
- 下游任务到达自己的执行时间后，自动获得上游最近一次完成输出。
- 用户能够确认任务之间的来源关系，并理解 Hermes 在运行时如何选择上下文。
- 上游缺少输出、暂停或删除时，用户可以理解下游如何继续运行。

### 产品结果

- 补齐 LightVela 与 Hermes `context_from` 的能力差距。
- 在不引入工作流调度引擎的前提下，支持可理解、可维护的多阶段自动化场景。
- 保持历史任务和未配置上游的普通任务完全兼容。

### 业务目标

- 降低用户配置和维护多阶段自动化任务的成本。
- 扩展自动任务能够覆盖的复杂使用场景。
- 建立串联任务数、关系变更和自动解绑结果等基础观测；首期不预设缺乏历史基线支持的增长百分比。

### 不做会怎样

- 用户继续依赖长任务、手工复制或 Hermes 原生配置，LightVela 页面无法承接完整场景。
- 多阶段任务缺少关系和执行来源可见性，出现旧结果或无结果时难以排查。
- LightVela 自动任务仍停留在彼此独立的任务管理器形态。

## 范围

### 本次包含

- 在现有创建/编辑任务弹窗增加“上游任务（可选）”单选控件。
- 表单中“调用技能”位于“上游任务”之前，几个“（可选）”使用一致的辅助文字样式。
- 国内站“调用技能”下拉的当前已选项支持勾转叉并点击清除；国际站保持原有选择交互。
- 每个任务最多关联一个上游任务。
- 允许继续串成 A → B → C。
- 上游候选仅来自同一 Agent 中正常运行的正式任务。
- 排除自身、临时测试任务、暂停任务、过期任务及可能形成循环依赖的任务。
- 下游任务按自身计划独立执行，不等待上游任务完成。
- 下游任务使用上游最近一次完成的非空输出；即使该输出来自失败运行，Hermes 也不会自动回退到更早的成功输出。
- 上游没有可用输出或读取失败时，Hermes 不注入上游上下文，下游仍按自身任务说明继续执行。
- 上游暂停后保留绑定，下游继续使用暂停前最近一次完成输出并显示暂停提示。
- 上游输出注入下游 Prompt 前由 Hermes 原生限制为最多 8,000 个字符，超出部分截断。
- 上游删除时自动解除直接下游绑定；下游继续独立执行。
- 删除执行前重新读取关系；依赖关系发生变化时停止删除并要求用户重新确认。解绑中途失败时回滚已经修改的直接下游，避免部分解绑。
- 对 Hermes 中已经存在的多上游配置进行只读展示和原样保留，LightVela 首期不允许在 UI 中把它改写为单上游。
- 关系数据未成功读取时，普通任务列表仍可使用，但不得新增、修改或删除可能影响关系的任务。
- 任务卡片、任务详情和执行记录展示必要的串联关系及原生语义说明；首期不声称展示 Hermes 未持久化的“本次实际注入来源”。
- 仅国内站提供；国际站保持原有自动任务体验。
- 历史任务保持原行为，无需迁移。

### 本次不包含

- 上游完成后立即触发下游。
- 一个任务关联多个上游任务。
- 在 LightVela UI 中编辑 Hermes 外部创建的多上游配置。
- 跨 Agent、跨实例或跨用户串联。
- 可视化任务链画布。
- 条件分支、并行汇聚、失败重试编排。
- 上游暂停后自动暂停下游。
- 跨任务统一编辑执行时间。
- 把 LightVela 改造成通用工作流编排器。

### 已知依赖

- 目标 Hermes 运行时支持 `context_from` 的创建、更新、读取和执行。
- LightVela 能够读取同一 Agent 的完整 Cron job 关系，完成候选过滤和循环检测。
- LightVela 能够读取任务当前的 `context_from` 关系，用于回显、候选过滤、循环检测和关系展示。
- 上游删除前，LightVela 能够查询并更新直接引用它的下游任务。
- Hermes 官方把 `context_from` 描述为 `cronjob` 工具参数，独立 CLI 文档未提供 `--context-from` 创建方式；本期已确认通过目标 Hermes 环境中的官方 Python `cronjob` 工具检测和写入该字段，不臆造 CLI 参数。
- 当前 Hermes 文档同时出现“最近成功输出”和“最近完成输出”表述；当前调度器实现以最新完成输出文件为准。本期按运行时原生行为验收，不在 LightVela 增加成功状态筛选。

## 方案决策

### 采用方案

在现有“添加/编辑自动任务”弹窗中增加“上游任务（可选）”单选选择器。用户从同一 Agent 的有效任务中选择一个上游，系统把稳定任务 ID 写入 `context_from`。

任务卡片、详情和执行记录增加轻量关系信息，不创建独立任务链页面。

表单沿用既有字段结构，并将相关可选能力统一排列为“调用技能 → 上游任务 → 通知方式”。上游任务和调用技能的国内站下拉均允许从当前已选项直接清除选择，减少额外的空选项和操作路径。

### 选择理由

- 与 Hermes 原生模型一致，首期只补齐能力入口和可见性。
- 与现有单弹窗创建流程一致，学习和开发成本较低。
- 单上游足以形成 A → B → C，覆盖核心多阶段场景。
- 避免首期引入多上游顺序、事件触发、条件分支和画布交互。
- 上游为可选项，确保普通任务和历史任务不受影响。

### 备选方案与取舍

#### 备选一：从任务卡片发起“添加后续任务”

- 优点：更符合从 A 向后搭建 B 的接力心智。
- 缺点：增加任务卡片动作和第二条创建路径，编辑关系仍需回到表单。
- 结论：首期不采用；后续可作为快捷入口评估。

#### 备选二：独立任务链画布

- 优点：任务关系更直观，适合复杂编排。
- 缺点：明显超出单上游定时串联范围，并容易让用户误认为系统支持完成触发、分支和汇聚。
- 结论：不采用。

#### 备选三：完成事件触发链

- 优点：上游成功后可立即由下游接手，并能绑定同一次运行结果。
- 缺点：`context_from` 本身不提供该语义，需要新增事件触发、运行实例绑定、失败传播和重试机制。
- 结论：本次延后。

## 功能详细描述

### 创建任务

在现有自动任务创建弹窗中增加：

```text
上游任务（可选）
[ 本任务执行时，将使用上游任务最近的输出作为上下文 ▼ ]
```

交互规则：

- 默认不关联，保持现有任务创建行为不变。
- “调用技能”展示在“上游任务”之前；“调用技能”“上游任务”“通知方式”的“（可选）”样式保持一致。
- 下拉框仅展示当前 Agent 中符合条件的任务。
- 每项只展示任务名称，不展示 Cron 表达式、执行周期或最近完成时间。
- 支持按任务名称搜索。
- 下拉不提供单独的“不关联”选项；当前已选项默认显示勾，悬停或键盘聚焦时切换为叉，点击后解除关联并关闭下拉。
- 保存时将上游稳定任务 ID 写入 `context_from`。

### 调用技能下拉对齐

- 国内站当前已选技能在下拉中默认显示勾；鼠标悬停或键盘聚焦时切换为叉，点击后清除技能并关闭下拉。
- 国内站已选技能在选择框右侧也提供明确的清除操作。
- 国际站不应用本次勾转叉和点击已选项清除的交互，继续保持原有调用技能下拉行为。

### 编辑任务

- 打开编辑弹窗时回显当前上游任务。
- 用户可以新增、更换或解除上游绑定。
- 编辑其他字段但未修改上游时，保持原绑定不变。
- 修改关系不会立即触发任务，仅影响后续计划运行。
- 保存失败时保留当前表单内容，并提示绑定更新失败。
- 若任务由 Hermes 外部配置了多个上游，页面展示现有上游名称和“暂不支持在 LightVela 中编辑”提示；用户只修改其他字段时必须原样保留多上游关系。

### 候选任务过滤

下列任务不出现在候选列表中：

- 当前正在编辑的任务自身。
- 已暂停或已过期任务。
- 测试运行产生的临时任务。
- 选择后会形成循环依赖的任务。

例如已有 A → B，则编辑 A 时不能选择 B 作为上游。

任务名称只用于展示，关系始终绑定稳定任务 ID；上游重命名后，下游自动显示新名称。

### 任务关系展示

任务卡片增加轻量标识：

```text
来自：每日新闻收集
```

任务详情增加“上游任务”信息：

- 上游任务名称。
- 上游当前状态。
- 当前任务自己的执行时间。
- “本任务执行时，将使用上游任务最近一次的输出作为上下文。”说明。

### 执行记录

下游执行记录展示该任务配置的上游关系和 Hermes 原生读取规则：

| 上游状态 | Hermes 原生行为 | 用户展示 |
| --- | --- | --- |
| 存在完成输出 | 读取最新非空输出并注入，最多 8,000 字符 | `上游：A · 运行时读取最近完成输出` |
| 最新完成输出来自失败运行 | 仍读取该最新输出，不回退旧成功结果 | `上游：A · 最近完成状态为失败` |
| 没有输出文件或输出为空 | 不注入上下文，下游继续执行 | `上游：A · 暂无可用输出` |
| 已暂停 | 使用暂停前最后留下的完成输出 | `上游：A · 已暂停，可能使用历史输出` |
| 读取输出失败 | 静默跳过上下文，下游继续执行 | `上游：A · 上下文可能未注入` |
| 已解除绑定 | 按普通任务执行 | 不显示上游关系信息 |

Hermes 当前不会在下游执行记录中持久化本次实际注入的来源文件和注入结果，因此首期只展示任务关系和可观测的上游状态，不把当前最新输出反推为历史运行实际使用的输出。若后续需要精确溯源，应由 Hermes 运行时新增执行级 provenance 元数据后再扩展。

### 暂停与恢复

- 暂停上游不改变绑定。
- 下游继续按计划执行，并使用上游暂停前最近一次完成输出。
- 下游任务卡片、详情和执行记录显示上游暂停警告。
- 恢复上游后关系自动恢复正常，不要求重新绑定。

### 删除上游任务

删除上游前，确认弹窗展示受影响的直接下游任务：

```text
“每日新闻收集”正在被以下任务使用：
- 每日新闻简报
- 每日选题推荐

删除后，这些任务将解除上游绑定并继续独立执行。
```

执行顺序：

1. 删除执行前重新读取完整关系，并与确认弹窗中的直接下游列表比较。
2. 关系已变化时停止删除、刷新影响列表并要求用户再次确认。
3. 关系未变化时逐个解除直接下游的 `context_from`，并记录各任务修改前的原始关系。
4. 任一解绑失败时，停止删除并把已经修改的直接下游回滚到原始关系；若回滚仍失败，明确提示需要检查的任务。
5. 确认全部解除成功后删除上游任务。
6. 刷新受影响任务状态。

任一直接下游解绑失败时，停止删除上游，避免遗留无效关系或持续读取遗留旧输出。

A → B → C 中删除 A 时，只解除 A → B；B → C 保持不变。

### 空态与异常状态

- 没有可选任务：选择框仍可展开，列表显示“暂无可关联的上游任务”，并允许继续创建普通任务。
- 任务列表加载失败：上游控件显示加载失败并可重试；不清空其他表单内容。
- Hermes 版本不支持 `context_from`：隐藏或禁用控件，并提示需要升级运行时。
- 暂时无法确认 Hermes 是否支持 `context_from`：不开放关系编辑，但不影响普通任务列表和普通任务操作。
- `jobs.json` 无法解析或关系未完成水合：不得把未知关系当作“无关联”；新增关系、变更关系和删除任务均失败关闭，刷新成功后再继续。
- 读取上游输出失败：Hermes 静默跳过上下文，下游继续执行；页面只展示“上下文可能未注入”，不伪造精确运行结论。
- 检测到循环依赖：阻止保存并提示“任务之间不能形成循环”。
- 上游在表单打开后被暂停、删除或过期：保存前重新校验，要求重新选择或解除绑定。

### 数据和接口约束

- 每个自动任务最多保存一个上游任务 ID。
- 未选择上游时不写入 `context_from`，历史和普通任务保持原行为。
- 编辑时必须区分保持、替换和清除三种语义。
- 关系以任务 ID 为准，不使用可重复或可变的任务名称作为关联键。
- 任务列表读取必须包含 `context_from`，否则无法回显、过滤或检测循环。
- 关系读取结果必须携带可信状态；“未配置上游”和“尚未成功读取关系”不得合并为同一种状态。
- 读取时兼容 Hermes 原生多上游数组；LightVela 创建和编辑只写一个上游，外部多上游配置只读展示并在普通保存时原样保留。
- 执行历史展示任务的上游关系和可观测状态；首期不要求保存 Hermes 当前未提供的执行级上下文来源元数据。
- 能力检测必须基于目标 Hermes 版本或实际字段支持情况，不依赖前端硬编码猜测。

## 状态变化

| 当前状态 | 用户操作或系统事件 | 目标状态 |
| --- | --- | --- |
| 未绑定 | 创建/编辑时选择有效上游 | 已绑定且上游正常 |
| 已绑定且上游正常 | 点击已选上游任务右侧的叉 | 未绑定 |
| 已绑定且上游正常 | 编辑时选择其他有效上游 | 已绑定新上游 |
| 已绑定且上游正常 | 上游被暂停 | 已绑定但上游暂停 |
| 已绑定但上游暂停 | 上游恢复 | 已绑定且上游正常 |
| 已绑定 | 上游删除且自动解绑成功 | 未绑定，下游继续独立执行 |
| 已绑定 | 上游删除但自动解绑失败 | 保持绑定，上游不删除 |
| 已绑定 | 删除确认后发现直接下游列表变化 | 停止删除，展示最新影响列表并等待再次确认 |
| 外部多上游 | 编辑其他普通字段 | 多上游关系原样保留 |
| 关系读取未知 | 新增、变更关系或删除任务 | 阻止操作，等待关系刷新成功 |
| 任意状态 | 保存会形成循环 | 阻止保存，关系不变 |

### 已确认设计结论

- 上游选择器只展示任务名称，不展示 Cron 表达式或最近完成时间。
- 上游选择器不提供“不关联”选项；当前已选项用勾转叉完成解除关联。
- 国内站调用技能采用同类勾转叉清除交互，国际站保持原交互。
- “调用技能”位于“上游任务”之前，几个“（可选）”使用一致的辅助样式。
- 任务卡片用低权重“来自：A”标识来源；上游暂停时同时显示文字状态，不只依赖颜色。
- 任务详情和最近执行展示当前可观测的上游状态及最近完成时间，但不冒充执行级精确溯源。
- 删除确认弹窗列出受影响的直接下游任务，依赖变化后刷新列表并要求再次确认。

### 已确认实现约束

- 复用现有任务列表生成候选和检测循环；创建、编辑或删除关系前重新读取可信关系快照。
- 编辑语义明确区分保持、替换和清除 `context_from`，普通字段保存不得误改关系。
- 通过目标 Hermes 环境中官方 `cronjob` 工具的参数签名检测 `context_from` 能力，并使用同一结构化工具写入关系。
- 页面只展示当前可观测的上游关系和状态；Hermes 未提供执行级来源元数据前，不推断某次历史运行实际使用的输出。

## 非功能性需求

### 性能

- 优先复用当前已经加载的任务列表生成候选项。
- 不为下拉框中的每个任务单独请求执行历史。
- 列表、卡片和详情不直接加载或渲染完整上游输出。
- 循环依赖检测在前端基于当前任务关系完成，任务数量较多时仍应保持即时响应。

### 兼容性

- 没有 `context_from` 的历史任务保持原行为。
- 不支持该字段的旧 Hermes 运行时不发送相关配置。
- 上游任务重命名不破坏关系。
- 前端回滚不得主动清除已经写入 Hermes 的串联配置。
- 沿用现有浏览器、平台和分辨率兼容要求。

### 安全与隐私

- 不允许跨 Agent、跨实例或跨用户引用任务输出。
- 上游输出进入下游上下文时必须被明确标记为任务输出数据，不把输出正文拼接成系统指令。
- 页面只展示来源元数据，不默认展示上游输出全文。
- 埋点和普通日志只记录任务 ID、状态和时间，不采集 Prompt 或执行输出正文。
- 删除关系更新失败时采用失败关闭策略，不留下不可解释的半删除状态。

### 国际化与无障碍

- 国内站提供中文文案；国际站不展示本能力入口。
- 下拉框、警告、状态标识和错误提示支持键盘访问与屏幕阅读器。
- 颜色不是区分正常、暂停、缺失和失败状态的唯一方式。

## 验收标准

1. 创建或编辑任务时，可以选择同一 Agent 中的一个正常运行任务作为上游。
2. 候选列表不会出现自身、暂停、过期、临时测试或会形成循环的任务。
3. 保存后，Hermes 任务配置中正确写入一个 `context_from` 任务 ID。
4. 再次编辑任务时，可以正确回显、更换或解除上游绑定。
5. 编辑其他字段但未修改上游时，原绑定保持不变。
6. 下游到达自己的执行时间后，Hermes 能够使用上游最近一次完成的非空输出作为上下文，最多注入 8,000 个字符。
7. 上游最近一次完成输出来自失败运行时，下游仍使用该输出，不回退到更早的成功输出；页面明确提示这一原生语义。
8. 上游没有输出、输出为空或读取失败时，下游继续执行，不因缺少上下文失败。
9. 上游暂停后，下游保留绑定并继续使用历史输出，同时展示暂停警告。
10. 恢复上游后，串联关系无需重新配置即可继续生效。
11. 删除上游时，删除确认展示直接下游任务；系统先解除绑定，再删除上游。
12. 任一下游解绑失败时，上游不会被删除，并给出可理解的错误提示。
13. A → B → C 中删除 A，只解除 A → B，不影响 B → C。
14. 任务卡片、详情和执行记录能够展示关系和可观测状态，但不泄露完整输出，也不把当前状态冒充为历史运行实际注入来源。
15. 上游重命名后，下游关系保持有效并展示新名称。
16. 保存会形成循环的关系时，系统阻止保存且不改变原关系。
17. 旧 Hermes 运行时不支持该能力时，控件被隐藏或禁用，不影响普通任务创建。
18. 历史和未绑定任务无需迁移，创建、编辑和执行行为保持正常。
19. 国内站完成创建、编辑、详情、执行、暂停、删除和异常状态验证。
20. 国际站不展示上游任务入口、不探测或读写 `context_from`，普通自动任务回归通过。
21. 表单按“调用技能 → 上游任务 → 通知方式”排列，三个字段的“（可选）”辅助样式一致。
22. 上游下拉只展示任务名称，不展示 Cron 表达式或最近完成时间；不提供“不关联”选项，已选项可通过勾转叉解除。
23. 国内站调用技能下拉的已选项支持勾转叉并点击清除；国际站继续保持原有已选项行为。
24. Hermes 外部多上游配置在页面只读展示；编辑其他字段不会压缩、清空或改写原关系。
25. 关系读取不可信时，关系变更和删除操作失败关闭；删除确认后关系发生变化时要求再次确认，解绑中途失败时回滚已修改的直接下游。

## 发布与观测

### 灰度与能力开关

- 仅国内站上线。
- 能力入口受 Hermes 版本或实际字段能力检测控制。
- 不支持 `context_from` 的实例保持现有普通任务体验。
- 上线前至少使用 A → B → C 验证连续两轮周期执行。

### 日志、埋点与指标

建议记录：

- 打开上游任务选择器。
- 创建任务时建立绑定。
- 编辑任务时新增、更换或解除绑定。
- 因循环依赖阻止保存。
- 配置关系创建、更换、解除，以及上游暂停或缺失等可观测状态。
- 删除上游时自动解绑成功或失败。

核心观测指标：

- 已配置串联的任务数。
- 串联任务执行次数。
- 自动解绑失败率。

隐私约束：

- 不采集任务说明全文。
- 不采集上游输出正文。
- 默认只记录关系操作、状态、结果和非敏感时间信息。

### 发布验证

- 正常 A → B → C 串联连续运行两轮。
- 上游有完成输出、最新完成输出来自失败运行、无输出、读取失败四类状态。
- 上游暂停、恢复和删除。
- 候选过滤、自引用和多节点循环检测。
- 创建、编辑、解除绑定和历史任务兼容。
- 国内站完整主流程及文案；国际站验证功能未启用且普通自动任务不受影响。

### 回滚

- 前端入口可以通过能力检测关闭。
- 已存在的 Hermes 原生串联配置予以保留，不在回滚时批量清除。
- 回滚后已有串联任务继续由 Hermes 按原配置运行。
- 普通自动任务不受回滚影响。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 目标 Hermes 版本不支持 `context_from` | 无法创建或编辑关系 | 通过官方 `cronjob` 工具参数签名检测能力，不支持或无法确认时关闭关系编辑，普通任务保持可用 |
| Hermes 文档中“最近成功”和“最近完成”表述不一致 | 用户可能误以为失败输出会被过滤 | 产品文案和验收以当前调度器“最新完成输出文件”行为为准，并明确不回退旧成功结果 |
| 上游执行时间晚于下游 | 下游使用旧结果或无结果 | 页面明确展示独立计划和来源时间，不宣传完成触发 |
| 上游暂停 | 下游长期使用旧结果 | 保留绑定但持续展示暂停状态和输出时间 |
| 上游删除时自动解绑部分失败 | 出现半删除和无效关系 | 全部直接下游解绑成功后才删除上游 |
| 删除确认后依赖关系发生变化 | 用户确认的影响范围与实际执行范围不一致 | 执行前重新读取并比较直接下游，变化时停止删除并要求再次确认 |
| 关系读取失败却被当作无关联 | 覆盖外部关系或错误删除仍被引用的任务 | 使用关系可信状态区分“无关联”和“未知”，关系操作失败关闭 |
| 解绑成功一部分后后续任务失败 | 直接下游进入部分解绑状态 | 保存原始关系并逆序回滚，回滚失败时只展示受影响任务，不泄露任务输出 |
| 循环关系 | 任务上下文相互依赖、结果不可解释 | 候选过滤加保存前全图校验 |
| 上游输出含不可信内容 | 下游模型可能错误遵循数据中的指令 | 运行时把上游内容标记为任务输出数据，页面不拼接为系统指令 |
| 区域隔离失效 | 国际站意外出现未计划能力 | 使用编译期 `isGlobal` 分支，并增加国际站专属回归测试 |
