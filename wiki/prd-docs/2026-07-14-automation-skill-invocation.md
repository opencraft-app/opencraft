## 背景与问题

LightVela 自动任务目前支持配置任务名称、执行时间、任务说明、生效时间段和通知方式，但创建与编辑表单不能绑定当前 Agent 已安装的 Skill。

Hermes Cron 已支持 Skill-backed job：任务执行时创建新的 Agent 会话，先加载绑定 Skill 的 `SKILL.md`，再把任务说明作为本次任务指令执行。LightVela 当前缺少对应的产品入口，导致用户只能在每个自动任务中重复描述工作方法，无法复用已经安装并验证过的 Skill。

### 当前用户怎么做

- 在自动任务的“任务说明”中同时填写工作方法和具体任务。
- 每个相似任务重复维护提示词，容易产生表达不一致和遗漏。
- 如果希望复用 Skill，只能绕过 LightVela 页面，通过 Hermes CLI 创建或编辑 Cron job。

### 当前卡点

- 页面无法选择已安装 Skill。
- 页面无法展示任务与 Skill 的绑定关系。
- Skill 后续被卸载时，用户无法从任务配置中快速判断失败原因。
- UI 能力与 Hermes Cron 已有能力不一致。

### 为什么现在要做

- Hermes Cron 的创建、编辑和执行模型已经支持 Skill，无需新增调度机制。
- LightVela 已有独立的 Skill 管理和自动任务入口，具备建立绑定关系的产品基础。
- 补齐入口后，用户可以把稳定的工作方法沉淀为 Skill，把每次变化的目标保留在任务说明中。

## 目标用户与场景

### 目标用户

- 已在 Agent 中安装 Skill 的 LightVela 用户。
- 使用自动任务定期执行资讯整理、内容生成、数据分析或其他标准流程的个人和团队用户。

### 典型场景

用户已安装一个用于资讯订阅和摘要的 Skill，希望每天 09:00 自动加载该 Skill，检查过去 24 小时的 AI 新闻，并将摘要发送到已配置的通知渠道。

### 频率和重要性

- 自动任务会周期性重复执行，配置错误会持续产生失败或偏离预期的结果。
- Skill 绑定需要清晰可见、可编辑、可移除，并在不可用时给出明确反馈。

## 目标

### 用户结果

- 创建或编辑自动任务时，可以显式选择一个当前 Agent 已安装的 Skill。
- 用户不选择 Skill 时，继续使用现有普通自动任务能力。
- 用户能够在任务详情中确认当前绑定的 Skill。
- Skill 不可用时，用户能够识别原因并重新安装、更换或移除绑定。

### 产品结果

- 补齐 LightVela 自动任务与 Hermes Skill-backed Cron 的能力差距。
- 降低用户重复维护复杂任务提示词的成本。
- 保持现有自动任务兼容，不引入强制迁移。

### 不做会怎样

- 用户仍需通过 CLI 使用 Skill-backed Cron，页面能力不完整。
- 相似自动任务继续重复维护工作方法，难以复用和统一。
- Skill 缺失导致的执行问题缺少可见的产品反馈。

## 范围

### 本次包含

- 创建自动任务时，显式选择一个当前 Agent 已安装的 Skill。
- Skill 为可选项，默认不选择。
- 编辑任务时回显、更换或移除 Skill。
- 任务详情展示 Skill 绑定关系。
- 已绑定 Skill 被卸载后的不可用状态和处理引导。
- Skill 列表为空、加载失败或编辑期间发生变化时的异常处理。
- 选择、切换或清除 Skill 时不修改任务说明，任务说明始终由用户手工填写或沿用既有内容。
- “调用技能”后提供帮助提示：“在此处选择技能后，Agent 会在执行任务前加载该技能，相比仅在任务说明中通过提示词要求调用技能更加稳定。”
- 国内站与国际站同步发布及中英文文案。
- 历史任务保持原有行为，无需迁移。

### 本次不包含

- 一个自动任务绑定多个 Skill。
- 根据 Skill 自动生成、推荐或改写任务说明。
- 在自动任务弹窗内安装、创建、学习或修改 Skill。
- 自动移除已经失效的 Skill 绑定。
- Skill 失效后静默降级为普通任务。
- 阻止用户卸载被自动任务引用的 Skill。
- 自动识别 Skill 是否兼容 Cron 非交互环境。
- 改造 Hermes Cron 调度、通知或运行机制。
- 对历史自动任务进行数据迁移。

### 已知依赖

- Hermes Cron 创建和编辑能力支持写入、替换和清除 Skill。
- LightVela 能够读取当前 Agent 已安装的 Skill 列表。
- 自动任务详情能够读取 Cron job 保存的 Skill 信息。
- Skill 名称/slug 必须与 Hermes 实际安装目录匹配。

## LightVela 影响面

- 前端页面/路由：自动任务创建、编辑、详情；不新增路由。
- Hermes/OpenClaw/运行时：复用 Hermes Cron 的 Skill-backed job，不改变调度机制。
- SkillHub/MCP/工具：复用当前 Agent 的已安装 Skill 列表，不在本需求中引入安装能力。
- SDK/文档/运营：补充自动任务调用 Skill 的使用说明和非交互限制；是否需要 SDK 调整由研发评估。

## 方案决策

### 采用方案

在现有“添加/编辑自动任务”弹窗中增加“调用 Skill（可选）”单选选择器，不创建新的任务向导。

选择器放在“任务说明”之后、“生效时间段”之前。用户先说明本次要做什么，再选择使用哪个 Skill 完成。

### 选择理由

- 与现有单弹窗创建流程一致，学习和开发成本较低。
- Skill 绑定对任务结果有直接影响，在主表单中展示比放入高级设置更容易发现。
- 一个任务只绑定一个 Skill，避免一期引入多 Skill 顺序和冲突处理。
- Skill 可选，确保现有用户和历史任务不受影响。

### 备选方案与取舍

#### 备选一：放入折叠的高级设置

- 优点：主表单更简洁。
- 缺点：入口较深，新能力难以发现。
- 结论：不采用。

#### 备选二：独立的 Skill 自动任务向导

- 优点：可以先选 Skill，再引导生成任务内容。
- 缺点：形成第二套创建流程，超出一期目标。
- 结论：不采用。

### 交互流程

#### 创建任务

1. 用户填写任务名称、执行时间和任务说明。
2. 用户打开“调用 Skill（可选）”选择器。
3. 系统加载当前 Agent 已安装的 Skill。
4. 用户保持“不调用 Skill”，或单选一个 Skill。
5. 用户提交任务。
6. 选择 Skill 时，系统把一个 Skill slug 写入 Cron job；未选择时不写入 Skill。
7. Hermes 到点执行时先加载 Skill，再执行任务说明。

#### 编辑任务

1. 打开编辑弹窗时回显当前 Skill 绑定。
2. 用户可以保持、更换 Skill，或选择“不调用 Skill”解除绑定。
3. 编辑其他字段但未修改 Skill 时，保持原绑定不变。
4. 保存后同步更新 Cron job。

#### 查看详情

1. 任务详情新增“调用 Skill”字段。
2. 已绑定且可用时展示 Skill 名称。
3. 未绑定时展示“不调用 Skill”。
4. 已绑定但当前未安装时展示原 Skill 名称和“不可用”状态。

### 状态变化

| 当前状态 | 用户操作或系统事件 | 目标状态 |
| --- | --- | --- |
| 未绑定 | 创建/编辑时选择 Skill | 已绑定且可用 |
| 已绑定且可用 | 编辑时选择“不调用 Skill” | 未绑定 |
| 已绑定且可用 | 编辑时选择其他 Skill | 已绑定新的 Skill |
| 已绑定且可用 | Skill 后续被卸载 | 已绑定但不可用 |
| 已绑定但不可用 | 用户重新安装同名 Skill | 已绑定且可用 |
| 已绑定但不可用 | 用户编辑并更换 Skill | 已绑定新的 Skill |
| 已绑定但不可用 | 用户编辑并移除 Skill | 未绑定 |

### 数据或接口约束

- 一期每个自动任务最多保存一个 Skill slug。
- 创建时选择 Skill，最终命令等价于增加一个 `--skill <slug>`。
- 编辑时更换 Skill，需要替换现有 Skill 列表。
- 编辑时移除 Skill，需要清除现有 Skill 列表。
- Skill slug 必须使用已安装列表返回的真实值，不能根据展示名称自行拼接。
- 具体 Skill 列表读取方式由研发评估，但产品契约是“当前 Agent 已安装的 Skill”。

### 异常和空态

- 没有安装任何 Skill：显示空态并引导前往技能管理；仍可创建普通任务。
- Skill 列表加载失败：保留其他表单内容并提供重试；仍可不选择 Skill 创建任务。
- Skill 在编辑期间被卸载：提交前提示已不可用，要求重新选择或取消绑定。
- Skill 在任务创建后被卸载：保留绑定，不自动降级；详情显示不可用，执行时展示 Hermes 实际错误。
- Skill 不兼容非交互环境：展示 Hermes 实际执行错误，不声称自动兼容。
- 历史任务：按未绑定 Skill 展示，行为保持不变。

### Cron 兼容性说明

Hermes Cron 在新的非交互 Agent 会话中运行。部分依赖提问、消息发送或交互确认的 Skill 可能无法使用。

一期不构造不存在的兼容性识别能力：

- 选择器展示全部已安装 Skill。
- 选择器内提示“自动任务在非交互环境中运行，请确认该 Skill 支持无人值守执行”。
- 不在执行失败时静默降级。

## 产品原型说明

- 目标页面/入口：Agent 控制台 → 自动任务 → 添加或编辑自动任务。
- 用户主路径：填写任务 → 可选 Skill → 配置生效时间和通知 → 创建。
- 页面结构：

```text
添加自动任务
├── 自动任务名称
├── 执行时间
├── 任务说明
├── 调用 Skill（可选）
│   ├── 不调用 Skill
│   ├── 搜索已安装 Skill
│   ├── Skill 名称与 slug
│   └── 非交互运行提示
├── 生效时间段
├── 通知方式
└── 取消 / 创建
```

- 关键组件：产品内自定义下拉选择器，不使用浏览器原生 `<select>`。
- 状态：默认、加载、空态、加载失败、已选择、已绑定但不可用。
- 主要操作：选择、更换、移除 Skill；前往技能管理；重试加载。
- 需要设计确认：选择器展开层、Skill 名称与 slug 层级、不可用状态的视觉表达。
- 需要前端确认：已安装 Skill 列表的复用方式、编辑时的 Skill 更新语义。
- 独立高保真原型：本次不单独生成；需求是在现有弹窗中增加一个表单字段和一个详情字段，文字结构足以进入研发评估。

## 验收标准

1. 创建自动任务时，“调用 Skill”为可选单选项，默认不选择。
2. 选择器只展示当前 Agent 已安装的 Skill，并支持按名称搜索。
3. 选择 Skill 后创建任务，Cron job 正确保存一个 Skill slug。
4. 未选择 Skill 时不传入 Skill 参数，任务行为与现有版本一致。
5. 编辑任务时能够回显、更换或移除已绑定的 Skill。
6. 编辑其他字段但未修改 Skill 时，原绑定保持不变。
7. 任务详情能够展示绑定的 Skill；未绑定时展示“不调用 Skill”。
8. Skill 被卸载后不自动解绑、不静默降级，任务详情显示不可用状态。
9. Skill 列表为空或加载失败时，不影响用户创建普通自动任务。
10. 历史自动任务无需迁移，创建、编辑和执行行为保持正常。
11. 国内站和国际站均完成创建、编辑、详情、移除绑定和异常状态验证。
12. 所有新增文案完成中英文国际化。
13. 埋点和普通日志不记录任务说明全文及用户自定义 Skill 内容。
14. “调用技能”后的帮助提示支持鼠标悬浮和键盘聚焦，并清晰说明显式选择技能的稳定性优势。

## 发布与观测

### 灰度/开关

- 一期不要求新增独立特性开关，随自动任务前端版本发布。
- 发布前分别验证国内站和国际站预览环境。

### 日志/埋点/指标

建议记录：

- 打开 Skill 选择器。
- 创建任务时是否绑定 Skill。
- 编辑任务时新增、更换或移除 Skill。
- Skill 列表加载成功、为空或失败。
- Skill-backed task 创建和更新的成功/失败结果。
- 因 Skill 不存在导致的执行失败类型。

隐私约束：

- 不采集任务说明全文。
- 不采集用户自定义 Skill 内容。
- 默认只记录是否绑定 Skill、操作类型和结果状态。
- 如需记录 Skill 标识，必须先确认现有数据规范允许，并避免采集用户自定义敏感名称。

### 回滚

- 前端回滚后，已保存的 Skill 绑定仍由 Hermes Cron 保留并继续按原配置执行。
- 回滚不得自动清除已有任务的 Skill 配置。
- 如果创建链路出现阻断，可回滚前端入口；已有普通自动任务不受影响。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Skill 不支持 Cron 非交互环境 | 执行失败 | 选择器提示限制，保留实际错误，不静默降级 |
| Skill 被卸载 | 周期性执行失败 | 保留绑定并显示不可用，引导重新安装、更换或移除 |
| 展示名称与 slug 不一致 | 绑定错误 | 保存已安装列表返回的真实 slug，展示名称仅用于阅读 |
| Skill 列表读取失败 | 无法选择 Skill | 允许重试，并保持普通任务创建可用 |
| 双站文案或能力不一致 | 验收遗漏 | 双站同步验证，新增文案统一进入 i18n |
