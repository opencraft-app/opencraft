# 双站 Soul 新推荐移除 MUM/MOMMY

## 基本信息

- 当前产品：LightVela Agent 人设页（`/agents/persona/`）
- 需求单状态：产品输入稿已确认，待产品评审
- 创建日期：2026-10-01
- 最后更新时间：2026-10-01
- 发布范围：国内站 `lightvela.com` 与国际站 `lightvela.ai` 同步

## 需求背景

产品决定不再向新抽卡或人格测试用户推荐“妈妈”类型的 Soul。国内站使用 `MUM` 标识，国际站各语言使用 `MOMMY` 标识；两者是同一类型在不同站点的呈现。已经抽到或应用该类型的用户仍需保有当前卡片与人设状态。本需求不推断移除原因，也不将其扩展为 SkillHub 来源下架。

## 目标用户与场景

- 目标用户：在 Agent 人设页抽取、重抽、测试或使用 Soul 卡片的国内站和国际站用户。
- 新抽卡或重抽：用户只会得到当前可推荐的其他 Soul。
- 人格测试：即使原匹配结果是该类型，用户仍能获得一张可用卡片。
- 历史使用：已抽到或已应用该类型的用户继续查看、使用原卡片。

## 目标

- `MUM/MOMMY` 不再通过 LightVela 人设页的新抽卡、重抽和人格测试进入用户卡片盘。
- 现有已抽卡片、已应用状态和详情能力保持可用。
- 两站同步生效，不影响其他 Soul 的现有流程。

## 范围

### 本次包含

- 国内站从 SkillHub 返回的候选池中排除 `MUM`，仅用于 LightVela 新抽卡、重抽及测试推荐。
- 国际站从当前各语言候选池中排除 `MOMMY`，覆盖中文、英文、印尼语、西班牙语、日语和韩语。
- 人格测试按现有匹配分数，从排除该类型后的可用候选中选择最高匹配 Soul；分数相同时沿用现有候选顺序。
- 保留历史卡片的本地化展示、详情、注入和已应用状态；历史卡片被用户主动重抽后，新卡仍遵循排除规则。

### 本次不包含

- 不修改或下架 SkillHub 的 Soul 数据、公共接口和其他使用方。
- 不删除 `MUM/MOMMY` 的详情或配置数据，不清理用户已保存的卡片和 Agent 当前 `SOUL.md`。
- 不改动 Agent 创建向导、人设上传、自定义人设或其他页面中的 Soul 来源。
- 不新增页面、入口、文案、埋点、后端接口或用户数据迁移。

- 优先级：由产品评审排期确定。
- 已知依赖：国内站 SkillHub 公共 Soul 列表、国际站本地化 Soul 数据、现有人格测试匹配逻辑及用户已抽卡片存储。

## 功能详细描述

### 新候选与测试推荐

1. 人设页加载候选池时，仅在 LightVela 的新推荐范围排除目标 slug。数据源保留原始详情，以供历史卡片继续使用。
2. 普通抽卡、重抽和人格测试使用同一可推荐范围；三个入口均不得新增目标卡片。
3. 人格测试仍按当前偏好分数计算相似度。如果原最高匹配是目标类型，则选择剩余候选中分数最高的一张，不出现空结果或不可操作结果。
4. 候选池加载失败、候选耗尽及卡槽已满时沿用现有状态与提示，不因本需求新增异常界面。

### 历史卡片

1. 已抽到的目标卡片保持显示；刷新、重新登录、切换国际站语言后仍按当前站点和语言正确展示。
2. 已应用状态与 Agent 中实际写入的人设保持原状。用户仍可查看详情、选择、重新注入或按现有规则删除、重抽该卡。
3. 用户主动重抽历史目标卡片时，替换结果不得再次为 `MUM/MOMMY`。
4. 当前 LightVela 人设页没有单张 Soul 的独立前端详情路由；本需求保留现有卡片详情入口和底层详情数据，不新增 URL。

### Demo 与原型判断

- 以现有人设页演示：新抽卡与人格测试不再产生该类型，历史卡片仍可查看和使用。
- 不另做交互原型：页面结构和交互路径不变，仅调整可推荐候选与测试匹配范围。

## 发布站点与同步策略

- 发布范围：国内站 `lightvela.com`、国际站 `lightvela.ai` 双站同步。
- 国内站是否同步：是；排除 `MUM`。
- 国际站是否同步：是；所有当前 Soul 卡片语言排除 `MOMMY`。
- 差异化原因：两站 Soul slug 和数据来源不同，用户可见结果一致。
- 路由与内容影响：仅 Agent 人设页及其抽卡、重抽、人格测试候选；不修改路由、SEO metadata、图片或文档。
- 上线顺序：双站随同一次前端发布生效。

## LightVela 影响面

- 前端页面/路由：`/agents/persona/` 的候选池、抽卡、重抽、人格测试与历史卡片展示。
- Hermes/OpenClaw/运行时：不修改写入机制或已有 `SOUL.md`。
- SkillHub/MCP/工具：SkillHub 不变；国内站仅在 LightVela 消费列表时排除新推荐候选。
- SDK/文档/运营：无新增交付。
- 权限/安全/数据：不新增权限，不删除或迁移历史数据。

## 非功能性需求

- 性能：不新增网络请求。
- 兼容性：沿用现有人设页桌面和移动端要求。
- 国际化：国际站各现有语言的新候选排除规则一致，历史卡片仍正确本地化。
- 无障碍与安全：沿用现有卡片交互和权限要求。

## 产物交接

- 产品：确认本 PRD 的双站范围、历史保留规则和验收标准，作为研发与 QA 输入。
- 前端：实现候选过滤与测试匹配范围调整，确保历史卡片不受新候选过滤影响；交付相邻回归测试。
- QA：在双站验证抽卡、重抽、测试结果、历史卡片及国际站语言切换；记录通过证据。
- 发布负责人：确认两站同次发布与回滚范围；无需 SkillHub 发布或数据迁移。
- 时序：产品评审确认后进入研发与 QA；双站验证通过后同步发布。

## 方案决策

- 采用方案：仅在 LightVela 排除新推荐候选，并对人格测试在剩余候选中重新选取最高匹配；历史卡片与详情数据保留。
- 选择理由：满足双站停止新增该类型的目标，同时维持已有用户状态，影响范围可控。
- 备选方案与取舍：同时从 SkillHub 来源下架会影响其他消费方，并与本次明确的 SkillHub 不变边界冲突，不采用。
- 延后或不做：不建立全局 Soul 上下架机制，不清理历史记录。

## 验收标准

1. 国内站新抽卡、重抽和人格测试均不新增 `MUM`；国际站各现有语言均不新增 `MOMMY`。
2. 当测试的原最高匹配为目标类型时，结果页显示剩余候选中分数最高的可用 Soul，详情和使用操作正常。
3. 两站已保存的目标卡片在刷新后继续显示；国际站切换语言后仍展示对应本地化内容。
4. 已应用状态与 Agent 当前人设不被自动更改；历史目标卡片的详情、重新注入、删除和重抽按现有规则工作。
5. 其他 Soul 的抽卡、测试推荐、注入和卡槽状态保持现有行为。
6. SkillHub 列表与详情接口及其他消费方不因本需求发生变更。

## 发布与观测

- 灰度/开关：不新增开关，随双站前端版本同步生效。
- 日志/埋点/指标：沿用现有抽卡与人格测试事件；本次不新增埋点。上线验证以双站入口与历史状态的 QA 结果为准。
- 回滚：回退 LightVela 的候选排除和测试匹配调整；无服务端数据迁移，历史卡片无需恢复。
