# 自动任务创建成功后发送通知确认

## 基本信息

- 当前产品：LightVela
- 需求状态：草稿
- 创建日期：2026-08-27
- 最后更新时间：2026-08-27
- 优先级：P1
- 发布范围：国内站、国际站同步

## 需求背景

用户添加自动任务后，目前只能在页面中看到创建成功，已选通知通道不会立即收到反馈。用户需要等到任务首次执行，才能确认自动任务与通知通道之间的关系，容易产生“任务是否添加成功、通知是否生效”的疑问。

本需求在自动任务创建成功后，立即向该任务选择的通知通道发送一条确认消息。

## 目标用户与场景

目标用户是使用 LightVela 自动任务，并为任务选择了一个或多个通知通道的用户。

典型场景：

1. 用户进入自动任务页面。
2. 用户通过空白表单或模板创建自动任务。
3. 用户选择一个或多个已配置的通知通道。
4. 自动任务创建成功。
5. 所有选中的通知通道分别收到创建确认消息。

## 产品目标

- 让用户在通知通道中直接获悉自动任务已经添加。
- 帮助用户确认当前任务与通知通道的关联。
- 不改变自动任务创建结果，不因确认消息发送失败而丢失任务。

## 本次范围

### 本次包含

- 普通添加和模板添加两种当前可用的自动任务创建路径。
- 仅在自动任务创建成功后发送。
- 仅向本次任务实际选中的全部通知通道发送。
- 支持一个任务选择多个通知通道，各通道独立投递。
- 国内站与国际站同步支持，并根据当前界面语言发送本地化文案。
- 部分或全部发送失败时，在页面显示非阻塞警告。

### 本次不包含

- 未选择通知通道时自动选择 Agent 的其他通道。
- 编辑、暂停、恢复或删除任务时发送消息。
- 为失败消息提供自动重试或手动重试入口。
- 修改定时任务正式执行结果的投递逻辑。
- 修改现有“测试消息”和“测试运行”的即时回执。
- 恢复当前已下线的场景任务入口。
- 新增通知开关或设置项。

### 已知依赖

- 自动任务创建成功状态及最终保存的通知目标。
- Hermes 现有即时消息发送能力。
- Agent 已配置并处于可用状态的通知通道。
- 现有 LightVela 国际化机制。

## 功能详细描述

### 1. 触发条件

同时满足以下条件时发送确认消息：

- 用户执行的是“创建自动任务”，不是编辑已有任务。
- 自动任务已由 Hermes 成功创建。
- 本次任务至少选择了一个通知通道。

未选择通知通道时，仅完成任务创建，不发送确认消息，也不显示额外提示。

### 2. 投递目标

以自动任务最终保存的通知目标为唯一依据：

- 选择一个通道：发送一条。
- 选择多个通道：分别向每个通道发送一条。
- 配置了具体 Chat ID：发送到对应 Chat ID。
- Agent 配置了其他通道、但本任务未选择：不发送。

### 3. 消息文案

中文：

> LightVela 已添加新的自动任务。

英文：

> LightVela has added a new automation.

其他已支持语言沿用现有国际化机制生成对应译文。

确认消息不包含任务提示词、Chat ID、账号信息等内容；第一版也不包含任务名称，避免把可能敏感的任务信息推送到外部会话。

### 4. 成功与失败状态

- 全部通道发送成功：沿用现有“自动任务创建成功”页面反馈，不增加额外提示。
- 部分通道发送失败：任务保持创建成功；页面提示“自动任务已添加，但部分通知通道发送确认消息失败。”
- 所有通道发送失败：同样不回滚任务，并显示上述非阻塞提示。
- 单个通道失败不影响其他通道继续发送。
- 不提供自动重试；用户可通过现有“测试消息”检查通道配置。

### 5. 执行顺序

```text
提交创建
  → Hermes 成功创建自动任务
  → 页面确认任务创建成功
  → 向任务选中的全部通知通道分别发送确认消息
  → 汇总投递结果
      → 全部成功：结束
      → 存在失败：显示非阻塞警告
```

确认消息投递属于创建后的附加动作，不得把消息发送失败转换成“自动任务创建失败”。

- 路由与内容影响：沿用现有 `/agents/automations/`；新增通知消息与页面错误提示的国际化文案；不影响图片、metadata、sitemap 或 SEO/GEO。

## LightVela 影响面

- 前端页面/路由：自动任务创建成功后的消息投递与错误反馈；不新增路由。
- Hermes/OpenClaw/运行时：复用现有即时发送能力，不触发 Agent 或 LLM，不新增调度任务。
- SkillHub/MCP/工具：无改动。
- SDK/文档/运营：无改动。
- 权限/安全/数据：沿用用户当前 Agent 和通知通道权限，不新增数据存储。

## 非功能性需求

- 通知发送失败不得回滚或删除已创建任务。
- 多通道之间相互隔离，不能因一个通道失败而中止其他通道。
- 消息内容不得包含任务提示词、通道凭证或 Chat ID。
- 沿用现有浏览器和设备兼容范围。
- 使用现有国际化机制，不在代码中按站点硬编码两套业务逻辑。
- 一次成功的用户创建操作，每个选中目标最多收到一条确认消息。
- 即时确认消息不得触发 Agent 或产生额外模型调用。

## 方案决策

### 采用方案

向本次任务选中的全部通知通道发送通用确认消息。

### 选择理由

- 与任务后续结果的投递范围保持一致。
- 不打扰用户未为该任务选择的通道。
- 通用文案不泄露任务内容。
- 发送失败不会损害已经创建成功的任务。

### 备选方案与取舍

- 向 Agent 已配置的所有通道发送：覆盖更广，但可能打扰未为该任务选择的会话，因此不采用。
- 只向第一个选中通道发送：实现更简单，但与当前多选能力不一致，因此不采用。

### 延后或不做

- 失败消息重试与独立重试入口。
- 用户自定义创建确认消息。
- 创建确认消息的独立开关。

## 验收标准

1. 创建任务且未选择通知通道时，任务成功创建，不发送确认消息。
2. 创建任务并选择一个通道时，该通道收到对应语言的确认消息。
3. 选择多个通道时，每个选中的通道分别收到一条消息。
4. 未被本任务选择的已配置通道不收到消息。
5. 配置具体 Chat ID 时，消息发送到该目标会话。
6. 编辑已有任务时不发送创建确认消息。
7. 单个通道发送失败时，任务仍然存在，其他通道仍继续发送。
8. 任一通道发送失败时，页面显示非阻塞警告，不显示“创建自动任务失败”。
9. 国内站与国际站均满足以上行为，并显示对应语言的消息。
10. 消息中不包含任务名称、提示词、Chat ID 或通道凭证。
11. 确认消息不触发 Agent 或产生额外模型调用。
12. 一次成功的创建操作中，每个选中目标最多收到一条确认消息。
