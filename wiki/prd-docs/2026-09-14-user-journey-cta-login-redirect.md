# 用户链路修正：登录按钮与 Hero/Footer CTA 分流逻辑

## 基本信息

- 当前产品：LightVela
- 需求单状态：草稿
- 创建人：keriaxu
- 创建日期：2026-09-14
- 最后更新时间：2026-09-14

## 需求背景

- 当前官网/营销站的登录按钮与 Hero/Footer CTA 跳转路径未按账号订阅状态分流：登录成功后统一进入 `/agents`，未订阅用户被直接带进控制台而不是订阅页，转化链路断裂；已订阅用户点 CTA 又可能被再次引导去购买，体验矛盾。
- 不做会怎样：未订阅用户流失在控制台空态里；已订阅用户被重复推销，产生"我已付费为什么还让我试用"的困惑，损伤付费用户信任。
- 用户价值：每个状态的用户都被带到下一步最正确的页面——没买的去订阅，买了的直接进控制台用 Agent。
- 业务价值：打通「访问 → 注册/登录 → 订阅 → 使用 Agent」的完整转化漏斗，减少链路漏损。

## 目标用户与场景

- 目标用户画像：访问 lightvela.com / lightvela.ai 的访客、注册未订阅用户、已订阅用户。
- 典型场景：
  1. 未登录访客点击 Header「登录 / Sign In」→ 登录成功 → 未订阅 → 应落在 `/subscribe`；已订阅 → 应落在 `/agents`。
  2. 未登录/未订阅用户点击 Hero 或 Footer CTA「免费试用 / Free trial」→ 直接进 `/subscribe` 看套餐（方案 A：先看套餐、点「订阅」下单时才引导登录，降低进套餐页摩擦）。
  3. 已订阅且有 Agent 的用户点击同一 CTA → 文案变为「我的智能体伙伴 / My AI Companion」→ 直接进 `/agents`。

## 目标

- 产品结果：登录与 CTA 两条链路在任意账号状态下都跳转到正确的下一站，Hero 与 Footer CTA 完全一致。
- 业务目标：减少未订阅用户登录后流失；杜绝已订阅用户被再次引导购买。

## 范围

- 本次包含：
  - Header 登录 / Sign In 登录成功后的按订阅状态分流。
  - Hero CTA 与 Footer CTA 的文案与跳转按状态统一（未登录、已登录未订阅、已登录已订阅三态）。
  - 未登录用户点 CTA：先进 `/subscribe` 意图，触发登录，登录后按订阅状态分流（未订阅留在 `/subscribe`；已订阅直接跳 `/agents`）。
  - 订阅成功后进入 `/agents`；若当前无 Agent，控制台**自动打开命名向导**（与「新建 Bot」完全一致：输入名称后创建），引导用户为首个 Bot 命名再创建。不在营销层写死默认名自动建号——首次订阅与「删除后重建」走同一条命名流程，避免体验分叉。
- 本次不包含：
  - 订阅/计费流程本身的改造（支付方式、套餐结构）。
  - Agent 创建流程的产品形态变化（沿用现有手动「新建 Bot」创建逻辑）。
  - 其他页面入口（导航栏菜单、文档站等）的跳转调整。
- 优先级：P0
- 已知依赖：登录回调后可获取账号订阅状态（现有接口）；`/agents` 无 Agent 时的「新建 Bot」空状态入口（现有能力）。

## 功能详细描述

### 1. 登录按钮路径（Header 登录 / Sign In）

登录按钮不得固定登录后进入 `/agents`，必须在登录成功后查询账号订阅状态分流：

```text
login success:
  if subscribed:
    redirect /agents
  else:
    redirect /subscribe
```

| 用户点击 | 登录前真实账号状态 | 登录成功后判断 | 最终跳转 |
| --- | --- | --- | --- |
| Header 登录 / Sign In | 未订阅 | 登录成功后识别未订阅 | `/subscribe` |
| Header 登录 / Sign In | 已订阅且已有 Agent | 登录成功后识别已订阅 | `/agents` |

### 2. Hero CTA / Footer CTA 路径

两个 CTA 必须作为同一类 CTA 处理：**文案一致、路径一致、状态判断一致**（建议前端收敛为同一组件/同一 hook 输出，避免两处实现漂移）。

| 用户当前状态 | CTA 文案（中/英） | 点击后 |
| --- | --- | --- |
| 未登录 | 免费试用 / Free trial | 直接进 `/subscribe` 看套餐（点「订阅」下单时才引导登录） |
| 已登录，未订阅 | 免费试用 / Free trial | 进 `/subscribe`，继续购买/开通 |
| 已登录，已订阅且有 Agent | 我的智能体伙伴 / My AI Companion | 直接进 `/agents` |

未登录用户点 CTA 的细分：

| 登录后识别结果 | 后续动作 |
| --- | --- |
| 账号未订阅 | 留在 `/subscribe`，继续购买/免费试用 |
| 账号已订阅且有 Agent | 不再购买，直接跳 `/agents` |

收敛后的统一逻辑：

```text
Hero/Footer CTA:
  if logged in and subscribed:
    text = 我的智能体伙伴 / My AI Companion
    target = /agents
  else:
    text = 免费试用 / Free trial
    target = /subscribe
```

### 3. 订阅成功后的固定动作

```text
subscription success:
  redirect /agents
  if no agent: show "新建 Bot" empty-state entry (manual create)
```

「已订阅但无 Agent」是允许的正常状态（例如用户删除了全部 Bot）：控制台落到
「即刻创建你的云端智能体伙伴 / 新建 Bot」空状态页，由用户命名后创建，营销层不做
第二次分流，也不写死默认名自动建号。

订阅成功首次进入控制台走 `/agents?create=1`（区别于 `?creating=` 的 provisioning
等待态）：控制台在订阅态就绪且账号还没有 Bot 时**自动打开命名向导**（与「新建 Bot」
同一弹窗、同一 `createBotAndNavigate` 创建逻辑），用户输入名称后才真正建 Bot。
这样「首次订阅」与「删除后重建」共用同一条命名流程，不再出现「首次订阅拿到写死的
默认名 Bot、重建才需命名」的分叉。若账号已有 Bot（重复回跳等）则不再引导命名，
直接落到正常控制台。

### 4. 关键红线（验收硬约束）

| 红线 | 要求 |
| --- | --- |
| Hero CTA 和 Footer CTA 必须一致 | 同一用户状态下，两处文案一致、路径一致 |
| 国内站和国际站逻辑必须一致 | 只做语言差异，不做路径差异 |
| 订阅前统一走 `/subscribe` | 未登录、已登录未订阅都一样 |
| 订阅后统一走 `/agents` | 已订阅代表已有 Agent，直接进控制台 |
| 登录成功后必须按订阅状态分流 | 未订阅去 `/subscribe`，已订阅去 `/agents` |
| CTA 不应该让已订阅用户再次购买 | 已登录已订阅用户点 CTA 文案为「我的智能体伙伴」并直接进 `/agents`；未登录用户走方案 A 进 `/subscribe` 看套餐，下单点「订阅」登录后由订阅页识别已订阅态拦截，不重复售卖 |
| 文案大小写统一 | 英文统一 `My AI Companion`、`Free trial`，不出现一处大写一处小写 |
| 多语言文案不写死 | 各语种 CTA 文案一律取自官方来源，**禁止自行翻译**；新增语种无需改代码即可生效 |

### 边界条件与异常处理

- 订阅状态查询失败/超时：按未订阅处理（落 `/subscribe`），不得白屏或卡死在中间页。
- 已订阅但暂无 Agent（异常/创建中状态）：跳 `/agents` 后由控制台展示创建中/引导态，不在营销层做第二次分流。
- 登录被用户取消：停留原页面，不发生跳转。
- CTA 文案状态切换需在登录态/订阅态就绪后渲染，避免闪现错误文案（默认未登录态文案，就绪后再切换）。

## 方案决策

- 采用方案：登录与 CTA 均以「账号订阅状态」为唯一分流依据，前端收敛为统一的 CTA 组件/逻辑模块。
- 选择理由：直接消除两类错位跳转（未订阅进控制台、已订阅被再次推销），改动集中在前端链路，双站零逻辑差异。
- 备选方案与取舍：仅在 CTA 处做状态判断、不动登录按钮（否决：登录链路同样错位，漏斗仍断）；后端在登录响应里直接下发目标路径（否决：引入后端耦合，前端已有订阅状态可得，YAGNI）。
- 延后或不做：其他入口的跳转统一、订阅流程改造。

## 产品原型说明

- 跳过原因：本次为已有页面（Header/Hero/Footer/回调）的跳转逻辑与文案修正，不新增页面结构，不改变交互形态；文字状态表已可完整表达。
