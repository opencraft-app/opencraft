# 自动任务支持 0 Token 固定通知与脚本任务

## 基本信息

- 当前产品：LightVela
- 需求状态：产品输入已确认，待产品与研发评审
- 创建人：LightVela 产品团队
- 创建日期：2026-09-06
- 最后更新时间：2026-09-06
- 需求类型：标准需求
- 优先级：P1
- 发布范围：国内站与国际站同步

## 需求来源与调研结论

### 需求来源

用户希望把 Hermes Agent 社区已经支持的不调用模型定时任务产品化，让用户可以在 LightVela 自动任务页面直接创建不消耗模型 Token 的确定性任务，并覆盖固定自然语言提醒和用户脚本两类场景。

### Hermes Agent 官方能力对齐

截至 2026-09-06，LightVela Hermes 公共镜像版本元数据指向 `v2026.8.31`（源码版本 `0.21.0`）。该版本及当前官方文档已经支持 script-only / `no_agent` Cron 任务：

- `no_agent=true` 时必须提供脚本；Prompt 和 Skills 不参与执行。
- 运行过程不初始化 AI Agent、模型会话或模型调用，因此不产生模型 Token。
- 脚本标准输出非空时，Hermes 将输出作为通知内容投递；空输出时保持静默。
- 非零退出或超时会进入失败处理。
- 脚本运行在 Hermes 所在主机的运行时用户权限下，不是独立安全沙箱。
- 脚本需要保存到 Hermes 管理的脚本目录；Bash 与 Python 均有明确执行方式。

官方参考：

- [Hermes Agent v2026.8.31 Script-only Cron Jobs](https://github.com/NousResearch/hermes-agent/blob/v2026.8.31/website/docs/guides/cron-script-only.md)
- [Hermes Agent Cron 官方文档](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/cron.md)
- [Hermes Agent Cron 工具实现](https://github.com/NousResearch/hermes-agent/blob/main/tools/cronjob_tools.py)
- [Hermes Agent Script Scheduler 实现](https://github.com/NousResearch/hermes-agent/blob/main/cron/scheduler_script.py)

### LightVela 当前差距

LightVela 已能从 Hermes Cron 数据中读取 `no_agent`，但现有自动任务产品主要按 Agent 任务设计：

- 创建表单要求填写 Prompt，创建命令未提供 `no_agent` 创建能力。
- 编辑能力没有完整表达执行模式及脚本任务属性。
- 测试运行仍按 Agent 任务创建一次性任务，无法复用 script-only 真实链路。
- 任务列表、详情和运行记录没有区分 Agent、固定通知和脚本任务。
- 用户无法通过页面创建、测试和管理已有的 Hermes script-only 能力。

## 需求背景

### 当前用户怎么做

用户目前可以通过 LightVela 自动任务让 Agent 定时理解 Prompt 并完成工作。即使任务结果完全确定，例如“每天十点提醒我喝水”或“检测磁盘占用，超过阈值才通知”，也需要以 Agent 任务方式执行，产生没有必要的模型调用。

熟悉 Hermes CLI 的用户可以绕过 LightVela 页面创建 `no_agent` 任务，但这种方式缺少产品入口、可理解的任务类型、统一的测试反馈和安全提示，不适合普通用户。

### 当前卡点

- 固定提醒也要经过模型，增加 Token 消耗和结果不确定性。
- 确定性检测脚本无法在 LightVela 页面中创建和维护。
- CLI 创建的 `no_agent` 任务在页面中缺少准确的类型和状态表达。
- 用户容易把“0 Token”误解为不使用任何计算资源。
- 脚本实际拥有主机运行时用户权限，必须通过产品交互明确提示风险。

### 用户价值

- 用更低的模型成本完成不需要推理的周期性工作。
- 固定通知不经过模型改写，内容稳定可预期。
- 脚本可以自行判断是否需要通知，正常状态保持静默。
- 无需使用 CLI，即可在统一页面创建、测试和管理任务。

### 产品价值

- 补齐 LightVela 与 Hermes Agent 官方 Cron 能力之间的产品差距。
- 建立 Agent 任务与确定性任务的清晰分层。
- 减少不必要的模型调用，同时保留现有自动任务的调度和渠道能力。

## 目标用户与场景

### 目标用户

- 希望设置喝水、休息、提交周报等固定提醒的普通用户。
- 希望定时运行 Bash 或 Python 检测脚本的开发者和运维用户。
- 已通过 Hermes CLI 创建 script-only Cron，希望在 LightVela 中统一查看和管理的用户。

### 典型场景

#### 场景一：固定提醒

用户创建“喝水提醒”，填写“该喝水啦，记得活动一下。”，设置每天 10:00，并选择已有通知渠道。到点后，系统不调用模型，直接发送该文本。

#### 场景二：条件检测

用户创建 Python 脚本任务，每小时检查磁盘占用。低于阈值时不输出并保持静默，超过阈值时打印告警文本，系统把标准输出原样发送到通知渠道。

#### 场景三：管理已有任务

用户曾通过 Hermes CLI 创建 `no_agent` 任务。LightVela 将其识别为脚本任务，并允许用户查看运行状态、暂停、恢复和删除定时任务；无法确认归属的脚本内容保持只读。

## 目标

### 用户结果

- 用户可以通过现有自动任务入口创建 Agent 任务或 0 Token 任务。
- 用户无需理解脚本即可创建固定自然语言通知。
- 用户可以创建、测试和管理 Bash/Python 脚本任务。
- 用户可以明确知道任务是否调用模型、是否发送了通知以及失败原因。

### 产品结果

- 将 Hermes `no_agent` 能力转化为可发现、可理解、可管理的产品体验。
- 保持现有定时规则和通知渠道体验一致，不形成第二套调度配置。
- 对“0 Token”的含义和脚本运行安全边界形成准确承诺。

### 观测目标

- 观测 0 Token 任务创建量、创建成功率、测试成功率和正式执行成功率。
- 观测固定通知与脚本任务的使用占比。
- 统计通过 0 Token 任务避免的模型调用次数，不在缺少可靠对照口径时宣称精确节省的 Token 数。

## 范围

### 本次包含

- 在现有自动任务创建流程中增加 Agent 任务与 0 Token 任务选择。
- 0 Token 任务包含固定通知和脚本任务。
- 固定通知由 LightVela 生成并管理确定性脚本，用户只填写通知文本。
- 脚本任务支持 Bash 和 Python。
- 三种任务复用现有定时规则、时区、通知渠道及启停能力。
- 创建、编辑、测试、列表、详情、最近运行、暂停、恢复和删除。
- 已有 Hermes `no_agent` 任务的识别和安全管理。
- 国内站与国际站同步发布及国际化文案。
- 脚本运行风险提示、敏感信息保护和异常反馈。

### 本次不包含

- 使用模型生成、解释、修复或总结脚本。
- 通过模型改写固定通知或脚本标准输出。
- 多步骤工作流、任务编排或上下游任务依赖。
- 新增通知渠道或改变现有渠道配置流程。
- 新增操作系统级 Cron 管理入口。
- Agent 任务与 0 Token 任务之间的直接转换。
- 固定通知与脚本任务之间的直接转换。
- 浏览器内提供完整 IDE、依赖安装或包管理能力。
- 为脚本建立新的独立安全沙箱。
- 修改套餐、计费或运行资源收费方式。

### 已知依赖

- 目标 Hermes 镜像完整支持 `no_agent` Cron 的创建、运行、更新、启停和删除。
- LightVela 能安全写入并管理 Hermes 脚本目录中的文件。
- 自动任务现有定时器、时区和通知渠道组件能够复用。
- 任务列表与最近运行数据能够补充执行模式和 0 Token 子类型。
- 目标镜像中的环境变量清理、输出脱敏、超时和进程终止行为需要在发布前实测。

## 方案决策

### 采用方案

在现有自动任务创建弹窗中增加两级任务类型选择：

1. 第一级选择 Agent 任务或 0 Token 任务。
2. 选择 0 Token 任务后，再选择固定通知或脚本任务。

任务表单拆成两部分：

- 执行内容：随任务类型变化。
- 执行与通知：定时规则、时区、通知渠道和启用状态，所有任务类型共用。

### 选择理由

- 用户先判断任务是否需要模型，再选择具体的确定性执行方式，心智清晰。
- 固定通知满足普通用户场景，同时仍然复用 Hermes 官方 `no_agent` 能力。
- 脚本任务覆盖更广，不把能力限制为“脚本检测”。
- 共用定时器和通知渠道可以保持当前体验，降低学习、设计和实现成本。
- 不引入新的 Hermes 运行类型，避免产品概念与底层能力不一致。

### 备选方案与取舍

#### 备选一：只提供脚本任务

- 优点：产品形态与 Hermes script-only 能力最直接。
- 缺点：普通用户为了发送固定提醒仍要理解和编写脚本。
- 结论：不采用；固定通知作为产品包装保留。

#### 备选二：把固定通知设计成独立 Hermes 任务类型

- 优点：用户概念直观。
- 缺点：需要新增底层运行模式，且与 Hermes 官方能力不一致。
- 结论：不采用；固定通知仍映射为 LightVela 管理的 `no_agent` 脚本。

#### 备选三：把能力命名为“脚本检测”

- 优点：突出监控告警场景。
- 缺点：无法覆盖数据同步、固定输出和其他确定性脚本。
- 结论：不采用；统一命名为“脚本任务”，检测只是典型场景之一。

### 延后或不做

- Agent 自动生成脚本。
- 可复用脚本模板市场。
- 多文件脚本、依赖包和密钥配置。
- 跨任务类型迁移。
- 单独的脚本沙箱和资源配额产品。

## 功能详细描述

### 1. 页面入口与信息架构

沿用 Agent 控制台的「自动任务」页面和现有「创建任务」按钮，不新增路由。

创建弹窗首先展示任务类型：

- Agent 任务：理解指令并自主完成工作；执行时调用模型并消耗 Token。
- 0 Token 任务：运行固定通知或确定性脚本；不调用模型，不消耗模型 Token。

“0 Token”附近持续展示辅助说明：

> 不调用模型，执行不消耗模型 Token；仍会使用运行资源。

### 2. 共用表单配置

Agent 任务、固定通知和脚本任务必须复用现有的以下配置能力：

- 定时规则。
- 时区。
- 生效时间段（当前产品支持时）。
- 一个或多个通知目标（按当前产品能力）。
- 启用或暂停状态。

复用要求：

- 使用同一组件、字段语义、默认值和校验规则，不为 0 Token 任务复制第二套配置。
- 切换任务类型或 0 Token 子类型时，已填写的共用配置保持不变。
- 两站分别展示当前站点已经支持的通知渠道，不因本需求新增或硬编码渠道。
- 未选择通知目标时，沿用现有自动任务的提交规则和反馈，不为 0 Token 任务建立不同规则。

### 3. Agent 任务

Agent 任务继续沿用现有执行逻辑：

- 用户填写任务名称和执行指令。
- 按现有能力选择 Skill 或其他 Agent 配置。
- 到点后创建 Agent 会话并调用模型。

本需求不能改变已有 Agent 任务的创建、编辑、执行和历史数据行为。

### 4. 固定通知

#### 用户输入

- 任务名称。
- 通知内容。
- 共用的执行与通知配置。

#### 产品行为

1. 用户提交固定通知。
2. LightVela 使用受控模板把通知内容写入一个唯一的、由 LightVela 管理的 Python 脚本。
3. LightVela 创建 `no_agent=true` 的 Hermes Cron job，并关联该脚本。
4. 到点后脚本输出用户填写的通知文本。
5. Hermes 将标准输出投递到任务选择的通知目标。

#### 约束

- 用户不查看、不编辑生成的脚本。
- 通知内容不经过模型生成、润色、总结或翻译。
- 文本写入脚本时必须安全处理引号、换行、Emoji 和多语言字符，不能通过字符串拼接形成可执行代码注入。
- “原样发送”指不经过模型语义改写；各通知渠道仍可按自身文本协议渲染换行和字符。
- LightVela 必须保存该脚本与任务之间的所有权关系，不能仅根据文件内容猜测是否可以删除。

### 5. 脚本任务

#### 用户输入

- 任务名称。
- 脚本语言：Bash 或 Python。
- 脚本内容。
- 共用的执行与通知配置。
- 脚本运行风险确认。

#### 运行语义

| 运行结果 | 任务状态 | 通知行为 |
| --- | --- | --- |
| 退出码为 `0`，标准输出非空 | 成功 | 将标准输出原样投递 |
| 退出码为 `0`，标准输出为空 | 静默成功 | 不发送结果通知 |
| 非零退出 | 失败 | 按 Hermes 失败机制发送异常提醒 |
| 超时或无法启动 | 失败 | 发送异常提醒并记录失败类型 |

脚本任务必须保证：

- 不创建 Agent 会话，不请求模型，不使用 Prompt 或 Skills。
- 不在脚本无输出时调用模型生成解释或兜底通知。
- 不在脚本失败时自动调用模型修复或总结错误。
- 用户脚本以文件方式交给 Hermes 执行，不能把脚本正文直接拼接进 Shell 命令。

### 6. 测试运行

三种任务使用同一「测试运行」入口，但必须进入各自的真实执行链路：

- Agent 任务：沿用现有 Agent 测试链路，并明确本次会调用模型。
- 固定通知：通过 `no_agent` 执行受管理脚本，发送一次固定通知。
- 脚本任务：通过 `no_agent` 执行用户脚本。

测试结果至少展示：

- 执行成功、静默成功或失败。
- 脚本任务的退出码或启动/超时错误。
- 是否产生标准输出。
- 是否尝试发送通知以及发送结果。

测试运行必须满足：

- 与正式任务使用相同执行模式和脚本语义。
- 测试失败不创建正式任务。
- 使用一次性临时任务时，结束后自动清理临时任务和 LightVela 创建的临时脚本。
- 创建结果不确定时不自动重复创建，避免产生重复任务。

### 7. 创建事务与异常

固定通知与脚本任务的创建顺序：

```text
校验表单与安全确认
  → 写入受管理脚本
  → 创建 Hermes no_agent Cron job
  → 读取并确认任务创建结果
  → 返回成功
```

异常处理：

- 脚本写入失败：不创建 Cron job，保留用户表单内容并展示错误。
- Cron job 明确创建失败：清理本次新建且尚未被任务引用的受管理脚本。
- 创建请求结果不确定：不自动重试；刷新任务列表确认是否已存在，再允许用户重试。
- 页面关闭或网络异常：不能留下页面不可见、无法管理的重复任务。
- 通知渠道不可用：沿用现有渠道校验和错误反馈。

### 8. 列表、详情和最近运行

任务卡片和详情使用以下标签：

- `Agent 任务`
- `0 Token · 固定通知`
- `0 Token · 脚本任务`

共同展示：

- 任务名称。
- 定时规则和时区。
- 通知目标。
- 启用状态和下次执行时间。
- 最近执行状态。
- 是否调用模型。

0 Token 任务额外展示：

- 固定通知：用户填写的通知内容。
- 脚本任务：脚本语言；有编辑权限时展示脚本内容。
- 最近运行：退出码、是否有输出、是否发送通知、失败类型。

列表和详情不能用“0 Token”替代真实运行状态。静默成功、发送成功、发送失败、脚本失败和超时必须可以区分。

### 9. 编辑

首期只允许同类型编辑：

- Agent 任务只能编辑为 Agent 任务。
- 固定通知只能编辑为固定通知。
- 脚本任务只能编辑为脚本任务。

任务类型在编辑页面只读。需要改变类型时，引导用户返回列表创建新任务，不提供复制迁移或自动转换能力。

编辑其他字段但未修改共用配置时，原定时规则、时区和通知目标保持不变。

### 10. 删除

删除顺序：

1. 删除或确认删除 Hermes Cron job。
2. 仅当脚本被明确标记为 LightVela 所有，且没有其他任务引用时，删除脚本文件。

约束：

- Cron job 删除失败时，不删除脚本。
- 外部脚本、共享脚本或归属不明的脚本不自动删除。
- 固定通知生成的受管理脚本遵循同一所有权与引用检查。

### 11. 已有 `no_agent` 任务兼容

- 所有已有 `no_agent` 任务在产品中统一识别为脚本任务。
- LightVela 创建且能确认脚本所有权的任务，可以正常编辑脚本。
- 外部创建或脚本归属不明的任务，脚本内容只读。
- 外部任务仍可查看、暂停、恢复和删除 Cron job。
- 删除外部任务时不删除关联脚本文件。
- 不自动把既有脚本识别为固定通知，避免基于脚本内容产生错误分类。

### 12. 数据与接口约束

产品数据需要稳定表达：

- 执行模式：Agent 或 `no_agent`。
- 产品子类型：固定通知或脚本任务。
- 脚本语言。
- 脚本归属：LightVela 管理、外部或未知。
- 脚本与任务的引用关系。
- 最近运行的退出码、输出状态、通知状态和失败类型。

固定通知是 LightVela 产品子类型，不是 Hermes 新增运行类型。子类型不能只通过脚本正文推断；需要由 LightVela 可持久化的数据或稳定的受管理标记表达。

创建 `no_agent` 任务时：

- 必须提供脚本。
- 不得携带会导致 Agent 执行的 Prompt、Skill 或降级配置。
- 不得在 Hermes 不支持 `no_agent` 时静默退回 Agent 任务。

## 状态与异常

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| 创建中 | 脚本写入和 Cron 创建均成功 | 创建成功，进入任务列表 |
| 创建中 | 脚本写入失败 | 创建失败，无 Cron 残留 |
| 创建中 | Cron 明确创建失败 | 创建失败，清理未引用的受管理脚本 |
| 创建中 | Cron 创建结果不确定 | 提示刷新确认，不自动重试 |
| 测试中 | 退出码 `0` 且有输出 | 显示成功和通知结果 |
| 测试中 | 退出码 `0` 且无输出 | 显示静默成功，不发送通知 |
| 测试中 | 非零退出或超时 | 显示失败类型和通知结果 |
| 已启用 | 用户暂停 | 停止后续调度，保留配置 |
| 已暂停 | 用户恢复 | 按原定时规则恢复调度 |
| 外部任务 | 打开编辑 | 共用配置按现有权限编辑，脚本内容只读 |
| 删除中 | Cron 删除失败 | 删除失败，保留脚本 |
| 删除中 | Cron 删除成功且脚本为独占受管理文件 | 删除脚本并完成删除 |

## 产品原型说明

- 目标页面/入口：Agent 控制台 → 自动任务 → 创建任务。
- 用户主路径：选择任务类型 → 填写执行内容 → 配置共用的执行与通知 → 测试运行 → 创建。
- 页面结构：

```text
创建自动任务
├── 任务类型
│   ├── Agent 任务
│   └── 0 Token 任务
│       ├── 固定通知
│       └── 脚本任务
├── 执行内容（随类型变化）
│   ├── Agent：任务名称、执行指令、已有 Agent 配置
│   ├── 固定通知：任务名称、通知内容
│   └── 脚本任务：任务名称、语言、脚本、安全确认
├── 执行与通知（所有类型共用）
│   ├── 定时规则与时区
│   ├── 生效时间段
│   └── 通知目标
└── 测试运行 / 取消 / 创建任务
```

- 已提供交互原型：支持切换 Agent/0 Token、固定通知/脚本任务，并演示测试和创建反馈。
- 关键状态：默认、测试中、静默成功、发送成功、失败、超时、创建中、只读外部脚本。
- 需要设计确认：任务类型层级、安全提醒强度、运行结果的信息层级、窄屏表单布局。
- 需要前端确认：共用字段组件复用方式、切换类型时的表单状态保持、现有 `no_agent` 任务回显。

- 国际站是否同步：是。
- 国内站是否同步：是。

## LightVela 影响面

- 前端页面/路由：自动任务创建、编辑、列表、详情、测试运行和最近运行；不新增路由。
- Hermes/OpenClaw/运行时：复用 Hermes `no_agent` Cron；补齐安全脚本写入、命令参数、结果读取和生命周期管理。

## 非功能性需求

### 性能与可靠性

- 创建、编辑、列表和详情沿用现有自动任务响应目标，无新增特殊页面性能指标。
- 同一次用户创建操作不能产生多个正式 Cron job。
- 测试任务和正式任务必须可区分，临时资源能够被清理。
- 关闭创建入口或前端回滚不能让已有 0 Token 任务失去查看、暂停和删除能力。

### 兼容性

- 沿用 LightVela 现有浏览器、桌面端和移动端兼容范围。
- 支持当前目标 Hermes 镜像中的 Bash 和 Python 运行方式。
- Hermes 版本不支持 `no_agent` 时，应禁用入口并明确提示版本不兼容，不能降级为 Agent 任务。

### 安全与隐私

- 脚本将在 Agent 环境中以运行时用户权限执行，页面不得宣称为隔离沙箱。
- 创建和测试脚本任务前必须展示安全提醒并要求用户确认。
- 沿用现有任务所有者及管理权限；无权限用户不能查看或修改脚本正文。
- 不在业务埋点、前端日志或普通运行日志中记录完整脚本和完整通知正文。
- 不向页面、任务输出或通知渠道泄露模型密钥、通道凭证及其他敏感环境变量。
- 发布前必须在目标 Hermes 镜像中验证环境变量清理、输出脱敏、超时和子进程终止行为；不能仅以官方主分支文档代替生产验证。
- 用户脚本内容必须以文件安全写入，不能通过命令拼接造成命令注入。

### 国际化与无障碍

- 所有新增文案进入现有 i18n 机制，覆盖国内站和国际站开放语言。
- 任务类型和子类型选择使用可访问的语义控件，并支持键盘操作和清晰焦点状态。
- 测试结果、校验错误和异步创建结果可以被辅助技术感知。
- 不能只用颜色区分 Agent、固定通知、脚本任务和运行状态。

## 数据埋点与观测

### 建议事件

- 打开自动任务创建弹窗。
- 选择 Agent 或 0 Token 任务。
- 选择固定通知或脚本任务。
- 发起测试运行及测试结果。
- 创建成功、明确失败或结果不确定。
- 正式执行成功、静默成功、失败或超时。
- 通知发送成功、部分失败或全部失败。
- 编辑、暂停、恢复和删除。

### 建议属性

- 站点和界面语言。
- 任务执行模式和产品子类型。
- 脚本语言。
- 操作结果和结构化失败类型。
- 是否产生输出、是否尝试通知及通知结果。

### 隐私限制

- 不采集脚本正文。
- 不采集固定通知正文或脚本标准输出全文。
- 不采集通知目标标识、凭证或用户环境变量。

### 核心指标

- 0 Token 任务创建量和创建成功率。
- 固定通知与脚本任务使用占比。
- 测试运行成功率。
- 正式执行成功率、静默成功率、失败率和超时率。
- 通知发送成功率。
- 避免的模型调用次数。

## 验收标准

1. 用户可以在现有自动任务创建入口选择 Agent 任务或 0 Token 任务。
2. 选择 0 Token 任务后，可以继续选择固定通知或脚本任务。
3. 三种任务使用相同的定时器、时区、通知渠道和校验规则。
4. 切换任务类型和子类型时，已填写的共用配置保持不变。
5. 创建固定通知后，Hermes 保存的是 `no_agent` 任务，用户无需查看或编写脚本。
6. 固定通知能够正确发送包含引号、换行、Emoji 和中英文字符的内容，且不发生代码注入或模型改写。
7. 固定通知和脚本任务执行时均不创建 Agent 会话、不请求模型服务、不产生模型 Token。
8. 脚本任务支持 Bash 和 Python，并在创建及测试前完成安全确认。
9. 脚本退出码为 `0` 且有标准输出时，输出被原样投递到任务选择的通知目标。
10. 脚本退出码为 `0` 且无标准输出时，任务显示静默成功且不发送结果通知。
11. 脚本非零退出、超时或无法启动时，任务显示失败类型，并按 Hermes 失败机制发送异常提醒。
12. 0 Token 任务不会在失败或无输出时自动降级为 Agent 任务。
13. 测试运行使用与正式任务相同的执行模式，并展示退出码、输出状态和通知结果。
14. 测试失败不会创建正式任务，测试结束后不会遗留一次性任务或 LightVela 临时脚本。
15. 脚本写入失败时不创建 Cron job；Cron 明确创建失败时清理本次未引用的受管理脚本。
16. 创建结果不确定时不自动重试，刷新后不会产生重复任务。
17. 任务列表和详情能够区分 Agent 任务、固定通知和脚本任务，并明确是否调用模型。
18. 最近运行能够区分发送成功、静默成功、通知失败、脚本失败和超时。
19. 同类型编辑能够正确更新执行内容和共用配置；跨类型转换不可用并有清晰引导。
20. 删除任务时，Cron 删除失败不会删除脚本；外部、共享或归属不明的脚本不会被自动删除。
21. 已有 `no_agent` 任务被识别为脚本任务；归属不明的脚本内容只读，但任务仍可查看、启停和删除。
22. 页面准确说明“0 Token”只代表不使用模型 Token，不能表达为零计算资源或完全免费。
23. 页面准确说明脚本运行在 Agent 环境中，不能表达为独立安全沙箱。
24. 普通日志和业务埋点不记录完整脚本、完整通知正文、完整标准输出、通道凭证或敏感环境变量。
25. 国内站与国际站均完成创建、编辑、测试、列表、详情、启停、删除和异常状态验证。
26. 所有新增文案完成中英文及现有开放语言的国际化，并通过现有生成资源检查。
27. 现有 Agent 任务和历史非 `no_agent` 任务无需迁移，创建、编辑和执行行为保持不变。

## 发布与观测

### 灰度与开关

- 使用功能开关控制新的 0 Token 创建入口。
- 先对内部账号开放，覆盖固定通知、脚本有输出、脚本无输出、非零退出、超时和通知失败场景。
- 内部验证通过后，国内站与国际站逐步开放。
- 两站产品行为保持一致，各自仅展示已有通知渠道。

### 发布门禁

- 在目标 Hermes 镜像中完成 `no_agent` 创建、测试、正式执行、更新、启停和删除验证。
- 通过代码或请求证据确认整个 0 Token 执行链路没有模型请求和 Agent 会话创建。
- 验证用户脚本无法通过创建命令拼接注入额外 Shell 指令。
- 验证敏感环境变量清理、输出脱敏、超时和子进程终止行为。
- 完成国内站和国际站的页面及通知渠道回归。

### 回滚

- 关闭功能开关后停止创建新的 0 Token 任务。
- 已有 0 Token 任务继续保留列表、详情、暂停和删除入口。
- 前端回滚不得删除、转换或修改已有 Cron job 和用户脚本。
- 若运行时能力存在风险，由发布或运行时负责人按事件范围暂停受影响任务；不得用删除用户脚本作为默认回滚方式。

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 用户把 0 Token 理解为完全免费 | 形成错误产品承诺 | 持续展示“不调用模型，仍会使用运行资源” |
| 用户误以为脚本在隔离沙箱中运行 | 执行不可信代码，影响 Agent 环境 | 明确主机权限边界，创建和测试前强确认 |
| 固定通知文本未安全序列化 | 代码注入或发送内容错误 | 使用受控模板和安全数据序列化，不拼接可执行代码 |
| 创建步骤部分失败 | 遗留孤立脚本或重复任务 | 事务化创建、所有权记录、明确失败清理、未知结果不重试 |
| 删除脚本归属判断错误 | 误删外部或共享文件 | 保存所有权和引用关系；未知或外部脚本永不自动删除 |
| UI 回滚后任务不可管理 | 后台任务继续执行但用户无法停用 | 创建入口与管理入口分离，回滚仍保留管理能力 |
| 官方主分支与目标镜像实现不同 | 安全或行为验收失真 | 以目标镜像实测为发布门禁，官方文档只作为能力依据 |
| 双站通知渠道不同 | 页面能力或验收不一致 | 复用各站现有渠道集合，统一功能语义和验收矩阵 |
