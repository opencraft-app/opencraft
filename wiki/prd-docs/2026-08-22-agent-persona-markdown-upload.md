## 需求背景

LightVela 当前在已有 Agent 的人设页提供“随机抽取人设”和“答题测试人设”两种获取方式。用户选中人设卡后，可以把生成的 Soul 注入当前 Agent。现有流程会在覆盖前备份旧 `SOUL.md`，写入新的 `SOUL.md`，并提示用户开启新会话使人设生效。

已经自行准备人设 Markdown 的用户，当前无法在该页面直接导入和检查自己的内容。用户需要依赖其他文件操作或命令方式处理，既增加使用门槛，也绕开了人设页已有的备份、覆盖确认和结果反馈流程。

本需求在人设页补充“上传人设文件”入口，让用户选择本地 `.md` 文件，在浏览器内完成格式校验、内容预览和编辑，并通过现有注入链路应用到当前 Agent。

### 当前用户怎么做

- 只能从人设卡池随机抽取或通过答题测试选择预设人设。
- 已有自定义 `SOUL.md` 时，需要通过其他文件或命令入口写入 Agent。
- 无法在人设页注入前检查和修改自定义内容。
- 无法在人设页明确识别当前 Agent 正在使用自定义人设。

### 当前卡点

- 自定义人设与现有人设页流程断开。
- 用户难以判断文件格式和大小是否适合注入。
- 直接覆盖可能导致旧人设丢失或用户误操作。
- 自定义人设注入后缺少稳定、可回读的页面状态。

### 用户价值

- 直接复用已经准备好的 Markdown 人设。
- 注入前可预览和修改，减少内容错误。
- 覆盖前有明确提醒，并保留旧人设备份。
- 页面刷新后仍能识别当前使用的自定义人设。

### 业务价值

- 降低自定义 Agent 人设的使用门槛。
- 扩大人设能力对专业用户和已有 Prompt 资产用户的覆盖。
- 把自定义人设纳入统一的人设注入、观测和问题反馈链路。

## 目标用户与场景

### 目标用户

- 已创建 LightVela Agent 的国内站用户。
- 已经拥有自定义人设 Markdown，希望应用到当前 Agent 的用户。
- 需要精确控制 Agent 角色、语气、工作原则、优先级和行为边界的用户。

### 典型场景

#### 导入已有 `SOUL.md`

用户已经在本地维护一份完整的人设 Markdown，希望通过控制台直接检查并注入当前 Agent。

#### 基于模板继续修改

用户从团队、社区或其他 Agent 获得一份人设 Markdown，希望在注入前调整名称、语气、边界和示例。

#### 替换当前人设

用户希望把当前预设人设替换为自定义人设，并在确认覆盖前保留旧版本备份。

## 目标

### 用户结果

- 用户可以在已有 Agent 的人设页选择一个 `.md` 文件。
- 系统能够明确说明文件是否满足技术格式要求。
- 用户可以在注入前查看和编辑完整内容。
- 用户确认后，自定义人设完整替换当前 Agent 的 `SOUL.md`。
- 注入失败时，编辑内容和旧人设均不丢失。
- 注入成功并重新进入页面后，用户仍能看到当前 Agent 使用的是自定义人设。

### 产品结果

- 在不建设通用文件管理器和自定义人设卡系统的前提下，补齐自定义人设导入能力。
- 复用现有 `SOUL.md` 写入、备份和生效提示，保持预设人设与自定义人设体验一致。
- 首期只在国内站验证需求强度、注入成功率和重复使用情况，再决定是否同步国际站。

### 业务目标

- 建立“入口点击 → 文件有效 → 打开编辑 → 确认覆盖 → 注入成功”的基础漏斗。
- 观测自定义人设的使用人数、成功率和重复使用率。
- 首期不预设缺乏历史基线支持的增长百分比。

### 不做会怎样

- 已有人设资产的用户继续绕开人设页手动处理 `SOUL.md`。
- 页面只能承接预设人设，无法覆盖更专业的自定义场景。
- 自定义内容缺少统一校验、备份和结果反馈，误操作与排障成本继续存在。

## 范围

### 本次包含

- 仅在已有 Agent 的人设页增加“上传人设文件”入口。
- 入口位于现有“随机抽取人设”“答题测试人设”和“注入”操作区域。
- 仅支持选择一个 `.md` 文件，扩展名判断大小写不敏感。
- 文件最大 20 KB，按 UTF-8 编码后的实际字节数计算，不按字符数或行数计算。
- 支持标准 UTF-8 和带 UTF-8 BOM 的文本；展示前去除 BOM。
- 文件内容必须非空，且不得包含二进制数据或异常控制字符。
- 上传后在浏览器内读取内容，不把原始文件作为独立文件上传或保存。
- 校验通过后在同一弹窗切换到编辑态，展示完整 Markdown 并允许修改。
- 编辑器持续展示当前 UTF-8 字节数和 20 KB 上限。
- 最终注入内容必须再次通过非空、UTF-8 字节数和异常字符校验。
- 缺少推荐人设字段时给出软提示，但不阻止注入。
- 注入前明确提示新内容将完整替换当前人设。
- 用户确认后，先备份旧 `SOUL.md`，再写入新内容。
- 写入采用不破坏旧文件的安全替换方式；任何失败都不得让旧人设变为空文件或半写入状态。
- 注入成功后沿用现有的新会话生效提示。
- 自定义人设注入成功后显示“已注入：自定义人设 · `<名称>`”。
- 展示名称优先读取 `Name:`，缺失时使用不含 `.md` 后缀的文件名。
- 页面刷新、重新进入或切回当前 Agent 后，仍能识别自定义人设及其展示名称。
- 自定义人设状态后提供编辑和下载图标，可修改或直接下载当前 Agent 实际 `SOUL.md`。
- 编辑保存继续自动备份旧文件并安全替换；下载固定使用文件名 `soul.md` 且不改写内容。
- 新增上传、校验、编辑、覆盖确认和注入结果的必要埋点。
- 抽卡结果卡片增加“注入此人设”，允许跳过先添加、再选中、再注入的操作链路。
- 抽卡直接注入仅在 Agent 写入成功后将该人设加入人设盘并标记“已注入”；失败或仅下载兜底时保留结果弹窗和原状态，支持重试。

### 本次不包含

- 创建 Agent 时上传人设。
- `.txt`、Word、PDF、ZIP 或其他格式。
- 一次上传多个文件。
- 把原始文件保存到云存储或提供原文件下载。
- 把上传内容保存为自定义人设卡。
- 自定义人设列表、版本管理、收藏、分享或市场发布。
- 与当前人设自动合并、追加或同时保留多个生效版本。
- 通用云端 Markdown 文件编辑器。
- 修改 `USER.md`、`MEMORY.md` 或其他 Hermes 上下文文件。
- 首期在国际站显示入口或开放能力。

### 已知依赖

- 当前 Agent 已经具备可用的 Hermes 运行环境和 `debug/exec` 写入链路。
- 现有 `SOUL.md` 备份目录和写入能力保持可用。
- 现有生效提示能够指导用户开启新会话。
- 20 KB 上限需要在补入固定 Soul 元数据后重新校验，并保证 Base64 编码和远程命令封装后仍低于现有命令大小限制。
- 页面需要能够从当前 Agent 的真实 `SOUL.md` 或与其一致的事实状态读取自定义来源和展示名称，不能只依赖当前浏览器内存。

## 方案决策

### 采用方案：上传后编辑并直接注入

在现有人设页操作区增加“上传人设文件”按钮。用户点击后先进入弹窗初始上传态，再在弹窗内选择 `.md` 文件。系统在浏览器中完成硬校验，并在同一弹窗中把内容载入编辑态。用户可以修改内容、查看大小和结构提示，随后通过现有“注入人设”语义覆盖当前 Agent 的 `SOUL.md`。

上传内容不占用人设卡槽，不生成自定义卡片，也不进入云存储。系统只保留最终确认的人设文本，以及识别当前自定义人设所需的来源和展示名称信息。

### 选择理由

- 与用户“已有 Markdown，直接应用”的核心目标最贴合。
- 复用现有注入、备份和生效提示，产品边界清晰。
- 注入前可检查和修改，比直接上传即覆盖更安全。
- 不引入自定义卡片的数据模型、管理入口和生命周期。
- 不把人设功能扩展成通用文件管理能力，符合首期 YAGNI。

### 备选方案与取舍

#### 备选一：保存为自定义人设卡

上传后生成一张长期可重复选择的人设卡。

不采用原因：需要新增自定义人设存储、卡片管理、删除、同步和状态一致性能力，超出本次“导入并注入”的目标。

#### 备选二：通过云存储管理 `SOUL.md`

用户先把文件上传到云存储，再选择或编辑目标文件。

不采用原因：会混淆普通工作文件与长期上下文文件，并把简单导入流程扩展成通用文件编辑器。

#### 备选三：上传后立即覆盖

文件校验通过后直接写入当前 Agent，不提供编辑和覆盖确认。

不采用原因：用户无法在写入前检查内容，误覆盖和格式问题的风险较高。

## 功能详细描述

### 1. 入口

- 页面：`/agents/persona/`。
- 站点：首期仅国内站 `lightvela.com`。
- 用户可见入口与初始上传态标题为“上传人设文件”；合法文件读取成功后的编辑态标题为“编辑人设文件”。
- 与“随机抽取人设”“答题测试人设”并列，保持为第三种获取人设的方式。
- 不改变现有人设卡数量、抽卡进度和选择状态。

### 2. 文件选择与读取

- 点击页面“上传人设文件”后先打开初始上传弹窗，不直接打开系统文件选择器。
- 初始上传态中央展示上传图标、“选择 Markdown 人设文件，将其内容填入 SOUL.md”、限制说明“仅支持 Markdown 文件，文件名不限，扩展名须为 .md，大小不超过 20 KB。”，以及“选择文件”按钮；点击该按钮后才打开系统文件选择器。
- 文件选择器声明只接受 `.md`，但不能只依赖浏览器 `accept`，选择后仍需执行完整校验。
- 文件读取期间显示加载状态并禁止重复触发。
- 用户取消文件选择时不显示错误，弹窗保持初始上传态，不改变当前 Agent 状态。

### 3. 硬校验

以下情况阻止进入编辑器，并显示可操作的具体原因：

| 校验项 | 通过条件 | 失败提示方向 |
| --- | --- | --- |
| 文件类型 | 文件名以 `.md` 结尾，大小写不敏感 | 请选择 Markdown（.md）文件 |
| 文件大小 | 原文件不超过 20 KB | 文件超过 20 KB，请精简后重试 |
| 文本编码 | 可按 UTF-8 解码，允许 UTF-8 BOM | 文件编码需为 UTF-8，请转换后重新上传。 |
| 有效内容 | 去除 BOM 和首尾空白后非空 | 人设内容不能为空 |
| 文本安全 | 不包含 NUL、二进制数据或除换行、回车、制表符外的异常控制字符 | 文件包含无法识别的内容 |

编辑后的最终内容在注入前再次校验：

- 去除首尾空白后必须非空。
- 按 UTF-8 编码后的内容不得超过 20 KB；补入固定 Soul 元数据后，最终写入的 `SOUL.md` 也不得超过 20 KB。
- 不得重新引入异常控制字符。
- 超限时保留编辑内容，并定位为可继续修改的错误，不关闭弹窗。

### 4. `SOUL.md` 内容格式

Hermes 读取 Markdown 文本作为人设上下文，本需求不把以下结构全部设为硬性 Schema。推荐格式为：

```md
# Soul

Slug: <可选的人设标识>
Name: <人设名称>
Summary: <可选的一句话摘要>

## Content

### 基础信息
...

### 核心气质
...

### 外显风格
...

### 语言系统
...

### 行动逻辑
...

### 行为边界
...

### 示例台词库
...

### Agent 运行偏好
...
```

字段说明：

- `Slug`：预设人设卡的标识；自定义上传不要求用户提供。
- `Name`：人设展示名称；缺失时使用文件名。注入时最多保留 80 个 UTF-8 字节且不得截断 Unicode 字符，避免 20 KB 边界文件因元数据重复超过远程命令限制。
- `Summary`：人设摘要，可选。
- `Content`：实际影响 Agent 行为的主体内容。
- Content 下的小节可以按用户需要增减，不要求固定顺序。

### 5. 软提示

以下情况只显示完善建议，不阻止注入：

- 缺少 `Name:`。
- 缺少角色定位，提示“建议补充角色定位（Identity）”。
- 缺少沟通风格，提示“建议补充沟通风格（Communication Style）”。
- 缺少工作原则，提示“建议补充工作原则（Working Principles）”。
- 缺少行为边界，提示“建议补充行为边界（Behavioral Boundaries）”。
- 内容过短，可能不足以形成稳定人设。

软提示不得声称系统已经理解或验证了人设质量，只说明推荐结构缺失。用户可以忽略提示继续注入。

### 6. 编辑弹窗

- 展示文件名或 `Name:`、Markdown 编辑区、当前 UTF-8 字节数和 20 KB 上限。
- 用户可以直接修改完整内容。
- 提供取消和“注入人设”操作。
- 取消时丢弃本次尚未注入的编辑内容，不改变当前人设。
- Markdown 预览若采用富文本渲染，必须过滤或转义 HTML、脚本和事件属性；也可以首期只提供安全的纯文本 Markdown 编辑视图。

### 7. 覆盖确认

- 当前 Agent 已存在 `SOUL.md` 时，点击“注入人设”必须显示覆盖确认。
- 弹窗标题显示“覆盖当前人设？”，说明仅显示“旧人设会自动备份，然后注入新人设。”，不嵌套重复提示框。
- 操作按钮为“返回编辑”和“覆盖并注入”，均置于右下角。
- 不提供自动合并、追加或同时保留选项。
- 用户取消后返回编辑弹窗，保留当前编辑内容。

### 8. 注入与结果

- 确认后进入注入中状态，禁止重复提交和再次选择文件。
- 写入前备份现有非空 `SOUL.md`。
- 新内容先写入临时文件，完整解码和写入成功后再安全替换目标文件。
- 任一步骤失败时保留或恢复旧 `SOUL.md`，不得留下空文件或半写入文件。
- 注入失败时保留编辑内容，显示可理解的失败信息并允许重试。
- 注入成功后关闭编辑和覆盖确认状态，显示自定义人设已注入。
- 沿用现有生效提示，引导用户开启新会话。

### 9. 当前人设状态

- 自定义人设成功注入后显示“已注入：自定义人设 · `<名称>`”。
- 展示名称优先使用 `Name:`；缺失时使用不含 `.md` 后缀的文件名。
- 系统可以补充内部自定义来源标识，但不得要求用户手工填写内部字段。
- 页面刷新、重新进入或切换 Agent 后，状态必须以当前 Agent 的真实 `SOUL.md` 或与其一致的事实状态为准。
- 自定义人设不生成卡片，也不占用八张人设卡槽。
- 后续注入预设人设时，自定义状态被预设人设状态替换；反向亦然。
- 状态文字后显示编辑和下载图标，状态文字本身不可点击。
- 编辑图标按需读取当前 Agent 实际 `SOUL.md` 并打开编辑弹窗；保存成功后刷新名称并提示发送 `/new`。
- 下载图标直接下载当前 Agent 实际原文为 `soul.md`，不打开编辑弹窗。
- 页面初始状态仍只读取 `Exists`、`Slug`、`Name`，不无条件传输完整 Markdown。

## 页面状态

| 状态 | 页面行为 |
| --- | --- |
| 默认 | 显示“上传人设文件”，不影响现有卡片和操作 |
| 初始上传 | 弹窗内显示上传图标、“选择 Markdown 人设文件，将其内容填入 SOUL.md”、限制说明“仅支持 Markdown 文件，文件名不限，扩展名须为 .md，大小不超过 20 KB。”和“选择文件”，不展示编辑框或注入按钮 |
| 文件读取中 | 显示加载，禁止重复选择 |
| 校验失败 | 在弹窗内显示具体原因，允许“重新上传文件” |
| 编辑 | 展示完整内容、结构提示和字节数 |
| 编辑内容超限 | 保留内容，禁止注入并提示精简 |
| 覆盖确认 | 说明完整替换和备份，支持取消返回 |
| 注入中 | 禁止关闭关键流程和重复提交 |
| 注入成功 | 显示当前自定义人设，并提示新会话生效 |
| 注入失败 | 保留编辑内容和旧人设，允许重试 |
| 重新进入页面 | 回读并展示当前自定义人设状态 |
| 编辑自定义人设 | 读取实际 `SOUL.md` 后打开编辑弹窗；未修改或硬校验失败时禁止保存 |
| 下载自定义人设 | 直接下载实际原文为 `soul.md`，不打开编辑弹窗 |
| 当前文件读取失败 | 按缺失、超限、内容异常或网络失败显示对应提示，不打开空弹窗或生成空文件 |

## 发布站点与同步策略

- 发布范围：分阶段发布。

- 路由与内容影响：国内站 `/agents/persona/` 页面、相关中文文案、埋点和国内站人设文档。
- 上线顺序：国内站先行；国际站是否同步需基于国内站数据和反馈另行决策。
- 拆单策略：首期使用一个国内站产品父单；未来国际站同步时，若仅为语言和轻量入口差异，可关联原父单推进，若校验、合规或验收差异明显则创建关联产品父单。

- Hermes/OpenClaw/运行时：复用 Hermes Home 下的 `SOUL.md`、现有 `debug/exec` 写入和备份能力；不修改 `USER.md`、`MEMORY.md`。

- 权限/安全/数据：沿用当前 Agent 管理权限；原始文件只在浏览器读取，不作为独立文件上传；最终确认的人设文本会写入当前 Agent 的 `SOUL.md`。
- 数据埋点：新增上传和注入漏斗，禁止记录人设正文、文件内容或其他用户敏感文本。

## 非功能性需求

### 性能

- 20 KB 以内文件的选择、UTF-8 解码和本地校验应在正常设备上即时完成，目标不超过 300 ms。
- 打开编辑弹窗不新增远程上传请求。
- 注入耗时沿用现有人设注入链路；需要记录耗时用于发现异常。

### 兼容性

- 沿用国内站当前支持的桌面和移动浏览器范围。
- 文件选择器、编辑弹窗和错误信息在小屏幕下必须可完整操作。
- `.md` 扩展名大小写不敏感。
- 支持 LF 和 CRLF，写入时可统一为 LF，但不得改变正文语义。

### 安全与权限

- 只能修改当前用户有权管理的当前 Agent。
- 文件选择、读取和编辑不得把原始文件发送到第三方服务。
- Markdown 预览不得执行 HTML、JavaScript、事件处理器或外部嵌入内容。
- 远程写入命令不得拼接未经安全编码的用户正文、文件名或元数据。
- 人设正文不得进入埋点、前端错误日志或普通服务日志。
- 写入失败必须保持旧 `SOUL.md` 可恢复。

### 国际化与无障碍

- 首期只在国内站显示入口，但新增文案仍应进入项目现有 i18n 管理体系。
- 按钮、文件选择、编辑区、提示和弹窗具有可读标签。
- 完整支持键盘操作、焦点进入与返回、错误关联和屏幕阅读器提示。
- 错误不能只通过颜色表达。

## 数据埋点与观测

建议记录以下语义事件，最终事件名按现有大同规范落地：

- “上传人设文件”入口点击。
- 文件选择完成。
- 文件硬校验失败，包含枚举化失败原因，不包含文件名和正文。
- 编辑弹窗打开、取消。
- 软提示展示和用户继续注入。
- 覆盖确认、覆盖取消。
- 注入开始、成功、失败和耗时。
- 注入来源标记为 `upload`，与现有 `draw` 等来源区分。
- 注入成功后进入新会话的转化。
- 自定义人设的使用人数和重复使用率。

核心漏斗：

```text
上传人设入口点击
  → 选择有效文件
  → 打开编辑弹窗
  → 确认覆盖
  → 注入成功
  → 开启新会话
```

## 产品原型说明

本需求新增用户可见入口、弹窗和多种状态，需要补充轻量 Demo；不要求单独制作高保真交互设计稿。

- 目标页面/入口：国内站 `/agents/persona/` 操作区的“上传人设文件”。
- 用户主路径：打开上传弹窗 → 选择文件 → 校验 → 编辑 → 确认覆盖 → 注入 → 新会话生效。
- 页面结构：复用现有人设页，在操作区增加入口，通过弹窗承载编辑和确认。
- 关键组件：上传按钮、初始上传态、隐藏文件选择器、编辑弹窗、字节数、结构提示、错误提示、覆盖确认、结果状态。
- 必须覆盖的状态：默认、初始上传、读取中、硬校验失败、编辑、内容超限、软提示、覆盖确认、注入中、成功、失败、重新进入页面后的自定义状态。
- 需要设计确认：按钮并列后的响应式布局、编辑器高度、提示层级、覆盖确认文案和自定义状态呈现。
- 需要前端确认：UTF-8 严格解码、字节数计算、安全预览、事实状态回读和安全替换方式。

## 验收标准

1. 国内站已有 Agent 的人设页显示“上传人设文件”，国际站本次不显示。
2. 点击“上传人设文件”后先打开初始上传弹窗，不直接唤起系统文件选择器；初始态展示上传图标、“选择 Markdown 人设文件，将其内容填入 SOUL.md”、限制说明“仅支持 Markdown 文件，文件名不限，扩展名须为 .md，大小不超过 20 KB。”和“选择文件”。
2.1 用户在弹窗内取消文件选择时无报错，保持初始上传态，当前人设不发生变化。
3. `.md` 扩展名大小写不敏感；非 `.md` 文件被阻止并显示明确原因。
4. 文件和最终编辑内容均按 UTF-8 实际字节数执行 20 KB 上限，超过上限时不得注入。
5. UTF-8 BOM 可被识别并去除；无效 UTF-8、空内容、二进制或异常控制字符被阻止。
6. 校验通过后，编辑弹窗完整展示 Markdown 内容，用户可以修改并看到实时字节数。
6.1 初始上传态与编辑态不显示可见说明行；覆盖确认态标题显示“覆盖当前人设？”，说明仅显示“旧人设会自动备份，然后注入新人设。”。
6.2 编辑框的细灰边框、圆角、聚焦样式及标题间距参考“添加自动任务”的“任务说明”，其中标题与编辑框间距为 6px。
6.3 编辑态和覆盖确认态的两个操作按钮均位于弹窗右下角，次操作在左、主操作在右。
7. 缺少 `Name:`、角色、沟通风格或行为边界时只显示软提示，用户仍可继续；沟通风格识别支持 `沟通风格`、`Communication Style`，并兼容语气、表达、Tone、Voice、Style 标题。
8. Markdown 预览不执行 HTML、脚本、事件属性或外部嵌入内容。
9. 当前 Agent 已有人设时，注入前必须明确提示完整覆盖和旧人设备份。
10. 用户取消覆盖后返回编辑态，编辑内容和旧人设均保持不变。
11. 用户确认后先备份旧 `SOUL.md`，再通过安全替换写入新内容。
12. 注入中重复点击不会发起第二次写入。
13. 任意写入失败都不会把旧人设变为空文件或半写入状态；编辑内容保留并可重试。
14. 注入成功后显示“已注入：自定义人设 · `<名称>`”。
15. 名称优先来自 `Name:`；缺失时使用不含 `.md` 后缀的文件名。
16. 页面刷新、重新进入或切换回当前 Agent 后，仍能识别自定义人设状态和名称。
17. 自定义人设不生成卡片、不占用卡槽、不改变抽卡进度。
18. 注入预设人设和自定义人设可以相互替换，页面状态始终与当前真实 `SOUL.md` 一致。
19. 注入成功后沿用现有的新会话生效提示。
20. 原始 `.md` 不作为独立文件上传、保存或提供下载；埋点和日志不记录正文。
21. 关闭国内站功能入口可以完成产品回滚，现有随机抽取和答题测试不受影响。
22. 抽卡结果卡片左侧显示“注入此人设”，右侧显示“添加，暂不注入”；两个按钮文案字号统一缩小。
23. 点击“注入此人设”后直接写入当前 Agent，不要求先将卡片加入人设盘或再次选中。
24. Agent 写入成功后，该卡片加入或替换到人设盘、成为当前选中项并显示“已注入”。
25. 写入失败或仅降级下载 `soul.md` 时，不加入卡片、不关闭抽卡结果，用户可重试或选择“添加，暂不注入”。
26. 自定义人设状态文字后显示“编辑自定义人设”和“下载自定义人设”图标按钮，状态文字不可点击；推荐人设和国际站不显示这些入口。
27. 编辑图标读取当前 Agent 实际 `SOUL.md` 后打开“编辑人设文件”弹窗，内容和实时 UTF-8 字节数与真实文件一致。
28. 当前文件内容未修改、为空、含非法控制字符或超过 20 KB 时，“保存修改”不可用；保存失败保留内容并可重试。
29. 保存修改沿用备份、临时文件和原子替换链路；成功后刷新展示名称并提示发送 `/new`。
30. 下载图标直接下载当前 Agent 实际原文为 `soul.md`，不打开编辑弹窗、不标准化内容，并清理临时对象 URL。
31. 文件缺失、超限、协议/UTF-8 异常、网络失败和切换 Agent 竞态均不会打开或下载错误 Agent 的内容。

## 发布与观测

### 灰度与开关

- 首期通过国内站区域判断启用，国际站构建不展示相关入口。
- 若需要小流量验证，可复用现有前端灰度机制；没有现成机制时不为本需求单独建设通用灰度平台。
- 上线前验证随机抽取、答题测试、预设人设注入和清除等既有流程未回归。

### 上线观测

- 文件硬校验失败原因分布。
- 编辑后放弃率和覆盖取消率。
- 注入成功率、失败原因和耗时。
- 自定义人设注入后的新会话转化。
- 使用人数、重复使用率和相关反馈。

### 国际站评估条件

国内站上线后，结合以下信息决定是否同步国际站：

- 自定义人设使用人数和重复使用率。
- 注入成功率及主要失败原因。
- 用户对 20 KB 上限和格式提示的反馈。
- 国际用户是否存在同类导入诉求。
- 国际站语言、内容安全、文档和验收差异。

### 回滚

- 隐藏或关闭“上传人设文件”入口及相关弹窗。
- 不删除已经注入的 `SOUL.md` 或已有备份。
- 不影响预设人设卡、随机抽取、答题测试和既有注入流程。
- 若新状态识别异常，页面必须优先保留当前真实 `SOUL.md`，不得主动清除或覆盖。
