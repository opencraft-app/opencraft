# 国内站续费用户交互优化

## 来源

- 需求来源：本轮 `/feai-start` 产品前置讨论。
- 相关链接：[TAPD 产品需求 #136414042](https://tapd.woa.com/tapd_fe/10132091/story/detail/1010132091136414042)；基于 mono2 最新 master 续费实现调查。
- 提出人/干系人：产品与研发协作讨论。

## 背景与问题

- 当前用户怎么做：国内站用户购买套餐后，可以在 `/account` 查看订阅套餐、权益有效期和积分使用；在 `/subscribe` 尝试新购时，若后端返回 `PASS_EXPIRED` 或 `PASS_ISOLATED`，页面会提示用户前往“我的账号”续费。
- 现在卡在哪里：续费后端接口、前端 Repository 方法、微信支付中转页和 `RenewPassModal` 已存在，但 `/account` 订阅卡片中的续费入口被隐藏，用户被引导到账号页后缺少可点击的续费动作；已创建 Agent 的用户也无法在日常使用的 `/agents` 页面快速感知套餐即将到期。
- 为什么现在要做：续费是存量付费用户继续使用 Agent 的关键路径。当前断点会让过期或隔离用户误以为只能销毁后重购，也会让临近到期用户在 Agent 使用场景中缺少提前感知。

## 目标用户与场景

- 目标用户：国内站 `lightvela.com` 已登录、已购买付费套餐并持有未删除 Pass 的用户，重点是已经创建过 Agent 的用户。
- 典型场景：
  - 用户在 `/subscribe` 试图重新开通套餐，被告知应续费。
  - 用户进入 `/account` 查看套餐状态，希望直接续费当前套餐。
  - 用户日常在 `/agents` 管理 Agent，套餐将在 7 日内到期，需要被轻量提醒。
- 频率和重要性：低频但高价值；续费失败会直接影响存量用户留存、Agent 可用性和客服补偿成本。

## 目标

- 用户结果：用户能在账号页明确看到续费入口，并完成当前套餐续费；已创建 Agent 的用户能在到期前 7 日内在 `/agents` 感知风险，并从 Agent 头部状态提醒直接唤起续费弹窗。
- 产品结果：补齐国内站续费用户路径，降低“去账号页但找不到续费”的断点，减少过期后被动恢复。
- 不做会怎样：订阅页继续把用户导向无入口页面，过期/隔离用户可能放弃续费或误触销毁；临近到期用户只在到期后才感知影响。

## 范围

- 本次包含：
  - `/account` 订阅卡片恢复并规范“立即续费”入口，支持 `active`、`expired`、`isolated` 三类可续费 Pass。
  - `/account` 续费入口点击后复用现有 `RenewPassModal`，支持月付、季付两个续费周期，对应 1 个月、3 个月，覆盖询价、下单、微信二维码支付和续费成功刷新。
  - `/subscribe` 遇到 `PASS_EXPIRED` / `PASS_ISOLATED` 时，错误提示改为更明确的账号页续费引导。
  - `/agents` 在用户已有 Agent 且套餐距离到期小于等于 7 日时，在 Agent 信息头部展示到期状态提醒；hover 展示剩余时间，点击直接唤起续费弹窗。
  - 续费失败、询价失败、支付未完成、支付完成后刷新等状态文案和验收口径。
- 本次不包含：
  - 国际站 `lightvela.ai` 续费体验。
  - 自动续费。
  - 套餐升级、降级、变配或换套餐。
  - 工具能力、SkillHub、MCP、专家包或自动任务能力上线。
  - 短信、邮件、企微、站外通知或运营活动。
  - 新增独立续费页。
- 已知依赖：
  - 国内站付费计费开关已启用。
  - `GET /v1/passes` 能返回当前用户未删除 Pass。
  - `POST /v1/passes/{pass_id}/renew/price`、`renew/order`、`renew/order-url` 续费链路可用。
  - 微信中转页已支持通过 `pid` 区分续费订单。

## 发布站点与同步策略

- 发布范围：国内站 `lightvela.com` only。
- 国际站是否同步：否，后续单独评估。
- 国内站是否同步：是。
- 差异化原因：本次依赖国内站人民币计价、微信支付、实名/付费 Pass、国内服务网关可选鉴权配置和国内用户续费心智；国际站支付、订阅模型和文案策略不在本轮范围。
- 路由与内容影响：影响 `/account`、`/subscribe`、`/agents` 的入口、提示文案和续费 CTA；不影响 sitemap、metadata、文档图片或国际站 i18n 发布策略。
- 上线顺序：国内站先行；上线后按续费链路验证结果再评估国际站是否需要独立产品需求。

## LightVela 影响面

- 前端页面/路由：
  - `/account`：订阅卡片恢复续费入口，续费弹窗成为可达路径。
  - `/subscribe`：过期/隔离拦截提示变为可行动引导。
  - `/agents`：在 Agent 信息头部新增到期状态提醒入口。
- Hermes/OpenClaw/运行时：不改 Agent 运行时、不改 Hermes/OpenClaw 命令行为；只在 Agent 管理页展示套餐到期风险。
- SkillHub/MCP/工具：不涉及，工具能力暂不上线。
- SDK/文档/运营：不改 SDK；如上线后需要运营说明，另行补充轻量公告或客服话术。
- 权限/安全/数据：不新增敏感数据存储；续费仍以当前登录用户持有的 `pass_id` 和后端鉴权为准。

## 方案决策

- 采用方案：方案 A，账号页续费闭环 + `/agents` Agent 头部到期状态提醒。
- 选择理由：
  - 最小化复用现有续费能力，修复当前最明确的用户断点。
  - `/account` 是订阅与权益管理的自然入口，适合承接确认续费、周期选择和支付。
  - `/agents` 是已创建 Agent 用户的高频页面，适合把到期风险放在 Agent 头部状态处提示；点击后复用同一个续费弹窗，减少用户先跳账号页再支付的绕行。
- 备选方案与取舍：
  - 方案 B：让 `/subscribe` 直接承接续费。优点是购买心智集中；缺点是新购和续费混在同一大页面，测试范围和状态分支更大，本轮不采用。
  - 方案 C：新增独立续费页。优点是流程清晰；缺点是新增路由、状态恢复和中转说明，当前能力已有账号页弹窗，投入不划算，本轮不采用。
- 交互或流程：
  1. 用户进入 `/account`，系统展示当前套餐、有效期、积分和状态。
  2. 当 Pass 可续费时，展示“立即续费”按钮；隔离期可同时展示“销毁套餐”按钮。
  3. 用户点击“立即续费”，打开现有续费弹窗，选择月付或季付并查看询价结果。
  4. 用户确认后生成续费订单和微信二维码；支付完成后账号页刷新 Pass，展示新的有效期。
  5. 用户在 `/subscribe` 触发过期/隔离拦截时，页面明确提示前往 `/account` 续费。
  6. 用户在 `/agents` 且已有 Agent，若当前有效 Pass 距离到期小于等于 7 日，在 Agent 信息头部展示到期状态提醒；hover 查看剩余时间，点击提醒直接唤起续费弹窗。
- 状态变化：
  - `active`：允许提前续费，按钮文案为“立即续费”；7 日内在 `/agents` 提醒。
  - `expired`：允许续费，账号页提示“套餐已过期，请及时续费以免进入隔离期”。
  - `isolated`：允许续费和销毁，账号页提示“可选择续费恢复使用或销毁当前套餐”。
  - `deleted`：不允许续费，本次不展示续费入口。
- 数据或接口：
  - 复用 `listMyPasses()` 获取 `activePass`、`latestPass` 和账号页 fallback pass。
  - 复用 `getRenewPrice(passId, { period, time_unit })` 询价。
  - 复用 `createRenewOrder(passId, { period, time_unit })` 下单。
  - 复用微信中转页 `getRenewOrderUrl` 拉起支付。
  - 不新增后端接口。
- 异常和空态：
  - 询价失败：提示“询价失败，可直接下单或稍后重试”，不阻塞用户尝试下单。
  - 下单失败：展示后端错误码映射后的用户友好文案。
  - 支付未完成：二维码阶段保留“刷新”手动校验能力。
  - 支付完成但刷新未拿到新有效期：保持弹窗可再次刷新，不宣称成功。
  - `/agents` 没有 Agent：不展示到期提醒。
  - `/agents` 没有有效 Pass：不展示 7 日内提醒，由 `/account` 和 `/subscribe` 的过期/隔离引导承接恢复路径。
- 延后或不做：
  - 用户自定义关闭提醒、站外通知、续费优惠、自动续费、变配和独立续费页均延后。

## 验收标准

- 验收 1：国内站 `/account` 中，持有 `active`、`expired` 或 `isolated` 未删除 Pass 的用户能看到“立即续费”入口；`deleted` Pass 不展示续费入口。
- 验收 2：点击“立即续费”后打开续费弹窗，默认月付，可切换季付并触发询价；月付对应 1 个月，季付对应 3 个月。
- 验收 3：询价成功时展示应付金额；询价失败时展示轻量错误且仍允许尝试下单。
- 验收 4：确认续费后调用续费下单链路，生成微信支付二维码；二维码中转页走续费 `renew/order-url` 路径。
- 验收 5：用户支付完成后，发起续费的页面刷新 Pass 并展示新的有效期；刷新未确认成功时不误报续费成功。
- 验收 6：`/subscribe` 遇到 `PASS_EXPIRED` 或 `PASS_ISOLATED` 时，错误提示明确告诉用户前往 `/account` 续费，并提供可点击动作或清晰入口。
- 验收 7：`/agents` 中，用户已有至少 1 个非创建中/非删除中的 Agent，且有效 Pass 距离到期小于等于 7 日时，在 Agent 信息头部展示到期状态提醒。
- 验收 8：`/agents` 到期状态提醒 hover 后展示剩余时间；大于等于 1 天时展示剩余 X 天，小于 1 天时展示剩余 X 小时；2-7 天和小于 2 天有不同提醒颜色；点击提醒可直接唤起续费弹窗。
- 验收 9：`/agents` 到期提醒不阻断用户继续管理 Agent，不使用弹窗或全屏遮罩。
- 验收 10：国际站构建不展示国内站续费入口或中文提醒，不引入国际站支付行为变化。
- 验收 11：本次不出现 SkillHub、MCP、工具能力或自动任务相关上线入口。
- 验收 12：相关页面的移动端布局不横向溢出，按钮和提醒文本不相互遮挡。
- 验收 13：续费弹窗内必须同时展示当前套餐、当前到期时间、续费时长、预计续费后到期时间和应付金额，用户确认前不需要跳出弹窗核对关键信息。
- 验收 14：续费弹窗覆盖询价中、询价失败、下单中、二维码支付中、支付未确认和续费成功状态；任一异常状态不误报成功、不丢失当前页面刷新、重试或关闭路径。

## 发布与观测

- 灰度/开关：复用现有国内站付费计费开关和区域化分支；不新增独立产品开关。
- 日志/指标：优先通过续费订单创建量、续费支付完成量、`/account` 续费入口点击、`/agents` 到期状态提醒点击和续费弹窗打开来源观察效果；若现有埋点体系未覆盖，研发实现时补轻量点击事件。
- 回滚：前端可隐藏续费入口和 `/agents` 提醒，保留后端续费接口不变；`/subscribe` 可回退到原提示文案。

## 产品原型说明

### 原型目标

本次原型不是新增独立续费页，而是在现有用户路径里补齐三个连续触点：`/agents` 提前感知、`/account` 承接续费、`/subscribe` 从误购路径回流。交互应保持工具型页面的克制感，优先使用行内提示、现有卡片操作区和现有续费弹窗，不使用全屏遮罩、营销式大横幅或强制弹窗打断用户。

### 信息架构

```text
/agents
  └─ Agent 信息头部状态提醒（已有 Agent + 有效 Pass <= 7 天）
       ├─ hover：展示剩余 X 天 / X 小时到期
       └─ click：打开 RenewPassModal

/account
  └─ 订阅套餐卡片
       ├─ 套餐信息 / 有效期 / 积分
       ├─ 状态提示：active / expired / isolated
       └─ 立即续费 → RenewPassModal
            ├─ 确认续费：周期选择 + 价格区 + 错误提示
            └─ 微信支付：二维码 + 刷新校验

/subscribe
  └─ PASS_EXPIRED / PASS_ISOLATED 错误
       └─ 前往我的账号续费 → /account
```

### `/agents` 临近到期提醒

- 展示条件：
  - 国内站。
  - 用户已登录。
  - 当前页面存在至少 1 个非 `provisioning`、非 `deleting` 的 Agent。
  - `activePass` 存在，且距离 `expired_time` 小于等于 7 天。
- 不展示条件：
  - 无 Agent。
  - 无有效 Pass。
  - Pass 已过期或已隔离，此时由 `/account` 与 `/subscribe` 的恢复路径承接，不在 `/agents` 做恢复流程。
  - 国际站。
- 推荐位置：放在 `/agents` 左侧 Agent 信息头部，也就是截图红框内的头像、Agent 名称、运行状态这一组区域；优先贴近“运行中”状态文本展示，不放在主内容区顶部。
- 视觉形态：不使用横幅 banner；在 Agent 运行状态旁增加一个小型套餐状态提醒，可采用状态点、细描边 chip 或短文本。更多菜单位置保持不变。
- 桌面布局：
  ```text
  ┌────────────────────────────────────┐
  │ [头像] 我的Hermes              [⋮] │
  │        ● 运行中  ·  套餐将到期      │
  └────────────────────────────────────┘
  ```
- 移动端布局：
  ```text
  [头像] 我的Hermes          [⋮]
         ● 运行中
         套餐将到期
  ```
- 文案规则：
  - 默认可见短文案：`套餐将到期`。
  - hover 提示，剩余大于等于 1 天：`套餐剩余 {{days}} 天到期，点击续费。`
  - hover 提示，剩余小于 1 天：`套餐剩余 {{hours}} 小时到期，点击续费。`
  - 剩余不足 1 小时时：`套餐不足 1 小时到期，点击续费。`
- 交互规则：
  - 鼠标 hover 到套餐状态提醒时展示 tooltip；tooltip 不遮挡 Agent 名称、更多菜单和左侧导航。
  - 点击套餐状态提醒直接打开 `RenewPassModal`，不跳转 `/account`。
  - 移动端没有 hover 时，状态提醒短文案常显，点击短文案打开 `RenewPassModal`。
  - 支付成功后刷新 `/agents` 的 Pass 状态，到期提醒消失或恢复为普通运行状态。
  - 不提供关闭按钮，避免用户误以为关闭后风险解除；后续若用户反馈干扰，再单独评估“本次会话关闭”。
  - 不阻断页面内任何 Agent 管理操作。
  - 不自动打开续费弹窗，避免用户刚进入工作页就被支付流程打断。
- 状态颜色：
  - 剩余 2-7 天：使用提醒色，例如琥珀色状态点或浅色 chip，表示“需要关注但未紧急”。
  - 剩余小于 2 天：使用更强提醒色，例如红色或橙红色，表示“即将影响使用”。
  - 正常大于 7 天：不展示套餐到期提醒，仅保留原 Agent 运行状态。

### `/account` 订阅卡片续费入口

- 推荐位置：沿用订阅套餐卡片底部操作区，放在套餐有效期和积分进度之后。
- 操作优先级：
  - `active` / `expired`：只展示主操作“立即续费”。
  - `isolated`：展示“立即续费”和“销毁套餐”，其中“立即续费”为主操作，“销毁套餐”为危险次级操作。
  - `deleted`：不展示续费入口。
- 桌面布局：
  ```text
  订阅套餐
  当前套餐：启航版
  订阅有效期：2026-07-01 - 2026-07-31        剩余 3 天
  已使用积分：...
  ───────────────────────────────────────────
  [立即续费]  [销毁套餐]
  套餐已进入隔离期，可选择续费恢复使用或销毁当前套餐。
  ```
- 移动端布局：
  - 主按钮和危险按钮允许换行，但按钮不挤压文本。
  - 状态说明位于按钮下方，占满一行。
  - “立即续费”不使用过宽的营销式 CTA，和账号页现有圆角/高度保持一致。
- 状态文案：
  - `active` 且剩余大于 7 天：`当前套餐可提前续费，续费后有效期将顺延。`
  - `active` 且剩余小于等于 7 天：`套餐将在 {{days}} 天后到期，建议及时续费。`
  - `expired`：`套餐已过期，请及时续费以免进入隔离期。`
  - `isolated`：`套餐已进入隔离期，可选择续费恢复使用或销毁当前套餐。销毁后可重新购买。`
- 交互规则：
  - 点击“立即续费”打开 `RenewPassModal`。
  - 打开弹窗前不再次请求询价；询价由弹窗内根据默认周期自动触发。
  - 续费成功后关闭弹窗并刷新账号页 Pass 数据。
  - 销毁能力保持原前置条件，仅 isolated 可触发，不因续费入口恢复而扩大范围。

### `RenewPassModal` 续费弹窗

- 设计目标：
  - 让用户在支付前一次性确认“给哪个套餐续费、续多久、续费后到什么时候、需要付多少钱”。
  - 续费流程保持在当前入口页面上下文内完成，可由 `/account` 或 `/agents` 唤起，不新增独立续费页。
  - 弹窗内状态稳定，询价、下单、支付确认过程中不出现大幅跳动或空白。
- 弹窗尺寸：
  - 桌面端建议宽度 480-520px，内容不超过一屏时不滚动。
  - 移动端使用屏幕宽度的安全边距，底部按钮可换行或纵向排列。
  - 底部操作区固定在弹窗底部；内容较长时只滚动主体区域。
- 信息层级：
  1. 标题区：展示阶段标题和一句辅助说明。
  2. 当前套餐区：展示套餐名称、套餐状态、当前到期时间。
  3. 续费选择区：展示月付、季付两个选项，并在选项内说明对应 1 个月、3 个月。
  4. 续费结果预估：展示“预计续费后到期时间”。
  5. 价格区：展示询价状态、应付金额和价格异常提示。
  6. 操作区：展示取消、确认续费、刷新等动作。
- 状态流转：
  ```text
  打开弹窗
    -> 默认选择月付并询价
    -> 用户切换续费时长
    -> 重新询价并更新预计到期时间
    -> 确认续费
    -> 创建续费订单
    -> 展示微信支付二维码
    -> 用户扫码支付
    -> 自动轮询或手动刷新校验
    -> 刷新 Pass
    -> 确认有效期变更后关闭弹窗
  ```
- 确认续费阶段原型：
  ```text
  ┌────────────────────────────────────┐
  │ 续费套餐                            │
  │ 为当前套餐延长有效期，续费后立即生效。 │
  │                                    │
  │ 当前套餐                            │
  │ 启航版                 生效中        │
  │ 当前到期：2026-07-31 23:59          │
  │                                    │
  │ 续费时长                            │
  │ [月付 1 个月]       [季付 3 个月]     │
  │                                    │
  │ 预计续费后到期                       │
  │ 2026-08-31 23:59                    │
  │                                    │
  │ 应付金额                            │
  │ ¥49.00                              │
  │                                    │
  │ 续费将按当前套餐到期时间顺延。          │
  │                     [取消] [确认续费] │
  └────────────────────────────────────┘
  ```
- 确认续费阶段交互：
  - 打开弹窗后默认选中月付，并立即发起询价。
  - 用户可选月付、季付两个固定周期；月付对应 `period=1`，季付对应 `period=3`，`time_unit` 均为月。
  - 切换时长后立即更新选中态和预计到期时间，同时重新询价；若上一次询价晚返回，只以最后一次选择的结果为准。
  - 询价中保留价格区高度，展示 `正在查询价格...`，确认按钮暂不可点击。
  - 询价成功后展示应付金额，确认按钮可点击。
  - 询价失败后展示 `询价失败，可稍后重试；也可以继续下单，最终金额以支付页为准。`，确认按钮可点击。
  - 点击确认后按钮进入 `正在创建订单...` 状态，并禁止重复点击。
  - 下单失败时保留用户已选时长，在按钮上方展示失败原因；用户可调整时长或再次确认。
- 支付阶段原型：
  ```text
  ┌────────────────────────────────────┐
  │ 微信扫码支付                         │
  │ 请使用微信完成当前续费订单支付。        │
  │                                    │
  │ 续费套餐：启航版                      │
  │ 续费时长：月付 1 个月                  │
  │ 应付金额：¥49.00                     │
  │                                    │
  │              [二维码]                │
  │                                    │
  │ 支付完成后页面会自动刷新。              │
  │                               [刷新] │
  └────────────────────────────────────┘
  ```
- 支付阶段交互：
  - 只有订单创建成功并拿到二维码后才切换到支付阶段。
  - 支付阶段保留订单摘要，避免用户扫码前忘记本次续费内容。
  - 支付阶段不提供“返回修改时长”，避免同一个订单金额与用户重新选择的时长不一致；用户如需修改，可关闭弹窗后重新发起续费。
  - 弹窗关闭不取消订单，仅结束当前页面的支付等待。
  - 支付中自动轮询 Pass 状态；用户点击“刷新”时立即触发一次刷新校验。
  - 只有刷新后确认 Pass 有效期已延长，才展示成功结果或关闭弹窗，并在当前页面提示 `续费成功，有效期已更新。`
  - 到达轮询上限或二维码可能过期时，展示 `暂未确认支付结果，请点击刷新或稍后再查看套餐状态；如未完成支付，可重新发起续费。`
- 关键文案：
  - 弹窗标题：`续费套餐`
  - 阶段说明：`为当前套餐延长有效期，续费后立即生效。`
  - 价格加载：`正在查询价格...`
  - 询价失败：`询价失败，可稍后重试；也可以继续下单，最终金额以支付页为准。`
  - 下单失败：`订单创建失败，请稍后重试。`
  - 支付标题：`微信扫码支付`
  - 支付说明：`请使用微信完成当前续费订单支付。`
  - 支付未确认：`暂未确认支付结果，请点击刷新或稍后再查看套餐状态。`
  - 成功提示：`续费成功，有效期已更新。`
- 状态与样式细节：
  - `active`：状态标记展示“生效中”。
  - `expired`：状态标记展示“已过期”，说明文案为 `当前套餐已过期，续费后将恢复使用。`
  - `isolated`：状态标记展示“隔离期”，说明文案为 `当前套餐已进入隔离期，续费后将恢复使用。`
  - 价格区使用普通正文和金额强调，不使用营销化大字号。
  - 价格区和错误区占位稳定，避免弹窗高度频繁变化。
- 可访问性：
  - 弹窗打开后焦点落在已选中的续费时长上。
  - 周期选项支持键盘切换，并有明确选中态、hover 态和 focus 态。
  - 提交中禁用关闭以外的重复提交动作；关闭弹窗后，焦点回到本次打开弹窗的入口，可能是 `/account` 的“立即续费”按钮，也可能是 `/agents` 的到期状态提醒。

### `/subscribe` 续费回流

- 触发条件：用户在 `/subscribe` 尝试新购，后端返回 `PASS_EXPIRED` 或 `PASS_ISOLATED`。
- 推荐形态：在现有错误区域内展示可行动提示，不在订阅页弹续费弹窗。
- 文案：
  - 标题：`当前套餐需要续费`
  - 描述：`你的套餐已过期或进入隔离期，请前往我的账号续费当前套餐。`
  - 操作：`前往续费`
- 交互：
  - 点击“前往续费”跳转 `/account`。
  - 不自动选择订阅页套餐卡，不进入新购确认订单弹窗。
  - 保留订阅页当前列表状态，用户返回时仍可查看套餐，但不能绕过续费规则直接新购。

### 端到端流程

- 流程 A：临近到期提前续费
  1. 用户已有 Agent，进入 `/agents`。
  2. 系统判断有效 Pass 剩余 3 天，在 Agent 信息头部展示“套餐将到期”状态提醒。
  3. 用户 hover 状态提醒查看 `套餐剩余 3 天到期，点击续费。`
  4. 用户点击状态提醒，直接打开续费弹窗，选择月付或季付并扫码支付。
  5. 支付完成后 `/agents` 刷新 Pass 状态，到期提醒消失或恢复为普通运行状态。
- 流程 B：过期后恢复
  1. 用户进入 `/subscribe` 尝试新购。
  2. 后端返回 `PASS_EXPIRED`。
  3. 页面提示“当前套餐需要续费”，用户点击“前往续费”。
  4. 用户在 `/account` 打开续费弹窗并完成支付。
- 流程 C：隔离期选择
  1. 用户进入 `/account`，订阅卡片显示隔离期提示。
  2. 用户看到“立即续费”和“销毁套餐”两个操作。
  3. 用户选择续费时进入续费弹窗；选择销毁时进入原有销毁确认流程。

### 需要设计确认

- `/agents` 到期状态提醒最终视觉：建议采用“运行状态后追加短文本/chip”的方式，2-7 天为琥珀色，小于 2 天为红色或橙红色。
- `/account` 中“立即续费”和“销毁套餐”的相对样式：建议主操作使用黑色或品牌强调色，销毁继续使用红色描边。
- `RenewPassModal` 支付阶段二维码说明是否需要补充“微信内完成支付后回到本页面”的辅助文案。

### 需要前端确认

- `/agents` 提醒插入点应放在 Agent 信息头部，贴近“运行中”状态；需要避开更多菜单、Agent 切换 tab 和 SDK 内容区。
- `activePass` 到期时间判断以 `expired_time` 的真实时间戳为准；展示时大于等于 1 天按天，小于 1 天按小时，不足 1 小时展示“不足 1 小时”。
- `/subscribe` 错误提示是否已有按钮型错误组件可复用；若没有，使用现有按钮和错误文本组合，不新增重型组件。
