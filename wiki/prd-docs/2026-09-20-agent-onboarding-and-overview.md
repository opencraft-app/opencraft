## 需求背景

多 Bot 与 Profile 基建（见关联需求）已交付，用户可以创建多个 Bot，但两个环节没有产品化：

1. **新建的 Bot 是一张白纸。** 用户拿到一个空 Agent，需要自己去技能页装技能、去定时任务页配调度、去人设页写 SOUL。三个页面分散在不同 Tab，新用户不知道该配什么、配到什么程度算「能用」。
2. **Agent 首页没有承载信息。** 进入 `/agents` 后直接是设置项列表，没有一个地方告诉用户「我的 Bot 现在是什么状态」「平台最近更新了什么」「我还可以配什么」。

同时，上一版创建入口存在两个已知问题：「新建 Bot」按钮需要在浏览器 Console 执行 `show()` 才显形（见关联需求的当前发布决策）；创建弹窗只收集 Bot 名字，与后续配置割裂。

## 目标用户与场景

### 目标用户

- **新订阅用户**：完成付费后首次进入 Agent，此前没有任何 Bot。
- **已有 Bot 的用户**：想再建一个专用 Bot（如已有通用助手，再建一个投研专用）。

### 典型场景

1. 用户订阅套餐后自动跳转 Agent 页，看到创建引导，选一个贴近自己需求的模板，等待配置完成后直接可用。
2. 用户不需要模板，只想要一个空白 Bot，填名字和头像后创建。
3. 已有 Bot 的用户点「新建 Bot」，可选择空白创建或从现有 Bot 复制配置。
4. 用户日常进入 Agent 总览页，查看 Bot 资料卡、平台最新动态、可添加的定时任务推荐。

## 产品目标

| 目标 | 可观察结果 |
|---|---|
| 新用户拿到的 Bot 开箱可用 | 选择模板创建后，该 Bot 的人设、用户画像、技能、定时任务四类配置均已写入，无需手动补配 |
| 创建过程可见 | 创建期间展示分步进度清单，每步有明确的进行中 / 成功 / 失败状态 |
| 部分失败不阻断 | 技能或定时任务写入失败时，Bot 仍创建成功且可用，失败步骤标注原因与补救入口 |
| 创建入口正式开放 | 「新建 Bot」不再依赖 Console 命令显形 |
| 总览页承载 Agent 概况 | 用户进入 `/agents` 默认看到总览，包含 Bot 资料卡、最新动态、定时任务推荐 |

> 转化率、留存率等度量目标：`[推荐待确认]` 补写时无历史基线数据。推荐在上线后先采集两周基线（新建 Bot 数 / 模板选择分布 / 配置完整率），再设定目标值。理由：无基线的目标值不可证伪。

## 范围

### 本轮已实现

**A. 创建引导**

- 单页表单：头像选择（几何图形 + 配色，支持「换一批」）、名字、描述（可选）。
- 表单下方展示模板推荐卡片，点击卡片打开模板详情弹窗，弹窗内可查看该模板的介绍、记忆、技能、定时任务四项内容后再决定是否创建。
- 两种创建方式：选模板创建（套用模板全部配置）、直接填表创建（仅写入名字/描述/头像）。
- 已有 Bot 时，表单内可选择「从其他 Bot 复制」，来源列表为当前账号下全部可见 Bot，主 Bot 排最前并标记。默认为空白创建。

**B. 配置进度页**

- 创建触发后进入进度页，展示分步清单，步骤顺序固定：写入人设 → 保存 Bot 资料 → 写入用户画像 → 安装技能（每个技能一步）→ 创建定时任务（每个任务一步）→ 启动网关。
- 每步三态：等待 / 进行中 / 完成或失败。顶部展示完成计数与进度条。
- 人设与资料写入属必需步骤，失败则终止流程；技能、用户画像、定时任务、网关属非必需步骤，失败不终止后续步骤。
- 全部完成后提供「进入 Bot」按钮，跳转到新建 Bot 自己的总览页。

**C. Agent 总览页**

按固定顺序展示四个板块：

1. **Hero 横幅**：套餐剩余天数、剩余积分、定时任务数、工作台数。
2. **我的 Bot**：当前 Bot 的头像、名字、描述，支持就地编辑。
3. **最新动态**：平台功能更新轮播（当前为静态内容）。
4. **定时任务推荐**：可一键添加的任务模板。

**D. 模板库**

共 10 个模板，按站点分流：

| 模板 | 国内站 | 国际站 | 国际站技能 | 国内站技能 |
|---|---|---|---|---|
| 健康管家 / Health Steward | ✅ | ✅ | 无 | 无 |
| 投研小行家 / Market Analyst | ✅ | ✅ | `stocks` | `westock-data` |
| 行业研究员 / Industry Researcher | ✅ | ✅ | `research` | 无 |
| 晨间情报员 / Morning Briefing | ✅ | ✅ | `research` | 无 |
| AI 学习搭子 / AI Study Buddy | ✅ | ✅ | `teach` | 无 |
| 增长实验官 / Growth Experimenter | ✅ | ✅ | `marketing-ideas` | 无 |
| 社媒灵感官 / Social Muse | ✅ | ✅ | `social-content` + `research` | `lingyi-wx-viral-script-generator` |
| 育儿参谋 | ✅ | ❌ | — | `parenting-expert` |
| 防骗员 | ✅ | ❌ | — | `anti-fraud` |
| 编程搭子 | ✅ | ❌ | — | `dev-expert` |

分流规则：

- **技能市场不同**：国际站用 skills.sh / GitHub 源，国内站用 SkillHub，同一技能在两站不一定都存在。
- **三个模板仅国内站展示**：其技能只在 SkillHub 上架，skills.sh 无对等物。给空技能会让模板名不副实（如「编程搭子」没有编程技能），因此整条不展示。
- **所有模板均不依赖用户自备 API Key**。国内站原「腾讯新闻」技能因需用户自行申请 Key 且 Key 缺失时会中断任务，已移除。

**E. 多语言**

- 模板的名称、描述、人设正文、记忆、技能说明、定时任务说明按站点提供中英两套文案。
- 创建进度页的步骤文案、表单默认值与占位符纳入 i18n 词典，覆盖 en-US / zh-Hant / ja-JP / ko-KR / es / id-ID 六个语种。

### 本阶段不包含

| 不包含项 | 原因 |
|---|---|
| 模板内容的后台配置能力 | 当前模板为前端静态定义，改动需发版。动态化待模板数量超过 20 个或需运营频繁调整时再评估 |
| 「最新动态」接入真实数据源 | 当前为静态内容 |
| 用户自定义模板 / 模板分享 | 优先验证官方模板的使用率 |
| 创建失败的自动重试入口 | 失败步骤引导用户到对应页面手动补配 |
| 模板配置的增量更新 | 模板内容更新后，已按旧版本创建的 Bot 不回溯 |

## 页面与交互设计

### 创建入口

| 用户状态 | 入口 | 行为 |
|---|---|---|
| 无任何 Bot（含订阅后首次进入） | 自动进入创建引导 | 直接展示引导表单，无需点击 |
| 已有 Bot | Agent 页「新建 Bot」按钮 | 点击后进入创建引导 |

- 「新建 Bot」按钮常驻显示，不再需要 Console 命令显形。
- 是否可创建仍由两个条件决定：多 Bot 功能开关（后端配置）、套餐 Bot 数量上限。达到上限时按钮置灰且 hover 提示原因。

### 创建引导流程

```
表单页 ──选择模板──> 模板详情弹窗 ──点「创建」──> 配置进度页 ──全部完成──> 新 Bot 总览页
   │                                                    │
   └──直接点「创建」──> 配置进度页（仅写入基础资料）───────┘
```

- 引导展开期间独占整页，不与总览页、设置区同屏。
- 配置过程中不可中断；退出方式为等待流程结束后点「进入 Bot」。
- 创建过程中页面不因 Bot 状态变化（provisioning → running）而重置表单或中断配置。

### 配置进度页状态

| 状态 | 展示 |
|---|---|
| 全部成功 | 「正在给 LightVela Bot 喂咖啡，唤醒大脑中…」+ 完成计数 |
| 部分失败 | 标题改为「Bot 已创建，但有 N 项配置没成功」；失败步骤标红并展示失败原因；底部提示「安装过程遇到了小阻碍，稍后可在「技能」和「定时任务」页面手动安装，Bot 本身已安装成功。」 |
| 必需步骤失败 | 展示失败原因，不继续后续步骤 |

失败原因展示规则：系统返回了错误信息时展示该信息原文；未返回时展示「这一步没成功，稍后可在对应页面重试」。

### 模板写入规则

用户选择模板后，模板内容按以下规则落到新 Bot：

| 模板字段 | 写入目标 | 覆盖方式 |
|---|---|---|
| 人设正文 instructions | SOUL.md | 新建时完整生成 |
| 名字 / 描述 | SOUL.md 元数据 + profile.yaml | 覆盖 |
| 记忆 memories | USER.md | 追加为独立小节 |
| 技能 skills | 逐个安装到该 Bot 的 Profile | 新增 |
| 定时任务 routines | 逐条创建 | 新增 |

- 用户在表单里填的描述与模板描述同时存在时，模板 instructions 为正文主体，用户描述作为「用户期望」小节追加。
- 编辑既有 Bot 时只更新 SOUL.md 的名字与简介两行元数据，正文保留，不覆盖用户在对话中调教出的人设。

## 验收标准

### 创建流程

```text
Given 账号下没有任何 Bot，用户完成订阅并跳转到 Agent 页
When 页面加载完成
Then 直接展示创建引导表单，不展示总览页或设置区
```

```text
Given 用户在创建引导表单页
When 点击「投研小行家」模板卡片
Then 弹出模板详情，可看到该模板的介绍、记忆、技能列表、定时任务列表
```

```text
Given 用户已打开模板详情弹窗
When 点击弹窗内的「创建」
Then 页面切换为配置进度清单，清单条目数等于该模板的配置项总数（人设 + 资料 + 画像 + 技能数 + 定时任务数 + 网关）
```

```text
Given 模板配置流程执行中
When 新 Bot 状态从 provisioning 变为 running
Then 进度页保持展示，不回到表单，不中断剩余步骤
```

```text
Given 模板包含 1 个技能和 2 个定时任务，且全部写入成功
When 流程结束后点击「进入 Bot」
Then 跳转到该新建 Bot 的总览页（非主 Bot 总览页）
And 该 Bot 的技能页可见已安装的技能
And 该 Bot 的定时任务页可见 2 条任务
```

```text
Given 模板包含 1 个技能，技能安装步骤失败
When 流程执行到该步骤
Then 该步骤标红并展示失败原因
And 后续定时任务步骤继续执行
And 流程结束后展示「Bot 已创建，但有 1 项配置没成功」
```

### 多 Bot 隔离

```text
Given 账号下已有主 Bot，用户新建第二个 Bot 并选择带技能的模板
When 配置流程全部完成
Then 技能安装在新 Bot 的 Profile 下
And 主 Bot 的技能列表不新增任何条目
```

### 区域与语言

```text
Given 用户访问国际站 lightvela.ai
When 打开创建引导表单
Then 模板推荐中不出现「育儿参谋」「防骗员」「编程搭子」
And 模板卡片的名称与描述为英文
```

```text
Given 用户在国际站以英文界面创建 Bot
When 进入配置进度页
Then 步骤清单文案为英文
And 表单默认名称与描述占位符为英文
```

```text

When 用户选择该模板创建
Then 生成 2 个定时任务步骤，无任务因调度文案无法解析而被跳过
```

### 总览页

```text
Given 用户进入 Agent 总览页
When 页面加载完成
Then 依次展示：总览标题、Hero 横幅、我的 Bot、最新动态、定时任务推荐
```

## 待确认问题

### A 类：推荐待确认

**A1. 模板配置失败后是否提供一键重试**

- 推荐：不提供，引导用户到对应页面手动补配。
- 理由：失败原因多样（技能不存在、网络中断、配额不足），一键重试无法区分可重试与不可重试场景，重复失败会放大挫败感。
- 取舍：用户需要多跳转一次页面。

**A2. 模板内容更新后，已创建的 Bot 是否回溯**

- 推荐：不回溯。
- 理由：Bot 创建后用户可在对话中修改人设，回溯会覆盖这些改动。
- 取舍：早期创建的 Bot 配置会逐渐落后于新模板。

**A3. 创建过程中是否允许用户中断**

- 推荐：不允许，仅在流程结束后提供出口。
- 理由：中断时机不确定会留下半配置状态的 Bot，清理逻辑复杂。
- 取舍：全部步骤失败时用户需等待流程走完。

### B 类：待外部事实

**B1. 技能安装的成功判定标准**

```text
缺失事实：acli / hermes 命令在技能安装失败时是否一定返回非零退出码
来源方：Hermes CLI 维护方
影响：当前判定仅依据退出码。若失败时仍返回 0，进度页会显示成功但技能实际未安装，用户在技能页看不到该技能且无任何错误提示
临时行为：保持现有判定；同时在失败步骤展示命令原始输出，便于用户与支持人员排查
```

**B2. 各模板技能的可用性与稳定性**

```text
缺失事实：7 个国际站技能（stocks / research / teach / marketing-ideas / social-content）与 4 个国内站技能（westock-data / parenting-expert / anti-fraud / dev-expert / lingyi-wx-viral-script-generator）当前在各自技能市场的上架状态与安装成功率
来源方：SkillHub 与 skills.sh 运营方
影响：技能下架或安装失败会导致对应模板的核心能力缺失，模板名不副实
临时行为：安装失败不阻断 Bot 创建；失败步骤提示用户到技能页手动安装
```

**B3. 上线后的度量基线**

```text
缺失事实：新建 Bot 数量、模板选择分布、配置完整率的历史基线
来源方：数据团队 / 大同埋点
影响：无法设定可验证的产品目标值
临时行为：先上线并采集两周数据，再回写产品目标章节
```

### C 类：待用户选择

**C1. 模板库是否需要后台配置能力**

- 推荐：本期不做，保持前端静态定义。
- 备选方案差异：做后台配置需要新增模板管理界面、存储与版本控制，工作量约为本期需求的 50%~80%`[待外部事实]`；收益是运营可自行调整模板内容而不依赖发版。
- 建议触发条件：模板数量超过 20 个，或出现单月两次以上的模板文案调整需求。

## 附录：与关联需求的差异

`2026-09-09-lightvela-multi-bot-profile.md` 中的以下决策在本轮被调整：

| 原决策 | 本轮调整 | 原因 |
|---|---|---|
| 「新建 Bot」按钮默认隐藏，需 Console 执行 `show()` 显形 | 按钮常驻显示 | 多 Bot 已具备完整创建流程，可面向普通用户开放。准入仍由功能开关与套餐上限把关 |
| 创建 Bot 使用弹窗，仅收集名字 | 改为整页创建引导，收集头像 / 名字 / 描述，并可选模板 | 原弹窗与后续配置割裂，用户需填两次名字 |
