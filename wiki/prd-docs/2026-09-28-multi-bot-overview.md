## 背景与目标
当前 Overview 位于 Bot 选择器下方，仅展示当前 Bot 的资料卡片。创建入口是选择器旁的加号，用户不易发现多 Bot 能力，也无法同时查看多个 Bot。

本次将 Overview 升为全局总览，保留现有账户横幅、产品动态及视觉风格，将 My Bot 替换为 My Bots 卡片区。用户无需逐个切换，即可发现、创建和管理自己的多个 Bot。

目标用户为已订阅、拥有一个或多个 Bot 的个人用户。典型场景包括创建第二个专用助手、检查多个助手状态、进入指定助手工作区、重命名/复制/删除指定助手，以及发现创建失败和未完成配置。

## 范围与非目标
本次包含：全局导航、显式创建按钮、多个 Bot 卡片、目标明确的打开/重命名/复制/删除/修复、创建中及删除中状态、空态与加载态、配额限制、桌面和移动端、国际化。

不包含：团队权限、批量删除、跨 Bot 会话或任务编辑、新套餐、后端多 Bot 机制改造、自动调度多个 Bot、上线发布。已有详细配置页及新手引导沿用现有流程。

## 方案决策
采用“现有总览升级 + 单 Bot 工作区”方案。保留账户横幅和 What's new，仅将中部升级为多 Bot 管理区，并将 Overview 从单 Bot 导航中提出。

备选“总览上方卡片、下方仍显示当前 Bot”改动较小，但全局和局部混杂；备选“仅侧栏常驻列表”虽切换快，仍不能同屏管理。两者不作为本期主方案。

## 功能与交互
### 1. 导航层级
- Overview 位于 Bot 选择器及 Explore/Chat 上方；访问时不依赖 `?bot=` 决定列表内容。
- 选择器下明确标注单 Bot 工作区；快速切换仍保留。
- 点击卡片“打开 Bot”进入该 Bot 的既有配置页面，URL 必须携带实际 Bot ID。
- 返回 Overview 后显示全量 Bot，不因当前选中 Bot 改变可见列表。
- 旧的带 `?bot=` 的 Overview 链接仍可访问，选中目标只影响后续工作区操作。

### 2. 创建入口
- My Bots 标题旁常驻“创建 Bot”文字按钮；列表尾部提供添加卡片，单 Bot 时同样可见。
- 空态保留一个明确的创建动作，避免重复引导。
- 两个入口复用现有引导。空白创建为默认，复制是可选路径；点击指定卡片“复制”预选该 Bot。
- 达到上限仍显示创建入口及具体原因。功能开关关闭时不扩大多 Bot 能力，继续原有单 Bot 体验。
- 套餐、实名、归属、前后端权限和创建数量校验沿用现有契约。
- 不打断现有创建配置流程；完成后回到总览，新增 Bot 出现在真实列表中。配置未完成的 Bot 可继续配置。

### 3. Bot 卡片
- 桌面两列，窄屏一列；不引入横向滑轨。
- 显示真实头像、名称、简介、生命周期状态、定时任务信息及详细管理入口。
- 资料按 `botId + profileId` 隔离读取，读取失败保留列表名称或同一目标的缓存。
- 创建中、删除中 Bot 也应展示，不能沿用仅面向可操作工作区的 `visibleBots` 过滤逻辑。
- 非运行态禁用需要运行时的操作；失败态提供修复及就近错误反馈。
- 通道连接摘要仅在有权威数据时展示。当前 context 的空 `connectedChannels` 不能证明断开，因此本期使用“配置通道”入口，不能伪造 Telegram/飞书已连接或断开。
- 不展示 Demo 中的最近使用时间；当前契约无可靠来源。

### 4. 卡片管理
- 重命名：弹窗明确目标，名称非空、沿用后端限制；请求成功后刷新列表及目标资料，失败保留输入并就近展示错误。
- 复制：打开已有创建引导并绑定所选来源 ID，不能退回“复制当前选中 Bot”。
- 删除：确认框保存目标 Bot ID，输入名称二次确认；主 Bot 需明确提示删除整个 Agent 的影响，存在其他同实例 Bot 时禁止删除主 Bot。失败不移除卡片。
- 修复：绑定失败卡片 ID；请求期间禁止重复提交，结果刷新真实列表。不能改变另一个 Bot 的配置。
- 操作中关闭弹窗或切换工作区不能导致完成结果写入新目标。

### 5. 账户横幅与内容
- 保留现有浅紫横幅、陪伴天数、有效期、积分和工作台统计；积分与工作台保持其现有账户接口口径。
- 定时任务仅在所有 Bot 都有明确 profile、读取全部成功时展示汇总；部分失败/暂停/未知时显示“—”，不将部分和当总数，不以 0 代替未知。
- 定时任务明细从各 Bot 卡片进入对应页面；总览统计不得错误跳到任意选中 Bot 的局部列表。
- What's new 保留在 Bot 列表后；全局页不展示会隐式操作当前 Bot 的推荐自动化模板。

## 状态与异常
| 状态 | 表现与操作 |
| --- | --- |
| 初次加载 | 结构占位，不闪现无 Bot |
| 无 Bot | 一个创建动作，保留订阅/权限前置 |
| 一个或多个 Bot | 展示全部授权范围内的 Bot；明确创建入口 |
| 创建中/删除中 | 保留卡片和状态，禁用不适用操作 |
| 创建失败 | 修复入口；修复失败就近显示原因 |
| 资料/任务读取失败 | 名称回落或“—”；可重试，不能假装空数据 |
| 到达配额 | 保留创建按钮，解释不能创建的原因 |
| 多 Bot 开关关闭 | 保持旧的单 Bot 总览与导航 |
| 初次引导/套餐升级 | 沿用现有完整引导与升级状态页，不被全局页抢占 |

## 影响面与非功能需求
- 前端：`agent-settings-page`、总览面板、新增 Bot 管理区、相关测试和翻译资源。
- 数据/权限：复用 Repository 的 list/create/rename/delete/retry 及现有 profile/cron 读取；无新增权限。
- 性能：仅进入总览时加载卡片资料和任务摘要，任务读取有并发上限，切换或卸载后丢弃旧结果。
- 无障碍：操作使用语义按钮，图标有名称；弹窗具备标题、焦点管理和键盘退出；不可用原因可见。
- 兼容性：沿用现有浏览器要求，验证 390px 与桌面布局；不修改 OpenCraft 镜像。

## 验收标准
1. 国际站进入 Overview 同时看到所有授权 Bot；改变左侧选中项不改变列表范围。
2. 创建按钮无需展开下拉即可看见；点击进入已有创建流程；配额满时不绕过门禁。
3. 卡片打开、重命名、复制、删除、修复均作用于明确的目标 Bot。
4. 主 Bot 删除约束不变；创建中和删除中仍有可见状态。
5. 多 Bot 关闭、初次订阅、创建引导、升级状态不回归。
6. 汇总口径明确；未知数据不显示成 0 或伪造连接状态。
7. 桌面双列、手机单列，无横向溢出，英文及其他现有语言无新增缺失。
8. 通过聚焦组件测试、类型检查、前端 check/test/build 及仓库 context 门禁；任何基线失败单独记录。
