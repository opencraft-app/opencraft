# Product Brief: mono

## 执行摘要

OpenClaw SaaS 是一个面向外部客户的 AI Agent 运行时托管服务。通过将 OpenClaw 实例的部署从传统的"用户自行购买云服务器"模式转变为"购买 Coding Plan 套餐即赠送"的 SaaS 模式，大幅降低用户的使用门槛。

用户无需了解服务器、网络、镜像等云概念，只需手机登录即可在数秒内获得一个开箱即用的 OpenClaw 实例。控制面通过调用沙箱服务 API 管理实例生命周期，底层网络隔离和资源调度由沙箱服务托管。这是腾讯云在 AI Agent 运行时领域的战略跟进产品，对标 KimiClaw、DucClaw 等竞品。

### 架构转型说明（2026-03-19）

原方案为控制面直接调用腾讯云 API 管理 VPC、CVM、安全组等云资源。现改为使用现成的沙箱服务（基于 E2B API），实现了架构大幅简化：
- 不再需要自建 VPC/子网/安全组/CLB/COS 管理
- 创建/销毁从异步编排改为同步调用
- 新增暂停/恢复、超时设置、日志/指标查询能力
- 部分功能不再支持（重启、重装系统、TAT 命令执行）

## 核心愿景

### 问题陈述

当前用户使用 OpenClaw 需要在腾讯云官网自行购买 CVM 实例，整个流程包括：注册云账号、实名认证、选择地域/机型/镜像、配置网络、设置安全组等多个步骤。对于大部分小白用户（特别是开发者和 AI 爱好者），这个流程门槛过高，心理负担重。

### 问题影响

- **用户流失**：潜在用户因购买流程繁琐而放弃
- **支持成本高**：大量用户咨询如何购买、配置服务器
- **竞争劣势**：竞品已提供更简化的 SaaS 化方案
- **市场机会流失**：无法快速触达不熟悉云服务的目标用户群体

### 为什么现有方案不足

| 方案 | 问题 |
|------|------|
| 腾讯云官网购买 | 流程复杂、需要云账号、对小白不友好 |
| 镜像市场一键部署 | 仍需用户有基础的云服务器知识 |
| 竞品 SaaS（KimiClaw 等） | 功能大同小异，但我们缺失这一产品形态 |

### 解决方案

构建 OpenClaw SaaS 控制面服务，提供：

1. **简化的用户入口**：用户购买 Coding Plan 套餐即赠送 OpenClaw 实例，手机登录即可使用
2. **沙箱服务托管**：通过沙箱服务 API 管理实例生命周期，底层网络隔离和资源调度自动完成
3. **完整的生命周期管理**：创建、查询、暂停、恢复、销毁一体化
4. **成本优化**：支持暂停/恢复实例，节省闲置资源成本

### 关键差异化

| 差异点 | 说明 |
|--------|------|
| **零门槛入口** | 挂载在 Coding Plan 套餐下，无需单独购买云资源 |
| **沙箱服务托管** | 底层网络隔离、资源调度由成熟的沙箱服务处理，控制面专注业务逻辑 |
| **成本优化** | 支持暂停/恢复实例，节省闲置资源成本 |
| **快速创建** | 同步调用沙箱 API，数秒内完成实例创建 |

## 目标用户

### 主要用户

#### 用户画像：小白用户 —— "小李"

- **背景**：对 AI Agent 感兴趣的普通用户或企业员工，技术水平较低甚至完全不懂技术。可能从社交媒体、朋友推荐或科技新闻中了解到 OpenClaw，想要尝试搭建自己的 AI Agent
- **动机**：想拥有一个属于自己的 AI Agent 运行环境，但不想（也不会）去处理服务器、网络、镜像等复杂的技术问题
- **当前痛点**：在腾讯云官网面对各种技术概念（CVM、VPC、安全组、镜像等）一头雾水，购买流程走到一半就放弃。即使成功购买了服务器，还需要自行配置 Coding Plan 和消息通道，门槛极高
- **成功标准**：手机登录 → 购买套餐 → 数秒后获得一个开箱即用的 OpenClaw 实例，全程无需理解任何云服务概念

#### 用户画像：企业用户 —— "张经理"

- **背景**：中小企业管理者或技术负责人，希望为团队引入 AI Agent 能力，技术水平一般
- **动机**：希望快速在企业内部署 AI Agent 来提升效率，可能需要多个实例
- **当前痛点**：评估过自建方案，但团队缺乏云运维能力，时间成本高
- **成功标准**：能快速获得可用的实例，后续可根据需要增加实例数量。支持暂停/恢复实例以优化成本

### 次要用户

#### 内部运维/运营人员

- **角色**：负责 OpenClaw SaaS 平台的日常运维和监控
- **需求**：监控实例状态、资源使用情况、异常告警、日志查询、可观测性
- **优先级**：低于核心购买流程，但基础的监控和可观测性需要在 MVP 中考虑

### 用户旅程

```
用户了解 OpenClaw → 搜索/访问产品页 → 手机号注册登录
    → 选择 Coding Plan 套餐 → 完成支付
    → 系统后台自动创建实例（同步调用沙箱服务 API）
    → 用户等待数秒
    → 获得可用的 OpenClaw 实例 + 访问入口
    → 开箱即用，开始体验 AI Agent
```

**关键 "aha!" 时刻**：用户完成支付后，无需任何技术操作，数秒内就看到自己的 OpenClaw 实例已经就绪，直接可以使用。

**注意**：当前控制面只负责"创建实例"到"实例就绪"这一段后端 API 逻辑，前端 UI、套餐购买、用户中心等由其他模块负责。

## MVP 范围

### 核心功能（P0）

| 功能 | 说明 |
|------|------|
| **实例创建** | 接收创建请求 → 配额检查 → 同步调用沙箱服务 API → 实例就绪 |
| **实例查询** | 查询单个实例状态和详情 |
| **实例列表** | 按用户批量列出所有实例 |
| **实例销毁** | 调用沙箱服务 API 销毁实例，释放配额 |
| **实例暂停/恢复** | 暂停实例节省成本，恢复实例继续使用 |
| **用户配额管理** | 控制单用户最大实例数量 |

### 次要功能（P1）

| 功能 | 说明 |
|------|------|
| **实例超时设置** | 设置实例自动过期时间 |
| **沙箱日志查询** | 查询实例运行日志，辅助问题排查 |
| **业务指标暴露** | Prometheus 格式暴露创建成功率、实例状态分布等指标 |
| **操作历史记录** | 查询实例操作历史，支持审计追溯 |

### MVP 不包含（Out of Scope）

| 功能 | 原因 |
|------|------|
| **实例重启** | 沙箱服务不支持 |
| **实例重装系统** | 沙箱服务不支持 |
| **一键更新（命令执行）** | 沙箱服务无命令执行 API |
| **Template 管理** | 运维侧概念，通过内部工具/CI 流程管理，非控制面职责 |
| **池化预创建** | 已规划但非首期（Phase 2） |
| **API 鉴权** | 上层平台负责，不在控制面范围内 |
| **前端 UI** | 其他团队负责 |
| **用户中心/登录/套餐** | 已有平台，不在当前范围 |
| **计费系统** | 上层平台负责 |
| **运营后台** | 低优先级，后续迭代 |

### MVP 成功标准

- 完整走通"创建 → 查询 → 暂停 → 恢复 → 销毁"生命周期
- 实例创建成功率 ≥ 99%
- 创建耗时 ≤ 30 秒
- API 可用性 ≥ 99.9%
- 支撑 200 个用户的实例管理

### 未来愿景

| 阶段 | 能力 |
|------|------|
| **Phase 2：池化加速** | 预创建沙箱资源池，实现毫秒级实例分配 |
| **Phase 3：运营能力** | 运营后台、批量管理、数据报表 |
| **Phase 4：弹性扩展** | 多规格支持、更丰富的实例配置选项 |
| **Phase 5：生态集成** | 更多 AI Agent 运行时支持 |
