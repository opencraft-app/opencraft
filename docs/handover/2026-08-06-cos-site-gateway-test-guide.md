### 怎么登录

测试环境没有接入正常的登录流程，需要手动塞一个 token 进浏览器：

1. 打开 https://lightclaw.pages.dev/

4. 刷新页面，就登录进去了

## 二、每个账号能用多少

这是从环境里实际读出来的数字，不是拍脑袋写的：

| 项目 | 额度 |
|---|---|
| 同时存在的站点数 | **1 个** |
| 单次上传的产物包大小 | ≤ 20 MB |
| 单个站点的文件数 | ≤ 500 个 |
| 站点存储总量 | 5 GB |
| 每月访问流量 | **10 GB** |

**「1 个站点」是同时存在的数量，不是一辈子只能建一个。** 把旧站点删掉，名额马上就还回来（实测 5 秒内），可以接着建新的。所以想试第二个创意，先删掉第一个就行。

**这一期开始，每月流量额度是真的会生效的。** 当月访问流量用满 10 GB 后，站点会自动停止对外服务，访问者看到「本月流量已用尽」，下个月自然恢复，期间站点文件一个字节都不会被删。正常试用碰不到这个量，但如果你把链接大范围分享出去、或者页面里放了大图大视频，是有可能撞到的。另外从真正超额到实际拦住有大约 90 秒的延迟，所以最终统计到的用量会比额度略高一点，这是预期内的。

## 三、建好的网站长什么样

建站成功后会拿到一个这样的地址：

```
http://ws-0b27ed9b1ba73580.sites.lightclaw.tech/
```

前面那串 `ws-` 开头的是站点编号，系统自动生成的。

### 注意：现在是 http，不是 https

地址开头是 `http://`，浏览器地址栏可能会显示「不安全」的提示。**这是预期内的，链接可以正常点开，不会打不开。**

原因很简单：这套子域名需要一张泛域名证书，证书这条线还在收尾，没配好之前先用 HTTP 让大家能正常试用。证书到位后会自动切成 `https://`，届时无需任何改动，链接形式也不变。

试用期间可以放心把链接发给别人看，只是**别在上面放任何真实的敏感信息**（原因见文末）。

### 发布后第一次访问，可能要等约 10 秒

上传完产物后立刻点链接，有可能看到 404。**等 10 秒左右再刷新一次就好了。**

这是发布流程里的一个已知延迟（后台任务有个重试节奏），不是发布失败。如果等了 30 秒还是 404，那才是真出问题了，请反馈。

## 四、能测什么

### 1. 基本的建站流程

- 建站 → 上传网页产物 → 打开链接看效果 → 删站
- 子路径能正常访问：`/about/` 和 `/about` 都能打开 `about/index.html`
- 站点自带的 `404.html` 会在访问不存在的页面时自动生效

### 2. 静态站点的各种页面形态

- 单页 / 多页：多页请用 hash 路由（`#/about`）或真实的 `.html` 文件
- 条件请求：同一个页面第二次打开会命中 304，不重复下载
- HTML 每次回源校验（重新发布后刷新就能看到新内容），其他静态资源有短缓存

### 3. 站点之间是隔离的

每个站点只能读到自己那份文件。想验证的话，可以在 URL 里拼各种 `../` 试图读别人的站点，
结果都会是 404，不会串站。

## 五、已知限制（**请务必看完这一节**）

这些不是 bug，是这套方案当前阶段的能力边界。提前知道边界在哪，就不会做到一半发现做不下去。

### 最重要的一条：这是纯静态托管，存不了任何数据

平台只做一件事：你上传什么文件，访问时就原样返回什么文件。**没有数据库、没有后端接口、
没有任何可以保存数据的地方。**

所以下面这些**当前一律做不了**：

- 留言板、评论区、聊天室
- 表单收集：报名、问卷、预约、询价、意见反馈
- 访问计数器、点赞、投票、抽奖
- 待办清单、记账本，任何"下次打开还在"的记录
- 电商下单、库存、支付
- 账号注册登录、用户中心、后台管理

**⚠️ 让 AI 生成页面时要特别留意这一点。** AI 很容易用浏览器本地存储
（localStorage）糊一个"看起来能用"的留言板：你自己在电脑上点一点，提交、显示，一切正常，
于是以为做好了。但它是**每台设备、每个浏览器各存各的**——你把链接发给同事，
对方打开是空的；你换手机打开，自己写的也不见了；清一次浏览器数据，全部消失。

也就是说那不是"功能弱一点"，而是**根本没实现你要的那件事**，而且要等真的用起来才发现。
测试时如果拿到一个能提交的表单或留言板，**请换一个浏览器（或手机）打开同一个链接确认一下**，
数据不在就是这个问题。建站 Skill 已经明确禁止 AI 这么做，如果还是出现了，请反馈。

碰到这类需求，可行的替代是：表单收集改成嵌入第三方问卷（问卷星、腾讯问卷）；
留言板改成展示页 + 留联系方式；电商改成商品展示页 + 询价。

### 适合测什么

个人主页 / 简历、产品与服务介绍页、落地页、作品集与图片展示、活动介绍页、
文档站、导航页——即"内容在发布时就确定、访问者只读"的场景。这类站点的效果、
排版、配色、响应式表现，都值得好好试。

### 其他限制

- 站点内容是公开的，任何人拿到链接都能看。**别放任何真实的敏感信息。**
- 多页面不能用 History 模式路由（`/about` 这种直接改地址栏的），
  子页面刷新会 404。用 hash 路由或真实的 `.html` 文件。
- 站内用不了需要 HTTPS 才能开放的浏览器能力（地理位置、摄像头、Service Worker），
  因为当前还是 http。

## 六、遇到问题怎么办

反馈的时候，请尽量带上这几样东西，能省掉大量来回确认的时间：

1. **你用的是哪个测试账号**（User 1 ~ User 6）
2. **站点地址**（那个 `http://ws-xxxx.sites.lightclaw.tech/` 的完整链接）
3. **具体哪一步出的问题**，最好有截图
4. 如果是页面上的报错，按 `F12` 打开开发者工具，把 Console 标签页里红色的报错信息一起截图

反馈渠道：直接在项目群里 @ 相关同学，或者找虾米老师。

几个常见情况可以先自查：

| 现象 | 先试试 |
|---|---|
| 刚发布完，打开是 404 | 等 10 秒刷新一次 |
| 浏览器提示「不安全」 | 正常的，见上文「现在是 http」那一节 |
| 建站按钮点了没反应，提示配额不足 | 你的账号已经有 1 个站点了，先把旧的删掉 |
| 站点一直停在「删除中」超过 1 分钟 | 这是异常，请反馈站点编号；后台有专门的恢复手段可以把它推完，名额会还回来 |
| 登录不上 / 一直跳回登录页 | 确认 token 粘贴时没多空格，粘完要刷新页面 |
| 表单/留言提交后换个浏览器打开是空的 | 这是预期的：平台存不了数据，见「已知限制」第一条 |

## 附：本文档的验证依据

这份说明里的每个数字和结论，都来自 2026-08-06 在测试环境上跑的完整验证：建站 → 上传产物 →
公网访问（HTTP 200）→ 子路径与自定义 404 → 删站 → 公网转 404 → 配额归还 → 二次建站成功。
额度数字取自接口实际返回值，不是抄的配置。

2026-08-06 傍晚随「站点收缩为纯静态托管」重新跑了一轮完整回归，20 项断言全部通过：
建站、发布、首页 200、子路径 200（带斜杠和不带斜杠）、不存在路径落到站点自带的 404、
静态路径的 POST/PUT/DELETE 一律 405（响应头 `Allow: GET, HEAD`）、删站后公网转 404、配额归还。
同时确认原先的数据面路径 `/__vela/data/*` 已经完全消失：GET 返回 404（走普通静态回源，
不再有特殊分支），写方法返回 405。

2026-08-06 夜间又补做了一轮流量与存储用量的验证：实际访问产生的流量、实际上传占用的存储，
和系统记下来的数字都精确吻合到字节，没有多算也没有少算；把额度临时调到低于已用量之后，
站点会按预期停止对外服务、访问时提示本月流量已用尽。
也就是说上面那张额度表里的数字是真会被执行的，不是摆设。
