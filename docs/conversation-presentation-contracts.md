## Tool Call 建模边界

协议层只提供权威事实，`chat-core` 将事实投影成平台无关的 Activity presentation，Web/RN 再选择图标、布局与可交互表面。

```text
Host AppServer Item
  -> TimelineBlock（事实、稳定 id、状态、输入输出、错误、耗时）
  -> ToolActivityPresentation（grouping、文案状态、是否可展开）
  -> Web / Native Activity renderer（测量、动画、字体、hover）
```

Skill、MCP App widget、可视化等外部领域向 `ToolActivityPresenterRegistry` 注册语义，并通过 `renderToolCallContent` 提供产品专属 body。注册表同样参与 `createAssistantTurnPresentationPlan` 和 Activity summary，所以插件不会出现“单行标题对了、外层分组仍错”的裂缝；注册和卸载是可订阅的。它们不能改变普通 MCP、命令、补丁、搜索和 Agent Activity 的核心状态机。携带 App resource URI 的 MCP 调用先标为 `standalone`，普通调用标为 `groupable`。审批 UI 只产生平台无关的 `WorkbenchInteractionAction`；唯一的协议映射器将其转换为 AppServer V2 response，因此 Web、Electron 和 Expo 不会各自猜一次协议。target item 仅用于把 pending 状态与工具执行关联，不能决定完整卡片的 DOM 归属；完整卡由 pending-request selector 选择并替换 Composer body，这一层与现有契约 的 `PendingRequestPanel → ApprovalRequestPromptRouter` 同构。

Expo/RN 不再把这些事实重新压成通用 JSON 卡片。它和 Web 共同消费 `createAssistantTurnPresentationPlan`、`ToolActivityPresentation`、`ToolCallContentPart`、聚合后的 Subagent Activity 与 `request_user_input` answer model；同一个 `ToolActivityPresenterRegistry` 同时参与两端分组和标题汇总，Web 的 `renderToolCallContent` 与 Native 的 `NativeToolCallContentRenderer` 只提供平台 body。平台层只实现触摸披露、图片/资源表面和 iPad Token，并通过同一个 typed AppServer adapter 回传交互。该边界已通过 Expo Web 导出与 iOS Metro bundle。
