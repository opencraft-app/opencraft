# 原生 Pi 命令行接入

Agent 管理中的 **Pi** 连接目标机器安装的 `pi` 命令。它与使用 OpenCraft 模型配置的
随包 Pi SDK 引擎分开：原生接入使用 `pi-cli:` 模型和 `picli_` 会话；已有 `pi_`
SDK 会话继续由原 owner 执行，不迁移配置或凭据。

## 本机与 Bash 接入机器

两条路径运行相同的 Local Agent Host、发现逻辑和执行 adapter。在要执行任务的机器上
安装 Pi（已有安装可以复用），运行 `pi` 配置模型或完成登录，再回到该机器的 Agent
管理点击重新检查并选择模型。安装入口使用 `@earendil-works/pi-coding-agent`；
配置命令必须在目标机器执行，本机登录不会替远端登录。

Bash 接入安装器和更新包包含这一 adapter，不内置另一份原生 CLI，也不复制本机
账号。已有机器通过其 `opencraft-machine --update` 更新后获得接入能力；这与升级
机器上的 Pi CLI 是两个操作。详见[个人机器接入](personal-machines.md)。

Host 按 PATH 和已有安装位置发现 CLI，排除本仓库自身 `node_modules/.bin/pi`，
避免开发工具注入的随包 SDK 命令遮蔽用户安装。认证与资源配置仍由 Pi 的原生
`PI_CODING_AGENT_DIR`／默认用户目录及工作区资源持有，OpenCraft 不复制密钥。
模型表可读仅表示发现成功，不保证外部提供方实际授权有效。

## 会话与能力

每个会话拥有独立原生 RPC 进程和实际工作目录，模型与思考档位由 Pi 确认。
图片能力按模型声明，发送前再次核对当前原生模型；不静默移除附件或更换模型。
接入沿用已连接原生 Agent 的 Full access 权限，不声明其他权限档或服务等级。
工具由原生 Pi 执行；不向它注入尚未实现的 Host 工具，未接通的扩展交互对话会取消。

原生 Pi 是 JSONL 历史的唯一写入者。通过 OpenCraft 创建的原生会话保存在 Host
私有 `connected-agents/pi-cli/native-sessions` 目录，Worker 读取会话图的当前分支，
保留图片、思考和工具结果。重新打开历史不启动推理进程。导入入口也读取目标机器
原生 Pi 配置目录下的 `sessions`，按原始文件与工作目录续接终端会话，不复制历史或
改成新提示词；无法确认原生身份、文件或工作目录时拒绝续接。导入不声明原生分支、
编辑或压缩操作。

输入确认与执行完成分开：RPC 接收消息后仍等待原生执行结束；停止走原生 abort，
执行中失联保留未知结果，不自动继续或重放。配置了执行沙盒时复用共享沙盒命令入口，
配置错误拒绝启动，不回退为未隔离本机执行；未配置的 Host 不声称已隔离。

## 验证边界

本次实际验证本机安装的 Pi 1.5.2：读取用户原生目录的四个模型；另用隔离配置和
本地模拟模型服务验证图片到达、Bash 工具、停止后子进程退出及无进程历史恢复，
没有调用用户的外部付费模型。协议测试还覆盖完成先于 ACK、重试、会话隔离、断线
不重放及错误沙盒配置。真实 Linux cgroup、远端 Pi 安装／账号和 Electron 安装包
不属于这组实机证据。
