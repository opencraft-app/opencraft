# OpenCraft 运行观测 V1 验收矩阵

对应 [平台规格 V1](observability-platform.md)。本文件定义未来实现的通过条件，**当前所有功能性、非功能性运行验收均为 not-run**。文档验证不改变这些状态。

验收等级：以下 F/NF 均为 V1 必须项；能力级 unsupported 的适用范围以规格声明为准，不能把必需项改成 unsupported 求通过。目标部署还须完成其私有装配验收。模拟与受控故障用于证伪，最终须有真实安装包、查询、浏览器及维护 Agent 的消费证据。

## 测量约定

- 每次运行固定 runId、UTC 窗口、源码/构建/运行组件身份、查询定义版本、metric schema、镜像 digest、硬件/浏览器和工作负载摘要。源码与运行版本分别记实。
- 冷导航、页内切换、缓存状态、前后台、合成/真实来源分开；开始计时之前的工作不能事后混进同名结果。
- 延迟报告至少有原始样本、样本数、中位数与 nearest-rank 样本 p95；小样本不代表总体 P95。失败、超时、未决、探针损失保留。
- NF 对照至少 20 个同工作负载配对样本，交错启用/关闭顺序，保留预热规则；CPU/内存场景另按条目时长执行。不能只挑较快的一轮。
- 允许隔离账号、测试 Host 和现有回放夹具；禁止中断共享执行、重发用户消息、清业务数据或制造全站故障获取样本。
- 物理手机和真实模型计量是独立范围；浏览器尺寸/CPU 模拟、协议替身、人工 hold-promise 都要标注。

## 证据清单与状态规则

实现方须产出一份机器可读验收清单，字段至少如下；示例中的 not-run 是状态示意，不是运行结果：

```json
{
  "specVersion": 1,
  "runId": "example-not-run",
  "target": "configured-reference-deployment",
  "window": {"from": null, "to": null},
  "components": [],
  "queryDefinitionRevision": null,
  "workload": {"kind": "not-run", "digest": null},
  "results": [
    {"id": "F-01", "status": "not-run", "evidenceRefs": [], "limitations": []}
  ],
  "remaining": ["all functional, nonfunctional and target-deployment checks"]
}
```

- 每个 F/NF 和目标部署项都须恰有一条结果；禁止漏项、把 skipped 当 pass或用一张总截图代替证据。
- 状态仅为 not-run、running、pass、fail、blocked；blocked写技术原因及下一步，不当成已通过。
- pass 必须绑定本次真实组件/构建和可读取证据；有关变更后旧结果不自动继承。未变化部分可复用但须写明来源版本及适用性。
- 失效/缺失/不足样本的比较可正确返回 inconclusive；其“诚实判定”测试可以通过，但不能据此声称优化效果通过。
- 最终交付给出安装入口、Grafana入口、CLI/Skill使用示例、实际组件身份、全部适用项结果、未覆盖范围及回退位置。目标部署未完成时只能称规格或阶段交付。
