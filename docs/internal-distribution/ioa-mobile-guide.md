# IOA 手机扫码入口

本批将手机引导功能纳入本仓库 `products/join/plugins/tencentoa`，由根 workspace 和锁文件统一构建。通用手机图标和公告国际化支持已在核心祖先提交中，不重复导入。来源为旧候选 de1244d6，仅移植插件源码、文案、测试及文档；旧产品锁文件和旧仓库环境配置不纳入。

手机引导使用现有公告窗口。当前实现以同源 iframe 打开当前真实工作区的正式应用入口，投影临时手机触控布局；聊天、终端、文件与概览全部沿用正式代码。二维码在浏览器内编码同一工作区路由，只保留 hostId/draftId，手机仍需正常登录与准入；不传递桌面凭据。已登录的桌面浏览器首次自动打开，内嵌工作区不注册引导，避免递归。展示记录位于当前站点 localStorage，关闭后不重复提醒，仍可从侧栏手动打开。功能和状态规则见[插件说明](../../products/join/plugins/tencentoa/README.md)。

本批新增的 qrcode 及其浏览器依赖全部编入前端资源，不新增服务端外部依赖、接口或数据库。发布仅替换从固定 env/local 提交构建的完整 Web 产物，保留现网 Gateway 程序、Brain/Hands、群聊和身份装配；manifest 分别记录 Web 来源和保留组件来源。

验证包括 IOA/Web/公告两端类型检查、插件/公告聚焦回归、完整产品 Web 构建，以及同一 WorkbenchRoot 和正式应用产物的父子页面烟测，候选需检查首开、关闭、刷新、手动重开、扫码与预览切换保持工作区、触控端抑制和主题。原有 hover 检查在未修改的 button.tsx:91 有基线失败，独立平台边界检查另行执行。发布沿 fast-release 锁、独立监督器和失败回退，实际运行结果记录在本机发布回执中。

面板采用上方二维码/交互预览、下方标题与一句说明的组合。底部提供关闭和手机扫码；二维码在预览区域内切换，iframe 在用户首次进入预览后保留，扫描时通过 inert 和 visibility 退出交互与无障碍树，不重建会话或清空输入。扫码和预览共用同一几何空间，窄/短窗口可滚动到操作区。加载边界仍由 ModalHost 统一持有。

面板默认展示二维码和“用微信扫一扫，打开当前工作区”。二维码由产品侧本地生成，使用 H 纠错级别，中央微信标识直接绘入 PNG；标识资源失败时降级为可扫描的普通二维码。首次打开不启动内嵌工作区，点击手机预览才创建 iframe，后续往返切换保持同一实例。二维码生成和解码检查覆盖首页及带 Host/草稿参数的会话链接。
