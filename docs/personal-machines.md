# 个人远程机器接入

当前接入入口在本地开发 Workbench 的「设置 → 模型/Agent 配置 → Agent 配置」，点击左侧目录上方的“＋”接入远程设备。
页面的 Agent 配置在前、模型配置在后；左侧选择 Agent，右侧配置接入状态与导入会话。
首次 Agent 接入页和旧导入会话页仍可进入远程命令表单，不需要先选本地模型。
点击「生成 Bash 接入命令」，命令自动包含当前 Server 地址及私有配对凭据，无需填写 URL；
经已有 Server 选择入口访问时，沿用当前目标 Server 的 admission origin，不把浏览器入口误当作另一个 Server。
在 Linux/macOS 的 x64 或 arm64 机器上执行。命令在 15 分钟内有效，只能认领一台机器。
机器归当前本地 human Actor 所有，暂用于 `myself`，不授予其他 Server 的成员权限。

接入后点击「查看 Agent」，该设备上的 Agent 会进入左侧同一目录并标记“远程”；选择后在右侧进入项目文件夹和会话导入，不切换当前聊天设备。
Codex/Cursor 的安装、登录、原生会话和工作目录都留在远端；接入过程不复制本机凭据。
Pi 同样通过这台机器的标准 Host 接入：在远端安装并运行 `pi` 完成配置，重新检查后
选择模型。新增支持随伴随程序更新，不要求生成另一套 Bash 认领命令；原生 CLI 与
伴随程序分别升级。能力和原生历史边界见[原生 Pi 命令行](native-pi-cli.md)。
历史导入也复用该 Host：Codex、Cursor、Pi、Claude Code 和 CodeBuddy CLI 读取目标
机器的原生会话，CodeBuddy IDE 读取该机器已接入 IDE 的当前账号和项目。CLI 和 IDE
不共用一份历史；IDE 还需新版桥接扩展。不会把本机历史或账号复制到远端。
发送消息仍由该机器的标准 Local Agent Host 和已有执行引擎处理。
机器离线会显示离线，恢复连接不会重放发送过的消息。
「撤销接入」会先持久撤销凭据，再关闭现有连接；不会删除远端原生会话。

安装器会验证源码归档的 SHA-256，复用现有的依赖安装、DSH 准备和 bridge 构建。
需要时会下载并校验固定的私有 Node 26.7.0，不替换系统 Node。
安装可能需要几分钟，依赖网络和构建环境。源码包由本地部署的 Git index 快照生成，
不是 npm/GitHub 正式发行版；开发改动须先进入 index，重启 `npm run dev:local` 后才能进入安装归档。

伴随进程主动连接 OpenCraft，远端不需要开放公网端口。
Linux 优先使用 systemd user service；不可用时及 macOS 使用后台进程，安装器明确报告
未配置重启后自动启动。远端安装完成会打印该机器专属 `opencraft-machine` 路径，
支持 `--status`、`--stop` 和 `--install`（重新启动）。本地控制经 owner-only Unix socket，
接入凭据保存在 `~/.opencraft/machines/<id>/connection.json`，权限为 0600。

## 部署边界

此轮只在 `scripts/dev-local.ts` 显式启用本地 owner 的入口，未在多用户 Headless 或
Electron 安装包启用。不能将一个部署的所有用户映射成这个本地 owner。

HTTPS 入口必须原样转发 `/__opencraft_machines/install.sh`、`source.tgz`、`enroll` 以及
`/__opencraft_relay/control`、`data`，支持 WebSocket，并保留各请求自己的 bearer。
安装脚本可读不代表可认领；下载源码、认领和反向连接分别校验配对或机器凭据。
不得为接入而把注入 owner token 的开发 Workbench 或 `/status`、`/<id>/rpc` 公开成匿名入口。
需要浏览器额外登录的 BB Connect 分享链接无法直接作为无人值守安装地址。
当前运行的 loopback 预览可用于开发测试，跨公网接入还需要配置这样的 HTTPS 入口。

## 实现复用

新加的是 owner 认领、私有登记和安装服务；连接复用 `connectRelay`/Relay control-data
帧、`relayDuplex` 与 LocalIngress。反向流直接进入进程内 ingress，只有 `/rpc` 可到达
持有私有凭据的原生 Host。Workbench 从服务端只读投影 Host profile，沿用既有
Host 选择、Agent 发现和历史导入；不在浏览器保存另一份可写机器登记。

## 单 owner HTTPS 中转接线

本地开发部署读取数据目录中权限 0600 的 `machine-relay.json`，含 schemaVersion、
origin、credential 和 ca。它只授权一个 dedicated relay 的个人机器入口；不是用户注册或
多租户账号。Server 主动连接中转的独立 control/data 路径，本机不新增公网监听。
中转和本地 ingress 都只允许安装、源码下载、认领及机器 control/data；不转发
Workbench、owner status/RPC、Hub 管理或更新路径。请求原有配对/机器 bearer 不替换。
生成前仍通过 HTTPS 探测对应 Server 的 hub ID；中转离线时不得生成不可用命令。

私有 CA 随生成命令固定，用于 curl、下载、认领和持续连接的正常 TLS 验证，不使用
`--insecure` 或关闭全局证书校验。中转发布密钥留在部署配置，不进入 Bash 配对命令。

## 短命令

受信任 HTTPS（或明确内网）入口生成「安装脚本 URL + 43 字符配对 key」命令。
安装器通过 Authorization bearer 领取 Server 保存的 hub ID、机器 ID 与源码摘要；
不把 key 放到 URL、访问日志或公开安装脚本。配置领取端点同样检查未认领、未过期、
未撤销状态。私有 CA 部署保留显式证书命令作为兼容路径，不能靠关闭 TLS 验证缩短。

## 更新与恢复

伴随进程通过受支持的更新命令升级，不要求用户编辑 systemd、替换脚本或重新认领。
新安装完成后，机器目录下的 `opencraft-machine` 支持：

- `--check-update`：检查更新，不停止当前运行版本。
- `--update`：后台下载、校验并准备新版本，再短暂重启伴随进程。
- `--rollback`：切回保留的上一程序版本；不回滚会话数据。
- `--recover`：恢复中断的版本切换；未知停止结果不会自动重放更新。

早期已安装版本尚无这些参数，可再次运行原 Server 的官方安装脚本并传 `--update`。
脚本优先复用已安装且版本匹配的私有 Node，不因登录 shell 缺少 Node 而重复下载。
脚本读取当前账号下已认领的 connection.json，无需配对 key；多台安装时在参数后指定
机器 ID。它只更新对应伴随进程拥有的运行文件和服务入口，不更改原生 Agent 安装、
账号或原生会话。认证/源站、机器 ID、hub ID、源码 SHA-256 和归档路径均校验。
已撤销机器不能下载更新。工作目录错误导致旧进程离线时，也能使用该入口完成升级。

新版本在机器目录的 releases 下独立准备，准备失败不停止旧版；切换前记录恢复日志。
只在新版连接就绪后提交成功，保留上版供回退。并发更新互斥，中断后走 --recover。
此处是程序包更新加受控重启，不是向运行中的模型会话注入新代码；正在执行的工作
应先完成再更新。更新不会擅自恢复历史输入。涉及不向后兼容的会话存储升级须另行
设计迁移/恢复，不得把程序回退宣称为数据库回退。

服务注册在替换现有 unit 前使用 systemd-analyze --user verify 校验候选文件。
WorkingDirectory 路径值与 ExecStart 参数分别编码，不共用带双引号的命令参数转义。
若旧更新在坏 unit 上中断，重新运行官方 --update 会先恢复已记录的旧运行文件，
不强制启动已知故障的旧版，再准备最新版。只有 systemd 确认 inactive/failed 时才跳过
重复 stop；活动或未知状态仍须确认停止，不能吞掉未知生命周期错误。

完整生命周期烟测在独立、可丢弃的已升级测试机上运行：
`node scripts/smoke/execution/smoke-personal-machine-lifecycle.mjs --state <机器目录> --allow-mutating-test-machine`。
它执行真实手动回退、再次升级和故意启动失败后的回退，并校验连接、身份配置与测试数据。
不得在用户生产机器运行此测试；初次安装、A→B 升级和整机重启还须在真实 user service 下分别验证。


## 机器在线与浏览器连接

设置页的机器在线状态来自 Server 对伴随进程反向连接的观测，与当前浏览器是否打开
该机器的 Host 会话分开。浏览器尚未连接时，机器仍可显示在线；连接详情显示「尚未连接」。
该观测只作为实时目录投影，不保存为机器配置、不改变 Host 配置版本，也不代表模型
或执行权限已就绪。打开机器仍走现有用户操作与连接流程。

点击「打开」进入机器详情时，会连接该机器的工作台并显示连接进度；失败时可重新连接。
连接后直接显示该机器上 Codex、Cursor 等 Agent 的实际检测结果和已有管理操作，不切换
当前聊天使用的机器，也不自动安装 Agent 或发送模型请求。连接短暂中断时保留已打开的
Agent 管理内容。此类反向接入的机器显示「通过当前 Server 连接」，不把内部代理地址
当作远端服务器地址展示。


## Codex 会话目录

新版伴随服务优先在历史 Worker 中只读查询 Codex 的原生 state 索引，使用会话名称与
创建／更新时间；旧版名称兼容 session_index.jsonl。活动和归档分开分页，排除原生子
Agent 上下文线程，不以首条长提示词冒充会话名称。没有原生索引时保留 ACP 列表兼容
路径，不对旧 Host 声称支持归档筛选。100 条是单次导入上限，界面会继续读取后续页。
列表支持搜索、更新／创建排序和原生目录提供的归档筛选；筛选不清空已有选择。
远端服务更新后才会返回新版名称、日期与完整原生目录，单独刷新网页不会更新远端读取器。


## 导入后的侧栏与新对话

已认领且在线的个人机器会自动读取会话目录，刷新网页后也能看到已经导入的记录；
这只读取元数据，不自动恢复原生会话或发送输入。没有原生项目分组的远端记录，侧栏
按真实工作目录与机器身份分组显示，保留原始时间。该分组属于界面，不写回为 Codex 项目。
已有目录缓存会保留来源路径；老缓存缺少路径时等待当前 Host 成功读取后补齐。

当前所选 API 模型未配置、但有已安装登录且提供可选模型的 Agent 时，新对话页提供
「使用 Agent · 机器」入口，不要求重复接入。仅有机器在线或旧模型缓存不能证明
Agent 可用；选择后通过原有工作台切换流程保留草稿，不会自动发送消息。

### 多个 Codex 数据目录

若本机保留了多套 Codex 数据，导入页提供「Codex 数据目录」选择，显示真实路径。
读取器会发现用户目录下的 `.codex`、`.codexl` 等原生会话目录；仅有数据库、没有
会话目录的辅助存储不会作为另一套会话导入。浏览优先展示有原生名称索引的数据源。
不同来源分别分页和计数，导入时保存来源绑定；续接使用对应 `CODEX_HOME`，即使
两个目录有相同会话 ID 也不会混用。已导入的默认目录会话保持原绑定。
此能力需要机器伴随服务支持数据源发现，旧版本会提示重试或更新。

侧栏有多个实例时按「实例 → 工作项目 → 会话」展示；只有一个实例时省略实例层。
实例使用机器身份分组，各连接的原生项目或真实工作目录仍保留各自归属。

“接入远程机器”由当前 OpenCraft 部署的接入管理端负责，独立于聊天中选择的执行机器。
即使当前使用远端 Codex，查看接入列表、生成命令和撤销接入仍经部署 owner 的认证端口；
不会把管理请求发送给那个远端伴随服务，也不为打开接入页自动切换聊天机器。
