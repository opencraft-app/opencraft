# 事项画布原型

一个不依赖构建的 HTML 原型：老板的工具，版式照聊天应用，一次只看一屏。底部三个标签：

- **事情**：一张待办清单。可以随手添加一件事；每件事可以分配负责人，没做完之前都能换人。点进去看现在差什么、负责人、进度、参与的人和交出的材料；轮到老板时，按钮在最上面。做完的事打勾沉到「已完成」。
- **员工**：全部 Bot，手上有事的排在前面。可以管理：改岗位和岗位提示、让他停工或回岗、在他的手机里决定他能联系谁、新增员工、把没事在身的移出团队。也能看他的手机（聊天记录）和电脑。电脑是 Codex 式的页面：任务列表，底部可以直接派一件事；点开一个任务有四个面板：对话（谁交办的、处理了哪几步、交出什么文件）、文件、浏览器、云电脑。
- **动态**：谁刚说了什么、做完了什么、老板把哪件事交给了谁，最新的在上面。

直接用浏览器打开 `index.html` 即可，电脑和手机都能用。全部是本地模拟，数据存在浏览器的 localStorage 里。

| 文件 | 负责 |
|---|---|
| `scenario.js` | 场景数据：Bot、联系方式和三件示例事情的步骤 |
| `engine.js` | 运行时：按步骤产生事件，状态由事件归并得到；不依赖 DOM |
| `app.js` / `styles.css` | 界面：三个标签和它们的下级页面 |
| `engine.test.mjs` | 引擎测试：`node --test examples/matter-canvas/engine.test.mjs` |

自己添加的事只有两步（负责人处理、老板验收）。浏览器和云电脑两个面板只是占位，没有接通真实的浏览器或云桌面；任务里的处理步骤是从事件推出来的示意。停工和发送许可会真的影响事情的推进；岗位和岗位提示目前只是保存和展示的文字。文案直接写在源码里，没有接入 Workbench 的国际化和设计系统。
