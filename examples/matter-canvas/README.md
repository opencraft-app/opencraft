# 事项画布原型

一个不依赖构建的 HTML 原型：老板的工具，版式照聊天应用，一次只看一屏。底部三个标签：

- **事情**：一张待办清单，分「要我出手的」和「别人在办的」，办完和取消的收进「已结束」一行。可以随手添加一件事。点进去只有五样：状态和一句话、轮到我时的按钮（分配、确认或退回）、负责人、子事情、经过。经过只列已经发生的事，交出的文件直接从经过里点开。换负责人和取消收在右上角「更多」里。员工自己推进事情；谁派的谁验收，所以子事情不进老板的清单。
- **员工**：先看手上有事的人，其余在「全部员工」里，那里也能新增。名片只有五行：他在联系谁、他能联系谁、他在做什么（Codex 式的任务页，可直接派一件事）、允许他做什么、岗位和提示。临时工「留下」和「移出团队」收在右上角「更多」里。
- **动态**：谁刚说了什么、做完了什么、老板把哪件事交给了谁，最新的在上面。

产品规格见 [OpenCraft Agent 公司：产品规格](https://claude.ai/artifact/A6P4C4qMKGZ5Wrk82HHAXD)（私有链接，需作者分享）。

直接用浏览器打开 `index.html` 即可，电脑和手机都能用。全部是本地模拟，数据存在浏览器的 localStorage 里。

| 文件 | 负责 |
|---|---|
| `scenario.js` | 场景数据：Bot、联系方式和三件示例事情的步骤 |
| `engine.js` | 运行时：按步骤产生事件，状态由事件归并得到；不依赖 DOM |
| `app.js` / `styles.css` | 界面：三个标签和它们的下级页面 |
| `engine.test.mjs` | 引擎测试：`node --test examples/matter-canvas/engine.test.mjs` |

自己添加的事只有两步（负责人处理、老板验收）。浏览器和云电脑两个面板只是占位，没有接通真实的浏览器或云桌面；任务里的处理步骤是从事件推出来的示意。「允许他做什么」的前三项和发消息的开关会真的影响事情的推进；岗位和岗位提示目前只是保存和展示的文字。文案直接写在源码里，没有接入 Workbench 的国际化和设计系统。
