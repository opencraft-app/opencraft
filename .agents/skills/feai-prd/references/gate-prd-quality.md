# Gate: 需求质量门禁

> `/feai-prd` 在提交 TAPD 前对照本 checklist 自检。写作标准见 `prd-writing-standard.md`。
> 门禁结论统一为三态：**通过 / 有条件通过 / 打回**（对齐仓库其他 gate）。

---

## 一、复杂度分层

先按以下维度用 `0/1/2` 打分，再决定启用哪些检查块：

角色/权限差异、对象与状态数量、异步或长流程、资金/权益/配额、敏感数据、不可逆操作、外部系统依赖、跨站点/多语言、灰度回滚、合规与滥用风险。

| 档位 | 触发特征 | 启用检查块 |
|---|---|---|
| **S** | 单角色、短流程、已有对象、无异步与高风险操作 | 二、三、四 |
| **M** | 多步骤流程、多角色/状态、外部依赖或明显异常路径 | 二、三、四 + 五 |
| **L** | 异步任务、跨系统/跨账号、敏感数据、资金权益、数据覆盖、不可逆操作、多站点发布 | 二、三、四、五 + 六 |

规则：

- 档位只决定检查深度，不得扩大原始需求范围。
- 不适用的检查项标注"不适用及原因"，不留空标题。
- 命中任一 L 档触发特征即升为 L，不取平均分。

---

## 二、硬门禁（Pass/Fail，任一 Fail → 打回）

- [ ] **H1** 需求命题明确：能一句话回答"为谁解决什么问题"
- [ ] **H2** 目标可判断：至少一个可观察的成功判断，不是"提升体验"
- [ ] **H3** 范围与非目标都写明：明确列出本次不做什么
- [ ] **H4** 主流程完整：有触发条件、关键步骤、成功结果、失败路径
- [ ] **H5** 验收标准可测试：数量达标（S ≥ 3 / M ≥ 4 / L ≥ 5），每条第三方可复现
- [ ] **H6** 无禁用表达：对照 `prd-writing-standard.md` 的禁用表达表
- [ ] **H7** 无逻辑冲突：描述内部无互相矛盾的说法
- [ ] **H8** 未决项已分类：每个未决问题标注 `[推荐待确认]` / `[待外部事实]` / `[待用户选择]` 之一，不留无归属的"待确认"
- [ ] **H9** 无编造事实：数字、比例、用户规模、性能基线都能回引到输入或标为待外部事实
- [ ] **H10** 标题与格式合规：标题符合命名规范，`description` 按模板段落用 Markdown 分节
- [ ] **H11** 模板必填字段全部有值

---

## 三、描述明确性

- [ ] 需求描述用可测试句式（见 `prd-writing-standard.md` 需求句法）
- [ ] 每条规则只描述一个可观察行为，复杂条件用决策表而非重复段落
- [ ] 术语在需求内首次出现时有定义，不依赖外部上下文
- [ ] 边界条件写明：输入上限、并发、重复提交、空数据

---

## 四、影响评估（只评级，不设计）

- [ ] 规模（S/M/L）已判定且与复杂度分层一致
- [ ] 影响范围已用一句话说明（涉及哪些业务模块 / 系统）
- [ ] **未包含技术方案 / 详细设计**：无「解决实现方案」、无具体改动文件清单、无可复用组件点名、无实现步骤

---

## 五、状态与异常（M/L 启用）

- [ ] 涉及的对象与状态已列出（状态 ≥ 3 个时给出状态流转）
- [ ] 关键异常有"触发条件 → 用户所见 → 默认下一步"
- [ ] 依赖失败、超时、权限不足的默认行为已定义
- [ ] 多角色时权限差异已写明
- [ ] 外部依赖的失败责任归属已明确

---

## 六、高风险控制（L 启用）

- [ ] 不可逆操作有二次确认或撤销窗口
- [ ] 资金/权益/配额变更有对账或护栏指标
- [ ] 敏感数据的可见范围与脱敏规则已定义
- [ ] 异步任务的执行中对象处置已定义（停止新建 / 存量可见）
- [ ] 灰度与回滚：开关粒度、观察窗口、停止条件、回滚动作已定义；无来源的数值标为待确认
- [ ] 跨系统场景下数据一致性窗口与冲突裁决已明确

---

## 严重级别与结论

| 级别 | 定义 | 影响结论 |
|---|---|---|
| **blocker** | 硬门禁 Fail，或缺失会导致研发无法开工 | → 打回 |
| **major** | 关键信息缺失或不可测试，研发需回头追问 | → 有条件通过 |
| **minor** | 表述可优化，不影响开工 | 不影响结论 |
| **note** | 建议性改进 | 不影响结论 |

| 结论 | 判定 | 后续动作 |
|---|---|---|
| **通过** | 无 blocker 且无 major | 可直接提交 |
| **有条件通过** | 无 blocker，存在 major | 提示 major 项，用户可选修改或提交 |
| **打回** | 存在 blocker | 强提示必须修正，用户仍可强制提交但需明确确认 |

> `/feai-prd` 不做强阻断：即使结论为「打回」，用户仍可选择强制提交（需二次确认）。门禁的作用是**让用户清楚代价**，而不是替用户决定。

---

## 输出格式

```text
## 需求质量检查报告

**复杂度档位**：{S/M/L}（触发：{命中的维度}）
**结论**：{通过 / 有条件通过 / 打回}

### 硬门禁
{全部通过} / {H{N} Fail：具体原因}

### blocker（{N} 项）
1. [{字段}] {问题} → {具体修改建议}

### major（{N} 项）
1. [{字段}] {问题} → {具体修改建议}

### minor / note（{N} 项）
1. [{字段}] {问题} → {建议}

### 未决项分类
- [推荐待确认] {项}：{推荐值} + {理由}
- [待外部事实] {项}：{缺失事实} / {来源方} / {影响} / {临时行为}
- [待用户选择] {项}：{推荐选项} + {备选差异}
```

检查完成后输出 `decision-cards.md` 的「质量检查结果」卡片，等待用户选择。
