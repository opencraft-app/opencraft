# 上下文工程双量表评分标准

门禁：Context 控制面 ≥85 且 P0=0，同时 Repository Documentation ≥85 且 P0=0。两套量表各自 100 分，不相加、不平均。

权重按失败影响设计：发现错误、权威冲突和规则无法执行会直接导致 Agent 拿错上下文或采取错误行动，因此占 Context 前 60 分；默认输入效率、任务恢复、工作流复用和生命周期决定系统能否持续运行，占后 40 分。文档量表中，服务责任是代码、Owner、操作与局部知识共同演进的主边界，所以为 25 分；母集和跨服务知识各 20 分，其余职责承担导航、派生和时效风险。

评分看责任和证据，不看特定目录名或文件数。公开行业依据和适用边界见 [industry-evidence.md](industry-evidence.md)。

## Observation 与算分

脚本 `schema_version: 3` 模板为每个维度列出固定 4 个 required observations。Agent 依 [assessment-contract.md](assessment-contract.md) 只提交 `pass/partial/fail/unknown`、理由、对象、证据和局限，不提交自报分或 level。

- `pass = 1`、`partial = 0.5`、`fail = 0`。
- 维度得分 = 维度权重 × required observations 状态值的算术平均。
- 任一 required observation 为 `unknown`，所属量表的总分为 `null`，只输出定性状态和证据缺口。
- 每维第 4 个 observation 是强证据槽；强槽 `pass` 必须有当前维度允许的 Validator、Test、Trace 或 Owner Review。Validator/Test 必须绑定 claim、与该 observation 内容证据相交的仓库输入 hashes，以及已命中的非敏感稳定输出 selector；同一执行事实指纹不得因更换 selector 或 receipt 而跨 claim 复用。`model_effect` 只作附录，不参与静态状态或分数。
- P0 单独阻断门禁，不会被其他高分抵消。

Observation ID 表示下表的通用概念要求。脚本应拒绝丢失、增加或重复 ID 的 Assessment，避免通过调整分母改分。

## Context 控制面 100 分

| 维度 | 分值 | Required observations | 为什么评/证据重点 |
|---|---:|---|---|
| 入口与分层路由 | 15 | 最短入口可发现；作用域与继承优先级明确；按任务渐进加载；代表性入口/路由检查可复现 | 所有任务的共同起点。必须证明 Agent 如何从入口到相关局部知识，不只证明文件存在。 |
| 真实任务路由覆盖 | 15 | 代表性任务分母已定义；必要上下文命中已核查；禁入内容未进运行时；覆盖/排除检查可复现 | 漏必读会直接导致错误。需要任务样本和可重放结果，不对未采样 Query 外推。 |
| 权威性与知识完整度 | 15 | 事实可回到正式来源；冲突/优先级处理明确；正确性/时效经抽样；权威性复核可追溯 | 错误或过期摘要与漏路由同级。至少需文件、Git 与内容抽检；候选 Catalog 不自动成为真源。 |
| 规则可执行性 | 15 | 关键规则/风险已识别；规则映射到检查/人工门禁；违规失败行为明确；关键规则检查可复现 | 决定设计是否成为可重复行为。Validator/测试须与 claim 绑定；23 条规则只作原则对照。 |
| 指令链 Token 预算 | 10 | 默认注入/按需读取边界明确；预算口径/目标/例外明确；当前默认指令链已测量；预算检查可复现 | 是重要效率约束，但静态字节不等于 API Token、缓存或准确率。预算值可采用仓库自有标准，需说明理由。 |
| 任务状态与反馈闭环 | 10 | 长期任务状态可恢复；完成条件绑定证据；失败/反馈进入下轮；闭环/恢复检查可复现 | 决定长任务能否恢复与持续修正。模板只能证明契约，真实采用需回执或 Git 实例。 |
| Skill 与工作流治理 | 10 | 触发/排除边界明确；入口/参考资料渐进披露；授权边界明确；Skill 契约/行为检查可复现 | 决定流程能否复用和扩展，但不替代仓库事实。Skill、命令、流程平台可等价映射。 |
| 生命周期、消费观测与评测隔离 | 10 | 知识创建/复查/失效/退出明确；运行时消费边界可观测；Gold/答案/评分与运行时隔离；隔离/消费检查可复现 | 防止知识无限堆积和评测污染。文件契约与真实消费分开取证；没有 trace 不得声称已消费。 |

## Repository Documentation 100 分

| 维度 | 分值 | Required observations | 为什么评/证据重点 |
|---|---:|---|---|
| 文档盘点与分类 | 20 | 文档母集/排除范围明确；按职责语义分类；重复/过期/归档可治理；盘点/分类检查可复现 | 没有母集就无法判断覆盖、重复、归档或污染。发现器可列文件，分类与排除必须由 Agent 核对。 |
| 服务责任与入口 | 25 | 真实组件分母已核查；Owner 来自权威声明；代码/责任/最短入口可共同演进；Owner/入口覆盖复核可追溯 | 日常研发的主边界，缺 Owner 或入口影响大量任务。分母从构建、部署、workspace 和现有 Catalog 综合判定。 |
| 跨服务工程知识层级 | 20 | 跨组件知识边界明确；架构/决策/运行知识分层；跨层回链权威源；层级完整性复核可追溯 | 承载无法在单服务内说清的真源。小仓可合并文件；按实际架构风险判定必需内容。 |
| 链接与入口完整性 | 15 | 链接扫描范围/限制明确；相对文件/图片目标可解析；引用源/文档锚点可解析；链接检查可复现 | 失效链接会直接中断人与 Agent 的证据链。通用链接扫描只证明它实际解析的链接范围。 |
| Context 派生接口 | 10 | 派生 Context 标明来源/范围；派生层回到正式知识；运行时消费/真源边界明确；来源/消费检查可复现 | 评估正式知识如何进入 Agent 运行时。等价索引、搜索或动态生成接口均可取证。 |
| 内容质量与时效 | 10 | 正文能支持目标任务；关键事实/步骤经源码或配置抽样；复查时间/维护责任明确；内容质量复核可追溯 | 防止结构高分掩盖正文错误和过期。抽检需报样本和局限；Validator 通过不自动证明语义正确。 |

## 仓库画像

- `empty`：无可用入口、控制面和成体系文档。
- `underbuilt`：有代码或文档，但入口、权威、派生、路由或生命周期没有闭合。
- `overbuilt`：入口超预算，文档增长但缺路由/权威，或多套真相并存。
- `managed`：入口、正式知识、Agent 消费接口、控制面和可复用工作流闭合。

画像必须有 rationale 和 signals，只决定建设策略，不直接决定分数。

## 证据等级

证据等级由脚本从已校验证据组合推导，报告要附推导理由：

- A：当前文件、完整 Git path+commit、Owner/权威和与 claim 绑定的 Validator/测试/回执可共同复现。
- B：文件与 Git 一致，但缺部分可执行、Owner 复核或消费证据。
- C：主要是当前文件声明、未提交资产或浅历史。
- Unknown：尚未完成 Agent Assessment，或关键证据源不可用。

## P0 / P1 / P2

- P0：评测污染、必要路由失败、无效安全契约、严重指令链超预算或敏感信息风险；阻断 V1。
- P1：Owner、来源、Catalog、服务入口、链接、任务/反馈闭环缺口；本轮优先修复。
- P2：不阻断静态 V1 的运行时增强或长期抽检。

## 能证明与不能证明

通过点分可以证明：在 Assessment 声明范围和证据时点，静态组织、入口、路由、权威、可执行性、生命周期骨架和评测隔离达到本量表门禁。

不能自动证明：全部正文永久正确、Agent 每次都消费了 Context、API Token/费用下降，或模型 Recall/MRR/准确率提升。它们分别需要持续内容抽检、Receipt/Trace、账单/调用记录和隔离模型实验。
