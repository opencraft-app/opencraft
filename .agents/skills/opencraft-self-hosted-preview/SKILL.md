# OpenCraft 自托管预览切换

当前代理可能运行在待替换的 OpenCraft 服务进程树中。若从该代理的工具调用里直接执行 `systemctl stop` 或 `restart`，服务会先终止当前调用，后续启动、回退和结果检查都可能无法执行。切换必须由不依赖该服务存活的独立执行者完成。

1. 先确认实际服务所有者：查监听端口的 PID、`/proc/<pid>/cgroup`、进程工作目录和 `systemctl show/cat`。分别记录 Web `version.json`、运行时文件哈希和数据目录；Web 文件可能单独更新，不能仅凭 buildId 推断运行时代码版本。
2. 在取得发布授权后，先准备隔离候选包，保留原包和数据目录。工作区有无关未提交改动时，不直接把整个工作区打进候选包；记录候选包来源和确切改动。完成相关测试、包级启动验收和回退路径后再切换。
3. 把停止旧服务、启动新服务、健康检查和失败回退写入独立脚本，交给服务进程树之外的 supervisor 执行，例如独立的 `systemd-run` service。先让提交命令返回，再由该 service 执行切换；不要在当前代理工具调用中同步停止承载它的服务。切换脚本应检查端口占用和实际旧服务，避免备用服务抢占端口。
4. 新服务启动后，从重新连接的会话核对监听 PID、所属 unit、工作目录、运行时哈希、Web buildId、健康响应和本次修复涉及的实际请求行为。提交了切换任务或看到 Web 版本变化都不算完成。失败时确认回退服务确实恢复，再报告当前运行状态。

遵循仓库 `AGENTS.md` 的发布授权边界；本 Skill 不额外授权重启、发布或读取凭据。验证请求使用本地夹具或无费用路径，不在日志中输出账户令牌。
