The CloudAgent HTTP Run API is for channel gateways, backend services, and test
clients that need to call CloudAgent without holding a long-lived ACP
WebSocket.

CloudAgent HTTP Run API 面向渠道网关、后端服务和测试客户端。它们可以调用 CloudAgent，而不需要持有长生命周期 ACP WebSocket。

Use this API for durable channel traffic. Do not multiplex many channel
conversations over one ACP WebSocket.

持久渠道流量应该使用这套 API。不要把多个渠道会话复用到同一条 ACP WebSocket 上。

## Base URL / 基础地址

Use the CloudAgent gateway HTTP base URL. Do not append `/acp`.

使用 CloudAgent gateway 的 HTTP 基础地址，不要追加 `/acp`。

Devcloud internal endpoint / Devcloud 内网入口：

```text
http://21.6.84.6
```

In-cluster endpoint / 集群内入口：

```text
http://cloudagent-gateway.dep.svc.cluster.local
```

## Authentication And Scope / 鉴权与作用域

Every request must identify the caller scope by either:

每个请求必须通过以下任一方式标识调用方作用域：

| Method | Headers |
| --- | --- |
| Bearer token / Bearer 令牌 | `Authorization: Bearer <token>` |
| Tenant/project scope / 租户项目作用域 | `X-Tenant-ID` and `X-Project-ID` |

Devcloud test scope / Devcloud 测试作用域：

```bash
export CLOUDAGENT_BASE_URL=http://21.6.84.6
export CLOUDAGENT_TENANT_ID=tenant-devcloud-dep
export CLOUDAGENT_PROJECT_ID=project-devcloud-dep
```

Common error if scope is missing / 缺少作用域时的常见错误：

```json
{
  "error": {
    "message": "X-Tenant-ID/X-Project-ID or Authorization: Bearer is required",
    "type": "invalid_request_error",
    "code": "identity_missing"
  }
}
```

```bash
curl -sS \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/capabilities"

```

## Basic Flow / 基本流程

1. Create or load a session.
2. Submit a run with a caller-generated `run_id`.
3. Read events using `after_seq`.
4. Read the final durable result.
5. If the observer disconnects, resume from the last committed `after_seq`.

1. 创建或加载会话。
2. 使用调用方生成的 `run_id` 提交运行。
3. 使用 `after_seq` 读取事件。
4. 读取最终持久化结果。
5. 如果观察方断开连接，从最后确认的 `after_seq` 继续读取。

## Create Session / 创建会话

```bash
curl -sS \
  -H "Content-Type: application/json" \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  -d '{
    "cwd": "/workspace",
    "agent_version": "builtin.v1",
    "workspace_version": "builtin.v1"
  }' \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/sessions"
```

Response / 响应：

```json
{
  "session_id": "session_xxx",
  "state": "ready",
  "runtime_generation": 1
}
```

## Submit Run / 提交运行

Generate a stable idempotency key per inbound channel message:

为每条入站渠道消息生成稳定的幂等 key：

```bash
export RUN_ID="job_channel_${MESSAGE_ID}"
```

Submit / 提交：

```bash
curl -sS \
  -H "Content-Type: application/json" \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  -d '{
    "run_id": "'$RUN_ID'",
    "text": "你好",
    "cwd": "/workspace"
  }' \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/sessions/$SESSION_ID/runs"
```

## Event Replay And Stream / 事件回放与流式读取

Replay committed events:

回放已提交事件：

```bash
curl -sS \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/runs/$RUN_ID/events?after_seq=0"
```

Stream new events as newline-delimited JSON:

以 newline-delimited JSON 方式读取新增事件：

```bash
curl -N \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/runs/$RUN_ID/events?after_seq=0&stream=true"
```

The stream is HTTP NDJSON. It is not WebSocket and not Server-Sent Events.

该流是 HTTP NDJSON，不是 WebSocket，也不是 Server-Sent Events。
