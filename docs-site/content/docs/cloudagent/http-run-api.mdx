  <span className="lang-en">The CloudAgent HTTP Session Events API is for channel gateways, backend services, and test clients that need to call CloudAgent without holding a long-lived ACP WebSocket.</span>
  <span className="lang-zh">CloudAgent HTTP Session Events API 面向渠道网关、后端服务和测试客户端。它们可以调用 CloudAgent，而不需要持有长生命周期 ACP WebSocket。</span>

  <span className="lang-zh">持久渠道流量应该使用这套 API。不要把多个渠道会话复用到同一条 ACP WebSocket 上。</span>
</p>

## <span className="lang-en">Basic Flow</span><span className="lang-zh">基本流程</span>

<div className="lang-en">

1. Create or load a session.
2. Submit a `user.message` event with a caller-generated `Idempotency-Key` or `client_event_id`.
3. Read session events using `after_seq`, `after_id`, or `Last-Event-ID`.
4. Stop on `session.status_idle` or `session.error`.
5. If the observer disconnects, resume from the last committed session cursor.

</div>

<div className="lang-zh">

1. 创建或加载会话。
2. 使用调用方生成的 `Idempotency-Key` 或 `client_event_id` 提交 `user.message` 事件。
3. 使用 `after_seq`、`after_id` 或 `Last-Event-ID` 读取会话事件。
4. 遇到 `session.status_idle` 或 `session.error` 后结束本轮观察。
5. 如果观察方断开连接，从最后确认的会话游标继续读取。

</div>

## <span className="lang-en">Submit User Message</span><span className="lang-zh">提交用户消息</span>

<p>
  <span className="lang-en">Generate a stable idempotency key per inbound channel message:</span>
  <span className="lang-zh">为每条入站渠道消息生成稳定的幂等 key：</span>
</p>

```bash
export IDEMPOTENCY_KEY="msg_channel_${MESSAGE_ID}"
```

<p>
  <span className="lang-en">Submit:</span>
  <span className="lang-zh">提交：</span>
</p>

```bash
curl -sS \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  -d '{
    "events": [
      {
        "type": "user.message",
        "client_event_id": "'"$IDEMPOTENCY_KEY"'",
        "content": [{"type": "text", "text": "你好"}]
      }
    ]
  }' \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/sessions/$SESSION_ID/events"
```

<p>
  <span className="lang-en">The response returns public session events. A `run_id` may be present as debugging metadata, but clients should continue by reading the session event stream.</span>
  <span className="lang-zh">响应会返回公开会话事件。`run_id` 可能作为调试元数据出现，但客户端应该继续读取会话事件流。</span>
</p>

## <span className="lang-en">Event Replay And Stream</span><span className="lang-zh">事件回放与流式读取</span>

<p>
  <span className="lang-en">Replay committed events:</span>
  <span className="lang-zh">回放已提交事件：</span>
</p>

```bash
curl -sS \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/sessions/$SESSION_ID/events?after_seq=0"
```

<p>
  <span className="lang-en">Stream new events as Server-Sent Events:</span>
  <span className="lang-zh">以 Server-Sent Events 方式读取新增事件：</span>
</p>

```bash
curl -N \
  -H "X-Tenant-ID: $CLOUDAGENT_TENANT_ID" \
  -H "X-Project-ID: $CLOUDAGENT_PROJECT_ID" \
  "$CLOUDAGENT_BASE_URL/v1/cloudagent/sessions/$SESSION_ID/events/stream?after_seq=0"
```

<p>
  <span className="lang-en">The stream is HTTP SSE with `Content-Type: text/event-stream`. Each `data:` payload is one public CloudAgent event JSON object. It is not WebSocket and it does not expose ACP `sessionUpdate` or Hermes wrapper stdout.</span>
  <span className="lang-zh">该流是 HTTP SSE，`Content-Type: text/event-stream`。每个 `data:` payload 都是一个 CloudAgent 公开事件 JSON 对象。它不是 WebSocket，也不会暴露 ACP `sessionUpdate` 或 Hermes wrapper stdout。</span>
</p>

```text
id: evt_session_xxx_1
event: agent.message
data: {"id":"evt_session_xxx_1","seq":1,"type":"agent.message","run_id":"job_durable_123","session_id":"session_xxx","schema_version":"1.0","content":[{"type":"text","text":"CLOUDAGENT_RUN_OK"}]}

id: evt_session_xxx_2
event: session.status_idle
data: {"id":"evt_session_xxx_2","seq":2,"type":"session.status_idle","run_id":"job_durable_123","session_id":"session_xxx","schema_version":"1.0","status":"idle","stop_reason":{"type":"end_turn"}}
```

<p>
  <span className="lang-en">Resume with `after_seq`, `after_id`, or the standard `Last-Event-ID` SSE header. `after_seq` wins when multiple cursors are present.</span>
  <span className="lang-zh">可以使用 `after_seq`、`after_id` 或标准 SSE header `Last-Event-ID` 恢复读取。多个游标同时存在时，以 `after_seq` 为准。</span>
</p>
