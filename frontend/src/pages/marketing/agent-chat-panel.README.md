# AgentChat host UI

`AgentChatStatusView` only receives loading/error text and the existing retry callback. It uses `AgentState` and the scoped shared Button; it does not own token requests, effects, a connection or SDK state. The SDK remains behind the existing `lazy` / Suspense import so its side-effect CSS is not loaded by the console shell alone.

`AgentChatPanel` retains the first-ready token lock, permanently stable initial API params object, token / expiry refs, existing refresh callback dependencies, locale storage synchronization, and exact ready/account/token mounting condition. It passes the original command executor and multiSession object through. The parent retains Bot/session/locale keys and retry policy; the view does not introduce an SDK key or change SDK features/reporting. Existing `WorkbenchPromptAutoSender` placement remains untouched; Workbench itself is excluded from this batch.

The new rendered host tests replace only the SDK boundary with a component recording actual mount / cleanup effects and received prop references. They assert error keyboard retry exactly once; idle-to-first-ready mounting; ready display updates keeping the same SDK DOM instance, initial API object, command executor and multiSession references; cached token reuse; expired-token refresh; and cleanup only on host unmount. Chinese and real English dictionaries are exercised. Source guards additionally retain the lazy import and pre-existing no-reset CSS boundary; these guards do not substitute for lifecycle assertions. No real WebSocket, SDK-internal or remote command behavior is claimed by these fixtures.
