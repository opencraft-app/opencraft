## 요약

**Hermes Agent와 OpenClaw의 근본적인 차이는 "축적"과 "연결"에 있습니다. Nous Research가 만든 Hermes Agent는 시간이 지날수록 사용자를 더 잘 이해하도록 설계된 자기 진화형 에이전트입니다. 장기 메모리(`USER.md` / `MEMORY.md` / SQLite+FTS5 / 스킬)를 핵심 요소로 다루며, 무엇을 기억하고 언제 스킬로 승격할지를 에이전트가 직접 결정합니다. Peter Steinberger가 이끄는 OpenClaw는 "모든 것을 연결"하기 위한 로컬 퍼스트 에이전트 및 자동화 게이트웨이입니다. 25개 이상의 모델과 20개 이상의 메시징 플랫폼을 연결할 수 있고, 사용자가 직접 스킬을 작성해 ClawHub로 배포합니다. Hermes를 선택하면 시간이 지날수록 성장하는 동반자를, OpenClaw를 선택하면 다양한 대상을 연결하는 제어 허브를 선택하는 셈입니다.**

---

## 이 두 오픈소스 에이전트가 계속해서 비교되는 이유

2026년 오픈소스 AI 에이전트 생태계를 살펴보면 두 제품을 자주 마주치게 됩니다. 둘 다 "로컬 퍼스트, 자체 호스팅, 크로스 플랫폼 채팅 연동"을 내세우고 범용 에이전트 프레임워크를 표방합니다. 웹사이트만 보면 서로 직접 경쟁하는 제품처럼 보입니다.

하지만 실제로 일주일 정도 사용하면 두 가지 의문이 생깁니다.

- OpenClaw는 플러그인을 수십 개 설치해도 왜 여전히 "매번 처음부터 시작"하는 반면, Hermes는 이틀만 사용해도 지난주 프로젝트 이름을 먼저 언급할까요?
- OpenClaw가 63일 만에 138개의 취약점을 공개했는데(그 중 7개는 중요) Hermes의 보안 권고 페이지가 거의 비어 있는 이유는 무엇입니까?

답은 간단합니다. **두 제품은 서로 완전히 다른 질문에 답하고 있습니다.**

- OpenClaw 답변: "내 인생의 모든 채널에 하나의 에이전트를 어떻게 연결합니까?"
- Hermes Agent 답변: "시간이 지날수록 나를 더 잘 이해하는 에이전트를 어떻게 만들 수 있나요?"

아래 섹션에서는 **포지셔닝, 아키텍처, 메모리, 스킬, 자체 진화 및 보안**이라는 6가지 차원에 걸쳐 이러한 차이점을 살펴봅니다.

## 1. 포지셔닝: 학습 루프 우선 vs 제어 평면 우선

| 차원 | Hermes Agent | OpenClaw |
|---|---|---|
| 개발 주체 | Nous Research | Peter Steinberger(오스트리아의 독립 개발자) |
| 포지셔닝 | 자기 진화형 AI 에이전트 | 로컬 퍼스트 에이전트 및 자동화 플랫폼 |
| 핵심 철학 | 학습 루프 우선 | 제어 평면 우선 |
| 차별점 | "축적" — 사용할수록 강해짐 | "연결" — 다양한 대상과 연결 가능 |
| 한 줄 요약 | **축적** 문제를 해결 | **연결** 문제를 해결 |

Hermes는 그리스 메신저 신의 이름을 따서 사용자를 대신하여 계속 관찰하고, 기록하고, 성장하는 "당신과 정보 사이의 메신저"로서의 역할을 암시합니다. OpenClaw는 다른 길을 택합니다. 자체적으로 20개 이상의 메시징 플랫폼과 25개 이상의 모델을 연결할 수 있는 **중앙 게이트웨이**가 된 다음 **사용자**가 모든 규칙, 모든 스킬 및 모든 트리거를 정의하도록 남겨둡니다.

하나는 사용자의 동반자가 되려 하고, 다른 하나는 사용자의 제어 허브가 되려 합니다. 이것이 가장 근본적인 차이입니다.

---

## 2. 아키텍처: 통합형 vs 게이트웨이형

**OpenClaw는 게이트웨이 형태의 4단 구조입니다.**

```
Gateway → Agent → Skills → Memory
```

핵심 엔지니어링 가치는 게이트웨이에 있습니다. 사용자가 WhatsApp, Telegram, Slack, Discord 또는 이메일에서 도착하든 모든 것이 동일한 에이전트 세션으로 수렴됩니다. 제어 평면은 깨끗하고 권한, 감사 및 라우팅이 모두 게이트웨이 계층에 있습니다.

**Hermes Agent는 통합형 구조**입니다. 모델 추론, 터미널 실행, 파일 작업, 브라우저 자동화, 웹 검색, 장기 메모리, 예약 작업, 다중 플랫폼 메시징이 **하나의 프로세스** 안에 모듈로 내장되어 있습니다. 메시지 라우터보다는 두뇌와 손, 노트를 갖고 사용자를 따라다니는 비서에 가깝습니다.

결과: **더 많은 플랫폼을 연결하려면 OpenClaw가 더 좋습니다. 에이전트 자체를 더 강하게 만들고 싶다면 Hermes가 더 좋습니다.**

---

## 3. 메모리: 정적 마크다운 파일 2개 vs 구조화된 레이어 4개

차이가 가장 극적으로 나타나는 부분이 바로 여기입니다.

### OpenClaw의 메모리: 두 개의 정적 마크다운 파일

- `MEMORY.md`는 "지속적인 사실"을 저장합니다.
- `memory/YYYY-MM-DD.md`는 "그날의 대화 내용"을 저장합니다.

디자인은 제한적이며 텍스트 편집기에 매우 친숙합니다. 하지만 여기에는 두 가지 기본 제한이 있습니다.

1. **지난 2일** 로그만 자동으로 로드됩니다. 이전 추억에서는 사용자가 수동으로 검색해야 합니다.
2. 메모리는 전적으로 **사람이 작성한** 자유 형식 텍스트이며, 무엇을 기억할 가치가 있는지 판단하는 과정에 에이전트가 참여하지 않습니다.

### Hermes Agent의 메모리: 4개의 협력 레이어

| 레이어 | 저장 위치 | 역할 |
|---|---|---|
| 프롬프트 메모리 | `MEMORY.md` + `USER.md` | 매 세션 시작 시 시스템 프롬프트에 고정하여 로드 |
| 세션 아카이브 | SQLite + FTS5 전문 검색 + LLM 요약 | 모든 세션을 저장하며 몇 주 뒤에도 검색 가능 |
| 스킬 | `SKILL.md` 파일 | 에이전트가 자체적으로 축적한 "실행 방법" |
| 외부 공급자 | Honcho, Mem0, Supermemory 등 | 지식 그래프, 의미 검색, 사용자 프로필 보완 |

이 4개 계층에서 가장 중요한 작업은 다음과 같습니다. **에이전트 자체가 `MEMORY.md`에 들어가는 항목, `USER.md`에 들어가는 항목, 스킬로 승격되는 항목을 결정합니다.** 이는 "시간이 지남에 따라 사용자를 더 잘 이해"하기 위한 물리적 기반입니다.

이 카테고리의 다른 기사에서는 `MEMORY.md`와 `USER.md` 간의 업무 분업, 업데이트 전략, 스킬과 메모리 간의 차이점을 자세히 설명합니다.

---

## 4. 스킬: 인간이 작성한 것과 에이전트가 작성한 것

스킬은 재사용 가능한 운영 절차입니다. 두 프레임워크 모두 이러한 기능을 갖추고 있지만 완전히 다른 방식으로 획득됩니다.

| 비교 | Hermes Agent | OpenClaw |
|---|---|---|
| 누가 쓰는가 | 에이전트는 복잡한 작업을 마친 후 **자동으로 증류**합니다 | 사용자는 Markdown을 직접 작성합니다 |
| 트리거 | 5개 이상의 도구 호출, 오류 후 성공적인 복구 등 | 사용자가 의도적으로 생성함 |
| 자체 최적화 | 약 15개 작업마다 회고 루프가 기존 스킬을 다시 작성함 | 자동 최적화 없음 |
| 개방형 표준 | [agentskills.io](https://agentskills.io)와 호환 | ClawHub 마켓플레이스를 통해 배포됨 |
| 보안 검토 | 내장 검사(프롬프트 인젝션, 자격 증명, 공급망 위험) | Snyk 감사에서는 5,700개 스킬 중 1,467개를 의심스러운 것으로 분류한 적이 있음 |

한 줄로 말하면: **Hermes의 스킬은 에이전트의 근육 메모리입니다. OpenClaw의 스킬은 사용자가 에이전트에 전달하는 사용 설명서입니다.**

---

## 5. 자기 진화: Hermes를 대체하기 어려운 핵심 루프

Hermes Agent에는 서로 결합되는 세 가지 학습 경로가 내장되어 있습니다.

1. **메모리 경로**: 세션이 SQLite에 도착하고 요약 후 FTS5 검색이 가능해집니다.
2. **스킬 경로**: 복잡한 작업 후에 구조화된 스킬이 자동으로 작성됩니다(단계, 함정, 확인 방법).
3. **훈련 경로**: 일상적인 도구 호출 기록 자체를 차세대 모델의 훈련 데이터로 활용할 수 있습니다.

Reddit 사용자는 Hermes가 2시간 내에 3개의 스킬 문서를 자동으로 생성한 후 반복적인 연구 작업의 효율성이 눈에 띄게 향상되었다고 보고했습니다.

OpenClaw에는 이 루프가 **없습니다**. 이는 에이전트의 라우터 및 스케줄러처럼 작동하며 **사용자 및 커뮤니티**에서 스킬을 추가하고, 플러그인을 설치하고, 서비스를 연결함으로써 발전했습니다.

두 경로 모두 본질적으로 더 나은 것은 아니지만 무엇을 선택하고 있는지 알아야 합니다. 하나는 **에이전트가 스스로 성장하도록** 하고, 다른 하나는 **인간이 에이전트가 성장하도록 가르칩니다**.

## 6. 보안: 기본 격리 방식 vs 기본 개방 방식

| 차원 | Hermes Agent | OpenClaw |
|---|---|---|
| 기본 샌드박스 | 읽기 전용 컨테이너 루트 + Linux capability 제거 | 없음 |
| 승인 | 승인 게이트는 기본적으로 켜짐 | 게이트웨이 인증은 기본적으로 꺼짐 |
| 인젝션 방어 | 프롬프트 인젝션 및 자격 증명 유출 검사 내장 | 내장 검사 없음 |
| 알려진 취약점 | 계층형 보호를 기본 제공 | 63일 동안 취약점 138건 공개, 그중 7건은 심각 |

**Hermes의 보안 원칙은 "기본적으로 제한하고 명시적으로 허용할 때만 완화"하는 방식이며, OpenClaw는 "기본적으로 열어 두고 사용자가 직접 강화"하는 방식입니다.** 전자는 개인정보 보호에 민감한 개인에게 편리하고, 후자는 기업 네트워크에서 맞춤형 제어를 구성하기에 더 유연합니다.

## 7. 그럼 어떤 걸 골라야 할까요?

**다음과 같은 경우 Hermes Agent를 선호하세요**

- 대화를 많이 할수록 당신을 더 잘 이해할 수 있는 장기 비서가 필요합니다.
- 개인 지식 관리, 장기 연구 또는 세션 간 추적에 사용됩니다.
- 토큰 소비를 줄이고 싶습니다(에이전트를 매번이 아니라 한 번만 학습).

**다음과 같은 경우 OpenClaw를 선호하세요**

- 주로 더 많은 채널과 더 많은 도구를 연결해야 합니다.
- 구체적인 팀 협업 및 중앙 집중식 감사 요구 사항이 있습니다.
- 이미 OpenClaw 생태계 내에 많은 스킬과 봇이 축적되어 있습니다.

## 8. 직접 구축하지 않고 Hermes를 사용하려면

Hermes Agent의 핵심 기능인 장기 메모리, 스스로 발전하는 스킬, 여러 플랫폼에서의 접근은 모두 같은 운영 조건을 필요로 합니다. **에이전트가 계속 온라인 상태를 유지하고, 전용 저장 공간을 사용하며, 한 사용자의 맥락을 일관되게 보관해야 합니다.**

즉, 이상적인 배포는 **절대로 오프라인 상태가 되지 않는 클라우드 인스턴스**입니다. 즉, 노트북 덮개를 닫아도 낮잠을 자지 않고, `nudge_interval`가 안정적으로 실행되며, 사용자가 여는 모든 터미널이 동일한 `~/.hermes/`에 도달합니다.

이것이 바로 [**LightVela**](https://lightvela.ai/)가 하는 일입니다. LightVela는 사용자가 직접 처리해야 하는 위의 모든 작업을 처리하는 **클라우드 호스팅 Hermes Agent 서비스**입니다.

- 로컬 배터리나 메모리를 소모하지 않고 한 번의 클릭으로 전용 클라우드 인스턴스를 활성화합니다.
- 실제 Hermes Agent를 사용하며, `MEMORY.md` / `USER.md` / 스킬도 원본 업스트림 메커니즘으로 동작합니다.
- 연중무휴 온라인이므로 전화, 노트북, Telegram, Lark 및 기타 모든 채널은 모두 귀하를 알고 있는 동일한 에이전트에 연결됩니다.
- 대화 데이터는 전용 서버에 보관되며 제3자와 공유되지 않습니다.

**위의 자체 진화 기능이 마음에 들지만 Ollama, SSH, systemd 및 백업 전략에 주말을 보내고 싶지 않다면 LightVela가 가장 짧은 경로일 가능성이 높습니다.**

## 핵심 요약

- Hermes와 OpenClaw는 서로 다른 문제를 해결합니다. **Hermes는 AI를 성장시키고, OpenClaw는 AI를 연결합니다.**
- 가장 큰 차이는 메모리입니다. OpenClaw는 정적 Markdown 파일 두 개를 사용하고, Hermes는 구조화된 네 레이어와 에이전트의 자체 판단을 사용합니다.
- 스킬은 "에이전트가 작성함"과 "사용자가 작성함"으로 분할됩니다. 보안은 "기본적으로 샌드박스 처리됨"과 "기본적으로 개방형"으로 구분됩니다.
- 다양한 대상을 연결하는 것이 우선이면 OpenClaw가, 시간이 지날수록 사용자를 더 잘 이해하는 에이전트가 필요하면 Hermes가 적합합니다. 자체 호스팅 없이 Hermes를 사용하려면 LightVela를 선택할 수 있습니다.
