# 더 자연스러운 IM 에이전트를 설계하는 방법: 대화 리듬, 그룹 규범, 장기 사회적 메모리

## 요약

**“더 사람답다”는 것은 실제 사람을 사칭한다는 뜻이 아닙니다. 표현, 응답, 장기 협업에서 안정적이고 이해하기 쉬운 행동을 유지한다는 뜻이며, 이는 대화 리듬, 그룹 규범, 장기 사회적 메모리라는 세 가지 요소로 결정됩니다.** 리듬은 언제 짧게 답하고, 언제 자세히 설명하고, 언제 멈추어 확인을 기다려야 하는지를 정합니다. 그룹 규범은 공유 공간에서 말하는 방식, 컨텍스트 인용 방식, 멤버의 경계를 존중하는 방식을 정합니다. 장기 사회적 메모리는 모든 메시지를 영구 기록으로 만들지 않으면서 확인된 관계 컨텍스트를 유지할지를 정합니다. 계층별로 구현하세요. 리듬과 규범은 안정적인 페르소나 수준 규칙으로 두고, 메모리에는 확인된 지속적 사실만 보관합니다. 이 가이드의 자연스러운 대화 체크리스트로 설계를 검증하세요.

![대화 리듬, 그룹 규범, 사회적 메모리를 활용한 자연스러운 IM 에이전트 설계](../images/use-case-10-lifelike-im-agent-rhythm-social-memory.png)

## 이 가이드가 필요한 사용자

투명성과 제어 가능성을 유지하면서 IM 에이전트가 더 자연스럽고 일관되게 느껴지기를 원하는 사용자를 위한 가이드입니다.

개인 어시스턴트, 학습 파트너, 리서치 파트너, 커뮤니티 어시스턴트를 설계하는 팀에 활용할 수 있습니다.

BotFather에서 Group Privacy를 비활성화하고, Bot을 그룹에 추가하고, `@bot_username`으로 멘션하면 Telegram 그룹 메시지를 지원합니다.
WhatsApp 그룹 기능은 해당 채널 문서의 지원 범위를 따르므로 이 그룹 규범은 설정을 마친 Telegram에 적용하고, 다른 채널에서 사용하기 전에는 지원 여부를 확인하세요.

## 안정적으로 유지할 항목 정하기

에이전트의 지속적인 행동을 네 계층으로 나눕니다.

| 계층 | 책임 | 권장 설정 |
|---|---|---|
| 페르소나 | 역할, 말투, 원칙, 경계 | SOUL.md |
| 관계 선호도 | 이름, 언어, 상세 수준, 상호작용 습관 | 사용자 프로필 |
| 사회적 메모리 | 확인된 공유 컨텍스트, 프로젝트 배경, 지속적인 합의 | 메모리 |
| 현재 리듬 | 현재 작업의 대화 컨텍스트, 길이, 긴급성 | 현재 세션 및 작업 프롬프트 |

일시적인 감정 하나나 우연한 답변 하나가 지속적인 페르소나를 바꾸게 하지 마세요.

모든 인사말, 모든 그룹 멤버의 메시지, 확인되지 않은 추론을 장기 사회적 메모리로 저장하지 마세요.

## 단계

### 1. 사칭 없이 자연스러운 역할 정의

[SOUL.md 페르소나 가이드](./im-agent-persona-soul-md.md)를 사용해 에이전트의 역할, 말투, 주도성 수준, 제한 사항을 정의합니다.

다음과 같은 브리프로 시작하세요.

    You are a stable, direct, and friendly research partner.
    Give the conclusion first, then add evidence and detail as needed.
    When the request is ambiguous, ask the single most important clarifying question.
    Remember confirmed long-term preferences, but do not save sensitive information or unconfirmed inferences.
    You are an AI assistant. Do not claim to be a human or pretend to have real-world experiences.

가상의 정체성으로 잘못된 신뢰를 만들지 않으면서 일관된 말투를 유지할 수 있습니다.

### 2. 대화 리듬 설계

다음과 같은 규칙으로 시작하세요.

- 간단한 사실 질문에는 한 문장에서 세 문장으로 직접 답합니다.

- 복잡한 작업을 처리하기 전에 목표를 다시 확인하고 단계와 위험을 나눕니다.

- 정보가 부족할 때 긴 양식을 보내지 말고 가장 중요한 질문 하나만 합니다.

- 사용자가 바쁘거나 급하거나 결론만 원한다고 말하면 답변 길이를 줄입니다.

- 사용자가 도출 과정, 튜토리얼, 회고를 요청하면 추론을 더 자세히 설명합니다.

- 외부 작업, 민감한 작업, 되돌릴 수 없는 작업 전에는 멈추고 확인을 기다립니다.

실제 작업으로 리듬을 검증하세요.

    Give me the three most important tasks for today in three sentences.

    Give me the conclusion first, then explain why you ranked them this way.

    This action changes external data. First tell me the impact and what needs confirmation.

에이전트가 같은 원칙을 유지하면서 작업과 사용자 선호도에 맞춰 답변 길이를 바꾸는지 확인하세요.

### 3. 사용자 프로필에 관계 선호도 저장

사용자 프로필은 언어, 이름, 시간대, 상세 수준, 일반적인 업무 방식에 적합합니다.

예를 들어 사용자가 Hermes에게 다음과 같이 말할 수 있습니다.

    Remember that I prefer concise, direct, conclusion-first replies.

관계 선호도는 소통 효율을 높여야 하며 사용자가 바꿀 수 없는 영구적인 성격 꼬리표가 되어서는 안 됩니다.

선호도가 바뀌면 페르소나 파일을 반복해서 편집하는 대신 Hermes에게 업데이트하거나 잊어 달라고 요청하세요.

### 4. 장기 사회적 메모리 설계

장기 메모리에 적합한 항목은 확인된 프로젝트 컨텍스트, 지속적인 협업 합의, 안정적으로 선호하는 이름, 반복해서 확인된 선호도입니다.

비밀번호, 인증 코드, 결제 정보, 의료 정보, 확인되지 않은 심리 판단, 일회성 잡담은 장기 메모리에 적합하지 않습니다.

Hermes에게 항목을 기억하거나 잊어 달라고 명시적으로 요청하고 [메모리 관리](../configuration/memory.md)에서 주기적으로 확인하고 정리하세요.

장기 메모리는 정보에 대한 사용자의 통제권을 빼앗지 않으면서 반복 질문을 줄여야 합니다.

### 5. 공유 공간의 그룹 규범 준비

Telegram은 그룹 메시지를 지원합니다.
Group Privacy를 비활성화하고 Bot을 그룹에 추가한 뒤 `@bot_username`으로 멘션해 실제 대화에 그룹 규범을 적용하세요.

그룹을 사용하기 전에 최소한 다음 항목을 정의합니다.

- Bot이 @멘션 또는 명시적인 명령 뒤에만 답하는지 여부.

- 신규 멤버 환영 메시지는 관리자가 트리거해야 하는지 여부.

- FAQ, 요약, 미리 알림의 빈도 제한.

- 멤버, 관리자, 사람에게 전달해야 하는 메시지를 구분하는 방법.

- 멤버 메시지가 공유 메모리에 들어가는지 여부와 다른 멤버에게 유출되지 않게 하는 방법.

- 분쟁, 불만, 운영 제안, 민감한 콘텐츠를 관리자에게 전달하는 방법.

그룹 규범은 채널 및 운영 규칙에 속하며 페르소나 프롬프트에만 의존해서는 안 됩니다.

### 6. 자동 작업으로 능동적 리듬 제어

능동적 메시지에는 명시적인 빈도, 시간 범위, 대상 채널, 일시 중지 방법이 필요합니다.

개인 미리 알림, 내부 요약, 주기적 확인에는 [자동 작업](../configuration/automation.md)을 사용하세요.

모든 자동 작업에 방해 금지 시간을 설정하고 대상 채널이 해당 능동적 전송 방식을 지원하는지 확인하세요.

고빈도 메시지로 동반자 느낌을 만들려고 하지 말고, 미리 알림을 중지하기 어렵게 만들지 마세요.

## 자연스러운 대화 체크리스트

- 에이전트가 사용자의 실제 질문에 먼저 답했나요?

- 작업 복잡도에 맞춰 길이를 조정했나요?

- 필요할 때 유용한 확인 질문을 했나요?

- 사용자의 심리를 추측하지 않고 확인된 선호도를 기억했나요?

- 실제 정체성이나 오프라인 경험을 암시하지 않고 AI임을 명확히 유지했나요?

- 외부 작업 전에 영향을 설명하고 확인을 기다렸나요?

- 방해 금지 시간, 거절, 잊기 요청을 존중했나요?

## FAQ

### 더 사람답다는 것이 에이전트가 AI라는 사실을 숨긴다는 뜻인가요?

아니요.

자연어, 안정적인 리듬, 이어지는 컨텍스트는 경험을 개선할 수 있지만 에이전트가 사람이라고 주장하거나 실제 경험을 지어내서는 안 됩니다.

### 모든 대화를 사회적 메모리로 저장해야 하나요?

아니요.

향후 협업에 도움이 되는 확인된 정보만 유지하고 메모리와 사용자 프로필을 정기적으로 검토하세요.

### 지금 Telegram과 WhatsApp에서 그룹 규범을 사용할 수 있나요?

이 가이드의 그룹 규범을 Telegram 그룹 메시지에 적용할 수 있습니다.
Group Privacy를 비활성화하고 Bot을 그룹에 추가한 뒤 `@bot_username`으로 멘션하여 페르소나, 리듬, FAQ, 미리 알림을 검증하세요.
WhatsApp 또는 다른 채널에서는 먼저 해당 채널의 그룹 지원 범위를 확인하세요.

### 에이전트 답변이 길 때도 있고 짧을 때도 있는 이유는 무엇인가요?

답변 길이는 작업 복잡도, 현재 프롬프트, 모델 출력, 사용자 선호도를 반영합니다.

사용자 프로필에 선호도를 설정하거나 현재 요청에서 결론만 또는 전체 도출 과정을 원한다고 명시하세요.
