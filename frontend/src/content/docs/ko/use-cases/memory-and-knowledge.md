# 에이전트로 장기 메모리와 개인 지식을 관리하는 방법

## 요약

**개인 지식은 두 종류로 나누어 관리해야 합니다. 사용자가 누구이고 어떤 방식으로 일하는지처럼 오래 유지되는 정보는 장기 메모리에, 계속 바뀌는 문서·노트·프로젝트 자료는 클라우드 스토리지에 두는 것이 적합합니다.** 둘을 한데 섞으면 정보의 안정성과 검색 편의성을 모두 잃기 쉽습니다. LightVela의 메모리는 대화가 바뀌어도 맥락을 이어 줍니다. 콘솔의 메모리 페이지에서는 `Memory`와 `User Profile` 탭에 보관된 내용을 확인하고 용량 한도를 조정할 수 있으며, 항목 추가와 삭제는 주로 Hermes와의 대화로 처리합니다. 클라우드 스토리지는 파일을 업로드·생성·정리·다운로드·이름 변경·삭제할 수 있는 작업 공간이며, 파일 하나의 최대 크기는 1GB입니다. 비밀번호, 키, 불필요한 민감 정보는 장기 메모리에 저장하지 마세요.

## 대상 독자

이 방식은 비서에게 모든 문서를 외우게 하지 않으면서도 사용자의 선호도와 반복 업무를 이해하게 하려는 사람에게 적합합니다. 진행 중인 프로젝트, 개인 연구, 학습 노트, 고객 업무처럼 같은 맥락을 여러 차례 다시 활용하는 워크플로에 유용합니다.

목표는 완벽한 자료 보관소를 만드는 것이 아닙니다. 중요한 맥락을 쉽게 찾고, 그중 오래 유지해야 할 내용을 Hermes가 일관되게 따르도록 하는 것입니다.

## 전제 조건

- 실행 중인 Hermes Agent와 콘솔 또는 연결된 채널에서 대화할 수 있는 환경.

- 정보를 보관하는 두 위치에 대한 기본 이해: 장기 맥락을 위한 [메모리 관리](../configuration/memory.md), 파일과 폴더를 위한 [클라우드 스토리지](../configuration/files.md).

- 보유한 모든 파일을 무작정 모은 목록이 아니라 실제로 반복해서 참고하는 소규모 자료 모음.

- Hermes가 유지하거나 검토하기를 원하는 항목에 대한 명확한 개인정보 보호 경계.

## 단계와 핵심 개념

### 1. 안정적인 컨텍스트와 참고 자료를 분리합니다

선호하는 글쓰기 방식, 시간대, 지속적인 역할, 반복되는 목표, 프로젝트 처리 규칙처럼 앞으로의 대화에 계속 영향을 줄 사실은 메모리에 넣으세요. 브리프, 회의록, 초안, 연구 파일처럼 내용이 계속 바뀌는 자료는 클라우드 스토리지에 보관합니다.

예를 들어 Hermes에 다음과 같이 말할 수 있습니다.

```text
Remember that I prefer research notes to separate facts, assumptions,
and open questions. Use that structure whenever we review a project.
```

모든 원문을 메모리에 저장하게 하는 것이 목적은 아닙니다. Hermes가 해당 문서를 어떤 방식으로 처리해야 하는지 오래 유지되는 기준을 알려 주는 것이 핵심입니다.

### 2. 반복해서 사용할 파일을 정리합니다

실제 작업 방식에 맞춰 클라우드 스토리지에 간단한 폴더 구조를 만드세요. 고객, 프로젝트, 강의, 연구 질문별로 폴더를 나누고 의미가 분명한 이름을 사용해 관련 자료를 함께 보관합니다.

파일과 관련하여 도움이 필요하면 Hermes에게 무엇을 하려는지 알려주고 관련 자료를 식별하세요. 예를 들면:

```text
Help me prepare for this project review. Use the latest brief and my
meeting notes, then list unresolved decisions and questions.
```

![프로젝트 파일이 있는 클라우드 스토리지 폴더](../images/use-case-memory-knowledge-storage.png)

### 3. 메모리가 항상 정확하다고 가정하지 말고 검토합니다

메모리 관리 페이지를 주기적으로 열어 `Memory`와 `User Profile` 탭을 확인하세요. 사용자 프로필은 사용자가 누구인지에 관한 안정적인 정보를, 메모리는 Hermes와 협업하며 쌓인 유용한 경험과 업무 맥락을 담습니다.

선호도가 바뀌면 대화 중에 명확하게 말하세요.

```text
I no longer want long weekly updates. Please forget that preference
and keep weekly summaries to five bullets.
```

메모리는 최신 상태를 유지할 때 가장 잘 작동합니다. 두 번째 충돌 명령을 추가하는 대신 Hermes를 잘못된 방향으로 이끄는 컨텍스트를 제거하거나 수정하십시오.

### 4. 검토한 지식을 실제 작업에 활용합니다

[채팅](../configuration/agent-chat.md) 페이지나 연결된 채널에서 문서와 메모리를 구체적인 작업으로 연결하세요. 비교표, 개요, 미해결 질문 목록, 특정 회의용 요약처럼 결과 형태를 명확히 요청하면 Hermes가 올바른 맥락을 사용했는지 확인하기 쉽습니다.

검토가 반복되는 리듬을 따르는 경우 [자동 작업](../configuration/automation.md)를 통해 폴더를 다시 방문하거나 정기적인 요약을 준비하도록 상기시켜 줄 수 있습니다. 광범위하고 개방형 작업을 부여하기보다는 간단한 알림이나 요약으로 시작하십시오.

## FAQ

### 메모리와 클라우드 스토리지의 차이점은 무엇인가요?

메모리는 Hermes가 사용자와 지속적인 협업 방식을 이해하도록 돕는 장기 맥락입니다. 클라우드 스토리지는 사용자가 관리하는 파일과 폴더를 보관합니다. 중요한 규칙과 선호도는 메모리에, 원본 자료는 파일로 두세요.

### Hermes는 자동으로 모든 파일을 장기 메모리로 처리합니까?

아니요. 구분을 의도적으로 유지하세요. 지속적인 컨텍스트를 위해 메모리 관리를 사용하고, 특정 작업 중에 참조하고 싶은 자료를 정리하려면 클라우드 스토리지를 사용하세요.

### Hermes에게 무언가를 잊어 달라고 요청할 수 있나요?

예. 더 이상 보관해서는 안 되는 내용을 Hermes에 알려주고 변경 사항을 확인하려면 관련 메모리 또는 사용자 프로필 정보를 검토하세요.

### 메모리에 무엇을 먼저 넣어야 하나요?

시간대, 커뮤니케이션 스타일, 역할, 활성 우선순위, 반복 작업에 선호하는 형식 등 거의 모든 대화의 질을 바꾸는 기본 설정부터 시작하세요.
