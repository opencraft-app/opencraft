# Hermes Agent로 일일 요약을 만드는 방법

## 요약

**일일 요약의 가치는 길이가 아니라 사용자가 요청하기 전에 적절한 컨텍스트를 전달하는 데 있으며, 수동 검토를 저장된 자동 작업으로 전환하면 이를 구현할 수 있습니다.** 네 가지가 필요합니다. 모델이 구성된 클라우드 Hermes Agent, 결과를 받을 연결 채널, 정보 수집을 위한 선택적 스킬, 그리고 자동 작업입니다. 자동 작업의 필드는 이름, 일정, 작업 지침, 활성 시간 범위, 알림 채널입니다. 성공 여부는 작업 지침에 달려 있습니다. 실행 시점에는 내용을 확인해 줄 사용자가 없으므로 프롬프트 자체에 목표, 범위 제한(기간 및 항목 수), 출력 형식, 보고할 내용이 없을 때의 처리 방법을 모두 담아야 합니다. 먼저 채팅에서 프롬프트를 수동으로 테스트한 뒤 자동 작업을 만들고, 첫 실제 실행이 끝나면 출력을 검토하세요.

![Hermes Agent가 전달한 일일 요약](../images/use-case-daily-summaries.webp)

## 이 활용 사례가 필요한 사용자

프로젝트, 메모, 파일 또는 반복 대화의 업데이트를 정기적으로 훑어보고 더 짧은 시작점을 원하는 사용자를 위한 활용 사례입니다. 개인 아침 브리핑, 일일 프로젝트 요약, 학습 기록, 후속 조치에 집중한 목록에 적합할 수 있습니다.

첫 요약은 목적을 좁게 잡는 것이 좋습니다. “모든 것을 요약해 줘”는 대개 너무 광범위합니다. “이 프로젝트의 변경 사항, 결정, 차단 요소, 다음 조치를 강조해 줘”처럼 요청하면 결과를 판단하고 개선하기가 훨씬 쉽습니다.

## 사전 요구 사항

- 실행 중인 Hermes Agent와 요약을 받을 연결 채널.

- 정상 작동하는 모델 설정 또는 체험 크레딧. Hermes가 응답하지 못하면 [모델 구성](../configuration/model.md)을 참고하세요.

- 명확한 컨텍스트 출처. 대화에 붙여넣는 자료, 클라우드 스토리지에서 관리하는 파일, 신뢰할 수 있고 관련성 높은 스킬이 접근하는 정보 등이 될 수 있습니다.

- 수동 프롬프트 없이 요약을 실행하려는 경우 선택적인 자동 작업 일정.

## 단계 및 핵심 개념

### 1. 요약이 도울 의사 결정 하나 정하기

먼저 요약이 필요한 순간을 정의하세요. 무엇을 먼저 작업할지 결정하거나, 프로젝트가 막혔는지 확인하거나, 하루 자리를 비운 뒤 진행 상황을 파악하는 경우가 있습니다.

출처와 출력 형식을 모두 정의하는 지침을 Hermes에 제공합니다.

```text
When I share project updates, summarize them in four sections:
what changed, decisions made, blockers, and the three next actions.
Keep it under 250 words and flag anything urgent.
```

이렇게 하면 일반적인 요청이 매일 비교할 수 있는 반복 가능한 형식으로 바뀝니다.

### 2. 원본 자료를 의도적으로 준비하기

Hermes는 사용자가 구성한 기능을 통해 받거나 접근할 수 있는 정보만 요약할 수 있습니다. 수동 워크플로라면 관련 업데이트를 대화에 붙여넣거나 전달하세요. 파일 기반 작업이라면 [클라우드 스토리지](../configuration/files.md)에 자료를 정리하고 현재 검토에서 중요한 문서 또는 폴더를 Hermes에 알려 주세요.

외부 데이터 소스가 필요하다면 신뢰할 수 있는 출처에서 적합한 스킬을 선택하고 사용 전에 동작을 확인하세요. [스킬 구성](../configuration/skill.md)은 일반적인 채팅을 넘어 Hermes를 확장하는 방법을 설명합니다.

![일일 요약을 위한 클라우드 스토리지 자료](../images/use-case-daily-summary-storage.png)

### 3. 먼저 일반 대화에서 출력 테스트

일정을 설정하기 전에 Hermes에 수동으로 요약을 요청하세요. 각 섹션이 유용한지, 문체가 충분히 간결한지, 중요한 세부 정보가 빠지지 않았는지 확인합니다.

다음과 같이 다듬을 수 있습니다.

```text
Put deadlines first.
```

```text
Do not repeat completed work unless it affects a next action.
```

```text
End with one question I should answer before tomorrow.
```

[채팅](../configuration/agent-chat.md) 페이지에서 지침을 반복해서 다듬은 뒤 반복 작업으로 전환하는 것이 좋습니다.

### 4. 이미 정상 작동하는 버전에 일정 설정

수동 프롬프트가 신뢰할 수 있는 결과를 만들면 자동 작업을 생성합니다. 구체적인 시간과 명시적인 지침을 설정하고, 결과를 전송하려면 연결된 알림 채널을 선택합니다.

```text
Every weekday at 6:00 PM, prepare a daily project summary from the
updates I shared today. Include changes, blockers, and the three most
important next actions. Send it as concise bullet points.
```

[자동 작업](../configuration/automation.md)에서 설정하세요. 처음 몇 차례 실행 결과를 검토하고 요약이 너무 광범위하거나 길거나 필요한 컨텍스트가 빠졌다면 지침 문구를 조정하세요.

## FAQ

### Hermes가 어떤 정보든 자동으로 요약할 수 있나요?

Hermes가 대화에서 받을 수 있거나, 구성된 파일 및 스킬을 통해 접근할 수 있거나, 설정된 워크플로로 얻을 수 있는 정보만 가능합니다. 출처를 명확히 하고 외부 액세스에는 신뢰할 수 있는 스킬을 사용하세요.

### 요약이 너무 일반적인 이유는 무엇인가요?

지침의 범위가 너무 넓을 가능성이 큽니다. 대상 사용자, 출처, 기간, 출력 섹션을 지정하세요. 일반적인 요약을 요청하는 것보다 결정, 차단 요소, 다음 조치를 요청하면 대개 더 실행 가능한 결과를 얻을 수 있습니다.

### 요약 일정을 바로 설정해야 하나요?

아니요. 먼저 프롬프트를 수동으로 테스트하세요. 좋은 결과를 구분할 수 있게 된 뒤 일정을 설정하면 유용하지 않은 형식을 고정하지 않고 시간을 절약할 수 있습니다.

### 요약이 도착하지 않으면 어떻게 해야 하나요?

자동 작업 상태와 알림 채널을 확인한 뒤 Hermes가 일반 대화에서 여전히 답할 수 있는지 점검하세요. 필요하면 다른 작업을 만들기 전에 [진단](../configuration/diagnostics.md)을 확인하세요.
