# 모델 전환

## 요약

**모델 전환을 사용하면 구성해 둔 모델 가운데 Hermes Agent가 현재 사용할 모델을 선택할 수 있습니다. 작업에 따라 속도, 성능, 비용 특성 또는 공급자 가용성이 달라져야 할 때 새 에이전트를 만드는 대신 모델을 전환합니다. 페르소나, 메모리, 스킬, 예약 작업은 모두 모델 외부에 저장되므로 모델을 바꾸면 추론 엔진만 교체됩니다. 아무것도 사라지거나 초기화되지 않으며 에이전트는 계속 사용자를 기억합니다. 각 에이전트에서는 한 번에 정확히 하나의 모델만 활성화됩니다.**

---

모델 전환을 사용하면 Hermes Agent가 다음 작업에 사용할 구성된 모델을 선택할 수 있습니다. 새 에이전트를 만들지 않고도 작업에 필요한 속도, 성능, 비용, 공급자 가용성의 균형에 맞춰 모델을 바꾸세요.

## 이 페이지에서 다루는 내용

- 사용 가능한 모델을 두 개 이상 준비하기
- 에이전트의 활성 모델 선택하기
- Chat에서 변경 사항 확인하기
- 목록에 나타나지 않거나 응답하지 않는 모델 문제 해결하기

> **알아 두세요:** 에이전트에서는 한 번에 하나의 모델만 활성화됩니다. 활성 모델을 전환해도 에이전트의 메모리, 클라우드 스토리지 파일, 스킬, 예약 작업은 삭제되지 않습니다.

## 시작하기 전에

1. 업데이트할 에이전트를 엽니다.
2. 대상 모델이 이미 구성되어 있고 계정에서 사용할 수 있는지 확인합니다. 그렇지 않다면 먼저 [모델 구성](./model.md)을 따르세요.
3. 새 모델이 정상적으로 응답하는지 확인할 간단한 테스트 프롬프트를 준비합니다.

## 활성 모델 전환

1. **Agents**를 열고 에이전트를 선택합니다.
2. **Models** 섹션을 엽니다.
3. 에이전트가 사용할 구성된 모델을 선택합니다.
4. 변경 사항을 저장하거나 적용한 뒤 에이전트의 활성 설정 업데이트가 끝날 때까지 기다립니다.

![LightVela 콘솔의 모델 공급자 선택기](../images/4-1-en.webp)

모델을 처음 선택하는 경우 [모델 구성](./model.md)에서 지원 공급자 또는 사용자 지정 모델을 추가한 뒤 이 페이지로 돌아오세요.

## 변경 사항 확인

[채팅](./agent-chat.md)을 열고 다음과 같이 짧고 위험도가 낮은 프롬프트를 보냅니다.

```text
Reply with the name of the current model if it is available, then summarize this sentence in one line: Model switching is ready.
```

에이전트가 정상적으로 응답하고 에이전트 콘솔에 표시된 모델이 선택한 모델과 일치하는지 확인합니다. 에이전트가 업데이트되는 동안 첫 응답이 조금 늦어진다면 잠시 기다린 뒤, 다른 설정을 바꾸기 전에 한 번 다시 시도하세요.

## 모델을 전환하기 좋은 시점

| 상황 | 고려할 사항 |
| --- | --- |
| 초안을 더 빠르게 작성해야 함 | 짧고 반복적인 작업에 맞는 구성된 모델을 선택합니다. |
| 더 강력한 추론이나 코드 지원이 필요한 작업 | 해당 유형의 작업용으로 구성한 모델을 선택합니다. |
| 공급자를 사용할 수 없거나 속도 제한에 걸림 | 구성된 다른 모델로 전환한 뒤 Chat에서 테스트합니다. |
| 출력 품질을 비교하고 있음 | 전환할 때마다 같은 짧은 프롬프트를 실행해 결과를 비교합니다. |

모델 전환은 향후 응답에 사용할 엔진을 변경합니다. 대화 기록을 옮기거나 [클라우드 스토리지](./files.md)의 파일을 다시 쓰거나 [스킬](./skill.md)과 [예약 작업](./automation.md)을 변경하지 않습니다.

Hermes Agent와 별도로 플러그인 우선 에이전트 환경을 살펴보려면 [DeepSeek Harness](./deepseek-harness.md)를 참고하세요.

## 모델 전환이 작동하지 않는 경우

1. [모델 구성](./model.md)으로 돌아가 대상 모델, 자격 증명, 공급자 설정이 모두 완료되었는지 확인합니다.
2. 해당 모델을 계정에서 사용할 수 있고 공급자 할당량 또는 크레딧이 충분한지 확인합니다.
3. 정상 작동이 확인된 모델을 선택해 Chat에서 테스트합니다.
4. 에이전트가 여전히 응답하지 않으면 모델 설정을 초기화하기 전에 [진단](./diagnostics.md)을 열어 최근 로그를 확인합니다.

> **팁:** 한 번에 하나만 변경하세요. 전환할 때마다 테스트하면 모델, 모델 설정, 작업 자체 중 어디에 문제가 있는지 훨씬 쉽게 구분할 수 있습니다.

## FAQ

### 원하는 모델이 목록에 표시되지 않는 이유는 무엇인가요?

구성이 완료된 모델만 선택할 수 있습니다. [모델 구성](./model.md)에서 모델을 추가하거나 설정을 마친 뒤 Models 섹션으로 돌아오세요.

### 모델을 전환하면 에이전트 메모리가 삭제되나요?

아니요. 활성 모델만 변경되고 에이전트의 메모리와 저장된 설정은 그대로 유지됩니다. 메모리는 [메모리](./memory.md)에서 별도로 확인할 수 있습니다.

### 결과가 마음에 들지 않으면 이전 모델로 돌아갈 수 있나요?

네. 구성된 다른 모델을 선택하고 변경 사항을 적용한 뒤 같은 프롬프트로 테스트하세요. 프롬프트를 동일하게 유지하면 더 유용한 비교 결과를 얻을 수 있습니다.
