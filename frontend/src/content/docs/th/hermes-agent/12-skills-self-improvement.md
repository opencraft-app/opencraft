## สรุป

**เอเจนต์จะพัฒนาด้วยการใช้งาน ไม่ใช่เพราะมันอัปเกรดตัวเองอย่างลึกลับในเบื้องหลัง แต่เป็นเพราะสิ่งสองประเภทถูกเก็บรักษาในรูปแบบที่มีโครงสร้าง: ข้อเท็จจริงที่เสถียรจะกลายเป็นความจำ (Memory) และวิธีการที่นำกลับมาใช้ใหม่ได้จะถูกบันทึกเป็นทักษะ (Skills) จากนั้นจะถูกโหลดเมื่อสถานการณ์ตรงกับ ความจำทำให้มันรู้ว่าอะไรเกิดขึ้น — ถูกเรียกคืนเมื่อคำถามตรงกัน ทักษะทำให้มันรู้ว่าครั้งต่อไปควรทำอะไร — ถูกโหลดเมื่อสถานการณ์ตรงกัน ตัวกระตุ้น รูปแบบ และอัตราการเปลี่ยนแปลงของพวกมันแตกต่างกันทั้งหมด ซึ่งเป็นเหตุผลว่าทำไมจึงไม่สามารถผสานรวมกันได้ Hermes ให้ `/learn` เพื่อให้เอเจนต์สามารถกลั่นกรองกระบวนการที่ได้รับการพิสูจน์จากเซสชันปัจจุบันเป็น `SKILL.md` โดยมี `/skills pending` สำหรับการตรวจสอบ ดังนั้น การปรับปรุงตัวเองจะไม่กลายเป็นการแก้ไขตัวเองอย่างไม่จำกัด ทักษะที่ถูกต้องต้องระบุสี่สิ่ง: เมื่อใดควรใช้มัน ขั้นตอนใดที่ต้องปฏิบัติตาม รูปแบบความสำเร็จเป็นอย่างไร และขอบเขตใดที่ต้องไม่ถูกละเมิด สิ่งที่สำคัญไม่ใช่ว่าจะบันทึกได้มากแค่ไหน แต่คือการที่มันคงอยู่ สามารถตรวจทานได้, ใช้ซ้ำได้, และปรับปรุงได้เมื่อสินค้ามีการเปลี่ยนแปลง.

## ประสบการณ์ที่ไม่สามารถนำกลับมาใช้ใหม่ได้ก็เป็นเพียงการสนทนา

ลองนึกย้อนกลับไปถึงเซสชันที่เป็นไปอย่างราบรื่นเป็นพิเศษ คุณและเอเจนต์ของคุณแก้ไขข้อผิดพลาดร่วมกัน หรือสร้างชุดบันทึกการปล่อยเวอร์ชันที่ดีจริง ๆ ระหว่างทางคุณแก้ไขมันสามถึงสี่ครั้ง: จำกัดขอบเขต รักษารูปแบบให้อยู่ในลักษณะเดียวกัน อย่าข้ามการตรวจสอบข้อใดข้อหนึ่ง ผลลัพธ์ที่ได้จึงมั่นคง

อีกหนึ่งสัปดาห์ต่อมา งานประเภทเดียวกันก็เข้ามา หากการแก้ไขเหล่านั้นอยู่แค่ในบันทึกการสนทนาของสัปดาห์ที่แล้ว คุณจะสังเกตว่าตัวเองพูดสิ่งเดียวกันอีกครั้ง — **การปรับแต่งนั้นไม่เคยกลายเป็นทรัพย์สิน เพียงแค่ค่าใช้จ่ายครั้งเดียวเท่านั้น**

นั่นคือคำถามที่แท้จริงเบื้องหลัง 'ยิ่งใช้ยิ่งดี' มันไม่เกี่ยวกับการที่เอเจนต์ฉลาดขึ้นอย่างลึกลับ มันเกี่ยวกับ **สิ่งที่ได้รับการพิสูจน์แล้วถูกเก็บรักษาในรูปแบบที่มีโครงสร้าง** สิ่งที่คุณเก็บ วิธีที่คุณเก็บ และที่ที่มันอยู่ เป็นตัวกำหนดว่าการสะสมเป็นเรื่องจริงหรือว่าทุกเซสชันเริ่มใหม่ทั้งหมด

## 1. สองประเภทของการสะสม ซึ่งไม่ควรสับสน

เอเจนต์สะสมสิ่งที่แตกต่างกันสองประการโดยพื้นฐาน

| การสะสม | สิ่งที่จัดเก็บ | วิธีการใช้งาน | อัตราการเปลี่ยนแปลง |
|---|---|---|---|
| **ความทรงจำ** | ข้อเท็จจริง ความชอบ ข้อสรุป ประวัติศาสตร์ | เรียกใช้เมื่อเกี่ยวข้องกับคำถามปัจจุบัน | สูง; อาจมีการเพิ่มข้อมูลในเกือบทุกเซสชัน |
| **ทักษะ** | สถานการณ์ ขั้นตอน ขอบเขต การตรวจสอบ | โหลดและดำเนินการเมื่อมีสถานการณ์ตรงกัน | ต่ำ; อาจคงอยู่นิ่งเป็นเดือน |

คู่ตัวอย่างที่ตรงกัน:

- “ผู้ใช้นี้ชอบสรุปผลก่อน” → **ความจำ** มันเป็นข้อเท็จจริงเกี่ยวกับคุณ  
- “ก่อนเขียนบันทึกการปล่อย ให้ตรวจสอบหมายเลขเวอร์ชันและตรวจสอบว่าลิงก์ทุกอันสามารถใช้งานได้” → **ทักษะ** มันเป็นขั้นตอนที่ต้องทำทุกครั้งเมื่อมีงานประเภทนั้นปรากฏ

พวกเขาไม่สามารถรวมกันได้ อย่างน้อยก็ด้วยสามสาเหตุ: **ตัวกระตุ้นที่ต่างกัน** (การจับคู่คำค้นกับการจับคู่สถานการณ์), **รูปแบบที่ต่างกัน** (รายการสั้นกับขั้นตอนที่เรียงลำดับ), และ **อัตราการเปลี่ยนแปลงที่ต่างกัน** (รายวันกับรายเดือน) การผสมขั้นตอนที่มั่นคงเข้ากับรายการข้อเท็จจริงที่เปลี่ยนแปลงเร็วจะทำให้ส่วนที่มั่นคงหายไป สำหรับข้อโต้แย้งทั้งหมด ดูได้ที่ "ความทรงจำไม่ใช่ทักษะ: วิธีที่เอเจนต์ Hermes แยกความทรงจำข้อเท็จจริงและความทรงจำกระบวนการ".

ความแตกต่างนี้มีประโยชน์ในทางปฏิบัติทันที: **เมื่อคุณพบว่าตัวเองกำลังแก้ไขพฤติกรรมแบบเดียวกันซ้ำแล้วซ้ำเล่า สิ่งที่คุณต้องการคือทักษะ ไม่ใช่ข้อเท็จจริงเพิ่มเติมในความทรงจำ**

## 2. ทักษะเป็นอย่างไร

ใน Hermes ทักษะโดยปกติคือ `SKILL.md` ที่มี YAML frontmatter ระบุทริกเกอร์และรายละเอียดสนับสนุน โดยประมาณ:

```yaml
---
name: release-note-format
trigger:
  when: "user asks to write release notes"
---

# Standard procedure for release notes

1. Confirm the version number and release date
2. Group entries as Added / Fixed / Changed
3. Verify every external link resolves
4. Check for internal project names or ports; replace with placeholders
5. Confirm length fits the publishing channel's limits
```

`trigger` คือสิ่งที่สำคัญ: มันหมายความว่าคุณไม่ต้องเรียกใช้งานทักษะด้วยตนเอง เมื่อมีการตรวจพบสถานการณ์ที่ตรงกัน ทักษะจะถูกโหลดโดยอัตโนมัติในฐานะคำสั่งลำดับความสำคัญสูงที่คอยชี้นำการทำงานนั้น

Hermes เพิ่มสองชั้นของการจัดระเบียบ:

- **ชุดทักษะ (Skill Bundle)** — แพ็กเกจของทักษะที่เกี่ยวข้องเพื่อเปิดใช้งาน ปิดใช้งาน หรือแบ่งปันเป็นกลุ่ม ชุด 'release pipeline' อาจมีการตรวจสอบก่อนเปิดตัว รูปแบบบันทึกการเปลี่ยนแปลง และขั้นตอนการย้อนกลับ  
- **`fallback_for_toolsets`** — ทักษะหนึ่งสามารถประกาศตัวเองว่าเป็นการสำรองเมื่อการเรียกใช้ชุดเครื่องมือที่กำหนดล้มเหลว ดังนั้นเส้นทางล้มเหลวจึงมีขั้นตอนที่กำหนดไว้ด้วย

ด้วยกัน สิ่งเหล่านี้เปลี่ยนทักษะจาก SOPs ที่แยกส่วนให้กลายเป็นวิธีการทำงานที่สามารถประกอบกันได้

## 3. `/learn`: เปลี่ยนการทำงานที่ประสบความสำเร็จครั้งหนึ่งให้กลายเป็นวิธีการ

การจับทักษะไม่จำเป็นต้องออกจากการสนทนาเพื่อเขียนไฟล์ Hermes มี `/learn` ซึ่งช่วยให้เอเจนต์สกัดขั้นตอนที่คุ้มค่าที่จะเก็บจากเซสชันปัจจุบันไปยัง `SKILL.md` ใหม่

คุณค่าของการออกแบบนี้คือ **การจับข้อมูลเกิดขึ้นในขณะที่ความจำยังสดใหม่** ทันทีหลังจากความร่วมมือที่ประสบความสำเร็จ ทั้งคุณและเอเจนต์ต่างรู้ขั้นตอนใดที่สำคัญและการแก้ไขใดที่จำเป็น เขียนสรุปอีกครั้งหลังจากหนึ่งสัปดาห์และรายละเอียดเหล่านั้นก็หายไปแล้ว

แต่การกลั่นกรองอัตโนมัติสร้างปัญหาที่ต้องได้รับการแก้ไข: **ถ้าเอเจนต์สามารถเพิ่มกฎพฤติกรรมให้กับตัวเองได้ตามต้องการ พฤติกรรมของมันจะไม่สามารถคาดเดาได้** Hermes จัดการเรื่องนี้ด้วยขั้นตอนการตรวจสอบ — ตรวจสอบทักษะที่รอดำเนินการผ่าน `/skills pending` และตัดสินใจว่าจะนำมาใช้หรือไม่ ซึ่งสิ่งนี้สะท้อนถึง `/memory pending` ทางด้านความจำ

**การพัฒนาตนเองไม่ใช่การปรับเปลี่ยนตนเองอย่างไม่จำกัด** หนทางที่เชื่อถือได้คือวิธีใหม่ต้อง **กลายเป็นกฎที่สามารถตรวจสอบได้** ก่อน แล้วจึงมีผลหลังจากยืนยันแล้ว ซึ่งนั่นคือสิ่งที่ทำให้การเติบโตของความสามารถอธิบายได้ ใช้ซ้ำได้ และแก้ไขได้

## 4. สี่สิ่งที่ทักษะที่ดีต้องระบุ

นี่คือสิ่งที่แยกทักษะที่มีประโยชน์ออกจากทักษะที่เป็นอันตราย หากละเว้นหนึ่งในสี่ข้อ ทักษะนั้นจะทำงานผิดพลาดในการปฏิบัติ

**ก่อนอื่น เมื่อใดควรใช้มัน** สถานการณ์ที่กระตุ้นต้องเฉพาะเจาะจง “เมื่อจัดการเอกสาร” กว้างเกินไปและจะปรากฏในบริบทที่ไม่เหมาะสม; “เมื่อผู้ใช้ขอหมายเหตุการปล่อย” เฉพาะเจาะจงเพียงพอ Skill ที่กว้างเกินไปแย่กว่าการไม่มี Skill เพราะมันรบกวนงานที่ไม่เกี่ยวข้อง

**ประการที่สอง ขั้นตอนที่ต้องปฏิบัติ** ขั้นตอนต้องเรียงลำดับและสามารถดำเนินการได้ “ให้ความสำคัญกับคุณภาพ” ไม่ใช่ขั้นตอน แต่ “ตรวจสอบว่าลิงก์ภายนอกทั้งหมดใช้งานได้” เป็นขั้นตอน วิธีทดสอบ: บุคคลอื่นสามารถปฏิบัติตามทักษะนี้และได้ผลลัพธ์ที่โดยรวมสอดคล้องกันหรือไม่?

**ประการที่สาม ลักษณะของความสำเร็จ** หากไม่มีเกณฑ์ความสำเร็จ เอเจนต์จะไม่สามารถตรวจสอบตนเองได้ และคุณก็ไม่สามารถตัดสินได้ว่าการดำเนินการนั้นยอมรับได้หรือไม่ ทำให้สามารถตรวจสอบได้ เช่น “มีทั้งสามกลุ่มครบ แต่ละกลุ่มมีอย่างน้อยหนึ่งรายการ หรือมีบันทึกชัดเจนว่ากลุ่มนั้นว่าง”

**ประการที่สี่ ขอบเขตใดบ้างที่ไม่ควรละเมิด** ระบุข้อห้ามอย่างชัดเจน เช่น “ไม่ใช้ชื่อโปรเจกต์ภายในจริงหรือพอร์ตในตัวอย่าง” ขอบเขตเป็นส่วนที่มักถูกละเว้นมากที่สุดของทักษะ และเป็นแหล่งที่มาของเหตุการณ์ผิดพลาดที่พบบ่อยที่สุด

ทักษะทั้งสี่มีลักษณะร่วมอย่างหนึ่ง: **พวกมันอ่านได้ดีทั้งต่อมนุษย์และต่อเอเจนต์** เพราะคุณสามารถเข้าใจสิ่งที่มันทำ คุณจึงสามารถแก้ไขมันได้อย่างแม่นยำเมื่อมันผิดพลาด — ซึ่งเป็นเงื่อนไขเบื้องต้นในการสามารถแก้ไขได้เลย

## 5. สามขั้นตอนที่ทำให้การสะสมคุ้มค่า

การจับภาพไม่ใช่การกระทำเพียงครั้งเดียว; มันเป็นกระบวนการที่มีลำดับ การข้ามขั้นตอนจะทำให้คุณภาพลดลง

**ขั้นตอนที่หนึ่ง: ทำให้เห็นว่าขั้นตอนนั้นใช้ได้จริงในงานจริงก่อน** อย่าเขียนทักษะจากจินตนาการ ขั้นตอนที่ไม่เคยถูกใช้กับงานจริงจะทำให้ข้อผิดพลาดแน่นแฟ้นขึ้นเมื่อตอนบันทึก ทำมันสักครั้ง และจดบันทึกการแก้ไขตลอดทาง

**ขั้นที่สอง: บันทึกขั้นตอนที่มั่นคงและสามารถนำกลับมาใช้ใหม่ได้** โปรดสังเกตคุณสมบัติทั้งสอง — **มั่นคง** (จะไม่เปลี่ยนแปลงในสัปดาห์หน้า) และ **สามารถนำกลับมาใช้ใหม่** (สามารถใช้ได้เกินกว่ากรณีเฉพาะนี้) ขั้นตอนแบบใช้ครั้งเดียวไม่คุ้มที่จะบันทึก การบำรุงรักษาจะมีค่าใช้จ่ายสูงกว่าผลตอบแทน

**ขั้นที่สาม: อัปเดตทักษะเมื่อผลิตภัณฑ์ เครื่องมือ หรือ นโยบายมีการเปลี่ยนแปลง** นี่คือขั้นตอนที่มักถูกข้ามไปมากที่สุด ทักษะที่เขียนเมื่อหกเดือนที่แล้วซึ่งอ้างอิงถึงจุดเข้าใช้งานที่ย้ายไปหรือขีดจำกัดที่ปรับแล้ว จะยังคงให้คำแนะนำที่ล้าสมัย **การนำประสบการณ์เก่ามาใช้อย่างไม่จำกัดนั้นอันตรายกว่าการไม่มีเลย**, เพราะมันมีความน่าเชื่อถือจากการที่เคยถูก 'พิสูจน์' แล้ว.

นิสัยการบำรุงรักษาที่ใช้งานได้จริง: เมื่อคุณพบว่าตัวเองต้องแก้ไขผลลัพธ์ของทักษะด้วยมือซ้ำๆ แสดงว่ามันหมดอายุแล้ว อัปเดตมันแทนการหาทางเลี่ยง

## 6. ข้อผิดพลาดที่พบบ่อย

| กับดัก | ปัญหา | ทำสิ่งนี้แทน |
|---|---|---|
| การเก็บกฎพฤติกรรมเป็นรายการความจำ | อาจเรียกคืนไม่ได้เมื่อมีการพลาดการค้นหา และถูกล้างออกโดยรายการใหม่ | เก็บกฎไว้ที่ `SOUL.md`, กระบวนการไว้ที่ทักษะ |
| การเขียนตัวกระตุ้นกว้าง ๆ “เพื่อต้องการให้ครอบคลุมมากขึ้น” | โหลดระหว่างงานที่ไม่เกี่ยวข้องและรบกวน | จำกัดให้เข้ากับสถานการณ์เฉพาะ |
| ขั้นตอนที่ไม่มีขอบเขต | ขั้นตอนทำงานถูกต้อง แต่ข้อมูลภายในอาจรั่วหรือเกินขีดจำกัด | เพิ่มข้อห้ามที่ชัดเจน |
| การจับทักษะจำนวนมากแต่ไม่เคยตัดทอน | ทักษะหมดอายุยังคงให้คำแนะนำผิดพลาด | ตรวจสอบเป็นระยะ; อัปเดตเมื่อต้องการ |
| คาดหวังการปรับปรุงด้วยตนเองโดยไม่ตรวจสอบ | พฤติกรรมไม่สามารถคาดเดาได้และยากต่อการวินิจฉัย | ยอมรับผ่าน `/skills pending` |
| การจับกระบวนการครั้งเดียว | ค่าใช้จ่ายในการบำรุงรักษาสูงกว่าประโยชน์ | จับเฉพาะกระบวนการที่มั่นคงและนำกลับมาใช้ได้ |

แถวที่สี่ควรได้รับการเน้น: **คุณค่าของห้องสมุดทักษะไม่ได้สัดส่วนกับขนาดของมัน** ทักษะที่หมดอายุอาจมีค่าใช้จ่ายมากกว่าทักษะดี ๆ สิบอัน เพราะมันโหลดโดยอัตโนมัติและดูน่าเชื่อถือ

## 7. วิธีการของ LightVela: วิธีการเป็นสินทรัพย์ของผู้ใช้ด้วย

Hermes ได้ทำให้การแยก Memory / Skill พร้อมสำหรับวิศวกรรมแล้ว แต่ยังคงมุ่งเป้าไปที่ผู้คนที่แก้ไข Markdown โดยตรง LightVela ใช้โมเดลที่โฮสต์บนคลาวด์และไม่เปิดเผยการทำงานระบบไฟล์ให้ผู้ใช้เห็น ดังนั้นการสะสมทั้งสองประเภทจึงทำงานดังนี้:

- **ทักษะมาจากตลาดสาธารณะ** — ทุกทักษะมาจาก Skills.sh และ ClawHub ตลาดทักษะที่แชร์โดย OpenClaw และ Hermes ดังนั้นคุณจึงไม่ต้องเขียนทักษะเหล่านั้นตั้งแต่เริ่มต้น  
- **ติดตั้งและจัดการทักษะในคอนโซล** — เรียกดูทักษะหรือตัวแพ็กเกจทักษะจาก Skills.sh และ ClawHub ติดตั้งทักษะเหล่านั้น และตรวจสอบที่แท็บ Installed การติดตั้งผ่านการสนทนายังคงเป็นอีกทางเลือกหนึ่ง; ตรวจสอบผลลัพธ์ก่อนใช้งาน  
- **สามารถดูหน่วยความจำในคอนโซล** — หน้าหน่วยความจำแสดงสิ่งที่เอเจนต์เก็บไว้และให้คุณปรับขีดจำกัดความจุได้; การเพิ่มและลบเกิดขึ้นผ่านการสนทนา  
- **เสถียรในทุกโมเดลและช่องทาง** — การสลับโมเดลจะไม่ล้างทักษะหรืองานที่ตั้งเวลาไว้ และทุกช่องทางที่เชื่อมต่อจะแชร์ทักษะและหน่วยความจำเหมือนกัน  
- **ความล้มเหลวสามารถติดตามได้** — เมื่อทักษะทำงานผิดพลาด ดูและส่งออกบันทึกล่าสุดใน Diagnostics (เลือกช่วงเวลา 1, 3, 6, 12 หรือ 24 ชั่วโมง) เพื่อค้นหาปัญหา

กล่าวอีกนัยหนึ่ง การใช้เอเจนต์บน LightVela หมายถึงการสะสมสองสิ่ง: ความทรงจำเกี่ยวกับคุณ และชุดทักษะที่ติดตั้งและตรวจสอบแล้ว **ทั้งสองอย่างมีประโยชน์ต่อคุณยาวนานกว่ารูปแบบใด ๆ เป็นการเฉพาะ**

## ประเด็นสำคัญ

- การเก่งขึ้นจากการใช้งานมาจากการสะสมอย่างเป็นระบบ ไม่ใช่การอัปเกรดตัวเองอย่างลึกลับ  
- ต้องแยกออกเป็นสองประเภท: **ความจำ (Memory)** เก็บข้อเท็จจริง (เรียกคืนเมื่อมีคำค้นตรงกัน) และ **ทักษะ (Skills)** เก็บวิธีการ (โหลดเมื่อสถานการณ์ตรงกัน)  
- เมื่อคุณแก้ไขพฤติกรรมเดียวกันซ้ำๆ ให้จับทักษะแทนการเพิ่มข้อเท็จจริงใหม่  
- `/learn` เก็บวิธีการเมื่อรายละเอียดยังสดใหม่; `/skills pending` ให้การทบทวน ดังนั้น **การปรับปรุงตัวเองไม่ใช่การแก้ไขตัวเองอย่างไม่สิ้นสุด**  
- ทักษะที่ดีต้องระบุสี่สิ่ง: **เมื่อใช้, ขั้นตอน, เกณฑ์ความสำเร็จ, และขอบเขต**  
- การจับทักษะมีสามขั้นตอน: พิสูจน์ในการทำงานจริง → จับขั้นตอนที่มั่นคงและนำกลับมาใช้ใหม่ได้ → อัปเดตเมื่อมีการเปลี่ยนแปลง **ทักษะที่หมดอายุอันตรายกว่าการไม่มีทักษะ**
