# LightVela vs セルフホストエージェント：どちらが最適ですか？

## 概要

**常時稼働するHermes Agentを、基盤となるコンピュータを管理せずに利用したい場合は、LightVelaがより適しています。** ランタイム、ツール、アップデート、ローカル環境を手動で制御したい場合は、自分のコンピュータでHermesを実行する方が良い選択です。最適な答えは、セットアップを運用したいのか、単にエージェントを使いたいのかによって異なります。

HermesはmacOS、Windows、Linux、WSL2などでローカルに実行できます。公式インストーラーはランタイムを設定した後、自分でモデルプロバイダー、ツール、メッセージングゲートウェイを選択できるようにします。[Hermesインストールガイド](https://hermes-agent.nousresearch.com/docs/getting-started/installation)はその方法を非常にわかりやすくしています。

> **分かりやすいことは、目立たないこととは同じではありません。** ローカルエージェントは制御権を与えてくれますが、同時に環境を整えておく責任も伴います。

## 概要

| あなたにとって重要なこと | Hermesを自分のコンピュータで実行する | LightVelaを使用する |
| - | - | - |
| **ハーメスが動作する場所** | 自分のマシン | 専用のクラウドランタイム |
| **日常的な管理** | ローカルの設定と環境を選択します | ホスティングされたコンソールでエージェントを管理します |
| **可用性** | コンピュータとプロセスを利用可能な状態に保ちます | ローカルデバイスに依存せずオンラインを維持するように設計されています |
| **設定の責任** | ランタイム、モデル、ツール、チャンネルを構成します | コアエージェント環境はあなたのためにホストされています |
| **最適** | スタックを所有することを楽しむビルダー | スタックを運用せずにHermesを使いたい人々 |

## 日常使用で何が変わるか

物の居場所を正確に知ることが好きなとき、ローカルルートは満足感があります。

Hermesをインストールし、モデルプロバイダーを選択し、ツールを有効にし、メッセージングアクセスが必要なときにゲートウェイを追加します。Hermes自身のクイックスタートでは、ゲートウェイ、スキル、音声、またはルーティングを追加する前に、まず一つのクリーンな会話を動作させることを推奨しています。これは、自己管理型セットアップにおいて理にかなったアドバイスです。[Hermesクイックスタート](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart/)は、ローカルインストールがボットや常時稼働のワークフローに成長することも示しています。

その柔軟性がポイントです。自分の環境で実験し、更新の方法を選び、すでに使用しているマシンを中心に構築することができます。

その代償は、普通の瞬間に後で現れます:

- **可用性:** エージェントを利用可能に保つには、コンピュータも利用可能な状態にしておく必要があります。
- **メンテナンス:** モデルの設定、ツール、ゲートウェイ、またはアップデートに注意が必要だと気づくのはあなたです。
- **範囲:** 「もう一つだけ」という考えが、個人の設定を徐々にあなたが維持するものに変えることがあります。

それはセルフホスティングを避ける理由にはなりません。ただ、それがあなたが受け入れる仕事なのです。

## LightVela がより適している場所

LightVelaは、マシン自体を操作するのではなく、Hermes Agentがあなたのために動作することを目的とする場合により意味を持ちます。

LightVelaはクラウドで専用のHermes Agentインスタンスを実行します。エージェントはローカルデバイスに依存せずオンラインのままになり、実際の操作部分は[モデル](https://lightvela.ai/docs/configuration/model), [チャンネル](https://lightvela.ai/docs/configuration)および[スキル](https://lightvela.ai/docs/configuration/skill)—コンソールから管理します。[LightVelaの概要](https://lightvela.ai/docs/overview)ホスト型モデルについて、分離されたランタイムやマルチチャネルアクセスを含めて説明します。

それにより、Hermes の利用感が変わります。既に会話しているチャネル、例えば[Telegram](https://lightvela.ai/docs/configuration/channel-telegram), [WhatsApp](https://lightvela.ai/docs/configuration/channel-whatsapp), [Discord](https://lightvela.ai/docs/configuration/channel-discord)や[Slack](https://lightvela.ai/docs/configuration/channel-slack)にエージェントを接続し、ノートパソコンを閉じていても使い続けることができます。意味のある選択は引き続き行えますが、個人用コンピュータを常時利用できる場所にする必要はありません。

多くの人にとって、有用な区別は簡単です:

> **LightVelaは制御する設定が少なくて済みます。セルフホスティングは設定に対するより多くの制御を与えます。**

エージェントを主に設定して作業に戻りたい場合、ホストされたコンソールが通常、より快適な出発点です。モデル、チャンネル、スキルも、[LightVela の構成概要](https://lightvela.ai/docs/configuration)。

## 自分のコンピュータでHermesを実行する方が適している場合

ランタイムの構築と制御がプロジェクトの一部である場合には、ローカル設定を選択してください。おそらくデスクトップワークフロー、ホームラボ、あるいは実践的なモデル実験のためです。

あなたはアップデート、認証情報、そして可用性を管理します。「自分のコンピュータ上で」ということは、すべてのモデル、ブラウザツール、または接続されたサービスがローカルになるわけではないので、制御している範囲を正確に把握してください。

## どちらを選ぶべきでしょうか？

次の場合はLightVelaを選んでください：

- **可用性を求める場合:** コンピュータに依存せず、Hermes をすぐに利用できる状態にしておきたい場合。
- **設定を好む場合:** エージェントの実行環境を維持するよりも、その設定を行いたい場合。
- **一つのコンソールを望む場合:** モデル、チャネル、スキルを管理するための明確な場所が欲しい場合。
- **すでにメッセージングアプリを使っている場合:** すでに使用しているチャンネルに適した常時利用可能なエージェントが欲しい。

自分のコンピュータで Hermes を選ぶ理由:

- **構築を楽しみたい場合:** ターミナル優先の設定や手を動かす実験が好き。
- **所有権が欲しい場合:** 自分の環境に合わせてランタイムを調整したい。
- **メンテナンスを受け入れられる場合:** モデルの設定、更新、ツール、可用性の管理ができる。

ある答えが普遍的に優れているふりをする必要はありません。質問の下にある質問から始めましょう：**私はインフラを運用したいのか、それとも必要なときにすぐ使えるエージェントが欲しいのか？**
