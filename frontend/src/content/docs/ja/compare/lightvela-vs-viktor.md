# LightVela vs Viktor.com：個人用AIエージェントを動かすならどちら？

## 概要

**長期メモリ、柔軟なモデル設定、メッセージングチャネル、スキル、定期タスクを備えた、常時利用可能な個人用AIパートナーが欲しいならLightVelaが適しています。** Slack、GitHub、Notion、Stripe、Salesforce、Google Adsなどの業務ツールを横断し、チームの共有ワークスペース内で働くAI同僚が必要ならViktor.comが適しています。

違いは単にどちらのAIが賢いかではありません。エージェントがどこに存在し、誰に属し、どの種類の仕事を担うよう設計されているかが判断軸です。

![個人用AIエージェントを動かすためのLightVelaとViktor.comの比較](../images/lightvela-vs-viktor.png)

## ひと目で比較

| 比較軸 | LightVela | Viktor.com |
| - | - | - |
| **主な役割** | 個人用クラウドAIエージェント | チーム向け共有AI同僚 |
| **主な画面** | Webコンソールとメッセージングチャネル | Slack、Microsoft Teams、Webアプリ、Discord |
| **メモリモデル** | 会話とチャネルをまたぐ個人用エージェントメモリ | 共有ワークスペースの文脈とメモリ |
| **連携** | メッセージングチャネル、スキル、スケジュールタスク、モデルプロバイダー | 3,200以上の業務ツール連携 |
| **設定方法** | サーバー保守不要のマネージドクラウドエージェント | Viktorを接続し、ツールを承認して仕事を委任 |
| **適する用途** | 個人支援と長期的な協働 | 複数ツールを横断する業務運用 |

## 本質的な違いは所有者

LightVelaは、長く使い続ける個人用エージェントを所有するという考えを中心にしています。Hermes Agentはクラウドで動き、個人端末がオフラインでも利用でき、対応するメッセージングチャネルからアクセスできます。メモリ、人格、モデル、スキル、スケジュールタスクは、1人のユーザーとの継続的な関係に合わせて設定されます。[LightVelaの概要](../01-overview.md)では、これらの要素の関係を説明しています。

Viktor.comは異なる方法を取ります。ViktorはSlackとMicrosoft Teams内に存在するAI同僚として説明され、チーム全体がメッセージを送り、チャネルへ招待し、ワークスペースの文脈を共有できます。現在の資料ではWebチャットとDiscordも説明されていますが、中心は個人用パートナーではなく共有作業環境です。

「自分の働き方を覚え、長く付き合うエージェントが欲しい」ならLightVelaが明確です。「会社のツールを横断し、全員のために動くAIが欲しい」ならViktorがその仕事に合わせて設計されています。

同じ所有境界は[LightVela vs Mira](./lightvela-vs-mira.md)にもあります。ただしMiraはTelegram会話から始まり、Viktorは共有業務ワークスペースと接続された運用から始まります。

## LightVelaが適している場合

普段のコミュニケーション場所をまたいでエージェントを利用したい場合、LightVelaが適しています。チャネルを接続し、モデルを設定し、[スキル](../configuration/skill.md)を追加し、定期的な[スケジュールタスク](../configuration/automation.md)を作成できます。サーバーを保守せず、同じエージェントにリマインダー、調査、情報整理、コンテンツ作業、日常会話を任せられます。

モデル層も柔軟です。対応するモデルプロバイダーを設定し、エージェントとの関係を作り直さずにモデルを変更できます。スキルはHermesの能力を拡張し、スケジュールタスクはいつ仕事を実行するかを決めます。

同じクラウド環境から別のエージェントランタイムを試す余地もあります。[DeepSeek Harness](../configuration/deepseek-harness.md)はHermes Agentとは別に管理されるサービスとして動作し、独自のWebUI、プロバイダー設定、プラグイン対応プロファイルを備えています。メインの個人用エージェントを置き換えず、プラグイン中心の環境を試したい場合に利用できます。

LightVelaでは次のような使い分けが可能です。

- メッセージングチャネルから質問する。
- 定期タスクをエージェントへ任せる。
- 特定ワークフロー向けのスキルを追加する。
- より広い文脈を失わずにモデルを変更する。
- Hermesを置き換えず、別のエージェントランタイムを試す。

トレードオフとして、LightVelaは1人と1体のエージェントとの関係が中心です。多数の業務システムへ書き込みを行うチーム全体のオペレーターが必要なら、Viktorの方が直接的です。

## Viktor.comが適している場合

Viktorの最大の強みは、業務ソフトウェアを横断する範囲です。公式資料ではCRM、分析、広告、エンジニアリング、財務、生産性ツールを含む3,200以上の連携を説明しています。[Viktorの連携ディレクトリ](https://viktor.com/integrations)では、企業の既存ツール群を横断する接続を確認できます。

依頼できる仕事も変わります。ワークフローの相談だけでなく、StripeとHubSpotの照合、Notionダッシュボードの更新、Linear課題のトリアージ、複数システムからのレポート作成などを依頼できます。

会話から定期作業を設定することもできます。SlackまたはTeamsでタスクを説明し、スケジュールを指定して確認すると、Viktorが繰り返し実行します。[スケジュールタスクの公式資料](https://viktor.com/docs/scheduled-tasks)で、この業務フローが説明されています。

技術チーム向けには、公開API、MCPサーバー、OpenAI／Anthropic互換アクセスがあります。非同期スレッド、実行、成果物、連携検索、利用状況、承認状態を扱う開発者向け機能により、エージェントをプログラム可能な業務フローへ組み込めます。

[セキュリティ資料](https://viktor.com/security)では、OAuthまたは安全なAPI接続、スコープ付きアクセス、機密操作前の承認、監査可能性、実行時にのみ資格情報を注入しモデルへ露出しない設計を説明しています。

トレードオフは共有所有です。複数の人と業務ツールが同じ運用文脈へ参加するワークスペースには価値がありますが、メモリ、ペルソナ、日々のルーチンが主に自分へ属する個人用エージェントとは異なる関係です。

## どちらを選ぶべきか

LightVelaが向いている条件：

- **個人用エージェントが欲しい：** 自分の習慣に合わせて役立つAIパートナーが必要。
- **継続性を重視する：** チーム全体の文脈より、長期メモリと1体の継続的な関係が重要。
- **メッセージングから使いたい：** 普段のチャネルからアクセスしたい。
- **設定を管理したい：** モデル、スキル、スケジュールタスク、振る舞いを自分のワークフローに合わせたい。
- **ランタイムを試したい：** 1つのクラウド環境でHermesと追加ランタイムを検証したい。

Viktor.comが向いている条件：

- **共有ワークスペースで働く：** Slack、Microsoft Teams、Discordが仕事の中心。
- **多人数で1体のAI同僚を使いたい：** チーム全員がメッセージを送り、チャネルへ招待したい。
- **業務ツールの幅が重要：** CRM、分析、財務、プロジェクト管理、開発ツールを接続したい。
- **ツール横断の実行が必要：** 回答の準備だけでなく業務操作を実行してほしい。
- **開発者向けアクセスが必要：** 公開API、MCP、SDK互換アクセスをワークフローに組み込みたい。

結論として、**個人向けの永続的なエージェント関係にはLightVela、業務ツールへ接続されたチーム向けAIオペレーターにはViktor.comが適しています。**
