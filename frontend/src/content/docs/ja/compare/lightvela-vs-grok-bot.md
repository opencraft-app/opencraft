# LightVela vs Grok Bot：個人用AIエージェントを動かすならどちら？

## 概要

**自分の習慣に合わせて設定し、再利用可能なスキルやスケジュールタスクを追加し、選んだチャネルから使い続けられる1体のHermes Agentが欲しいなら、LightVelaが適しています。** 複数のアプリを横断し、クラウドコンピューター上で並列に委任作業を進める永続的なAIチームメイトが必要なら、Grok Botが適しています。どちらも通常のチャットボットを超えていますが、中心となる仕事は異なります。

![個人用AIエージェントを動かすためのLightVelaとGrok Botの比較](../images/lightvela-vs-grok-bot.png)

## ひと目で比較

| 比較軸 | LightVela | Grok Bot |
| - | - | - |
| **最適な用途** | 長期的に使う個人用AIエージェント | アプリやWebサイトを横断する委任作業 |
| **中心となる体験** | 必要なときに使える、自分で設定したエージェント | チームメイトのように扱える永続的なBot |
| **設定の中心** | スキル、スケジュールタスク、メモリ、ペルソナ、モデル、チャネル | Bot、クラウドコンピューター、コネクター、ルーチン、承認 |
| **日常の利用方法** | メッセージングチャネルと永続的なエージェント環境 | Grok BotのデスクトップおよびiOS体験 |
| **強み** | 自分向けに継続改善する個人ワークフロー | ブラウザーやアプリ操作を伴う多段階作業 |

## 日常利用で変わること

違いは、1回のプロンプトでどちらが賢く見えるかではありません。エージェントが日常のどこに存在し、1体の永続的なアシスタントを育てたいのか、複数のBotへ仕事を委任したいのかが判断軸です。

LightVelaでは、クラウド上のHermes Agentを自分の働き方に合わせて設定し、必要が変わっても同じエージェントと会話を続けます。再利用可能な[スキル](../configuration/skill.md)を追加し、[スケジュールタスク](../configuration/automation.md)を設定し、[モデル](../configuration/model.md)を選び、普段使うチャネルへ接続できます。これにより、単発のやり取りを継続的なワークフローへ変えられます。

毎朝のブリーフィング、定期的なウォッチリスト、コンテンツ草稿、リマインダーなどを、毎回ゼロから組み直す必要はありません。LightVelaは、1体のエージェント、進化する1つの設定、支援方法を改善する1つの場所という継続性を中心に設計されています。

Grok Botは、より業務実行寄りの方向を目指しています。[xAIのGrok Bot概要](https://docs.x.ai/grok-bot/overview)では、Botを、永続的なクラウドコンピューター上でブラウザー、ファイルシステム、ターミナルを使える名前付きAIチームメイトとして説明しています。アプリやWebサイトを横断し、時間をまたいでコンテキストを保持し、承認が必要なときにユーザーへ戻ります。複数のBotはユーザー単位の1台のコンピューターを共有し、コンテキストを引き継ぎながら並列実行できます。

この仕組みは、多数のWebアプリを扱う広く複雑な仕事に向いています。一方、自分の習慣に合わせて少しずつ役立つようになる1体の個人用エージェントを求める場合は、LightVelaの方が焦点が明確です。この差は[LightVela vs Genspark](./lightvela-vs-genspark.md)にも似ていますが、Grok Botは永続的なコンピューターとBot間の引き継ぎによって、委任実行をさらに前面に出しています。

## LightVelaが適している場合

AIエージェントを自分の作業環境の一部として一貫して使いたいなら、LightVelaが適しています。複数のデジタル同僚を監督したいわけではなく、タスクごとに別のクラウドコンピューターを用意する必要もない場合です。

毎朝の情報確認、競合のウォッチ、製品更新からソーシャル投稿への変換、週次リサーチ要約などを任せられます。価値は1回の完璧な回答ではなく、役立ったやり取りを継続実行できる仕事へ変えられることにあります。

スキルは再利用可能な能力を与え、スケジュールタスクは決めた時刻に定型作業を実行します。朝のブリーフィングから始め、調査スキルを追加し、最も確認しやすいチャネルへ結果を送る、といった構成が可能です。

固定された製品体験を受け入れるのではなく、エージェントの役割を自分で設定したい場合にも向いています。モデル、推奨したい振る舞い、追加能力、表示するチャネルを選べます。[LightVelaの概要](../01-overview.md)では、これらの要素の関係を説明しています。

トレードオフは焦点の狭さです。LightVelaは1体のクラウドホスト型Hermes Agentとユーザーとの継続的な関係を中心にしています。未知のサイトへログインし、複数のツール内で完成した成果物まで作る広範なデスクトップ作業環境が必要なら、Grok Botの方が自然です。

## Grok Botが適している場合

ブラウザー操作や複数Botの同時作業を含め、複数のアプリを横断して仕事を完了させる必要がある場合、Grok Botが適しています。[xAIの公式発表](https://x.ai/news/introducing-grok-bot)では、BotがアプリやWebサイトへサインインし、専用の永続的なクラウドコンピューターを使い、必要な時点で承認を求めながら仕事を完了できると説明しています。

ワークフロー学習にも対応します。多段階の手順を見せてルーチンとして保存し、オンデマンドまたはスケジュールで再実行できます。別製品の[Grok Automations](https://x.ai/news/grok-automations)は、スケジュール実行やメールトリガー、各実行に付随するコネクターとスキルを提供します。

アカウント調査、CRM更新、受信トレイ整理、Webサイト確認、複数の専門Botの調整など、運用作業を委任したい場合に魅力があります。実際のブラウザーやアプリで仕事を進められるクラウドコンピューターは、チャット草稿で止まらないという明確な差になります。

境界も重要です。各ユーザーのBotは、ファイル、ブラウザーセッション、アプリのログイン情報を含む1台の永続的なクラウドコンピューターを共有します。引き継ぎには有効ですが、別々のBotが別々のセキュリティ境界になるわけではありません。慎重に設定した役割、スキル、メモリ、メッセージングアクセスを持つ1体の個人用エージェントが目的なら、LightVelaの方が明確です。

## どちらを選ぶべきか

LightVelaが向いている条件：

- **1体の個人用エージェントが欲しい：** 設定を改善するほど役立つHermes Agentを使いたい。
- **継続性を重視する：** 同じエージェントに設定を保持し、長期的に使いたい。
- **ルーチンを設定したい：** スキルと定期的なスケジュールタスクを自分の習慣に合わせたい。
- **メッセージングから使いたい：** 普段のチャネルからエージェントへアクセスしたい。
- **直接管理したい：** モデル、ペルソナ、能力、ワークフローを自分で決めたい。

Grok Botが向いている条件：

- **実行を委任したい：** 実際のアプリやWebサイトを通じて多段階作業を完了させたい。
- **クラウドコンピューターが必要：** ブラウザー、ファイルシステム、ターミナルが仕事に含まれる。
- **複数のチームメイトが必要：** 永続的なBot同士で協調、引き継ぎ、並列実行したい。
- **実演からルーチン化したい：** 一度見せた手順を後から再実行したい。
- **承認ポイントが必要：** Botに自律作業させ、判断が必要なときだけ戻ってほしい。

結論として、**自分のルーチンに合わせて育てる1体の個人用AIエージェントにはLightVela、複数のアプリを横断する仕事を永続的なクラウドチームメイトへ委任するならGrok Botが適しています。**

Telegramを中心に使うアシスタントとも比較したい場合は、[LightVela vs Mira](./lightvela-vs-mira.md)を参照してください。
