# 自動化

## 概要

**オートメーションを使用すると、Hermes Agent は固定された時間、間隔、または一度きりのスケジュールで作業を能動的に実行し、選択した通知チャネルに結果を送信できます。テンプレートから開始することも、名前、実行ルール、タスク指示、有効期間、通知設定をカスタマイズすることもでき、その後、タスクリストからタスクの状態を管理することを続けられます。**

オートメーションを作成または編集する際に、上流タスクにリンクすることもできます。後で実行する際は、上流タスクの最新の完了した出力を追加のコンテキストとして使用します。これは、「まず情報を収集し、その後要約する」といったワークフローを複数のステップに分割する場合に便利です。

オートメーションを利用すると、Hermes Agent は指定された作業をあらかじめ設定されたスケジュールやトリガー条件で実行できるため、同じ操作を手動で繰り返す必要がありません。典型的なシナリオには、スケジュールされたリマインダー、日次レポートの生成、ニュースの追跡、コンテンツの公開などがあります。

各タスクは柔軟なスケジュール設定や実行ルールに対応しているため、AIアシスタントが積極的に作業を続けることができます。

## 自動化の追加

- **名前**: 自動化プランに名前を付けます。
- **スケジュール**: タスクの周期を設定します。固定曜日、固定間隔、または一度だけの実行から選択します。
- **タスクの指示**: エージェントが自動化を実行するためのプロンプトを書きます。
- **上流タスク**: 任意です。リンクされると、このタスクは実行時に上流タスクの最新完了出力をコンテキストとして使用します。
- **有効時間帯**: タスクが実行可能な時間範囲を制限します。24時間有効にしたい場合は空白のままにします。
- **通知**: タスク実行通知を受け取るチャネルを選択するためのオプショントグル。

## 上流タスクのリンク

作業の一部を安定した複数ステップのフローに分割する場合、上流タスクは役立ちます：

1. 最初のタスクは基礎素材を収集または生成します。
2. 二番目のタスクは最初のタスクにリンクし、直近で完了した出力に基づいて整理、フィルタリング、または書き換えを続行します。
3. その後のタスクは前のステップにリンクし続けることで、明確な処理チェーンを形成できます。

一般的な例:

- 毎朝候補者の情報を収集し、その後、下流のタスクに簡潔な日報を作成させます。
- まず週ごとのプロジェクトの進捗を要約し、その後、下流のタスクにチーム向けのバージョンを作成させます。
- まずやるべき項目を要約し、その後、下流のタスクに優先順位順に並べ替えてリマインダー文を作成させます。

上流のタスクをリンクしても、2つのタスク構成をコピーやマージすることはありません。現在のタスクは引き続き自身のスケジュール、タスク指示、有効ウィンドウ、および通知設定に従って実行されます。単に上流タスクの最新の完了出力を追加のコンテキストとして受け取るだけです。Hermes `context_from` は1つ以上のタスクIDを参照することをサポートしています。製品ページが現在単一の上流タスクセレクタを表示している場合には、ページで許可されている範囲でのみ構成してください。チェーンタスクは、同じスケジューラのティックでまだ実行中の上流タスクを待ちませんので、上流と下流のスケジュールはずらして設定する必要があります。

タスクの指示では、上流の出力をどのように使用するかをまだ説明する必要があります。例えば：「上流タスクからの候補ニュースに基づいて、AIエージェント製品に関連する項目のみ5つ残し、中国語で要約を書いてください。」単に「処理を続ける」と書くのは避けてください。なぜなら、それでは下流タスクが何を処理すべきか分かりにくくなるからです。

## タスクテンプレート

どのオートメーションを設定すべきか分からない場合は、「テンプレート」をクリックして、既成のオートメーションプランを選んでください。

## オートメーションの管理

オートメーションを作成した後は、「オートメーション」ページで有効なタスクを確認できます。

このページから、オートメーションの詳細を確認したり、タスクを編集したり、一時停止したり、必要に応じて削除したりできます。

リンクされたタスクについては、上流タスクを削除する前に、下流タスクが上流タスクの最新の完了出力に依存していないか確認してください。

## 検証

オートメーションを作成または編集した後、「正常に保存されました」で止まらないでください。次のことを確認してください：

1. タスクがオートメーションリストに表示され、その状態が期待通りであること。
2. スケジュール、有効ウィンドウ、および通知設定が正しいこと。
3. 上流のタスクがリンクされている場合、上流のタスクにはすでに最新の完了済み出力があります。
4. 1回の実運転後、最新の実行記録を確認してください。
5. 欠落している背景を推測するのではなく、出力が実際に上流タスクの結果を使用したかどうかを確認してください。

## 一般的な障害対応

| 症状 | 考えられる原因 | 推奨される対応方法 |
|---|---|---|
| 下流のタスクが上流の結果を使用しなかった | 上流のタスクがリンクされていないか、上流のタスクがまだ完了した出力を持っていないか、または両方のタスクが同じスケジューラーのティックで実行された可能性があります | 上流のタスクを再度選択し、上流のタスクを一度正常に実行してから、下流のタスクをスケジュールしてください |
| 出力が要点を外しています | タスクの指示が「たった今」や「上記の内容」などの曖昧な参照に依存しすぎています | 目標、範囲、出力形式、および上流の出力の使用方法を明確に記述してください |
| チェーンされたワークフローは時間とともに混乱してきます | 1つのタスクが多くのステップを扱っている、または上流および下流の責任が不明確である | ワークフローを分割して、各タスクが明確な1つのステップを担当するようにする |
