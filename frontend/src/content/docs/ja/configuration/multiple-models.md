# モデル切り替え

## 概要

**モデル切り替えを使うと、Hermes Agentが現在使用している構成済みモデルの中から選択できます。タスクに応じて速度、性能、コストプロファイル、またはプロバイダーの利用状況が異なる場合、新しいエージェントを作る代わりにモデルを切り替えます。これは、ペルソナ、メモリ、スキル、およびスケジュールタスクがすべてモデルの外部に保存されるため、モデルを変更しても推論エンジンだけが入れ替わる仕組みであり、何も失われたり消去されたりせず、エージェントは引き続きあなたを覚えています。各エージェントには同時に正確に1つのアクティブモデルがあります。**

---

モデル切り替えでは、Hermes Agent が次の作業で使用する構成済みモデルを選択できます。タスクによって速度、能力、コスト、または提供者の利用状況のバランスが異なる場合に、新しいエージェントを作成せずに切り替えが可能です。

## このページの内容

- 複数の使用可能なモデルを準備する
- エージェントのアクティブモデルを選択する
- チャットでの変更を確認する
- 表示されない、または応答できないモデルのトラブルシューティング

> **知っておくと便利:** エージェントは一度に一つのアクティブモデルを使用します。アクティブモデルを切り替えても、エージェントのメモリ、クラウドストレージのファイル、スキル、またはスケジュールタスクは消去されません。

## 始める前に

1. 更新したいエージェントを開きます。
2. 対象モデルがすでに設定されており、アカウントで利用可能であることを確認してください。そうでない場合は、[モデルの設定](./model.md)を最初に行ってください。
3. 新しいモデルが期待通りに応答するか確認できる簡単なテストプロンプトを用意してください。

## アクティブモデルを切り替える

1. **エージェント**を開き、エージェントを選択します。
2. **モデル**セクションを開きます。
3. エージェントに使用させたい設定済みモデルを選択してください。
4. 変更を保存または適用し、エージェントがアクティブな設定の更新を完了するまで待ちます。

![LightVelaコンソールのモデルプロバイダーセレクター](../images/4-1-en.webp)

初めてモデルを選択する場合は、[モデルの設定](./model.md)ここに戻る前に、サポートされているプロバイダーまたはカスタムモデルを追加してください。

## 変更を確認する

オープン[チャット](./agent-chat.md)そして、短くリスクの低いプロンプトを送信します。例えば：

```text
Reply with the name of the current model if it is available, then summarize this sentence in one line: Model switching is ready.
```

エージェントが正常に応答すること、およびエージェントコンソールに表示されているモデルが選択したものと一致していることを確認してください。最初の応答に少し時間がかかる場合は、エージェントが更新される間、少し待ってから再試行し、それでも変更を加える前にもう一度確認してください。

## 切り替える適切なタイミングを選ぶ

| 状況 | 考慮すべきこと |
| --- | --- |
| より速い初稿が必要 | 短く定型的な作業に適した設定済みモデルを選んでください。 |
| 作業により強力な推論やコード支援が必要 | その種類の作業向けに設定したモデルを選んでください。 |
| プロバイダーが利用できないか、レート制限されています | 別の設定済みモデルに切り替え、Chatでテストしてください。 |
| 出力の品質を比較しています | 切り替えごとに同じ小さいプロンプトを実行し、結果を比較してください。 |

モデル切り替えは、今後の応答に使用されるエンジンを変更します。会話履歴を移動したり、ファイルを書き直したりすることはありません。[クラウドストレージ](./files.md)、または変更することはありません。[スキル](./skill.md)および[スケジュールタスク](./automation.md)。

Hermes Agentと並行して、独立したプラグインファーストのエージェント環境を試す場合は、[DeepSeek Harness](./deepseek-harness.md)をご覧ください。

## 切り替えがうまくいかない場合

1. に戻る[モデルの設定](./model.md)対象モデル、資格情報、プロバイダー設定が完全であることを確認してください。
2. モデルがアカウントで利用可能であり、プロバイダーのクォータやクレジットが十分にあることを確認します。
3. 既知の正常に動作するモデルを選択し、チャットでテストします。
4. エージェントがそれでも応答できない場合は、[診断](./diagnostics.md)を開き、モデル設定をリセットする前に最近のログを確認してください。

> **ヒント:** 一度に1つずつ変更してください。各変更後にテストすることで、問題がモデル、設定、またはタスク自体のどれにあるかを判別しやすくなります。

## FAQ

### なぜ欲しいモデルが一覧に表示されないのですか？

選択できるのは設定済みのモデルのみです。モデルを追加するか、[モデルの設定](./model.md)でモデルを完成させてから、モデルセクションに戻ってください。

### モデルを切り替えるとエージェントのメモリは消えますか？

いいえ。アクティブなモデルは変更されますが、エージェントのメモリや保存された設定はそのままです。メモリは[メモリ](./memory.md)。

### 結果が気に入らなかった場合、元に戻すことはできますか？

はい。別の設定済みモデルを選択し、変更を適用して、同じプロンプトでテストしてください。プロンプトを一貫して使用することで、より有用な比較が可能になります。
