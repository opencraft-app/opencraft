

## 概要

**Hermes AgentとOpenClawの根本的な違いは「蓄積」と「接続」です：Nous Researchによって構築されたHermesは、時間とともにあなたをよりよく理解するように設計された自己進化型エージェントです。長期記憶（`USER.md` / `MEMORY.md` / SQLite+FTS5 / スキル）を最優先の存在として扱い、エージェント自身が何を記憶するか、いつそれをスキルに昇格させるかを決定します。Peter Steinbergerが率いるOpenClawは、ローカルファーストのエージェントおよび自動化ゲートウェイで、「すべてを接続する」ことを目的としています：25以上のモデルと20以上のメッセージングプラットフォームが接続可能で、スキルはユーザーによって手書きされ、ClawHubを通じて配布されます。Hermesを選ぶということは、成長するパートナーを選ぶことを意味します時間とともに強くなる；OpenClawを選ぶということは、何にでも接続できるコントロールデスクを選ぶことを意味します。

---

## なぜこの二つのオープンソースエージェントは比較され続けるのか

2026年のオープンソースAIエージェントの状況では、この二つの名前を避けることはほぼ不可能です。どちらも「ローカル優先、セルフホスト可能、クロスプラットフォームチャット統合」を宣伝し、どちらも汎用エージェントフレームワークと名乗り、一見するとホームページは競合製品のように見えます。

しかし、実際に一週間使ってみると、二つの疑問が頭から離れなくなります：

- なぜOpenClawは、たくさんのプラグインをインストールしてもまだ「毎回ゼロから始まる」のに、Hermesはわずか2日で先週のプロジェクト名を自動的に表示するのでしょうか？
- なぜOpenClawは63日間で138件の脆弱性（そのうち7件は重大）を公開したのに対し、Hermesのセキュリティアドバイザリページはほとんど空なのでしょうか？

答え：**実際には、彼らは全く異なる2つの質問に答えているのです。**

- OpenClawが答えるのは：「人生のすべてのチャネルに1つのエージェントを接続するにはどうすればいいですか？」
- Hermes Agentが答えるのは：「時間が経つにつれて、自分をよりよく理解してくれるエージェントを作るにはどうすればいいですか？」

以下のセクションでは、6つの観点（**位置づけ、アーキテクチャ、メモリ、スキル、自己進化、セキュリティ**）にわたる違いを説明します。

---

## 1. 位置づけ：ラーニングループ優先 vs コントロールプレーン優先

| 観点 | Hermes Agent | OpenClaw |
|---|---|---|
| 開発者 | Nous Research | ピーター・シュタインベルガー（独立開発者、オーストリア） |
| 位置づけ | 自己進化型AIエージェント | ローカルファーストのエージェントおよび自動化プラットフォーム |
| 基本理念 | まず学習ループ | まずコントロールプレーン |
| 堀 | 「蓄積」— 使用すればするほど強くなる | 「接続」— 何にでも接続できる |
| 一行で | **蓄積**の問題を解決する | **接続**の問題を解決する |

Hermesはギリシャの伝令の神にちなんで名付けられており、「あなたと情報の間の使者」として、あなたの代わりに観察し、記録し、成長し続ける役割を示唆しています。OpenClawは別の道を選びます。それは自らを**中央ゲートウェイ**にし、20以上のメッセージングプラットフォームや25以上のモデルを接続できるようにして、**人間であるあなた**にすべてのルール、スキル、トリガーを定義させます。

一方はあなたのカウンターパートになりたいという欲求を持ち、もう一方はあなたのコントロールデスクになりたいという欲求を持ちます。それが最も基本的な分かれ目です。

---

## 2. アーキテクチャ: 統合型 vs ゲートウェイ型

**OpenClawはゲートウェイ型の4段構造です：**

```
Gateway → Agent → Skills → Memory
```

その核心的なエンジニアリング価値はゲートウェイにあります：ユーザーがWhatsApp、Telegram、Slack、Discord、またはメールから到達した場合でも、すべて同じエージェントセッションに収束します。コントロールプレーンはシンプルで、権限管理、監査、ルーティングはすべてゲートウェイ層に存在します。

**Hermes Agentは統合型構造です**：モデル推論、端末実行、ファイル操作、ブラウザ自動化、ウェブ取得、長期記憶、スケジュールタスク、マルチプラットフォームメッセージングが**同じプロセス**のモジュールとして組み込まれています。メッセージルーターというよりも、あなたと共に旅するアシスタントのように振る舞います — 脳、手、ノートを持ったアシスタントです。

その結果：**もしより多くのプラットフォームに接続したい場合、OpenClawの方が優れています；エージェント自体を強化したい場合は、Hermesの方が優れています。**

## 3. メモリ：2つの静的Markdownファイル vs 4つの構造化されたレイヤー

ここで違いが最も顕著に現れます。

### OpenClawのメモリ: 2つの静的なMarkdownファイル

- `MEMORY.md`は「永続的な事実」を保存します。
- `memory/YYYY-MM-DD.md`は「その日の会話コンテキスト」を保存します。

デザインは控えめで非常にテキストエディタに優しいです。しかし、2つの組み込みの制限があります:

1. **直近2日分**のログしか自動で読み込まれず、それ以前のメモリはユーザーが手動で検索する必要があります。
2. メモリは完全に**人間がフォーマットした**自由形式のテキストであり、エージェントが何を記憶する価値があるかを決めることには関与しません。

### Hermes Agentの記憶: 4つの協力する層

| 層 | キャリア | 役割 |
|---|---|---|
| プロンプト記憶 | `MEMORY.md` + `USER.md` | 毎回のセッションの開始時にシステムプロンプトに「固定」される |
| セッションアーカイブ | SQLite + FTS5全文検索 + LLMサマリー | すべてのセッションを保存; 数週間後に取得可能 |
| スキル | `SKILL.md`ファイル | エージェントが独自に蓄積する「やり方」 |
| 外部プロバイダー | Honcho、Mem0、Supermemoryなど。 | ナレッジグラフの補強、セマンティック検索、ユーザープロファイル |

これら4層全体で最も重要な行動は次の通りです：**エージェント自体が、何を`MEMORY.md`に入れるか、何を`USER.md`に入れるか、そして何をスキルに昇格させるかを決定します。** これが「時間の経過とともにあなたをよりよく理解する」という物理的な基盤です。

このカテゴリの他の記事では、`MEMORY.md`と`USER.md`の役割分担、更新戦略、スキルとメモリの違いについて掘り下げています。

## 4. スキル：人間が書いたもの vs エージェントが書いたもの

スキルとは再利用可能な操作手順です。どちらのフレームワークにも存在しますが、取得方法はまったく異なります：

| 比較 | Hermes Agent | OpenClaw |
|---|---|---|
| 誰が書くか | エージェントは複雑なタスクを完了した後に**自動的に抽出**します | ユーザーはMarkdownを手で書きます |
| トリガー | 5回以上のツール呼び出し、エラー後の成功した回復など | ユーザーによって意図的に作成されます |
| 自己最適化 | 約15回のタスクごとに反省ループで古いスキルが書き換えられます | 自動最適化なし |
| オープン標準 | [agentskills.io](https://agentskills.io)と互換性あり | ClawHubマーケットプレイスで配布 |
| セキュリティレビュー | 組み込みスキャン（プロンプトインジェクション、認証情報、サプライチェーンリスク） | Snykの監査で、5,700のスキルのうち1,467が疑わしいと一度検出されました |

一言で言うと：**Hermesのスキルはエージェントの筋肉記憶であり、OpenClawのスキルはユーザーがエージェントに渡す操作マニュアルです。**

## 5. 自己進化：ループとして Hermes は最も置き換えが難しい部分

Hermes Agent には互いに組み合わさる三つの組み込み学習パスがあります：

1. **メモリーパス**: セッションは SQLite に保存され、要約後に FTS5 で検索可能になります。
2. **スキルパス**: 複雑なタスクの後、構造化されたスキル（手順、落とし穴、検証方法）が自動的に作成されます。
3. **トレーニングパス**: 日常のツール呼び出し記録自体が、次世代モデルの学習データとして使用可能です。

Redditのユーザーは、Hermesが2時間以内に3つのスキル文書を自動的に作成した後、繰り返しの研究作業における効率が目に見えて向上したと報告しています。

OpenClaw **にはこのループはありません**。それはむしろエージェントのルーターおよびスケジューラーのように振る舞い、その進化は**ユーザーやコミュニティ**がスキルを追加したり、プラグインをインストールしたり、サービスを接続したりすることから生まれます。

どちらのルートが本質的に優れているわけではありませんが、何を選んでいるのかを知っておくべきです：一方は**エージェント自身が成長する**ことを可能にし、もう一方は**人間がエージェントに成長を教える**ということです。

## 6. セキュリティ：デフォルトでサンドボックス化されている vs デフォルトでオープン

| 観点 | Hermes Agent | OpenClaw |
|---|---|---|
| デフォルトのサンドボックス | 読み取り専用のコンテナルート + 権限削減 | なし |
| 認証 | 承認ゲートはデフォルトでオン | ゲートウェイ認証はデフォルトでオフ |
| インジェクション防御 | 組み込みのプロンプトインジェクション/資格情報漏洩スキャン | 組み込みスキャンなし |
| 既知の脆弱性 | 標準としての多層保護 | 63日間で138の脆弱性が公開され、7件が重大 |

**Hermesのセキュリティ姿勢は「デフォルトで制限されており、明示的に指示した場合にのみ緩められる」ですが、OpenClawの姿勢は「デフォルトでオープンで、自分で強化する」ものです。** 前者はプライバシー重視の人に優しく、後者は企業ネットワーク内でのカスタムコントロールに柔軟です。

## 7. では、どちらを選ぶべきでしょうか？

**次の場合はHermes Agentを推奨します:**

- 話せば話すほどあなたを理解してくれる、長期的なアシスタントを望む場合。
- 個人的な知識管理、長期的な研究、またはセッションを跨いだ追跡に使用する場合。
- トークンの消費を減らしたい（毎回教えるのではなく、一度だけエージェントに教える）。

**次の場合はOpenClawを推奨します:**

- 主に、より多くのチャネルやツールを接続する必要がある場合。
- 具体的なチームコラボレーションや集中監査の要件がある場合。
- OpenClawエコシステム内ですでに多くのスキルやボットを蓄積している場合。

## 8. 自分で構築せずにHermesを利用したい場合

Hermes Agent が最も得意とする3つのこと — 長期記憶、自己進化するスキル、マルチプラットフォームアクセス — はすべて同じ物理的前提に基づいています: **常にオンラインであり、自分専用のストレージを持ち、あなた自身のものであること。**

つまり理想的な展開は **オフラインにならないクラウドインスタンス** です: ノートパソコンの蓋を閉じても休眠せず、`nudge_interval` は確実に作動し、開くすべての端末が同じ `~/.hermes/` にアクセスできます。

それがまさに[**LightVela**](https://lightvela.ai/)が行うことです。LightVela は **クラウドホストされた Hermes Agent サービス** で、通常あなた自身が処理する必要がある上記のすべてを管理します:

- ワンクリックで専用クラウドインスタンスを起動し、ローカルのバッテリーやメモリに負担をかけません;
- 本物のHermes Agent内蔵で、オリジナルの上流メカニズムを使用した`MEMORY.md` / `USER.md` / スキル;
- 24時間オンライン、電話、ノートパソコン、Telegram、Lark、その他のチャンネルすべてがあなたを知る同じエージェントに接続;
- 会話データは専用サーバーに保持され、第三者と共有されません。

**上記の自己進化機能が魅力的でも、Ollama、SSH、systemd、バックアップ戦略に週末を費やしたくない場合、LightVelaが最も短い道のりである可能性が高いです。**

## 重要なポイント

- Hermes と OpenClaw はどちらも優れていますが、単に異なる課題に対応しています：**Hermes は AI を成長させ、OpenClaw は AI を接続させます。**
- 最も顕著な違いはメモリです：OpenClaw は 2 つの静的 Markdown ファイル、Hermes は 4 層の構造化レイヤーとエージェント側の意思決定があります。
- スキルは「エージェントが書いたもの」と「ユーザーが書いたもの」に分かれ、セキュリティは「デフォルトでサンドボックス化されている」と「デフォルトでオープン」という違いがあります。
- すべてを接続するにはOpenClawを選び、時間とともにあなたのことをより理解するエージェントが欲しい場合はHermesを選んでください — そしてセルフホスティングの作業なしでそれを望む場合はLightVelaを使ってください。
