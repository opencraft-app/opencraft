# LightVelaとDiscordを体験：あなたのAIエージェント Discord Bot があなたのチャンネルにサービスを提供します

## 概要

**LightVelaを使うと、クラウド上のHermes AgentをDiscordに接続し、承認済みコミュニティの文脈と運用境界を与え、定期的な質問、オンボーディング、イベントサポートに利用できるようにできます。** 最小限の手順は、エージェントを作成し、その指示を設定し、Discordチャンネルを接続し、ボットを招待し、サポートされているDiscord会話で実際の質問をテストすることです。

最近の共有エージェント製品には、[Claude Tag](https://www.anthropic.com/news/introducing-claude-tag)および[Viktor](https://slack.com/marketplace/A0A2VN5TR5K-viktor)があり、エージェントがすでにグループがコミュニケーションを取っている場所で動作するとより有用である理由を示しています。
LightVelaは、別のボットアプリケーションを構築してホストする必要なく、そのパターンをDiscordコミュニティにもたらします。

![LightVela エージェントが Discord コミュニティに接続](../images/use-case-discord-community-agent.webp)

## 対象者と期待される成果

このユースケースは、すでに使用している会話スペースで信頼できるAIヘルパーを求めるゲームコミュニティ、開発者コミュニティ、趣味のグループ、およびイベントサーバー向けです。

期待される成果は、承認された質問に答え、メンバーを適切なチャンネルやイベント情報に案内し、オンボーディングをサポートし、スケジュールタスクが適用される場合に設定済みのリマインダーを送信できる、十分にブリーフィングされたDiscordエージェントです。

人間のモデレーターの代替ではありません。
機密性の高いモデレーションの決定、アカウントの操作、紛争、および承認された知識の範囲外の事項は人間に任せるべきです。

## 前提条件

- 設定されたモデルを使った稼働中のLightVelaHermes Agentです。

- Discordアカウントと、ボットを追加する権限があるサーバーです。

- サーバールール、FAQ、イベント詳細、チャンネルの目的、エスカレーション連絡先など、承認済みのソース資料。

- エージェントが回答できる内容、回答を拒否すべき内容、いつエスカレーションすべきかの明確な境界。

- その[Discord チャンネル設定ガイド](../configuration/channel-discord.md)および[スケジュールタスクガイド](../configuration/automation.md)参照可能です。

## 手順

### 1. ボットを招待する前にエージェントを作成する

Discord の資格情報ではなく、まずエージェントの役割と成果から始める。
Discord ボットは Hermes への入口であるため、LightVela で設定された指示やモデルが、接続後の動作を決定します。

コミュニティで最もよくある質問と、それぞれに対する最小限で有用な回答を書き出してください。
例えば、ルールページ、サポートチャンネル、イベントスケジュール、登録手順、モデレーターへのエスカレーション経路を挙げてください。

### 2. エージェントに承認されたコミュニティの文脈を与える

エージェントが使用できる情報と従うべき境界を設定してください。
役立つ開始指示は次のようになるかもしれません：

```text
You are the community assistant for this Discord server.

Answer questions using approved information.
Help members find the right channel or event details.
Be friendly and concise.
Escalate sensitive moderation issues to human moderators.
Never invent rules, announcements, or event times.
If the approved information does not answer a question, say that you do not know and point the member to a human moderator.
```

エージェントの設定されたコンテキストに、耐久性のある操作設定を保持してください。
変更されるスケジュール、アナウンスメント、およびイベント資料は、エージェントが使用する前に確認できるワークフロー内に保持してください。
ボットのトークン、パスワード、または不要な個人情報を長期コンテキストに置かないでください。

### 3. Discord を接続し、ボットを招待する

LightVela で、チャネル設定を開き、Discord を選択します。
Discord アプリケーションを作成するか選択し、ボットを追加し、そのトークンを生成して、トークンを Discord 接続カードに貼り付けます。

Discord 開発者ポータルで、メッセージ内容を読み取るために必要なメッセージ内容インテントを有効にします。
サーバーが必要とする最小限のボットスコープと権限を使用してください。例：チャンネルの閲覧、メッセージの送信、メッセージ履歴の読み取りなど。
次に、招待リンクを生成して、ボットを対象のサーバーに追加します。

完全な手順に従ってください[Discord 設定ステップ](../configuration/channel-discord.md)現在の認証および権限フローのために。

![開発者ポータルでの Discord ボット権限](../images/discord-6-global.webp)

### 4. 実際のコミュニティの質問でエージェントをテストする

コンソールにDiscordが接続済みと表示されたら、サポートされているDiscordの会話からいくつかの代表的な質問を送信します。
有用な回答と安全な不確実性の両方をテストする質問を使用します：

```text
Where can I find the event schedule?

Which channel should I use for technical support?

I am new here. What should I read first?

What is the rule for an issue that is not covered in the FAQ?
```

期待される結果は、単に流暢な回答ではありません。
エージェントは承認された情報を使用し、回答を簡潔に保ち、規則をでっちあげず、質問がモデレーターを必要とする場合はエスカレーションする必要があります。

ボットが応答しない場合、まずDiscordチャンネルが接続されていること、モデルが利用可能であること、ボットにメッセージの読み取りと送信の権限があること、そしてメッセージコンテンツインテントが有効になっていることを確認してください。

### 5. コアパスが機能するようになってから定期サポートを追加する

質問への回答が信頼できるようになったら、登録リマインダー、イベントカウントダウン、モデレーターサマリーなどの定期作業用の狭いスケジュールタスクを追加してください。
LightVelaスケジュールタスクは、1回実行、固定曜日、または固定間隔での実行をサポートし、任意で有効期間や通知チャンネルを設定できます。

例えば、次のように設定できます：

```text
Every Thursday at 18:00, remind the event channel about Saturday's tournament.
Use only the approved schedule and rules.
Include the start time, time zone, registration deadline, and the channel for questions.
If any detail is missing, say which detail needs a moderator update instead of guessing.
```

まずは1つのリマインダーから始め、その出力を確認してから、さらにスケジュールされた作業を追加してください。
については、参照してください[スケジュールタスク](../configuration/automation.md)利用可能なスケジュールおよび通知設定。

## 実用的なチェックリスト

| ステージ | アクション | LightVela コンポーネント | 期待される結果または失敗の信号 |
| --- | --- | --- | --- |
| 定義 | コミュニティロール、承認済みの事実、エスカレーションルールを記述する | エージェントの指示 | モデレーターは、エージェントが答えられることと答えられないことを説明できます |
| 接続 | Discord ボットトークンを追加し、最小権限でボットを招待します | Discord チャンネル | Discord が接続済みとして表示され、ボットがサーバーに存在します |
| テスト | 既知のFAQの質問と未知または機密の質問をします | Discord 会話 | 最初の質問には根拠のある回答が与えられ、2つ目の質問は拒否されるかエスカレーションされます |
| 繰り返し | 狭いスケジュールで1つのリマインダーまたは概要を追加する | スケジュールタスク | メッセージは、選択された通知チャネルに予定通り届く |
| レビュー | 回答、スケジュール、変更されたイベント情報を確認する | エージェントおよびスケジュールタスク管理 | 古いルールやお知らせは混乱を引き起こす前に修正される |

## 共有されたDiscordエージェントが手伝えること

### 誰もが尋ねる質問に答える

あらゆるコミュニティは、少数の質問を繰り返します：

- イベントのスケジュールはどこですか？

- サポート用のチャンネルはどれですか？

- トーナメントにどうやって参加しますか？

- サーバーのルールはどこにありますか？

メンバーは、モデレーターがオンラインになるのを待つ代わりに、サポートされているDiscordの会話でエージェントに質問できます。
承認された情報が明確であれば、回答は一貫しており、情報が不足している場合はエージェントが「分からない」と答えることもできます。

### イベントマネージャーにならずにイベント運営を手助けする

イベントでは、登録、タイムゾーン、ルールのリマインダー、直前の変更に関する多くの小さな質問が生じます。
エージェントは繰り返しの質問に対応し、設定されたリマインダーを提供できます。一方で、主催者は情報源や最終決定の管理を維持できます。

### 新しいメンバーにより良い最初の1時間を提供する

新しいメンバーは次のような簡単な質問から始めることができます:

```text
I am new here. Where should I start?
```

エージェントは彼らを正しいチャネルに導き、承認されたコミュニティの基本を説明し、次のステップを1つ提供することができます。
これにより、エージェントにモデレーションの判断を求めることなく、最初のやり取りが有用になります。

## ゼロからDiscordボットをコーディングする場合と比較して

カスタムDiscordボットは、深くカスタマイズされたコマンドや製品固有のワークフローが必要なときに適切な選択です。
また、アプリケーションのロジック、資格情報、デプロイメント、継続的なメンテナンスを自分で管理することを意味します。
LightVelaはエージェントから始まり、コンソールでその動作を記述できます。

| 標準のコーディングされたボット | LightVela for Discord |
| --- | --- |
| コマンドとイベントハンドラを作成する | エージェントが行うべきことを説明する |
| FAQやルールをコードやデータベースに保存する | 承認済みのコンテキストと境界をエージェントに与える |
| リマインダー用のスケジューラを作成する | コンソールでスケジュールタスクを作成する |
| 行動の変更を展開する | エージェントの指示を更新し、結果を確認する |
| ボットのインフラとロジックを維持する | コミュニティ運営とモデレーションに集中する |

これはすべてのカスタムボットを不要にするわけではありません。
これは、コミュニティが完全なボット製品を構築する前に、実用的なDiscordエージェントを起動する方法を提供します。

## 検証と境界

少なくとも1つの既知の質問、1つの情報不足の質問、1つの敏感なモデレーション質問でシナリオを確認します。
エージェントが承認された回答を使用しているか、確信が持てない場合に認めるか、即興で対応せずエスカレーションしているかを確認します。

Discord 設定ガイドは、ボットの認証、サーバーおよびチャンネルとの相互作用、メッセージ内容へのアクセス、チャンネルレイヤーでの積極的なメッセージについて記録しています。
また、グループチャットのサポートに関する現在の制限についても記録しています。
展開が広範なメンションや特定のマルチユーザー会話モードに依存する場合は、公開リリース前に対象サーバーでその挙動を確認してください。

人間のモデレーターは、禁止処置、悪用報告、紛争、ポリシー変更、承認済みコンテキストに追加されていない発表について引き続き責任を負います。

## FAQ

### Discord ボットをコーディングする必要がありますか？

このユースケースには該当しません。
HermesはLightVelaで設定し、Discordチャンネルに接続し、生成されたBotをサーバーに招待します。
カスタムコードは、LightVelaが提供しない非常に特定のコマンドやワークフローには依然として適しています。

### エージェントはサーバーのルールに関する質問に答えられますか？

はい、ルールが承認されたコンテキストに含まれ、プロンプトでそれを作り出したり上書きしたりしないよう指示されている場合に可能です。
ルールが不明確であったり問題が敏感な場合は、メンバーを人間のモデレーターに案内させてください。

### イベントのリマインダーを自動で送信できますか?

はい、Discord チャネルのドキュメントには、チャネルレイヤーでプロアクティブメッセージがサポートされていると記載されています。
で収集してください。[スケジュールタスク](../configuration/automation.md)スケジュール、タスク指示、有効期間、および通知チャンネルを定義するには。

### エージェントがモデレーションの判断を行うべきですか?

いいえ。
説明、ルーティング、リマインダー、要約には使用し、人間のモデレーターが執行および機微なケースの権限を保持します。

## 結論

Hermes Agentを作成し、承認されたコミュニティのコンテキストを与え、Discordを接続し、ボットを招待し、スケジュールタスクを追加する前に実際の質問でテストします。
この手順によって、プライベートなAIエージェントを、サーバーのルール、権限、および人間によるエスカレーションの境界を管理しながら、役立つコミュニティ向けのヘルパーに変えることができます。

このパターンのより焦点を絞ったバージョンについては、参照してください[AIエージェント能力を持つDiscordイベントボットを強化する](./discord-event-agent.md)。
