# エージェントと一緒に長期記憶と個人知識を管理する方法

## 概要

**個人的な知識には、別々に管理する必要がある2つの形があります。自分が誰であり、どのように働くかに関する安定した情報は長期記憶に属し、進化するドキュメント、ノート、プロジェクト資料はクラウドストレージに属します。** 両方を一つのものとして管理すると、安定性と検索性の両方を失うことになります。LightVelaでは、記憶が会話を通して文脈を保持します — コンソールの記憶ページは、別々のメモリとユーザープロファイルタブで保持された内容を表示し、容量制限を調整でき、追加や削除は主にHermesとの会話を通じて行われます。クラウドストレージはファイル作業スペースであり、アップロード、作成、整理、ダウンロード、名前変更をサポートします。削除、1ファイルあたり1GBの制限付き。守るべきルールは1つだけ：パスワード、キー、不要な機密データを長期記憶に書き込まないこと。

![LightVela エージェントメモリと個人の知識](../images/use-case-agent-memory.webp)

## 対象者

このパターンは、アシスタントに毎回すべての文書を記憶させることなく、自分の好みや繰り返し行う作業を理解してもらいたい人向けです。継続的なプロジェクト、個人的なリサーチ、学習ノート、クライアント業務、同じコンテキストが長期間戻ってくる作業フローに役立ちます。

目標は完璧なアーカイブを作ることではありません。重要なコンテキストを見つけやすくし、ヘルメスが保持すべき部分と整合するようにすることです。

## 前提条件

- Hermes Agent を実行し続け、コンソールや接続されたチャネルを通じてそれとチャットする方法。

- 情報が存在できる二つの場所に関する基本的な理解：[メモリ管理](../configuration/memory.md)長期的な文脈のために、[クラウドストレージ](../configuration/files.md)ファイルやフォルダのために。

- 所有するすべてのファイルの未編集のバックログではなく、実際に繰り返し使用する少数の資料。

- ハーメスに保持または確認してほしい内容のための明確なプライバシー境界。

## 手順 / 主要な概念

### 1. 安定したコンテキストと参考資料を分ける

将来の会話に影響を与えるべき事実をメモリに入れる：あなたの好む文章スタイル、タイムゾーン、現在の役割、繰り返しの目標、あるいはプロジェクトの扱い方に関するルールなど。変更が頻繁にある資料—ブリーフィング、会議のメモ、ドラフト、研究ファイル—はクラウドストレージに保存してください。

例えば、あなたはハーメスに次のように伝えるかもしれません：

```text
Remember that I prefer research notes to separate facts, assumptions,
and open questions. Use that structure whenever we review a project.
```

ポイントは、Hermes にすべてのソースドキュメントを記憶として保存させることではありません。ポイントは、それらのドキュメントをどのように扱いたいかを理解させるための永続的な方法を提供することです。

### 2. 再訪する予定のファイルを整理する

実際の作業に合わせて、Cloud Storage に小さなフォルダ構造を作成します。意味のある名前を使い、関連する資料はまとめておきます。例えば、クライアント、プロジェクト、コース、または研究課題ごとにフォルダを作るなどです。

ファイルの助けが必要なときは、Hermes に自分が何をしようとしているかを伝え、関連する資料を特定します。例えば：

```text
Help me prepare for this project review. Use the latest brief and my
meeting notes, then list unresolved decisions and questions.
```

![プロジェクトファイルを含むクラウドストレージフォルダ](../images/use-case-memory-knowledge-storage.png)

### 3. 記憶を永遠に正しいと仮定するのではなく、レビューする

定期的にメモリ管理を開き、メモリとユーザープロファイルのタブを確認してください。ユーザープロファイルはあなたが誰であるかの安定した姿を示します。メモリは、Hermesとの協力から得た有益な経験や作業コンテキストを保持します。

もし好みが変わった場合は、会話で率直に伝えましょう:

```text
I no longer want long weekly updates. Please forget that preference
and keep weekly summaries to five bullets.
```

メモリは最新の状態に保つことで最も効果的に機能します。Hermesを誤った方向に導くようなコンテキストは、二重で矛盾する指示を追加するのではなく、削除または修正してください。

### 4. レビューした知識を実際の会話に変える

次の[チャット](../configuration/agent-chat.md)ページや接続されたチャンネルを使って、ドキュメントや記憶を具体的な次のステップに変える。比較、アウトライン、一連の未解決の質問、または特定の会議の要約を求める。即時の結果が具体的であればあるほど、Hermesが正しい文脈を持っているか確認しやすくなる。

レビューが定期的なリズムに従う場合、[自動化](../configuration/automation.md)フォルダを再訪することや定期的なまとめを準備することを思い出させることができます。広範で自由なタスクを与えるのではなく、まずは簡単なリマインダーや要約から始めましょう。

## FAQ

### メモリとクラウドストレージの違いは何ですか？

メモリは、Hermesがあなたや進行中のコラボレーションを理解するのを助ける永続的なコンテキストです。クラウドストレージは、あなたが管理するファイルやフォルダ用です。メモリには重要なルールや好みを記録し、ファイルには基となる資料を保持するべきです。

### Hermesはすべてのファイルを自動的に長期メモリとして扱いますか？

いいえ。区別を意図的に保ってください。永続的なコンテキストにはメモリ管理を使用し、特定の作業中に参照したい資料を整理するにはクラウドストレージを使用してください。

### ヘルメスに何かを忘れてもらうことはできますか？

はい。保持しない内容をヘルメスに伝えた後、変更を確認したい場合は関連するメモリやユーザープロファイル情報を確認してください。

### まずメモリに何を入れるべきですか？

ほとんどすべての会話の質を変える設定から始めましょう：あなたのタイムゾーン、コミュニケーションスタイル、役割、優先的に取り組む事項、および定期的な作業の形式の好みです。
