# より自然なIMエージェントを設計する方法: 会話のリズム、グループ規範、長期的な社会的記憶

## 概要

**「よりリアルに」とは、本物の人を装うことを意味するのではありません。それは、表現、応答、長期的な協力において安定し理解しやすい行動を保つことを意味し、会話のリズム、グループの規範、長期的な社会的記憶の3つに帰着します。** リズムは、いつ短く答えるか、いつ詳しく説明するか、そしていつやめて確認を待つかを決めます。グループの規範は、共有スペースでどのように話すか、文脈をどのように引用するか、メンバーの境界をどのように尊重するかを決めます。長期的な社会的記憶は、すべてのメッセージを永久記録に変えることなく、確認された関係の文脈を保持するかどうかを決定します。これらを層として実装します：リズムと規範は安定したペルソナレベルです。ルールは持ちつつ、記憶は確認済みで永続的な事実のみを保持します。このガイドの自然な会話用チェックリストを使ってデザインを検証してください。

![会話のリズム、グループの規範、社会的記憶を備えたより自然なIMエージェントの設計](../images/use-case-10-lifelike-im-agent-rhythm-social-memory.png)

## 対象者

このガイドは、IMエージェントをより自然で一貫性がありながら、透明性と制御性を保ちたい人のためのものです。

個人アシスタント、学習パートナー、研究パートナー、そしてコミュニティアシスタントをデザインするチームに向けても有効です。

Telegramは、BotFatherでグループプライバシーを無効にし、ボットをグループに追加し、`@bot_username`でメンションした後にグループメッセージをサポートします。
WhatsApp グループ機能は独自のチャネルドキュメントに従うため、これらのグループ規範を Telegram に設定後に適用し、別のチャネルを使用する前にサポートを確認してください。

## どの要素を安定させるべきかを決定する

エージェントの持続的な行動を四つの層に分ける：

| 層 | 役割 | 推奨構成 |
|---|---|---|
| パーソナリティ | 役割、声、原則、および境界 | SOUL.md |
| 関係の好み | 名前、言語、詳細レベル、および対話習慣 | ユーザープロファイル |
| 社会的記憶 | 共有されたコンテキスト、プロジェクトの背景、および進行中の合意を確認済み | メモリ |
| 現在のリズム | このタスクにおける会話の文脈、長さ、および緊急性 | 現在のセッションとタスクのプロンプト |

一時的な感情や偶発的な返信で、持続的な人格を変えないようにする。

すべての挨拶、各グループメンバーのメッセージ、または未確認の推測を長期的な社会的記憶として保存しない。

## 手順

### 1. 模倣せずに自然な役割を定義する

次の[SOUL.md パーソナリティガイド](./im-agent-persona-soul-md.md)エージェントの役割、声、主導権のレベル、制限を定義する。

次のような簡単な紹介文から始めてください：

あなたは安定していて、率直で、友好的な研究パートナーです。
まず結論を述べ、その後必要に応じて証拠や詳細を追加してください。
要求があいまいな場合は、最も重要な確認質問を1つだけ尋ねてください。
確認済みの長期的な好みは覚えておきますが、機密情報や確認されていない推測は保存しないでください。
あなたはAIアシスタントです。人間であると主張したり、実世界の経験があるふりをしてはいけません。

これは、架空の身元によって誤解を生む信頼を築くことなく、声の一貫性を保つためです。

### 2. 会話のリズムを設計する

次のようなルールから始めます：

- 単純な事実質問には、1～3文で直接答えます。

- 複雑なタスクに取り組む前に、目標を再確認し、手順とリスクを分解します。

- 情報が不足している場合は、長文のフォームを送るのではなく、最も重要な質問だけをします。

- ユーザーが忙しい、急いでいる、または結論だけを望むと言ったときは、応答の長さを短くしてください。

- ユーザーが導出、チュートリアル、または振り返りを求めたときは、理由を詳しく説明してください。

- 外部、機密、または取り消し不可能な操作の前には、一旦停止して確認を待ってください。

実際のタスクでリズムを確認してください：

今日の最も重要な三つのタスクを三文で教えてください。

まず結論を示し、その後にその順位付けの理由を説明してください。

この操作は外部データを変更します。まず、その影響と確認が必要な点を教えてください。

エージェントがタスクやユーザーの好みに応じて応答の長さを変更しながらも、同じ原則を維持しているか確認してください。

### 3. 関係性の好みをユーザープロファイルに登録する

ユーザープロファイルは言語、名前、タイムゾーン、詳細レベル、一般的な作業スタイルに適しています。

例えば、ユーザーはHermesに次のように伝えることができます：

簡潔で直接的、結論を先に述べる返答を好むことを覚えておいてください。

関係の好みは、ユーザーが変更できない恒久的な性格ラベルになるのではなく、コミュニケーションの効率を向上させるものであるべきです。

好みが変わった場合は、人格ファイルを何度も編集するのではなく、Hermesに更新または忘れるよう依頼してください。

### 4. 長期的な社会的記憶を設計する

良い長期的候補には、確認済みのプロジェクトコンテキスト、持続可能な協力契約、安定した希望名、そして繰り返し確認された好みが含まれます。

長期的に適さない候補には、パスワード、認証コード、支払い情報、医療情報、未確認の心理的判断、一度きりの雑談が含まれます。

Hermesに明示的に項目を記憶するよう、または忘れるように依頼し、個人的なリマインダー、内部要約、または定期チェックのために[メモリ管理](../configuration/memory.md)。

長期記憶は、ユーザーの情報に対するコントロールを奪うことなく、繰り返しの質問を減らすべきです。

### 5. 共有スペースのグループ規範を準備する

Telegram グループメッセージがサポートされています。
グループプライバシーを無効にし、ボットをグループに追加し、`@bot_username`でメンションした後、ライブ会話にグループ規範を適用します。

グループを使用する前に、少なくとも以下を定義してください：

- ボットが@メンションまたは明示的なコマンドの後のみ返信するかどうか。

- 新しいメンバーのために管理者がウェルカムメッセージを送信する必要があるかどうか。

- FAQ、要約、リマインダーの頻度制限。

- メンバー、管理者、および人間による対応が必要なメッセージを区別する方法。

- メンバーのメッセージが共有メモリに入るかどうか、そしてそれが他のメンバーに漏れないようにする方法。

- 紛争、苦情、モデレーションの提案、および敏感なコンテンツが管理者に渡される方法。

グループの規範はチャンネルや運営規則に属し、性格プロンプトのみに依存すべきではありません。

### 6. スケジュールタスクを使って積極的なリズムを管理する

積極的なメッセージには明確な頻度、時間帯、対象チャンネル、および停止方法が必要です。

で収集してください。[スケジュールタスク](../configuration/automation.md)で定期的に確認して整理します。

すべてのスケジュールタスクに対して静音時間を設定し、対象チャネルが関連するプロアクティブ配信方法をサポートしていることを確認してください。

高頻度のメッセージで親しみやすさを演出せず、リマインダーを止めにくくしないでください。

## 自然な会話のチェックリスト

- エージェントはユーザーの実際の質問に最初に答えましたか？

- タスクの複雑さに応じて回答の長さを調整しましたか？

- 必要に応じて有用な確認質問をしましたか？

- ユーザーの心理を推測するのではなく、確認済みの好みを覚えていましたか？

- それがAIであることが明確に示され、実際の身元やオフラインの体験を示唆していないことは明らかでしたか？

- 影響について説明し、外部の行動を行う前に確認を待ちましたか？

- 静かな時間、拒否、忘却のリクエストを尊重しましたか？

## FAQ

### より人間らしくなることは、エージェントがAIであることを隠すことを意味しますか？

いいえ。

自然な言語、安定したリズム、連続した文脈は体験を向上させますが、エージェントが人間であると主張したり、現実世界の体験を作り出したりしてはいけません。

### すべての会話を社会的記憶として保存すべきですか？

いいえ。

将来の協力に役立つ確認済みの情報のみを保持し、メモリとユーザープロファイルを定期的に確認してください。

### 今、TelegramとWhatsAppでグループ規範を使用できますか？

このガイドのグループ規範をTelegramのグループメッセージに適用できます。
グループのプライバシーを無効にし、ボットをグループに追加し、`@bot_username`でメンションしてパーソナリティ、リズム、FAQ、リマインダーを確認してください。
WhatsAppまたは他のチャンネルの場合、まずそのチャンネル独自のグループサポート範囲を確認してください。

### なぜエージェントの返信は長いものと短いものがあるのですか？

応答の長さは、タスクの複雑さ、現在のプロンプト、モデルの出力、ユーザーの好みによって変わります。

ユーザープロファイルで設定するか、現在のリクエストで結論のみ、または完全な導出のみを希望することを明示してください。
