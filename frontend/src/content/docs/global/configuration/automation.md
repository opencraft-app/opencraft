# 自动任务

## 摘要

自动任务让 Hermes Agent 按固定时间、间隔或单次计划主动执行工作，并把结果发送到选定的通知通道。你可以从模板开始，也可以自定义名称、执行规则、任务说明、生效时段和通知方式，再在任务列表中持续管理运行状态。

创建或编辑自动任务时，也可以关联一个上游任务；后续执行时，当前任务会使用上游任务最近一次完成输出作为额外上下文。这适合把“先收集信息，再整理摘要”这类连续流程拆成多步。

自动任务（Tasks）可让 Hermes Agent 按照预设时间或触发条件，自动执行指定工作，无需人工重复操作。适用于定时提醒、日报生成、新闻追踪、内容发布等场景。

所有任务均可灵活配置执行频率与运行规则，让你的 AI 助手持续主动工作。

## 添加自动任务

- **名称**：自动化任务方案命名
- **执行时间**：设置任务执行周期（固定星期、固定间隔、单次执行三选一）
- **任务说明**：填写任务提示词，供智能代理执行自动化方案
- **上游任务**：可选。关联后，本任务执行时会使用上游任务最近一次完成输出作为上下文。
- **生效时间段**：限定任务有效运行时段（留空代表全天候持续运行）
- **通知方式**：可选开关，勾选接收任务执行通知的渠道

## 关联上游任务

上游任务适合把一项工作拆成稳定的多段流程：

1. 第一个任务负责收集或生成基础材料。
2. 第二个任务关联第一个任务，并基于最近一次完成输出继续整理、筛选或改写。
3. 后续任务可以继续关联前一步任务，形成清晰的处理链路。

常见例子：

- 每天早上先抓取候选信息，再由下游任务生成一份精简日报。
- 每周先整理项目进展，再由下游任务生成发送给团队的版本。
- 先汇总待办事项，再由下游任务按优先级重排并生成提醒文案。

关联上游任务不会复制或合并两份任务配置。当前任务仍按自己的执行时间、任务说明、生效时间段和通知方式运行，只是在执行时多拿到一份来自上游最近一次完成输出的上下文。Hermes 底层 `context_from` 支持引用一个或多个任务 ID；如果产品页面当前只提供单个上游任务选择，就按页面可选范围配置。串联任务不会等待同一轮调度里仍在运行的上游任务，因此需要把上下游执行时间错开。

任务说明里仍要写清楚如何使用上游输出，例如“基于上游任务给出的候选新闻，只保留与 AI Agent 产品相关的 5 条，并输出中文摘要”。不要只写“继续处理”，否则下游任务很难判断要处理什么。

## 自定任务模板

若不清楚需要配置什么自动化任务，可点击「模板」选用现成的自动任务方案。

## 自动任务管理

自动化任务创建完成后，可在「自动任务」页面查看已启用任务。

在此页面可按需查看自动化任务详情、编辑修改、暂停运行或删除你的自动任务。

对于有关联关系的任务，删除上游任务前要先检查是否还有下游任务依赖它的最近一次完成输出。

## 结果校验

创建或编辑后，不要只看“保存成功”。建议按下面顺序确认：

1. 任务出现在自动任务列表中，状态符合预期。
2. 执行时间、生效时间段和通知方式正确。
3. 如果关联了上游任务，上游任务已经有最近一次完成输出。
4. 等待一次真实执行后，查看最近执行记录。
5. 检查输出是否真的使用了上游任务结果，而不是重新猜测背景。

## 常见失败处理

| 现象 | 可能原因 | 建议处理 |
|---|---|---|
| 下游任务没有用到上游结果 | 未关联上游任务，或上游任务还没有完成输出，或上下游在同一轮调度中同时运行 | 重新选择上游任务，先让上游任务成功执行一次，并把下游执行时间排在上游之后 |
| 输出偏离预期 | 任务说明过于依赖“刚才”“上面内容”等模糊指代 | 写清目标、范围、输出格式，以及如何使用上游输出 |
| 链式任务越跑越乱 | 单个任务承担步骤过多，或上下游职责不清 | 拆分任务，保持每个任务只负责一个清晰步骤 |
