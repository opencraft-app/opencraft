# 模型切换

## 摘要

**模型切换用于选择 Hermes Agent 当前使用的已配置模型。当任务需要不同的速度、能力、成本取向或提供商可用性时，你可以直接切换模型，而无需新建一个 Agent。关键在于人格、记忆、技能与自动任务都存放在模型之外，因此换模型只替换推理引擎，不会带走或清空它们——Agent 依然记得你。当前每个 Agent 同一时刻仅一个模型生效。**

---

模型切换用于选择 Hermes Agent 当前使用的已配置模型。当任务需要不同的速度、能力、成本取向或提供商可用性时，你可以切换模型，而无需新建一个 Agent。

## 本页覆盖

- 准备多个可用模型
- 为 Agent 选择当前生效的模型
- 在聊天中确认切换结果
- 处理模型未显示或无法回复的问题

> **说明：** 一个 Agent 同一时间只会使用一个生效模型。切换模型不会清除 Agent 的记忆、云存储文件、技能或自动化设置。

## 开始前

1. 打开需要更新的 Agent。
2. 确认目标模型已经配置完成，且你的账户可以使用它。尚未配置时，先完成[配置模型](./model.md)。
3. 准备一条简短测试消息，用于确认新模型能够正常回复。

## 切换当前模型

1. 打开 **Agents**，选择目标 Agent。
2. 打开 **Models** 区域。
3. 选择希望 Agent 使用的已配置模型。
4. 保存或应用变更，等待 Agent 完成当前生效配置的更新。

![模型选择器](../images/4-1.webp)

如果是第一次选择模型，先在[配置模型](./model.md)中添加支持的提供商或自定义模型，然后回到此处继续。

## 确认切换结果

打开[聊天](./agent-chat.md)，发送一条简短、低风险的测试消息，例如：

```text
如果可以，请说明当前使用的模型名称；然后用一句话总结：模型切换已准备就绪。
```

确认 Agent 能正常回复，且 Agent 控制台显示的是你选择的模型。如果刚切换后的首次回复稍慢，请稍等后重试一次，再决定是否继续修改。

## 什么时候适合切换模型

| 场景 | 可以考虑的方向 |
| --- | --- |
| 需要更快完成初稿 | 选择适合短任务、常规工作的已配置模型。 |
| 任务需要更强的推理或代码协助 | 选择你已为这类工作配置好的模型。 |
| 某个提供商不可用或受到限流 | 切换到另一款已配置模型，并在聊天中测试。 |
| 希望比较输出质量 | 每次切换后使用同一条小测试消息，再比较结果。 |

模型切换只会改变后续回复使用的引擎。它不会移动聊天记录、改写[云存储](./files.md)中的文件，也不会变更[技能](./skill.md)和[自动化](./automation.md)。

## 切换后无法使用怎么办

1. 回到[配置模型](./model.md)，确认目标模型、凭证和提供商设置完整。
2. 确认该模型对你的账户可用，并且提供商侧配额或额度充足。
3. 选择一个已知可用的模型，在聊天中测试。
4. 如果 Agent 仍无法回复，打开[诊断中心](./diagnostics.md)查看近期日志，再决定是否重置模型配置。

> **提示：** 每次只改一个因素。每次切换后都测试，可以更快区分问题出在模型、配置，还是任务本身。

## 常见问题

### 为什么列表中没有我要用的模型？

只有已经配置完成的模型可以选择。请先在[配置模型](./model.md)中添加或完成该模型，再回到 Models 区域。

### 切换模型会清除 Agent 的记忆吗？

不会。生效模型会改变，但 Agent 的记忆和已保存设置会保留。需要单独查看记忆时，可前往[记忆](./memory.md)。

### 对效果不满意时可以切回去吗？

可以。选择另一款已配置模型，应用变更后用同一条测试消息验证。保持测试消息一致，比较结果会更有参考价值。
