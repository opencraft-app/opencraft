## 摘要

**Hermes Agent 的"大脑"可以换，但换掉的是模型层，不是整个 Agent。**
模型负责理解与生成。
Agent 层负责目标、工具、记忆、人格、通道和调度。
因此更换模型通常不会删除 `SOUL.md`、`USER.md` 或 `MEMORY.md`，但它会改变 Agent 推理、调用工具和表达答案的方式。

---

## 引子：换模型，到底换掉了什么

把 Hermes Agent 想成一个人时，模型很像即时思考能力。
它决定这一次如何读懂问题、如何规划、如何组织语言。
但一个长期工作的 Agent 还有另一层更稳定的东西：它是谁、记得谁、能做什么、在哪些通道出现、什么时候主动执行任务。

## 一、模型层：负责这一次怎么想

模型层提供推理和生成能力。
它影响回答质量、速度、语言风格，以及面对复杂任务时的规划能力。
模型不是用户资料库，也不是任务调度器。

| 换模型会影响 | 换模型不会直接删除 |
| --- | --- |
| 推理质量与速度 | 用户偏好与长期记忆 |
| 工具调用与表达风格 | Persona 规则 |
| 新会话的回答方式 | 已连接通道与文件 |

## 二、Agent 层：负责让思考持续发生

Agent 层把模型放进一个可持续工作的系统。
它保存身份与人格，管理 Memory 和 Skill，接入消息通道，并在需要时调度自动任务。
模型可以替换，Agent 的长期工作上下文仍然留在这些独立层里。

## 三、真正需要注意的是自动任务

普通聊天会直接使用当前模型配置。
定时任务则可能在创建时记录具体模型。
LightVela 在模型切换时会提示是否同步尚未结束的自动任务，避免任务继续使用旧模型而产生意外的质量、可用性或用量差异。

## 结论

换模型不是给 Agent"洗脑"。
它是在保留长期身份与工作资产的前提下，更换本次推理的引擎。
