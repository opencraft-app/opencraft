## 摘要

**一个 Agent 可以同时出现在多个聊天软件里，因为通道是入口，Agent 才是持续工作的主体。**
消息网关把 Telegram、WhatsApp、Discord 等不同格式的消息收进来，统一路由到同一个 Agent，再把结果送回正确的会话。
这让人格、记忆、Skills 和自动任务不必为每个平台复制一份。

---

## 引子：同一个人，为什么能在不同 App 里继续聊

用户在 Telegram 问了一个问题，又在 WhatsApp 继续追问时，体验不应该像换了一个机器人。
难点不在于多接几个 API。
难点在于让所有入口指向同一份 Agent 身份和上下文。

## 一、通道不是 Agent

Telegram、WhatsApp、Discord 和 WeChat 是**消息通道**。
它们负责把消息送到网关，也负责接收投递结果。
Agent 是独立于通道的工作主体。

```text
聊天软件 → 消息网关 → 同一个 Hermes Agent → 工具、记忆、Skills → 原通道
```

## 二、网关做的三件事

1. **接收并标准化**：不同平台的消息、用户和会话标识被转换成统一的处理请求。
2. **路由**：网关根据已连接配置把请求交给对应 Agent，而不是新建一份人格或记忆。
3. **投递**：Agent 完成后，网关把结果返回正确的平台和对话位置。

## 三、统一不等于没有边界

同一个 Agent 可以有多个入口，但每个通道仍有自己的授权、消息格式和投递限制。
连接新通道后，应先做测试消息，再确认 Agent 的回复确实回到了预期会话。

## 结论

多通道的关键不是"把机器人复制七份"，而是让七个入口共享一个长期工作的 Agent。
