## 摘要

**Hermes Agent 的性格不是一段固定人设文案，而是 Persona、用户偏好与长期记忆共同形成的工作方式。**
`SOUL.md` 规定"我是谁、怎样做事"。
`USER.md` 记录"你希望我怎样对待你"。
`MEMORY.md` 保存"我们已经一起确认过什么"。

---

## 引子：为什么同样的人设，对不同用户应该不同

一个"耐心的研究助手"对两位用户不应说完全一样的话。
有人要结论先行，有人需要完整推导。
有人长期在做产品，有人只想安排日常生活。
人格给出稳定原则，用户偏好和记忆让原则落到具体关系里。

## 一、Persona：稳定的行为宪法

Persona 通常写在 `SOUL.md`。
它定义角色、语气、优先级、边界和长期行为准则。
它不是每次聊天临时猜出来的心情。

## 二、用户偏好：关系的默认设置

`USER.md` 适合保存稳定的偏好，例如语言、沟通节奏、常用工具和禁忌。
它让 Agent 不必每次重新询问"你希望我详细一点还是简短一点"。

## 三、长期记忆：共同经历的证据

`MEMORY.md` 保存项目状态、已经做出的决定和可复用事实。
它不应该替代 Persona，也不应该装进所有短期情绪。

## 结论

Persona 决定原则。
用户偏好决定默认交互方式。
长期记忆决定 Agent 知道哪些共同背景。
三者分开，Agent 才能既稳定又个性化。
