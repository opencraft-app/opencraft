## 摘要

**Hermes Agent 的文件不应被看成一个杂乱文件夹，而应分成工作目录、上下文文件和持久存储三类。**
工作目录承载任务输入与输出。
`SOUL.md`、`USER.md`、`MEMORY.md` 承载 Agent 在会话中需要理解的长期上下文。
文件能力则让用户以受控方式管理可保存、可复用的资料。

---

## 引子：文件放在哪里，决定 Agent 能不能真正接着做

一个 Agent 读完文件、生成报告、下次再继续处理，靠的不只是聊天记录。
它需要知道哪些文件是当前任务素材，哪些是长期规则，哪些可以被安全保存和取回。

## 一、工作目录：任务发生的地方

工作目录用于当前任务的输入、生成物和工具执行。
它应有明确边界，工具不能任意越过工作区访问系统路径。
这让读写文件既可用，也更可控。

## 二、上下文文件：不是附件，而是长期约定

| 文件 | 主要作用 |
| --- | --- |
| `SOUL.md` | 角色、语气、行为边界 |
| `USER.md` | 稳定用户偏好与画像 |
| `MEMORY.md` | 跨会话事实、项目状态与决策 |

这些文件不等同于普通上传资料。
它们决定 Agent 如何理解关系和工作背景。

## 三、存储的正确边界

重要资料应放进受控的文件与存储能力，而不是依赖一次聊天粘贴。
同时，不要把密码、密钥或不必要的敏感信息写进长期上下文文件。

## 结论

工作目录负责做事。
上下文文件负责记住如何做事、为谁做事。
受控存储负责让资料在需要时可安全复用。
