# Meet LightVela for Discord：服务你所在频道的 AI Agent Discord Bot

## 摘要

**LightVela 可以把云端托管的 Hermes Agent 接入 Discord，为它提供经过确认的社群上下文和工作边界，并用于处理重复性问答、新成员引导和活动支持。** 最小可行流程是创建 Agent、配置指令、连接 Discord 通道、邀请 Bot，然后在受支持的 Discord 会话中测试真实问题。

Anthropic 的 [Claude Tag](https://www.anthropic.com/news/introducing-claude-tag) 和 [Viktor](https://slack.com/marketplace/A0A2VN5TR5K-viktor) 等近期共享 Agent 产品说明了一个趋势：当 Agent 出现在群体已经沟通的地方时，它更容易成为实际协作者。
LightVela 把这种模式带到 Discord 社群，同时不要求你先单独开发和托管一套 Bot 应用。

![连接到 Discord 社群的 LightVela Agent](../images/use-case-discord-community-agent.webp)

## 适合谁以及预期结果

这个使用方式适合游戏社群、开发者社群、兴趣群组和活动服务器，希望在成员已经使用的沟通空间中提供可靠 AI 助手的团队或个人。

预期结果是一个经过充分说明的 Discord Agent，可以回答已确认的问题，帮助成员找到正确的频道或活动信息，支持新成员入门，并在适合时通过定时任务发送经过配置的提醒。

它不是人类管理员的替代品。
敏感的管理决策、账号操作、争议处理，以及超出已批准知识边界的问题，都应该交给人工管理员。

## 前置条件

- 一个已经运行并完成模型配置的 LightVela Hermes Agent。

- 一个可以登录 Discord 的账号，以及一个你有权限添加 Bot 的服务器。

- 已确认的资料，例如服务器规则、常见问题、活动详情、频道用途和管理员联系方式。

- 明确的边界，规定 Agent 可以回答什么、必须拒绝什么，以及什么时候需要升级给人工管理员。

- 可供参考的 [Discord 通道配置指南](../configuration/channel-discord.md) 和[定时任务指南](../configuration/automation.md)。

## 操作步骤

### 1. 先创建 Agent，再邀请 Bot

先确定 Agent 的角色和目标，不要从 Discord 凭据开始。
Discord Bot 是 Hermes 的一个入口，因此 LightVela 中配置的指令和模型会决定它接入后的行为。

先写下社群最常见的问题，以及每个问题最小但有用的答案。
例如，列出规则页面、支持频道、活动日程、报名流程和管理员升级路径。

### 2. 为 Agent 提供经过确认的社群上下文

为 Agent 配置它可以使用的信息，以及它必须遵守的边界。
可以从下面这段初始指令开始：

```text
你是这个 Discord 服务器的社群助手。

使用经过确认的信息回答问题。
帮助成员找到正确的频道或活动详情。
保持友好和简洁。
将敏感的管理问题升级给人工管理员。
绝不要编造规则、公告或活动时间。
如果已确认的信息无法回答问题，请说明你不知道，并把成员引导给人工管理员。
```

把应该长期保持的工作偏好放在 Agent 的配置上下文中。
把会变化的日程、公告和活动材料放在可以被复查的工作流程中。
不要把 Bot Token、密码或不必要的个人信息放入长期上下文。

### 3. 连接 Discord 并邀请 Bot

在 LightVela 中打开通道配置并选择 Discord。
创建或选择 Discord Application，添加 Bot，生成 Token，然后把 Token 粘贴到 Discord 连接卡片中。

在 Discord Developer Portal 中开启读取消息内容所需的 Message Content Intent。
按照最小权限原则配置 Bot Scope 和权限，例如查看频道、发送消息和读取消息历史。
随后生成邀请链接，把 Bot 添加到目标服务器。

按照完整的 [Discord 配置步骤](../configuration/channel-discord.md) 完成当前授权和权限流程。

![Discord Developer Portal 中的 Bot 权限配置](../images/discord-6-global.webp)

### 4. 用真实的社群问题测试 Agent

当控制台显示 Discord 已接入后，在受支持的 Discord 会话中发送几条有代表性的问题。
既要测试有用的答案，也要测试安全的不确定性：

```text
在哪里可以找到活动日程？

技术支持应该去哪个频道？

我是新成员，应该先看什么？

遇到 FAQ 没有覆盖的问题，应该怎么办？
```

预期结果不只是语言流畅。
Agent 应该使用已确认的信息，保持回答简洁，不编造规则，并在问题需要管理员处理时进行升级。

如果 Bot 没有回复，请先确认 Discord 通道显示为已接入、模型可用、Bot 拥有读取和发送消息的权限，并且 Message Content Intent 已开启。

### 5. 核心流程稳定后再增加重复性支持

当问答已经稳定后，可以为报名提醒、活动倒计时或管理员总结增加一个范围明确的定时任务。
LightVela 定时任务支持单次执行、固定星期或固定间隔，也支持可选的生效时间段和通知渠道。

例如，你可以配置：

```text
每周四 18:00 在活动频道提醒周六的比赛。
只使用已经确认的日程和规则。
包含开始时间、时区、报名截止时间和问题咨询频道。
如果缺少任何详情，请说明需要管理员补充哪项信息，不要猜测。
```

先从一个提醒开始，并在增加更多定时工作之前复查它的输出。
关于可用的时间安排和通知设置，请查看[定时任务](../configuration/automation.md)。

## 共享 Discord Agent 可以做什么

### 回答每个人都会问的问题

每个社群都会反复出现一小组问题：

- 活动日程在哪里？

- 哪个频道用于支持？

- 如何参加比赛？

- 服务器规则在哪里？

成员可以在受支持的 Discord 会话中向 Agent 提问，不必等待管理员在线。
只要已确认的信息足够清楚，回答就能保持一致；当信息缺失时，Agent 也可以说明自己不知道。

### 帮助运营活动，但不替代活动负责人

活动会带来许多重复的小问题，包括报名、时区、规则提醒和临时变更。
Agent 可以处理重复性问题并发送已配置的提醒，而组织者仍然掌握信息来源和最终决策。

### 让新成员拥有更好的第一个小时

新成员可以从一个简单的问题开始：

```text
我是新成员，应该从哪里开始？
```

Agent 可以把他们引导到正确的频道，解释已经确认的社群基础信息，并给出一个简单的下一步。
这能让第一次互动更有帮助，同时不要求 Agent 做管理决策。

## 与从零开发 Discord Bot 相比

当你需要高度定制的命令或产品专属流程时，自定义 Discord Bot 仍然是合适的选择。
但这也意味着你需要维护应用逻辑、凭据、部署和后续更新。
LightVela 从 Agent 开始，让你在控制台中描述它的行为。

| 标准代码 Bot | LightVela for Discord |
| --- | --- |
| 编写命令和事件处理器 | 描述 Agent 应该做什么 |
| 把 FAQ 和规则存入代码或数据库 | 提供已确认的上下文和边界 |
| 为提醒建立调度器 | 在控制台创建定时任务 |
| 部署行为变化 | 更新 Agent 指令并复查结果 |
| 维护 Bot 基础设施和逻辑 | 专注社群运营和人工管理 |

这不意味着所有自定义 Bot 都不再需要。
它提供了一条实际可行的路径，让社群不用先开发完整的 Bot 产品，也能上线有用的 Discord Agent。

## 验证方式与边界

至少用一个已知问题、一个信息缺失问题和一个敏感管理问题验证这个场景。
检查 Agent 是否使用已确认的答案，是否承认不确定性，以及是否在需要时升级而不是自行发挥。

当前 Discord 通道文档说明了 Bot 授权、服务器与频道互动、消息内容读取以及通道层面的主动发送消息能力。
文档同时说明了当前关于群聊支持的限制。
如果你的上线流程依赖广泛的成员提及或特定的多人会话模式，请在公开上线前先在目标服务器中确认实际行为。

人工管理员仍然负责封禁、滥用举报、争议处理、规则变更和未被加入已确认上下文的公告。

## 常见问题

### 我需要自己编写 Discord Bot 吗？

这个使用方式不需要。
你可以在 LightVela 中配置 Hermes，连接 Discord 通道，然后把生成的 Bot 邀请到服务器。
如果需要高度特定的命令或流程，自定义代码仍然合适。

### Agent 可以回答服务器规则问题吗？

可以，前提是规则已经加入已确认的上下文，并且指令要求 Agent 不得编造或覆盖规则。
当规则不清楚或问题敏感时，应让它把成员引导给人工管理员。

### 它可以自动发送活动提醒吗？

可以，Discord 通道文档将主动发送消息列为通道层面的支持能力。
使用[定时任务](../configuration/automation.md)定义时间安排、任务说明、生效时间段和通知频道。

### Agent 应该做管理决策吗？

不应该。
让它负责解释、引导、提醒和总结，把执行规则和处理敏感情况的权力留给人工管理员。

## 结论

创建 Hermes Agent，提供经过确认的社群上下文，连接 Discord，邀请 Bot，然后用真实问题测试，再增加定时任务。
这个顺序可以把私人的 AI Agent 变成有用的社群助手，同时让服务器规则、权限和人工升级边界始终由你控制。
