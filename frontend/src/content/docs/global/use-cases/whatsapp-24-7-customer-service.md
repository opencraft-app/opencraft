# 如何在 WhatsApp 中配置 24/7 AI 客服：人格、知识、技能与自动化？

## 摘要

**WhatsApp 可以作为客户与 Hermes Agent 进行 1 对 1 沟通的入口，用于持续回答常见问题、整理客户需求并生成服务草稿；但这里的「24/7」指服务运行、模型可用、通道连接正常时可随时响应，不等同于不间断服务承诺或人工客服 SLA。** 另一个必须理解的约束是：WhatsApp 的主动消息仍受会话窗口、模板消息与通道配置限制，因此自动化提醒必须与客户主动发起的对话分开设计，不能假设可以随时向客户推送。落地顺序是人格、知识、技能、自动化四层依次搭建：人格定口径与转人工条件，知识沉淀 FAQ，技能补充可复用流程，自动化承担定时汇总类工作。

![在 WhatsApp 中配置 24/7 AI 客服](../images/use-case-09-whatsapp-24-7-customer-service.png)

## 适合谁

这篇指南适合希望在 WhatsApp 中部署个人客服、产品咨询助手或售后分流助手的用户。

它尤其适合需要统一客服口径、沉淀 FAQ、减少重复回复，并在复杂问题上转人工的团队。

## 前置条件

- 一个已经运行中的 LightVela Hermes Agent。
  如果你还没有创建 Agent，可以先查看[快速开始](../02-quickstart.md)。

- 一个已经配置好的模型或可用的体验积分。

- 一个可以使用的 WhatsApp 账号，并按照[配置通道 - WhatsApp](../configuration/channel-whatsapp.md)完成接入。

- 已整理的产品资料、服务时间、升级路径和人工联系方式。

- 明确哪些操作只能由人工执行或确认。

## 先理解 24/7 客服的五层配置

| 层级 | 负责什么 | 适合放在哪里 |
|---|---|---|
| 人格 | 角色、语气、优先级和服务边界 | SOUL.md 或[人设](./im-agent-persona-soul-md.md) |
| 知识 | 产品 FAQ、政策、服务时间和升级路径 | [云存储](../configuration/files.md)中的资料 |
| 技能 | 检索、整理、生成草稿和其他具体动作 | [Skill](../configuration/skill.md) |
| 记忆 | 已确认的客户偏好和长期协作背景 | [记忆管理](../configuration/memory.md) |
| 自动化 | 定时检查、内部提醒和主动通知 | [定时任务](../configuration/automation.md) |

不要把大量产品资料塞进人格，也不要把未经确认的客户内容直接当作长期记忆。

## 操作步骤

### 1. 先接入并验证 WhatsApp 1 对 1 对话

在目标 Hermes Agent 的通道设置中选择 WhatsApp，按照[配置通道 - WhatsApp](../configuration/channel-whatsapp.md)完成扫码授权。

在 WhatsApp 中打开对应联系人并发送一条测试消息，确认管理台显示已接入且能正常收到回复。

当前 WhatsApp 通道不支持群聊，因此本文的客服流程默认面向 1 对 1 客户对话。

### 2. 写一份客服人格说明

用[SOUL.md 人格指南](./im-agent-persona-soul-md.md)定义客服助手的身份、语气、回答顺序和升级边界。

客服人格可以从下面的说明开始：

    你是我们的产品客服助手。
    先回答客户当前最需要知道的结论，再给出必要步骤。
    只根据已确认的产品资料回答，不确定时明确说明并建议转人工。
    不承诺退款、改价、身份核验、删除数据或其他高风险结果。
    需要向外部系统发送内容或执行修改时，先说明影响并等待人工确认。

稳定的服务原则放进人格，具体产品答案放进可维护的资料。

### 3. 整理客服知识库

建议至少准备以下几类资料：

- 产品和套餐 FAQ。

- 服务时间、响应预期和人工联系方式。

- 退款、取消、升级和故障处理规则。

- 常见错误及排查步骤。

- 哪些请求必须转人工，以及转人工时需要收集哪些信息。

将资料按主题拆成容易维护的文件，并放入[云存储](../configuration/files.md)。

先用低风险问题测试资料是否能被正确引用：

    只根据已准备的客服资料回答这个问题。
    如果资料中没有答案，请说明缺少哪项信息，并给出转人工建议。

### 4. 安装并验证必要的 Skill

如果需要知识检索、工单整理、网页查询或内容生成，可以从 [Skills.sh](https://skills.sh/) 或 [ClawHub](https://clawhub.ai/) 选择可信 Skill。

在 WhatsApp 对话中请求安装前，先让 Hermes 说明 Skill 会读取什么、调用哪些外部服务，以及是否会主动发送消息。

高危 Skill 可能在安装前请求二次确认，确认前请阅读[配置技能](../configuration/skill.md)中的权限和安全提示。

安装后先测试草稿、摘要和 FAQ 检索，不要直接让新 Skill 执行退款、删数据或向客户发送未经审核的内容。

### 5. 设置客户偏好和长期记忆

只有经过确认、对未来服务有帮助的信息才适合写入记忆或用户画像。

例如，客户明确要求使用英文、希望先看结论，或已经确认了一个持续处理中的工单状态。

客户密码、验证码、支付信息、完整身份信息和不必要的敏感资料不应写入长期记忆。

可以在对话中请求 Hermes 记住或忘掉某项偏好，并定期在管理台检查[记忆管理](../configuration/memory.md)页面。

### 6. 配置自动化和主动消息

适合定时任务的客服工作包括内部待办提醒、未关闭工单检查和每日服务摘要。

在[定时任务](../configuration/automation.md)中设置执行时间、生效时间段和通知方式。

WhatsApp 主动消息可能受到会话窗口或已审核模板消息限制，客户没有先发起对话时不要默认普通文本一定能投递。

先用自己的测试号码验证通知是否成功、内容是否合适，以及失败时是否有清晰的内部处理路径。

### 7. 建立人工接管流程

当问题涉及退款、付款、身份核验、法律承诺、投诉升级或资料不足时，客服 Agent 应该停止猜测并转人工。

转人工消息至少要说明当前已知事实、缺少的信息、建议的下一步和客户是否需要再次描述问题。

每天抽查一部分对话，重点检查错误引用、过度承诺、敏感信息处理和重复主动消息。

## 一套可复用的客服回答顺序

1. 先给直接结论。

2. 引用最相关的资料或步骤。

3. 说明限制、费用、时间或所需信息。

4. 如果无法确定，明确转人工。

5. 只有在允许且经过确认时，才执行外部操作。

## 常见问题

### 24/7 是否意味着 WhatsApp 一定会随时回复？

不意味着。

Agent 需要运行、模型需要可用、WhatsApp 通道需要保持连接，而且主动消息还可能受到会话窗口和模板消息规则限制。

### WhatsApp 客服可以处理群聊吗？

当前 WhatsApp 通道文档明确说明不支持群聊，仅支持 1 对 1 对话。

如果需要群聊客服，应先确认其他目标通道是否有明确的群聊支持文档，不要根据 1 对 1 能力推断群聊可用。

### 客服资料应该放进记忆还是云存储？

产品 FAQ、政策和大量参考资料更适合放入云存储。

记忆和用户画像更适合保存少量稳定的客户偏好、已确认事实和长期协作背景。

### 可以让 Skill 自动给客户发消息吗？

只有在通道能力、业务授权、消息模板和人工审核规则都明确时才应启用。

默认先让 Skill 生成草稿或内部提醒，再由人工确认需要发送的内容。
