# 如何通过 Skill 把 IM Agent 变成客服、社群助手或 AI 伴侣？

Skill 负责扩展 Hermes Agent 的任务能力，而 SOUL.md 负责定义它稳定的角色、语气和行为边界。

把两者配合起来，你可以让同一个 IM Agent 更适合处理客户问题、维护社群，或陪伴你完成长期协作。

![通过 Skill 把 IM Agent 变成客服、社群助手或 AI 伴侣](../images/use-case-06-im-agent-skill-scenarios.png)

## 适合谁

这篇指南适合已经接入 Telegram、WhatsApp 或其他消息通道，并希望把 Agent 用在具体工作场景中的用户。

它尤其适合客服负责人、社群运营者，以及希望拥有长期陪伴型 AI 的个人用户。

## 前置条件

- 一个已经运行中的 LightVela Hermes Agent。
  如果你还没有创建 Agent，可以先查看[快速开始](../02-quickstart.md)。

- 一个已经可以正常对话的消息通道。
  你可以先阅读[如何在 Telegram 中配置一个具有独立人格的 Hermes Agent](./telegram-persona-agent.md)或[如何在 WhatsApp 中配置一个具有独立人格的 Hermes Agent](./whatsapp-persona-agent.md)。

- 对目标场景、允许的操作和需要人工接管的情况有初步定义。

- 准备从 [Skills.sh](https://skills.sh/) 或 [ClawHub](https://clawhub.ai/) 选择可信的 Skill。

## 先理解 Skill 与人格的分工

Skill 是可调用的能力包，例如浏览网页、整理资料、生成日报或执行特定流程。

SOUL.md 更适合描述 Agent 是谁、如何说话、如何做判断，以及哪些事情必须先征求确认。

用户画像和长期记忆则用于保存你的身份、偏好、已确认事实和持续推进的事项。

不要把客服话术、群组规则和高风险操作权限全部塞进同一份人格描述中。

## 操作步骤

### 1. 先确定 Agent 要服务的场景

不同场景需要不同的 Skill 组合和安全边界。

| 场景 | 主要目标 | Skill 方向 | 必须先定义的边界 |
|---|---|---|---|
| 客服助手 | 回答常见问题并分流复杂请求 | 知识检索、工单整理、订单查询 | 不确定时转人工，不擅自承诺退款或改动订单 |
| 社群助手 | 欢迎新成员、回答 FAQ、整理讨论 | 内容检索、摘要、定时提醒 | 不刷屏，不泄露成员信息，不代替管理员做处罚决定 |
| AI 伴侣 | 提供稳定的陪伴、提醒和长期协作 | 记忆整理、日程提醒、内容生成 | 尊重拒绝和隐私，不制造依赖，不把猜测说成事实 |

先选一个主要场景开始，不要一开始同时安装大量 Skill。

### 2. 准备资料和人格说明

客服场景可以先准备产品 FAQ、服务时间、升级路径和人工联系方式。

社群场景可以先准备入群欢迎词、常见问题、社区规范和摘要格式。

AI 伴侣场景可以先写下希望保持的称呼、语气、主动程度和不希望触碰的话题。

需要长期供 Agent 查阅的资料可以放进[云存储](../configuration/files.md)，稳定的人格规则可以通过[人设](./im-agent-persona-soul-md.md)写入 SOUL.md。

### 3. 选择并安装 Skill

LightVela 当前支持通过对话请求 Hermes 安装来自 Skills.sh 或 ClawHub 的 Skill。

在已经接入的通道中发送类似下面的请求：

    请从 Skills.sh 或 ClawHub 安装一个适合整理客服 FAQ 的 Skill，并先说明它需要哪些权限。

如果你已经知道 Skill 名称，可以明确指定：

    请安装 [Skill 名称]，先告诉我它会读取什么内容、调用哪些外部服务，以及是否会主动发送消息。

管理台中的可视化 Skill 安装入口仍以页面实际状态为准，详细安装方式请查看[配置技能](../configuration/skill.md)。

高危 Skill 可能在安装前触发二次确认。

在确认之前，先阅读 Skill 的来源、权限、外部 API 调用和主动执行行为。

### 4. 分场景验证 Skill 是否真的有用

先在 1 对 1 对话中测试，不要直接让新 Skill 面向大量用户运行。

客服助手可以先发送：

    根据已准备的 FAQ，回答这个问题；如果资料中没有答案，请明确告诉我并建议转人工。

社群助手可以先发送：

    根据这段讨论生成一份不超过五条的摘要，并列出仍然没有结论的问题。

AI 伴侣可以先发送：

    请用我设定的语气给出今天的简短 check-in，并说明哪些内容会被长期记住。

检查 Agent 是否调用了正确的 Skill，是否引用了正确资料，以及是否在不确定时停下来说明限制。

### 5. 把重复工作交给自动任务

欢迎词、FAQ、摘要和提醒都可能需要不同的触发方式。

适合固定时间执行的工作可以使用[自动任务](../configuration/automation.md)，例如每天发送一次社群讨论摘要或提醒客服团队处理未关闭事项。

自动任务的通知方式和目标通道需要单独确认，不要默认所有通道都能接收相同类型的主动消息。

## 三种场景的落地建议

### 客服助手

让 Skill 负责查找资料、整理上下文和生成草稿，让 SOUL.md 负责保持专业、清晰和克制的表达。

对于退款、改价、身份核验、删除数据或其他高风险动作，要求 Agent 先说明影响并等待人工确认。

当资料不足、用户情绪升级或请求超出授权范围时，优先转人工，不要为了保持对话连续而猜测答案。

### 社群助手

让 Skill 负责检索 FAQ、提炼讨论和生成提醒，让 Agent 的人格说明负责遵守社群语气与管理员规则。

群聊的接入、@触发、权限和消息投递能力取决于具体通道，配置前必须查看对应的通道文档。

如果目标通道当前不支持群聊，先在 1 对 1 对话中验证 Skill 和内容流程，不要把文章中的设计清单当成已上线的群聊功能。

### AI 伴侣

让 SOUL.md 描述稳定的陪伴方式，让记忆和用户画像保存经过确认的偏好与长期背景。

主动提醒应当有明确频率、暂停方式和安静时段，避免把“主动”误解成无限制地发送消息。

如果希望 Agent 记住某项偏好，可以直接在对话中请求记住；如果不想保留某项信息，也可以请求忘掉。

## 安全检查清单

- 安装前确认 Skill 的来源、权限和外部服务依赖。

- 测试阶段先使用 1 对 1 对话和低风险资料。

- 不让 Agent 在没有确认的情况下发送外部消息、修改订单、删除文件或执行不可逆操作。

- 为客服和社群场景准备人工接管路径。

- 定期检查记忆、用户画像和云存储中的内容，删除不再需要的信息。

## 常见问题

### 安装 Skill 后 Agent 会自动改变人格吗？

不会。

Skill 主要扩展 Agent 能做什么，人格由 SOUL.md 和相关配置定义。

Skill 的提示和输出可能影响某次任务的表达方式，但不应替代你对稳定角色和边界的设置。

### 客服 Skill 可以直接处理退款吗？

只有在相关系统权限、业务规则和人工确认流程都明确允许时，才应考虑这类操作。

默认建议让 Agent 先查询规则、生成处理建议，并在真正执行前等待确认。

### 社群助手可以直接加入 Telegram 群组吗？

当前 LightVela 的 Telegram 文档仍以 1 对 1 对话为支持范围，群聊方案请先阅读[Telegram 群组 AI 社群助手的能力边界说明](./telegram-group-community-assistant.md)。

### 我应该把所有资料都放进记忆吗？

不应该。

长期记忆适合保存少量稳定事实，产品 FAQ、社区规则和大量参考资料更适合放在[云存储](../configuration/files.md)或由 Skill 按需读取。
