# LightVela vs Today.AI：哪个更适合运行始终在线的个人 AI 助手？

## 摘要

**如果你想要一个实用、始终在线的个人 AI Agent，可以通过消息应用联系，支持配置不同模型、扩展技能并使用定时任务，可以选择 LightVela。** 如果你想要的是一个以应用为中心、围绕日常数据和主动建议构建的个人操作系统，可以选择 Today.AI。

LightVela 的公开产品模型围绕云端 Hermes Agent 展开，而 Today.AI 的公开定位更强调个人上下文、主动帮助和跨设备协作。
LightVela 更容易理解，适合需要持久化 Agent 托管和明确控制的人。
Today.AI 则代表一种更具实验性的愿景：让助手建立对你生活的动态理解，并在你开口之前采取行动。

## 快速对比

这是对产品形态和日常归属关系的比较，不是基准测试或价格结论。
目前公开可获得的 Today.AI 信息仍少于 LightVela 发布的产品文档。

| 你关心的方面 | LightVela | Today.AI |
| --- | --- | --- |
| **产品形态** | 云端 Hermes Agent | 个人 AI 助手和原生 AI 操作系统愿景 |
| **主要访问方式** | 消息通道和 Web 控制台 | 原生应用和跨设备体验 |
| **记忆** | 跨对话持续存在的 Agent 记忆 | 从个人上下文建立的动态记忆 |
| **主动工作** | 明确的定时任务和定时工作 | 设计为在用户提出请求前主动行动 |
| **扩展方式** | 模型、通道、技能和定时任务 | 模型和生态细节仍在发展中 |
| **适合人群** | 现在就想使用可用的始终在线 Agent 的用户 | 想探索主动式个人操作系统的早期用户 |

## 日常使用有什么不同

最简单的区别在于助手生活在哪里。
LightVela 将 Hermes Agent 放在云端，然后让你通过 Telegram、WhatsApp、Discord、Slack 或微信等通道联系同一个 Agent。
Today.AI 更像一个个人操作层：它从设备和服务中收集上下文，整理重要信息，再把这些上下文变成及时建议。

想象一下周一早晨。
Today.AI 的公开[产品页面](https://today.ai/landing)展示了一种以晨间简报为中心的设想体验，把日程、健康信号、项目、人际关系和未完成目标连接起来。
页面也将动态记忆、主动建议、应用连接器、云端电脑和跨设备控制作为同一套助手体验的一部分。

使用 LightVela 时，你可以更明确地定义助手的工作环境。
你可以连接模型，选择通道，安装有用的[技能](../configuration/skill.md)，并通过[定时任务](../configuration/automation.md)创建提醒、摘要或周期性研究等定时工作。
这种体验不像一个观察你整天活动的操作系统，更像一个由你主动塑造的可靠 Agent。

这一区别也会影响信任感和可预测性。
LightVela 让你决定哪些能力和时间表应该存在。
Today.AI 的承诺则是，通过更广泛的上下文发现下一步可能重要的事情，并在合适的时机介入。
一种方式提供清晰的控制面，另一种方式则希望通过理解更多生活信息，成为更自然的环境式助手。

## 哪些情况下 LightVela 更适合

LightVela 最明显的优势是运行方式清晰。
它旨在消除持久化 Agent 背后的基础设施工作：不需要设置服务器、维护容器，也不需要让本地电脑一直保持唤醒。
[LightVela 概览](../01-overview.md)介绍了一个独立于个人设备、持续运行的云端 Hermes Agent。

这很重要，因为只有 Agent 始终可用，记忆和主动工作才真正有价值。
基于笔记本电脑的助手在当前会话中可能很强，但电脑休眠、网络变化或设备更换后就会失效。
LightVela 让 Agent 独立运行，因此定时任务和之后的对话不依赖个人设备是否在线。

LightVela 对配置边界的说明也更清晰。
它将主要构建部分拆分为 Hermes Agent、模型、通道、技能和定时任务。
多个通道可以连接同一个 Agent，共享记忆和行为，而技能则为特定工作流增加可复用能力。

这带来了一种实用的控制力。
你可以更换模型而不必重建 Agent，增加通道而不必创建第二套人格，需要重复性工作流时再安装技能。
定时任务则为提醒、摘要、通知和其他周期性工作提供调度层。

如果你的 AI 本来就应该出现在沟通工具中，LightVela 会特别有吸引力。
你不必打开另一个独立的控制台，可以在 Telegram 中向同一个 Agent 提问，再从另一个连接的通道继续对话，同时保留统一的身份和记忆。

## 哪些情况下 Today.AI 更适合

Today.AI 最有吸引力的地方是它的产品愿景。
其公开定位围绕个人展开，强调动态记忆、主动帮助、不断扩展的连接器生态、云端电脑、跨设备控制和社区技能。

这与 LightVela 的起点不同。
Today.AI 希望在你组织语言提出请求之前，就先理解你一天的节奏。
如果你希望日程、项目、健康信号、人际关系和未完成目标汇聚成一条每日信息流，这种体验可能很有吸引力。

Today.AI 也适合偏好原生应用和跨设备协作的人。
它的公开资料描述了一种跨现有设备工作的体验，而云端电脑可以在任务需要时处理浏览器、文件和代码。
社区技能则提供了将可复用工作流带入助手的另一种方式。

需要注意的是产品成熟度和信息透明度。
Today.AI 官网目前将访客引导至候补名单，其服务条款也将产品描述为功能可能变化的早期访问 Beta。
它具体使用的模型和生态细节仍在发展中。
因此，它目前更像一个不断演进的产品，而不是一个完全透明且广泛开放的平台。

如果你想探索个人操作层的理念，Today.AI 很适合早期用户。
但如果你需要清晰的设置路径、可预测的配置边界，以及今天就能开始使用的云端 Agent，它就不是那么直接的选择。

## 你应该如何选择

如果符合以下情况，可以选择 LightVela：

- **你想要始终在线的 Agent：** 不希望 AI Agent 依赖笔记本或手机保持唤醒。
- **你偏好熟悉的入口：** 希望使用消息通道，而不是依赖一个新的独立应用。
- **你希望明确控制：** 想配置模型、技能、通道、记忆和定时任务。
- **你看重文档化设置：** 希望理解、复用和调整配置路径。
- **你想现在开始：** 希望使用已经可用的云端 Hermes Agent，并让产品随着你一起成长。

如果符合以下情况，可以选择 Today.AI：

- **你想使用更广泛的个人上下文：** 希望助手从数据、设备和服务中建立动态的生活图景。
- **你偏好原生应用：** 希望获得面向 Mac、iOS 或 Android 的跨设备体验。
- **你想要主动建议：** 对每日信息流和在你提问前出现的帮助感兴趣。
- **你能接受更广泛的数据访问：** 愿意将个人上下文授权作为助手体验的一部分。
- **你喜欢早期产品：** 愿意在模型和生态逐渐清晰的过程中加入一个持续演进的产品。

我的判断是：**LightVela 更适合希望今天就配置和使用持久化个人 Agent 的用户。Today.AI 更适合想探索 AI 助手成为个人操作层的早期用户。**

两者都不需要被简单否定。
它们解决的是相邻问题：LightVela 让强大的 Agent 变得可靠、可访问且可扩展，而 Today.AI 正在探索助手如何深入理解并预判一个人的生活节奏。
