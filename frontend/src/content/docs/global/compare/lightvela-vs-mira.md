# LightVela vs Mira：哪个更适合运行你的个人 AI Agent？

## 摘要

**如果你想要一个围绕日常习惯配置、可以安装可复用技能，并通过自动任务和自己选择的消息通道持续工作的个人 Hermes Agent，可以选择 LightVela。** 如果 Telegram 已经是你工作和社群活动的主要场所，而你希望把对话变成跟进、总结、提醒和实际操作，可以选择 Mira。

两者都超越了普通聊天窗口，但出发点不同：Mira 是以 Telegram 为中心的助手，LightVela 则是一个可以逐渐扩展为更广泛工作流系统的可配置个人 Agent。

![LightVela 与 Mira 运行个人 AI Agent 的对比](../images/lightvela-vs-mira.png)

## 快速对比

| 你关心的方面 | LightVela | Mira |
| --- | --- | --- |
| **适合场景** | 长期运行的个人 AI Agent | Telegram 内的个人或团队助手 |
| **核心体验** | 围绕日常习惯和偏好配置一个 Agent | 让 Agent 理解对话并直接从聊天中执行操作 |
| **设置重点** | 技能、自动任务、记忆、人设、模型和通道 | Telegram 对话、群组上下文、连接工具和周期性操作 |
| **日常价值** | 一个超越单次对话、持续工作的稳定 Agent | 减少聊天、任务和连接工具之间的上下文切换 |
| **最强场景** | 应该随时间持续改进的个人工作流 | 基于聊天的跟进、简报、内容和团队协作 |

## 日常使用有什么不同

实际差异不在于某一次提示词里谁给出的答案更好，而在于 Agent 如何进入你的日常，以及你希望自己塑造多少运行方式。

使用 LightVela 时，你可以围绕自己的工作方式配置云端 Hermes Agent，并随着需求变化持续和同一个 Agent 对话。
你可以安装可复用的[技能](../configuration/skill.md)、安排[自动任务](../configuration/automation.md)、选择[模型](../configuration/model.md)，并连接自己实际使用的通道。
这样，一次有用的对话就能逐渐变成持续工作的流程。

你可以让 Agent 每天生成简报、定期关注信息、起草内容或发送提醒，而不必每次重新搭建流程。
LightVela 的重点就是这种连续性：一个 Agent、一套不断完善的配置，以及一个可以持续调整的协作方式。

[Mira](https://mira.tg/) 从另一个方向出发。
它原生运行在 Telegram 中，可以用于个人聊天、群组和频道，不需要打开独立应用。
Mira 将自己定位为一个能够记住上下文、总结对话、追踪决定、连接外部工具，并把消息转化为实际操作的 Agent。

当工作的起点本来就是一段对话时，Mira 会显得非常自然。
团队可以把 Mira 加入群组，询问已经做出的决定，把共识转成后续任务，或者直接请求一份简报，而不必离开 Telegram。
这种体验更像是在共享聊天里交办工作，而不是配置一个独立的个人工作空间。

## 哪些情况下 LightVela 更适合

如果你希望 AI Agent 成为个人工作系统中稳定的一部分，LightVela 会更适合。
你不只是让助手回应最新消息，而是在塑造 Agent 应该如何行动、应该了解什么、可以使用哪些能力，以及什么时候主动工作。

你可以让 Agent 每天早上检查信息、关注竞争对手、把产品更新整理成社交内容，或每周总结一个研究主题。
真正有价值的不是某次回答多么惊艳，而是能把一次有用的互动变成持续运行的工作。

这正是技能和自动任务发挥作用的地方。
技能为 Agent 提供可复用的能力，自动任务则让重复工作按计划发生，不必依赖你在准确的时间记得发出提示词。
你可以先从每日简报开始，再添加研究技能，并把结果发送到最容易看到的通道。

如果你更关心配置 Agent 的角色，而不是接受一个固定的产品体验，LightVela 也是更直接的选择。
你可以选择模型，调整希望 Agent 遵循的行为，增加需要的能力，并决定它出现在哪些通道中。
[LightVela 概览](../01-overview.md)介绍了这些部分如何组合起来。

这种选择的代价是，LightVela 有意围绕一个不断成长的个人 Agent 构建。
如果你的主要需求是理解和处理繁忙的 Telegram 对话，Mira 可能会更直接。

## 哪些情况下 Mira 更适合

如果 Telegram 已经是你工作、社群和决策发生的地方，Mira 会更适合。
其官网介绍了一个原生运行在 Telegram 中的助手，可以处理内容、收件箱、加密资产监控、购物、旅行计划、提醒和连接工具。
它的核心优势是，请求产生时所需的上下文已经在当前聊天里。

Mira 也很适合团队和社群。
它可以理解谁说了什么，总结长篇群聊，找出尚未解决的决定，并帮助把对话转成分配给具体成员的后续任务。
对于产品团队、创始人、创作者和社群运营者来说，如果他们大部分时间都在 Telegram 而不是独立任务系统中，这种能力很实用。

同一个以 Telegram 为中心的模式也可以支持每日简报和周期性工作流。
你可以在合适的时间请求总结，委托研究任务，或直接在聊天体验中连接 GitHub、Notion 和 Google Drive 等服务。
Mira 的官方文档还强调了广泛的工具和集成能力，因此助手可以从回答进一步执行操作，而不要求你切换上下文。

它的边界同样清晰。
Mira 针对 Telegram 界面和其中的社交上下文进行了优化。
如果你想长期设计一个 Agent 的人设、模型、技能、自动任务和消息通道，LightVela 提供了更明确的控制面。

## 你应该如何选择

如果符合以下情况，可以选择 LightVela：

- **你想要一个个人 Agent：** 希望拥有一个会随着配置不断变有用的云端 Hermes Agent。
- **你看重连续性：** 希望同一个 Agent 长期在线并保留你的设置。
- **你偏好可配置的日常流程：** 希望围绕自己的习惯使用可复用技能和周期性自动任务。
- **你希望灵活访问：** 希望通过适合自己工作方式的通道联系 Agent。
- **你希望直接控制：** 想管理模型、人设、能力和工作流形态。

如果符合以下情况，可以选择 Mira：

- **你主要使用 Telegram：** 个人工作、团队决策或社群活动已经发生在聊天中。
- **你需要对话记忆：** 希望 Agent 理解大家说了什么，以及还有哪些事情需要完成。
- **你想快速交办：** 希望把一条消息变成提醒、任务、总结、草稿或连接工具的操作。
- **你需要群组协作：** 希望一个共享助手参与个人聊天和群组对话。
- **你偏好少量设置：** 希望先和 Agent 聊起来，而不是先配置一个独立工作空间。

我的判断是：**LightVela 更适合运行一个围绕个人习惯成长的个人 AI Agent，Mira 更适合把 Telegram 作为对话、工作和跟进的主要操作界面。**

如果你还想了解另一种执行模式，可以查看 [LightVela 与 Grok Bot 的对比](./lightvela-vs-grok-bot.md)。

如果你问的是“哪个 Agent 应该生活在我的 Telegram 对话里”，Mira 可能是更直接的答案。

如果你问的是“我应该在哪里运行一个每天都会持续塑造和使用的 AI Agent”，LightVela 会更合适。
