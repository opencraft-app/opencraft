# Frontend Design Notes

本文档用于维护前端跨页面、跨业务复用的组件设计规范，包括组件的视觉样式、布局、交互、响应式行为和可访问性约束。

- 规则应面向一类可复用组件或交互模式，不针对某个页面、功能、接口或临时需求单独定制。
- 具体业务流程、数据规则和功能验收标准应记录在对应的 OpenSpec、PRD 或功能文档中，不写入本文档。
- 新增规则前应先确认它能被多个场景复用；仅对单一功能成立的实现细节应留在该功能的代码或规格中。

## Corner Radius

页面内的卡片、面板、列表项和表单容器默认使用 `rounded-md`。除非是头像、圆形图标按钮、胶囊标签、弹窗外壳或明确需要强调柔和感的特殊组件，不要随手使用 `rounded-lg` / `rounded-xl` / `rounded-2xl`。

这样可以让工作台、设置页和任务面板保持更克制的工具感，避免卡片弧度过大导致界面显得松散、偏营销化。

## Card Shadow

Agent 控制台、诊断中心等工具型页面的同级卡片必须使用一致的轻阴影。默认卡片阴影使用 `0 10px 30px rgba(15,23,42,0.04)`，对应 Tailwind arbitrary value：`shadow-[0_10px_30px_rgba(15,23,42,0.04)]`。

- 同一页面或同一卡片组内，不要混用 `shadow-sm`、`shadow-md` 等预设阴影与自定义卡片阴影；新增卡片应先复用相邻同级卡片的阴影值。
- 卡片阴影应保持低透明度，只用于轻微区分白色卡片与页面背景，避免明显黑边、悬浮感过重或营销页式的大面积投影。
- 按钮、标签、下拉浮层、Tooltip 和 Dialog 不属于此规则范围，继续使用各自组件规范定义的阴影。

## Modal Layout

弹窗标题区和首个内容块必须结构隔离，不能依赖内容块第一行的 padding、line-height 或顶部 margin 来“撑开”标题间距。标题容器应显式承担底部留白，例如使用 `mb-5` / `pb-4`；首个内容块再从正常文档流开始。

- 带边框列表、表格、卡片组的弹窗，标题和内容之间必须有清晰可见的空白节奏，内容边框不能贴近或侵入标题基线。
- 不要用负 margin、绝对定位或 overflow 裁切来调整首个内容块的位置；如果出现标题与内容贴住、重叠或看似被内容顶上来的情况，优先检查标题容器与内容容器的结构间距。
- 调整这类问题时，不要只反复修改内容块自身的 `mt-*`。应让标题区拥有间距责任，内容区保持独立，避免后续首行高度、滚动容器或列表样式变化后再次回归。
- 多阶段弹窗使用稳定壳体：标题、进度轨道和操作区保持位置稳定，仅替换中间内容画布，避免每一步整体尺寸与焦点位置大幅跳动。
- 步骤轨道使用弹性连接线，不写固定像素宽度；当前步骤必须有 `aria-current="step"`，完成态、当前态和未开始态同时通过文字或语义区分。
- 桌面端主操作按钮保持紧凑并靠右，说明文案放在左侧；移动端改为全宽按钮。阶段切换只动画 `opacity` / `transform`，时长不超过 200ms，并尊重 reduced motion。
- 涉及敏感信息或不可轻易中断的流程，应使用可访问的 Dialog 语义、焦点锁定和关闭后焦点恢复；遮罩点击默认不关闭，Esc 与明确的关闭按钮可退出。

## Dropdown / Select

产品内的下拉选择器不要直接依赖浏览器原生 `<select>` 展开菜单。原生菜单的选中态、边框、阴影和字体会跟随系统实现，容易和 Agent 控制台、自动任务弹窗等自定义浮层风格不一致。

- 触发器优先使用按钮式控件：白底、轻边框、圆角或胶囊形态、右侧 `ChevronDown`，通过 `aria-haspopup="listbox"` / `aria-expanded` 保留语义。
- 展开层使用产品内浮层样式：白底、`border border-black/10`、`rounded-xl`、`p-1.5`、`shadow-xl`，位置从触发器下方 `top-[calc(100%+6px)]` 展开。
- 选项使用按钮渲染，`role="option"` / `aria-selected` 标记当前值；选中态使用项目内统一的高对比样式，不暴露系统蓝色高亮。
- 需要解释范围、限制或完整能力入口时，在菜单顶部或底部放静态提示文案，而不是塞进不可选的 `<option>`。例如导出、批量操作这类补充说明可以作为菜单说明文本，和可选项保持清晰区分。
- 菜单宽度可以独立于触发器。触发器应保持紧凑，浮层需要承载提示文案时可以适当加宽，避免长文案撑破或换行过碎。

## View More / Collapse

列表、搜索结果等内容超过首屏展示数量时，底部的展开 / 收起入口使用轻量胶囊按钮，不要做成主操作按钮或带填充色的 CTA。

Skills 搜索结果使用 SDK 风格的单列结构：所有结果共用一个 `rounded-md` 带边框容器，每个技能占一行并用浅色底边分隔，不使用双列独立卡片。行内从左到右依次为批量选择、名称与 slug/简介、安装状态；搜索结果行不显示技能图标、来源徽标或热门标记。标题右侧批量“安装”按钮保持 `h-9 px-6 text-sm`。hover 仅使用轻微背景色，不能增加独立卡片阴影或浮层效果。移动端保持同一信息顺序并允许文本截断，不横向滚动。

搜索结果的安装状态必须就近显示在对应行。批量开始后，尚未执行的选中项显示中性“等待中”，当前项显示带轻量转圈图标的“安装中...”，成功项显示“已安装”；搜索结果标题下同时显示轻量进度行“正在安装 (i/n)：技能名称”，任务结束后自动收起。普通错误使用浅红色“失败”状态，后端明确返回 skip/跳过语义时使用中性“已跳过”状态；两种状态旁都提供轻量描边“重试”按钮，重试期间显示“重试中...”。成功后切换为已安装，不能只依赖全局 Toast 表达进度或失败。

Skills 搜索与安装必须显式区分“无结果”和“请求失败”。单个来源失败时保留其他来源结果，并在列表上方使用浅黄色行内提示说明结果可能不完整；全部来源失败时只显示失败提示和“重试”，不能回退为“没有找到”。批量安装开始后，页签、搜索、清空、来源、排序以及所有安装和选择入口都进入禁用态；进度行提供“取消剩余任务”，当前命令执行完后停止后续项并把未执行项标记为“已跳过”。长时间运行的远端命令必须有有限超时，避免页面永久卡在忙碌态。

- 收起状态使用文案「查看更多」并在右侧放 `ChevronDown`；展开状态使用文案「收起」并在右侧放 `ChevronUp`。
- 默认尺寸为 `h-8 min-w-28 px-3`，文字使用 `text-xs font-semibold`，文字与图标间距使用 `gap-1.5`。
- 使用透明背景、轻边框和胶囊圆角：`rounded-full border border-black/[0.08] bg-transparent`；默认不加阴影，不在 hover 时添加背景填充。
- 默认文字颜色使用 `text-black/60`；hover 仅增强边框和文字，例如 `hover:border-black/15 hover:text-black/80`。
- 箭头使用 `size-3.5`，与文字颜色保持一致，不额外使用强调色。
- 按钮必须保留清晰的键盘焦点样式，并通过 `aria-expanded={true | false}` 暴露当前展开状态。
- 推荐完整样式：`inline-flex h-8 min-w-28 items-center justify-center gap-1.5 rounded-full border border-black/[0.08] bg-transparent px-3 text-xs font-semibold text-black/60 transition-colors hover:border-black/15 hover:text-black/80 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[var(--ring)] focus-visible:ring-offset-2`。

## Carousel Navigation

横向轮播或分批展示卡片时，上一项 / 下一项按钮必须贴近它们控制的内容，并分别位于内容视口左右两侧；不要把两个方向按钮并排放在标题行右侧。用户应能从按钮位置直接判断移动方向和受控区域。

- 标题独占一行，轮播操作区下一行使用“左按钮 / 内容视口 / 右按钮”的顺序；内容视口使用 `min-w-0 flex-1 overflow-hidden`，两侧按钮使用 `shrink-0`，避免挤压或遮挡卡片。
- 左按钮使用 `ChevronLeft` 并表达“上一批 / 上一项”，右按钮使用 `ChevronRight` 并表达“下一批 / 下一项”；按钮必须提供与动作一致的 `aria-label`。
- 两侧按钮应在卡片组高度方向居中对齐，不悬浮在标题、角标或某一张卡片上方，避免方向按钮看起来只控制局部内容。
- 到达首项或末项时保留对应按钮位置并进入禁用态，不能直接隐藏按钮导致卡片组宽度或位置跳动。
- 调整按钮位置时不得改变原有分页状态、切换动画、减弱动态效果设置和键盘可访问性。

## Installed Skills Table

已安装技能使用结构化列表展示 `名称/Slug / 分类 / 来源 / 版本 / 操作`。分类必须来自 SkillHub 或 Hermes 列表命令返回的数据，缺失时显示“未分类”，不要根据技能名称或 slug 推断。

- 名称列始终展示两行：第一行展示名称，第二行使用等宽字体展示原始 slug；两者相同时也不折叠。
- 桌面端各字段独立成列；移动端分类、来源和版本依次折行并带字段提示，删除按钮保持在右侧。
- 来源可以使用紧凑徽标，分类使用普通次级文本，避免两列都呈现为标签导致视觉噪声。
- 顶部同时提供名称搜索、分类筛选和来源筛选；名称搜索也应匹配原始分类值和本地化分类文案。列表每页展示 10 条，并在底部使用轻量上一页 / 下一页导航，避免已安装数量增长后页面过长。
- 来源筛选的固定优先顺序为 `全部来源 / SkillHub / 系统预置 / 本地安装`；其他实际存在的来源继续显示在后面，不能为了固定顺序而隐藏。
- 来源识别按真实安装记录和目录判断：SkillHub 安装记录优先，bundled manifest 命中显示“系统预置”；实际位于 `$HOME/.hermes/skills/` 的非预置技能显示“其他”。只有不在该目录、且 Hermes 原生列表明确返回 `Source=local` 的技能才显示“本地安装”。
- `installed` / `enabled` 等正常状态不额外占一列；仅在名称旁提示 `disabled` / `failed` 等异常状态。
- 加载失败不能显示成“还没有已安装的技能”，必须显示就近错误和“重试”。部分 registry 来源不可用时使用浅黄色行内提示，来源无法确认的行显示“来源暂不可用”且禁用删除。
- 系统预置技能不提供删除入口；其他技能只有在卸载命令执行并重新查询确认已移除后，才显示“卸载成功”。

## Hover Tooltip

设置页里的自定义 hover/focus 悬浮提示，默认使用文件管理器当前统一后的 tooltip 样式。

- 无裁剪祖先的简单场景，触发器外层可以使用 `group relative inline-flex`。
- 内联 Tooltip 默认展示在触发器上方并居中对齐：`absolute bottom-full left-1/2 mb-2 -translate-x-1/2`；位于滚动或裁剪容器时改用下述 Portal 规则。
- 视觉样式：白底深色字，`border border-[var(--border-subtle)]`，`rounded-md`，`px-3 py-1.5`，`text-[11px] font-medium`，轻阴影如 `0 8px 24px rgba(15,23,42,0.12)`。
- Tooltip 底部带白底小三角，可以用一个 `h-2 w-2 rotate-45` 的方块实现，并给三角加底边/右边边框衔接气泡。
- 行为：Tooltip 本体必须允许鼠标进入和文本选择，使用 `pointer-events-auto select-text`，不要使用 `pointer-events-none`。默认 `opacity-0`，`group-hover` 和必要的 `group-focus-within` 时显示，过渡时间保持短。
- 可复制性：当鼠标从触发器移到 tooltip 气泡内时，气泡应保持可见，用户可以拖拽选择并复制里面的文案。使用 portal 或 JS 控制显隐的 tooltip，需要在触发器与气泡之间保留短暂 hover 缓冲，或让气泡自身的 `mouseenter` / `mouseleave` 参与显隐状态。
- 裁剪边界（强制）：只要 Tooltip 触发器位于 `overflow-hidden`、`overflow-auto`、`overflow-y-auto`、滚动弹窗或其他会建立裁剪区域的祖先内，禁止把 Tooltip 作为该容器内的 `absolute` 子元素。必须通过 `createPortal(..., document.body)` 或项目统一浮层组件渲染为 `fixed` 浮层，并基于触发器的 `getBoundingClientRect()` 定位；窗口 resize 或祖先滚动时需要同步更新位置。
- `z-index` 无法突破祖先的 overflow clipping。发现 Tooltip 被弹窗、面板或滚动区截断时，不要通过继续提高 `z-index` 修复；验收时至少检查浮层已脱离裁剪容器，并验证贴近容器边缘时仍完整可见。
- 不要用浏览器原生 `title` 来替代这个样式；禁用按钮需要解释原因时，也使用这套 tooltip，例如 `未选择文件`。
