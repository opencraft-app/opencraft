# 自动任务支持获取上游任务的 Context Proposal

## 需求来源

- 产品输入：[2026-08-13-自动任务支持获取上游任务的Context.md](../../wiki/prd-docs/2026-08-13-自动任务支持获取上游任务的Context.md)
- 目标模块：Agent 控制台 → 自动任务
- TAPD：本次不创建、不关联
- 发布范围：仅国内站 `lightvela.com`；国际站 `lightvela.ai` 保持原有自动任务体验
- 需求规模：L（预计影响 5 个以上文件，包含 Cron 数据模型、结构化写入、表单组件、关系展示、删除联动、i18n 和测试）

## 背景

LightVela 当前只能管理彼此独立的 Hermes Cron 任务，页面没有暴露 Hermes 原生 `context_from`。用户无法在自动任务表单中配置“B 在自己的执行时间读取 A 最近一次完成输出”，也无法从任务列表理解已有关系。

本期只补齐 Hermes 原生定时串联，不引入完成事件触发、工作流画布或通用编排能力。

## 产品语义

- 每个 LightVela 自动任务最多选择一个同 Agent 上游；单上游仍可组成 A → B → C。
- 下游按自身计划执行，不等待同一时刻仍在运行的上游。
- 当前 Hermes 调度器读取上游最新的非空完成输出文件，不按成功或失败过滤，也不回退到更早的成功输出。
- 注入内容由 Hermes 原生截断到最多 8,000 个字符。
- 上游没有输出、输出为空或读取失败时，Hermes 静默跳过上下文，下游继续执行。
- Hermes 当前不持久化某次下游运行实际注入的来源文件；LightVela 只展示关系和可观测状态，不伪造执行级溯源。

## 目标

- 创建或编辑自动任务时，可搜索并选择一个有效上游。
- 正确写入、读取、保持、更换和清除 `context_from`。
- 阻止自引用和直接/间接循环依赖。
- 在卡片、详情和最近执行详情中展示上游关系及原生语义提示。
- 上游暂停时保留关系；上游删除时先解除直接下游关系，再删除上游。
- 不支持该字段的旧 Hermes 实例继续使用普通自动任务，不受影响。
- 历史任务无需迁移；未配置上游时行为完全不变。

## 范围

### 本次包含

- `CronJob` 补充 `context_from`，从 `jobs.json` 安全归一化。
- Hermes `context_from` 能力检测。
- 官方 `cronjob` 结构化 create/update/remove 适配，仅在关系操作需要时使用。
- 上游选择器、候选过滤、循环检测和外部多上游兼容。
- 任务卡片、任务详情、最近执行详情中的关系展示。
- 删除上游前的直接下游预览、解绑、失败回滚和删除阻断。
- 国内站功能、共享 i18n 资源、单元测试及组件测试；国际站仅增加“不启用该能力”的回归测试。

### 本次不包含

- 上游完成后立即触发下游。
- LightVela 创建多上游关系。
- 跨 Agent、跨实例或跨用户串联。
- 条件分支、并行汇聚、统一重试和工作流画布。
- 按成功状态筛选或回退到更早成功输出。
- 修改 Hermes 调度器或为执行记录新增运行时 provenance。
- 读取、展示、埋点或上传上游输出正文。
- TAPD 建单、产品动态或帮助文档发布。

## 方案选择

采用“现有 CLI + 官方结构化关系适配器”的渐进方案：

- 普通任务继续走当前稳定的 Hermes CLI 路径。
- 创建带上游的任务、修改上游关系和删除联动使用 Hermes 官方 `cronjob` Python 工具。
- 列表仍以 `hermes cron list --all` 为主，并从 `jobs.json` 补齐 `context_from`。

不采用以下方案：

1. 全量迁移全部 Cron CRUD 到结构化工具：长期方向更统一，但首期回归面覆盖场景任务、测试运行和模型钉住逻辑，超出本需求。
2. 直接修改 `jobs.json`：绕过 Hermes 校验、锁和原子写入，不符合官方管理约束。

## 用户验收标准

1. 创建或编辑任务时，可从同一 Agent 的正常正式任务中选择一个上游。
2. 候选不包含自身、暂停、过期、临时测试任务或会形成循环的任务。
3. 保存后 `context_from` 写入稳定任务 ID；再次编辑可正确回显、更换或解除。
4. 未修改上游时保留原关系；外部多上游配置不会被页面静默缩减。
5. 下游按自身计划读取上游最新完成的非空输出，不等待、不筛选失败结果。
6. 无输出或读取失败时，下游继续运行；注入内容最多 8,000 个字符。
7. 上游暂停后关系保留，并展示可能使用历史输出的提示。
8. 删除上游前展示直接下游；全部解绑成功后才删除，失败时停止并尽力恢复已解绑关系。
9. A → B → C 删除 A 时只解除 A → B，B → C 保持不变。
10. 卡片、详情和最近执行详情展示关系，但不把当前状态冒充为历史运行实际注入来源。
11. 不支持 `context_from` 的实例不展示可用入口，普通任务 CRUD 保持正常。
12. 国内站完整能力通过回归验证；国际站不展示、不探测、不读写 `context_from`，普通自动任务路径保持不变。

## 风险与依赖

- Hermes 文档存在“最近成功”与“最近完成”两种表述；验收以目标运行时调度器的最新完成输出行为为准。
- 结构化工具不存在或签名不含 `context_from` 时必须安全降级，不能尝试未知 CLI 参数。
- 删除解绑不是数据库事务；实现需要失败回滚，并在回滚也失败时返回明确的人工修复提示。
- 关系可能由 Hermes CLI、对话或其他客户端改动；每次打开表单和删除前都必须基于最新任务列表重新校验。
- 上游输出属于不可信数据；LightVela 不拼接内容，全部注入由 Hermes 原生边界完成。

## 规划结论

- 规模：L；按 `flow-cost.md` 的“影响文件 > 5”条件由 M 升级。
- 工作流模式：仓库全局配置为 `single_agent`；进入实现阶段时按 L 级门禁做角色隔离和最终 full review，本需求不启用额外 capability。
- 设计输入已确认；进入技术规格评审后再生成实施计划。
