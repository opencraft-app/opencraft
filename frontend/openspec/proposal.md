# 国内站登录弹窗交互优化 Proposal

## 背景

国内站登录弹窗需要突出默认推荐路径，并把手机号登录从隐藏入口调整为正式入口。当前线上后端已支持微信、QQ OAuth start/callback 和手机号验证码登录；本次不新增后端接口，避免引入发布顺序和网关放行风险。

## 目标

- 国内站登录弹窗默认展示微信登录。
- 微信登录使用现有 `/auth/oauth/wechat/start` 跳转方式，视觉上与 QQ 登录保持一致。
- 手机号登录成为正式入口，不再依赖 `show_phone_login()`。
- 任一登录方式被选中时，另外两种方式作为底部小按钮展示。
- 底部其他登录方式使用 logo + 文案，无边框，中间用竖线分隔。
- 登录协议作为三种登录方式的统一前置条件；微信 / QQ 位于“其他登录方式”上方，手机登录位于登录按钮上方。
- 手机号登录表单遵循项目 `DESIGN.md` 的轻量弹窗表单风格，避免过粗边框、过大圆角和字段标题堆叠造成的沉重感。

## 范围

### 本次包含

- `LoginModal` 国内站三方式切换。
- 微信、QQ 使用现有 OAuth start URL 跳转。
- 手机号验证码表单正式展示。
- 底部其他登录方式样式优化。
- 手机号登录表单样式、禁用态、字段级错误提示优化。
- i18n 文案更新。
- 登录弹窗相关单测更新。

### 本次不包含

- 后端接口、网关配置、OAuth callback 行为调整。
- 微信扫码嵌入弹窗。
- 国际站 Google / GitHub 登录改版。
- `/auth/sign-in` 独立登录页重构。
- QQ、微信、手机号账号合并或绑定。
- 实名认证、套餐、支付、订阅链路调整。

## 发布站点

- 发布范围：国内站 `lightvela.com` only。
- 国际站：不本次同步。

## 验收标准

1. 国内站登录弹窗打开后默认展示微信登录按钮。
2. 勾选协议后点击微信按钮跳转现有微信 OAuth start URL。
3. 切换到手机后展示手机号验证码登录表单。
4. 切换到 QQ 后展示 QQ 登录按钮并跳转现有 QQ OAuth start URL。
5. 未勾选协议时，微信、QQ 和手机号登录动作都展示统一提示，不发起登录。
6. 底部“其他登录方式”始终只展示当前未选中的两种方式。
7. 底部按钮包含 logo，按钮无边框，按钮之间用竖线分隔。
8. 底部微信、QQ、手机 logo 视觉尺寸一致。
9. 手机登录不展示副标题“使用手机号和短信验证码登录”，也不展示视觉字段标题。
10. 手机登录协议勾选展示在登录按钮上方。
11. 手机号或验证码为空时登录按钮不可点击。
12. 手机号或验证码错误时，错误文案以红字展示在对应输入框下方，并将对应输入框边框置红。
13. 手机登录输入框保持轻边框、`rounded-md`、普通字重和浅聚焦态。
14. 底部其他登录方式与弹窗下边框之间保留足够留白。
15. 国际站登录行为保持不变。
