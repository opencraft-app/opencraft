# 国内站续费用户交互优化：需求提案

## 文档状态

- 状态：规划完成，待用户确认后进入实现。
- 规模：M（标准开发）。
- 执行模式：single_agent。
- 开发分支：`feat/walkercao-0722-renewal-interaction-design`。
- 产品来源：本地 PRD `product/prd/2026-07-22-renewal-interaction-design.md`。
- TAPD 产品需求：[TAPD #136414042](https://tapd.woa.com/tapd_fe/10132091/story/detail/1010132091136414042)。
- 发布范围：国内站 `lightvela.com` only。

## 背景

国内站用户已具备续费后端能力、前端 Repository 方法、微信支付中转页和账号页内的 `RenewPassModal`，但账号页订阅卡片中的续费入口仍被隐藏。`/subscribe` 在过期或隔离状态下会提示用户去账号页续费，但用户到达账号页后找不到可执行动作。

同时，已经创建 Agent 的用户日常高频使用 `/agents`，但当前无法在 Agent 管理场景中提前感知套餐即将到期。这个断点会让用户到期后才发现 Agent 使用受影响，续费恢复成本更高。

## 用户目标

1. 在 `/account` 明确看到当前套餐的续费入口，并完成当前套餐续费。
2. 在续费弹窗里确认套餐、状态、当前到期时间、续费时长、预计续费后到期时间和应付金额。
3. 在 `/agents` 的 Agent 信息头部直接感知套餐临近到期，并可点击状态提醒打开续费弹窗。
4. 在 `/subscribe` 被过期或隔离拦截时，获得明确的账号页续费路径。

## 范围

### 本次包含

- `/account` 订阅卡片恢复“立即续费”入口，支持 `active`、`expired`、`isolated` 三类未删除 Pass。
- 抽取并复用 `RenewPassModal`，供 `/account` 和 `/agents` 两个入口共同唤起。
- 续费周期收敛为月付和季付：月付对应 1 个月，季付对应 3 个月。
- 续费弹窗状态文案调整：`active` 展示为“生效中”。
- 支付阶段删除“二维码有效期约 9 分钟”，仅保留“支付完成后页面会自动刷新”。
- 支付阶段手动按钮从“我已完成支付”改为“刷新”。
- `/agents` Agent 信息头部增加到期状态提醒，hover 展示剩余时间，点击打开续费弹窗。
- `/subscribe` 对 `PASS_EXPIRED` / `PASS_ISOLATED` 展示更明确的续费引导。
- 覆盖询价失败、下单失败、支付未确认、刷新后确认成功、移动端布局和国际站隔离。

### 本次不包含

- 国际站 `lightvela.ai` 续费体验。
- 自动续费。
- 套餐升级、降级、变配或换套餐。
- 工具能力、SkillHub、MCP、专家包或自动任务能力上线。
- 短信、邮件、企微、站外通知或运营活动。
- 新增独立续费页。
- 新增后端接口。

## 方案决策

### 采用方案：账号页续费闭环 + Agent 头部到期状态提醒

1. `/account` 保持订阅与权益管理的主入口，负责展示套餐状态、续费入口、过期或隔离恢复路径。
2. 将账号页内已有的 `RenewPassModal` 抽取为可复用组件，保持续费下单、微信二维码支付和 Pass 刷新逻辑一致。
3. `/agents` 不新增顶部 banner，而是在截图红框对应的 Agent 信息头部状态区增加短提醒，贴近“运行中”状态展示。
4. `/agents` 的提醒点击直接打开续费弹窗，不绕行 `/account`，降低续费路径长度。
5. `/subscribe` 继续只做错误回流，不承接完整续费弹窗，避免新购与续费路径混杂。

### 未采用方案

| 方案 | 不采用原因 |
| --- | --- |
| `/agents` 主内容区顶部 banner | 会占用控制台工作区主内容，并与用户希望放在 Agent 信息头部的图示位置不一致。 |
| `/subscribe` 直接承接续费弹窗 | 新购和续费混在订阅页主流程中，状态分支更大，也更容易让用户误以为可以换套餐。 |
| 新增独立续费页 | 当前已有弹窗和续费接口，新增路由会增加状态恢复、支付中转和测试成本。 |

## 关键交互

### `/agents` 到期状态提醒

- 展示条件：国内站、已登录、已有至少 1 个非创建中/非删除中的 Agent、`activePass` 距离到期小于等于 7 日。
- 位置：Agent 信息头部，贴近“运行中”状态，不进入主内容区顶部。
- 短文案：`套餐将到期`。
- hover：剩余大于等于 1 天展示 `套餐剩余 {{days}} 天到期，点击续费。`；小于 1 天展示 `套餐剩余 {{hours}} 小时到期，点击续费。`；不足 1 小时展示 `套餐不足 1 小时到期，点击续费。`
- 颜色：剩余 2-7 天用琥珀色提醒；剩余小于 2 天用红色或橙红色提醒；大于 7 天不展示。
- 点击：直接打开 `RenewPassModal`。
- 移动端：短文案常显，点击打开弹窗。

### `RenewPassModal`

- 入口：`/account` 的“立即续费”和 `/agents` 的到期状态提醒。
- 当前套餐状态：`active` 展示“生效中”，`expired` 展示“已过期”，`isolated` 展示“隔离期”。
- 续费周期：月付 1 个月、季付 3 个月；默认月付。
- 询价中：展示 `正在查询价格...`，确认按钮暂不可点击。
- 询价失败：展示轻量错误，可继续下单，最终金额以支付页为准。
- 支付阶段：展示订单摘要、二维码、`支付完成后页面会自动刷新。` 和“刷新”按钮。
- 成功判定：只有刷新后确认同一 Pass 的 `expired_time` 推后，才展示成功并关闭弹窗或刷新当前页面状态。

## 验收标准

1. 国内站 `/account` 中，持有 `active`、`expired` 或 `isolated` 未删除 Pass 的用户能看到“立即续费”；`deleted` Pass 不展示。
2. 点击“立即续费”后打开续费弹窗，默认月付，可切换季付并触发询价；月付对应 1 个月，季付对应 3 个月。
3. 询价成功展示应付金额；询价失败展示轻量错误且仍允许尝试下单。
4. 确认续费后调用续费下单链路，生成微信支付二维码；二维码中转页走续费 `renew/order-url` 路径。
5. 用户支付完成后，发起续费的页面刷新 Pass 并展示新的有效期；刷新未确认成功时不误报成功。
6. `/subscribe` 遇到 `PASS_EXPIRED` 或 `PASS_ISOLATED` 时，错误提示明确告诉用户前往 `/account` 续费，并提供可点击动作或清晰入口。
7. `/agents` 中，用户已有至少 1 个非创建中/非删除中的 Agent，且有效 Pass 距离到期小于等于 7 日时，在 Agent 信息头部展示到期状态提醒。
8. `/agents` 到期状态提醒 hover 后展示剩余时间；大于等于 1 天展示剩余 X 天，小于 1 天展示剩余 X 小时；2-7 天和小于 2 天有不同提醒颜色；点击提醒可直接唤起续费弹窗。
9. `/agents` 到期提醒不阻断用户继续管理 Agent，不使用弹窗或全屏遮罩自动打断。
10. 国际站构建不展示国内站续费入口或中文提醒，不引入国际站支付行为变化。
11. 本次不出现 SkillHub、MCP、工具能力或自动任务相关上线入口。
12. 相关页面移动端不横向溢出，按钮和提醒文本不相互遮挡。

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| 续费弹窗从账号页局部组件变为复用组件后产生状态耦合 | 组件只通过 props 接收 `pass`、`plans`、`onSuccess` 和 `onClose`，成功后由调用方刷新当前页面状态。 |
| `/agents` 到期提醒误显示在无 Agent 或国际站场景 | 展示条件同时检查 `isCN`、Agent 列表、`activePass` 和到期时间。 |
| 支付完成后误报成功 | 只在刷新后确认 `expired_time` 推后时成功；未确认时保留刷新或重试路径。 |
| 询价失败与继续下单金额不一致 | 明确文案说明最终金额以支付页为准，确认按钮在询价失败后才可继续。 |
| 旧测试默认断言续费入口隐藏 | 更新测试契约，改为仅在隐藏工具开关以外的国内可续费场景展示续费入口。 |
| 国际站行为被打包进去 | 国内站分支必须走 `isCN` / `isGlobal` 编译期常量，国际站目标测试覆盖“不展示”。 |
