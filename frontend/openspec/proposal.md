# 诊断中心工作区备份与恢复交互优化提案

## 背景

诊断中心已有 Hermes 工作区导入/导出能力，但当前界面更像 worker action 调试面板：导出和导入分成两行操作，日志混合展示，失败时会直接暴露 `timed out waiting ... last=PENDING` 等底层错误。用户难以判断当前任务类型、下一步动作和失败后的可恢复路径。

## 目标

把“工作区备份与恢复”优化成诊断中心里的任务控制台，让用户围绕“备份到邮箱 / 从备份恢复”完成闭环：

- 用户能一眼看出当前是否有任务、任务类型、阶段和最近结果。
- 发起导出/导入前有清晰前置检查和确认，不再依赖浏览器原生 `window.confirm`。
- 任务进行中自动轮询，手动刷新只是补充动作。
- 失败信息就地展示，主文案产品化，技术详情可展开复制。
- 导出和导入日志不再混成一条无归属时间线。

## 非目标

- 不修改 service-gateway 或 workers 的 API 协议。
- 不改变导出范围，仍然只处理 `/home/agentuser/.hermes`。
- 不新增取消任务能力；后端已有 cancel 路由，但本轮先聚焦主流程和失败体验。
- 不把导入改造成整机恢复；导入仍是 Hermes 工作区覆盖恢复。

## 验收标准

- 未绑定邮箱、Agent 非 running、已有任务运行中时，按钮状态和提示能在面板内说明原因。
- 点击“备份到邮箱”后，通过产品内确认弹窗发起任务；成功后显示当前导出进度并自动轮询。
- 点击“从备份恢复”后，先选择 zip，再确认文件名、大小和目标 Agent；确认后显示导入进度并自动轮询。
- `PENDING`、TAT 超时、zip 损坏、邮箱缺失等常见错误显示为用户能理解的文案，原始错误进入详情。
- 任务详情日志按导出/导入归属展示，默认保持克制，失败时可展开。
- 相关文案通过 i18n 生成文件补齐，类型检查和针对性测试通过。
