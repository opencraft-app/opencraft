# 国内站 Agent 审批模式设计

## 背景与目标

国内站 Agent 的「高级设置」已提供记忆与上下文配置，但用户仍需进入终端才能调整 Hermes 对危险命令的审批策略。本次在现有页面增加「审批模式」，让用户查看并修改目标 Agent 当前实际生效的 `approvals.mode`，同时对完全关闭审批的高风险选择增加明确确认。

截图仅作为单行设置与下拉控件的交互参考，不引入截图中的其他 Safety 配置。

## 范围

- 仅修改国内站 `/agents/settings`；国际站继续不生成该入口，直接访问仍返回 404。
- 在页面最上方新增「安全」分组，并将「审批模式」作为该分组的第一项。
- 支持 Hermes 官方的三个值：

| 页面值 | Hermes 值 | 含义 |
|---|---|---|
| 智能审批 | `smart` | 自动判断风险，仅在不确定时询问用户 |
| 始终询问 | `manual` | 危险命令需要用户明确批准 |
| 关闭审批 | `off` | 不再执行危险命令审批检查 |

- 不新增审批超时、命令白名单、私网访问、文件检查点等截图中的其他设置。
- 不修改 LightVela Hermes 镜像的初始预置值；新建实例仍可按镜像配置得到 `off`，页面只负责读取并呈现真实有效值。

## 方案选择

扩展现有 typed settings 框架，新增 select 类型、字符串值和按字段区分的应用策略，不为审批模式复制独立的数据读取与保存模块。

未采用以下方案：

- 独立审批模式模块：隔离更彻底，但会重复现有读取、保存、回读、错误和版本兼容逻辑。
- 无条件复用现有保存链路：实现最少，但会在修改 `approvals.mode` 后不必要地重启 Gateway，不符合 Hermes 的即时生效语义。

## 信息架构与文案

页面分组顺序为：

1. 安全
2. 记忆
3. 上下文管理

「安全」分组说明使用「管理 Agent 执行危险命令时的审批方式。」。

审批模式行：

- 标题：「审批模式」
- 说明：「设置 Agent 遇到危险命令时如何请求审批。」
- 控件：与现有表单视觉一致的下拉选择器，显示中文值。
- 可访问名称使用「审批模式」，键盘可聚焦并可通过方向键选择。

安全分组与后续分组沿用现有低对比度分隔线；组内不新增卡片或横线。select 控制列与数字输入项一样保留固定桌面宽度，移动端按现有单列布局自然换行。

## 交互

### 普通切换

- 从任意模式切换到「智能审批」或「始终询问」时立即保存。
- 选中当前值时不发起保存。
- 保存期间禁用全部设置控件，避免与其他单项保存或分组恢复并发。
- 保存成功显示现有顶部 Toast「已保存」。

### 切换到关闭审批

选择「关闭审批」时先打开风险确认弹窗，不立即保存：

- 标题：「确认关闭命令审批？」
- 说明：「关闭后，Agent 执行危险命令时将不再请求你的批准。请仅在可信环境中使用。」
- 操作：「取消」与「确认关闭」
- 「确认关闭」使用危险操作红色按钮；取消、关闭按钮、点击遮罩或 Esc 均不修改配置，并让下拉框继续显示原值。
- 确认后才进入保存状态；保存失败时仍显示原来的有效值。

如果页面初次读取到的有效值已经是 `off`，下拉框直接显示「关闭审批」，不额外弹窗；只有用户主动从其他值切换到 `off` 时确认。

### 恢复默认

「安全」分组沿用现有「恢复默认」按钮与分组级确认弹窗。确认后仅对显式存在的 `approvals.mode` 执行 `hermes config unset approvals.mode`，回读确认该字段重新沿用 Hermes 官方默认值 `smart`。

- 恢复默认不写入 LightVela 镜像预置值 `off`。
- 安全分组已经沿用默认值时，「恢复默认」按钮置灰。
- 恢复成功显示 Toast「已恢复默认」。
- 因 `approvals.mode` 即时生效，恢复默认也不重启 Gateway。

## 类型与配置映射

在现有设置模型中新增：

- key：`approvalMode`
- Hermes key：`approvals.mode`
- value：`"smart" | "manual" | "off"`
- group：`security`
- control kind：`select`
- apply policy：`immediate`

现有布尔和数字字段继续使用 `restartGateway` 策略。值校验必须基于静态 allowlist；前端不能接受任意配置 key、任意枚举值或任意 shell 片段。

## 读取与版本兼容

现有批量读取命令增加 `approvals.mode`：

1. 通过 `hermes config get approvals.mode --json` 读取当前有效值。
2. 只读 `~/.hermes/config.yaml`，判断 `approvals.mode` 是否显式存在，用于 `defaultedKeys`。
3. 仅接受 `smart`、`manual`、`off`；其他返回值视为无效配置并让整次快照读取失败，避免展示前端猜测值。
4. CLI 不支持该 key 时，将 `approvalMode` 放入 `unsupportedKeys`，页面显示「当前 Agent 版本不支持」并禁用控件。

## 保存与错误语义

保存审批模式的链路为：

1. 执行 `hermes config set approvals.mode <value>`。
2. 不获取、不执行 Gateway 重启命令。
3. 完整回读设置快照。
4. 仅在 `approvalMode` 与目标值一致时报告成功。

错误状态沿用现有结果类型：

- config set 失败：`failed`，显示「保存失败」并保留旧值。
- config set 成功但回读失败或值不一致：`partial`，提示配置可能已保存但尚未验证，建议刷新确认。
- 其他六项设置的 `config set → Gateway restart → 回读验证` 链路保持不变。

分组恢复默认根据目标字段的应用策略决定是否重启：安全分组不重启；记忆和上下文分组继续只重启一次。

## 状态与并发

- `loading`、Agent 非运行态、任一字段 `saving` 或任一分组 `resetting` 时，审批模式控件遵循现有全局禁用规则。
- 风险确认弹窗打开期间尚未发生配置修改。
- 请求 ID 变化或组件卸载后，迟到的保存与回读结果不能更新页面状态。
- `unsupported` 状态只读展示，不提供恢复默认操作；分组是否已默认仅计算支持的安全字段。

## 测试与验收

### 配置层

- 读取命令包含 `approvals.mode`，能够解析三个合法值和显式/默认状态。
- 拒绝未知字符串并阻止构造配置写入命令。
- 构造命令严格等于 `hermes config set approvals.mode smart|manual|off`。
- 旧版 CLI 不支持时正确进入 `unsupportedKeys`。

### 保存与恢复

- 保存审批模式只执行 config set 和回读，不获取或执行 Gateway 重启命令。
- 回读值不一致时返回 `partial`。
- 安全分组恢复默认只 unset `approvals.mode` 并回读，确认默认值为 `smart`，不重启 Gateway。
- 记忆与上下文设置的现有重启行为保持不变。

### 页面

- 页面渲染三个分组、七个设置行，安全分组位于最上方。
- 下拉框展示三种模式及当前有效值。
- 切换到 `smart`、`manual` 直接保存；切换到 `off` 必须确认。
- 取消风险弹窗不保存且恢复原显示值；确认后才保存。
- 初始值为 `off` 时直接展示，不在加载时弹窗。
- Agent 停止、保存中、恢复中和版本不支持状态均禁用控件。
- 安全分组恢复默认后显示「智能审批」。

### 区域边界

- 国内站左侧导航与 `/agents/settings` 页面正常展示新增设置。
- 国际站不展示「高级设置」入口，且 `/agents/settings` 继续不生成并返回 404。
