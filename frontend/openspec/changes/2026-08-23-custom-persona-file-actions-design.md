# 自定义人设文件编辑与下载设计

## 背景

国内站 Agent 人设页已经支持上传 Markdown 并安全写入当前 Agent 的 `SOUL.md`。页面刷新后只读取文件存在性、`Slug` 和 `Name`，因此可以展示“已注入：自定义人设 · <名称>”，但用户无法从页面查看、修改或下载 Agent 当前实际生效的完整文件。

本次在自定义人设已注入状态上补充按需编辑和下载能力。内容来源必须是 Agent 当前实际 `SOUL.md`，不能依赖浏览器内存或最初上传的本地文件。

## 目标

- 在“已注入：自定义人设 · <名称>”后显示编辑图标和下载图标。
- 点击编辑图标后读取当前 Agent 实际 `SOUL.md`，在弹窗中编辑并安全保存。
- 点击下载图标后直接读取并下载当前 Agent 实际 `SOUL.md`，不打开编辑弹窗。
- 保持页面初始状态读取轻量，不在每次刷新时传输完整 Markdown。
- 保存继续沿用备份、临时文件和原子替换规则，失败时不破坏旧文件。

## 非目标

- 不为推荐人设卡片增加相同的状态操作区。
- 不新增后端 API、数据库存储或浏览器持久化副本。
- 不在编辑弹窗中提供上传其他文件、结构建议或下载按钮。
- 不改变国际站行为。
- 不让已存在的 Agent 会话热加载修改后的 `SOUL.md`；保存后仍需发送 `/new`。

## 方案选择

采用独立的按需全文读取命令：页面初始化继续使用现有身份读取命令，只有用户点击编辑或下载图标时才读取完整文件。

未采用以下方案：

- 扩展现有身份读取命令：会在每次页面刷新和每次注入后同步时传输全文，增加不必要的数据量，也破坏现有最小读取契约。
- 缓存最初上传内容：刷新后丢失，且无法反映通过其他方式修改后的 Agent 实际文件。

## 交互设计

### 状态入口

只有 `Slug: custom-upload` 的自定义人设状态显示两个图标按钮，位置在“已注入：自定义人设 · <名称>”文本之后：

1. 编辑图标，`aria-label` 和悬浮提示为“编辑自定义人设”。
2. 下载图标，`aria-label` 和悬浮提示为“下载自定义人设”。

两个操作只由图标按钮触发，状态文字本身不变成可点击区域。读取过程中对应图标进入加载态并禁止重复点击；另一个图标也暂时禁用，避免并发读取同一文件。

### 编辑弹窗

- 标题：“编辑人设文件”。
- 文件名行：`SOUL.md`。
- 编辑框复用上传人设编辑态的边框、圆角、等宽字体和 6px 标题间距。
- 显示实时 UTF-8 字节数和 `20 KB` 上限。
- 右下角操作为“取消”和“保存修改”，不放下载按钮。
- 内容未改变、内容为空、包含非法控制字符或超过 20 KB 时禁用“保存修改”。
- 保存时使用现有自定义人设标准化逻辑，保持 `Slug: custom-upload` 和有效 `Name:`，再使用现有安全写入命令备份并原子覆盖。
- 保存成功后关闭弹窗、刷新自定义人设名称，并提示“人设已更新，请发送 /new 开始新会话以生效”。
- 保存失败时保留弹窗和编辑内容，显示“保存失败，请检查网络后重试”。

### 直接下载

- 点击下载图标后按需读取当前实际 `SOUL.md`。
- 读取成功后使用 UTF-8 `Blob` 下载，文件名固定为 `soul.md`。
- 下载内容是读取到的 Agent 当前文件，不经过标准化或改写。
- 创建的对象 URL 和临时 `<a>` 在触发后立即清理。

### 读取失败

- 文件不存在或为空：提示“当前 Agent 没有可用的人设文件”，并触发一次身份状态刷新。
- 文件超过 20 KB：提示“当前人设文件超过 20 KB，暂不支持在线编辑或下载”。
- 输出格式异常、Base64 解码失败或非 UTF-8：提示“无法读取人设文件，请重试”。
- 网络或 Agent 命令失败：提示“无法读取人设文件，请检查网络后重试”。

编辑入口读取失败时不打开空编辑器；下载入口读取失败时不创建本地文件。

## 技术设计

### 按需读取命令

在 `agent-buddy-command.ts` 新增独立命令构造器，不修改 `buildHermesSoulReadCommand()`：

```ts
buildHermesSoulContentReadCommand(): string
```

命令读取 `${HERMES_HOME:-$HOME/.hermes}/SOUL.md`，先检查文件非空和字节数，再输出稳定协议：

```text
Exists: yes
ByteLength: 1302
ContentBase64: <单行 Base64>
```

文件不存在或为空时只输出 `Exists: no`；超过 `20 * 1024` 字节时输出 `Exists: yes`、`TooLarge: yes` 和实际字节数，不输出正文。Base64 用单行输出，避免 Markdown 中的换行、控制字符或类似协议字段干扰解析。

### 内容解析

新增纯函数：

```ts
type HermesSoulContentResult =
  | { status: "ready"; markdown: string; byteLength: number }
  | { status: "missing" }
  | { status: "too_large"; byteLength: number }
  | { status: "invalid" };

parseHermesSoulContent(output: string): HermesSoulContentResult
```

解析器必须：

- 只接受明确的状态协议。
- 严格校验 `ByteLength` 为非负整数且不超过 20 KB。
- Base64 解码后按 UTF-8 严格解码。
- 校验解码后的实际字节数与 `ByteLength` 一致。
- 对缺失字段、非法 Base64、无效 UTF-8 或长度不一致返回 `invalid`。

### 前端组件边界

新增 `CustomPersonaFileModal` 组件，职责限定为：

- 接收已读取的初始 Markdown。
- 管理编辑值、实时校验、保存中和保存失败状态。
- 通过 `onSave({ markdown, displayName })` 把标准化后的内容交回面板写入。

`BuddyPanel` 负责：

- 图标入口和读取/下载加载态。
- 调用 Agent 命令读取当前全文。
- 创建浏览器下载。
- 调用现有安全写入链路保存编辑结果。
- 保存后刷新实际身份状态和展示名称。

### 并发与 Agent 切换

- 全文读取复用当前 `operationReqIdRef` / `activeBotIdRef` 风格的请求身份检查。
- 切换 `botId`、组件卸载或较新读取开始后，旧读取结果不得打开弹窗、触发下载、覆盖编辑内容或显示成功提示。
- 保存期间禁止关闭弹窗和重复提交。

## 测试设计

### 命令与纯函数

- 全文读取命令只在文件存在、非空且不超过 20 KB 时输出单行 Base64。
- 不存在、空文件和超过 20 KB 返回对应状态且不输出正文。
- 中文和多行 Markdown 可以完整往返。
- 非法 Base64、无效 UTF-8、长度不一致和未知输出返回 `invalid`。
- 现有身份读取命令继续不输出完整 Markdown。

### 编辑弹窗

- 展示 `SOUL.md`、当前内容、字节数、取消和“保存修改”。
- 未修改、空内容、控制字符和超过 20 KB 时禁止保存。
- 保存失败保留内容并可重试；保存中禁止关闭和重复提交。

### BuddyPanel

- 自定义人设状态显示编辑和下载图标；推荐人设状态不显示。
- 编辑图标读取实际文件后打开弹窗；保存使用备份原子写入命令，并刷新展示名称。
- 下载图标读取实际文件后下载 `soul.md`，内容与 Agent 文件完全一致，不打开弹窗。
- 读取失败、文件缺失、超限和下载异常都有对应提示，不产生空文件。
- 切换 Agent 后忽略旧读取和保存结果。
- 国际站不新增入口。

## 验收标准

1. 自定义人设状态文字后显示编辑与下载图标，并具备明确无障碍名称。
2. 编辑图标打开的弹窗展示当前 Agent 实际 `SOUL.md`，允许修改并显示 UTF-8 字节数。
3. “保存修改”先备份旧文件，再原子覆盖；失败不破坏旧文件。
4. 保存成功后展示名称与真实文件一致，并提示发送 `/new`。
5. 下载图标直接下载当前 Agent 实际文件为 `soul.md`，不打开编辑弹窗。
6. 页面初始身份同步仍不读取完整 Markdown。
7. 读取、保存、下载和 Agent 切换的失败与竞态均不会展示或写入错误 Agent 的内容。
8. 国内站相关测试、TypeScript、i18n 和差异检查通过；国际站行为不变。

## 实现与验证结果

- 已新增按需全文读取命令和严格解析器；20 KB 以内内容使用单行 Base64 往返，缺失、超限、非法 Base64、无效 UTF-8 和长度不一致均有明确状态。
- 已在国内站自定义人设状态后接入编辑与下载图标；国际站不渲染新增入口。
- 编辑弹窗读取当前 Agent 实际 `SOUL.md`，保存复用现有备份、临时文件和原子替换命令；下载直接输出读取原文为 `soul.md`。
- 相关 6 个测试文件共 73 个用例通过；国际站隔离定向用例通过；`pnpm check`、`pnpm i18n:check` 和 `git diff --check` 通过。
- 本地页面可访问，但浏览器会话未登录且认证服务暂时不可用，未在真实 Agent 上执行远端读写；未伪造该项浏览器结果。
