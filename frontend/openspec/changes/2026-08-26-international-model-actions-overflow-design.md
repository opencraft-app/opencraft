# 国际站模型表单操作按钮防裁切设计

## 背景

国际站模型配置表单把 API Key 输入框与“获取可用模型”按钮、模型选择器与“检测模型状态”按钮组合在同一个固定高度控件中。操作按钮当前在桌面断点固定为 `144px`，同时继承 `whitespace-nowrap`；组合控件使用 `overflow-hidden` 保持一体化边框。

西语文案 `Obtener modelos disponibles` 和 `Comprobar el estado del modelo` 的实际内容宽度分别约为 `170px` 与 `181px`，超过按钮可用宽度，因而被组合控件右边界裁切。问题属于国际站长文案适配，不涉及模型探测或连接检测逻辑。

## 目标

- 国际站模型表单的两个操作按钮完整展示当前语言文案。
- 桌面宽度下保留输入框与按钮的一体化横向布局。
- 窄屏空间不足时允许操作按钮移动到输入控件下方并占满可用宽度。
- 保留按钮的加载态、禁用态、点击行为、焦点样式和组合控件视觉。
- 国内站继续使用现有紧凑固定宽度布局。

## 范围

- 为 `AgentModelConfigPanel` 增加明确的国际站布局输入，由现有设置页区域常量传入。
- 仅在国际站作用域下调整 API Key 与模型选择两组复合控件的响应式布局。
- 添加布局回归测试，覆盖国际站自适应按钮、窄屏换行能力和国内站既有样式隔离。
- 在已登录西语模型页测量按钮内容和容器边界，确认无裁切。

## 非目标

- 不缩短或改写西语翻译。
- 不修改模型 Provider、API Key、探测、状态检测或添加模型逻辑。
- 不修改国际站以外页面的通用 `Button`、`Input` 或 `Select` 组件。
- 不改变国内站模型表单布局。

## 方案比较

### 方案 A：国际站按钮使用更大的固定宽度

实现简单，但只能覆盖当前西语长度；后续更长语言仍可能再次裁切，窄屏还会持续挤压输入区域。

### 方案 B：缩短西语文案

不会改变布局，但牺牲文案准确性，且不能解决其他国际语言的同类风险。

### 方案 C：国际站按内容自适应并在窄屏换行（采用）

国际站桌面端让操作按钮按内容最小宽度参与 Flex 布局，按钮不再受 `144px` 上限约束；窄屏时复合控件切换为纵向布局，操作按钮占满下一行。国内站继续使用原有固定宽度类。该方案从布局层解决长语言问题，同时保持桌面视觉和业务行为。

## 详细设计

`AgentSettingsPage` 已通过 `isGlobal` 区分构建区域，因此由调用方把该布尔值传给 `AgentModelConfigPanel`，避免组件自行根据当前翻译文本或浏览器语言猜测站点。

组件保留现有基础样式常量，并在国际站条件下追加响应式类：

- 复合控件在窄屏使用纵向流和自动高度；从 `sm` 断点恢复当前横向、固定高度的一体化布局。
- 国际站操作按钮在窄屏使用完整宽度和顶部边框；桌面端恢复左边框，并以内容宽度和必要内边距决定尺寸。
- 输入框和 Select 保持 `min-width: 0`，避免长占位文本反向撑破容器。
- 国内站不追加国际站类，继续使用当前 `w-28 sm:w-36` 的紧凑按钮。

不采用文本截断、省略号或缩小字号，因为两个操作都是主要表单动作，完整文案比维持单行固定宽度更重要。

## 测试与验收

1. 组件测试先断言国际站复合控件和按钮具备自适应、窄屏换行类，并确认国内站仍保留固定宽度类。
2. 既有模型配置交互测试继续通过，证明探测和连接检测行为未改变。
3. `pnpm check` 与 `git diff --check` 通过。
4. 已登录西语 `/agents/models/` 页面中：
   - 两个按钮的 `scrollWidth` 不大于 `clientWidth`；
   - 按钮右边界不越过复合控件右边界；
   - API Key 输入、模型选择和按钮加载/禁用视觉无异常。
5. 窄屏 smoke 中按钮位于输入控件下方，页面不产生横向滚动。

## 风险与回退

主要风险是窄屏纵向布局会增加表单高度，以及桌面端更长按钮会压缩输入区域。使用 `sm` 断点限制纵向布局，并让输入区域保持 `min-width: 0`；当前桌面容器约 `998px`，可充分容纳约 `181px` 的西语操作文本。

若视觉验收不接受窄屏增加高度，可仅回退国际站条件类，不影响任何模型数据、请求或用户配置。
