# Provider 分组内添加模型与角色展示优化

状态：设计草稿，待用户评审；本轮仅创建分支、调查代码和编写方案。

分支：`frontsandbox/model-provider-add-model`

基线：2026-09-09 拉取的 `origin/master`，`2b871615d604a1761d8f36ac0e1c58f0ecd63c52`。

## 需求与范围

用户希望在已配置的 Provider 分组内继续添加模型，复用已经保存的 API Key、API 端点和协议；同一个自定义 Provider 下能够保留多个模型。主模型操作与实际角色需要明确区分，避免将单选圆点、按钮对号误认为当前主模型。

本稿建议国内站、国际站共用同一行为，覆盖已配置的自定义 Provider、预置模型 API 和 Coding Plan；各类模型来源沿用当前规则。具体发布站点与发布批次在实施前确认。本轮不发布、不建 TAPD、不提交 MR。

下方完整表单继续负责新 Provider 配置。既有自定义 Provider 身份生成规则保留，组内操作直接使用已保存身份；名称相同不构成跨端点合并依据。

下列路径相对 `frontend/src/pages/marketing/agent-model-config/`。

| 事实 | 证据 | 对方案的影响 |
| --- | --- | --- |
| 已配置模型按 providerKey + 有效路由端点分组 | `agent-model-config-panel.tsx:getConfiguredProviderGroupKey` | 复用已有分组，保持不同端点隔离 |
| 预置 Provider 会补入产品目录候选；自定义组不补入 | `groupConfiguredModelsByProvider` | 预置组沿用七彩石目录，自定义组增加发现入口 |
| 当前 master 的“设为主模型”按钮已经没有对号 | 同文件模型行操作区 | 截图不能证明当前源码仍有对号，部署版本需另查 |
| 行首 radio 只修改 selectedConfiguredModelByProvider，操作按钮直接操作所在行 model | 同文件已配置列表 | radio 不负责切换运行角色，可删除这层页面选择状态 |
| 底部 add 必须提交新的加密凭据 | `handleAdd`、`hermes-model-config-command.ts:execute(add)` | 不能原样复用底部提交动作实现免填 Key |
| 脚本已向 providers.<id>.models 合并模型，并保留已有模型元数据 | `add_provider_model` | 无需为每个模型创建新的 Provider |
| 当前 read_snapshot 仅将 discover_models=false 的非发现缓存对象映射全部投影 | `read_snapshot` | 动态发现 Provider 中多个“仅添加”模型可能仍会漏显，必须补充持久化区分 |
| assign 可从同 Provider 已保存配置构造候选，保留凭据并写入主备 | `find_assignable`、`execute(assign)` | 可复用身份解析、凭据保留和事务校验，但追加需要单独的无角色副作用语义 |

Hermes 本地源码参考版本 `31e41eed347f62de312e59ccc822b30a635d4aba`：

- `hermes_cli/web_models.py:CustomEndpointUpdate` 同时支持单个默认 model、models 列表和 make_default=false。
- `hermes_cli/web_server.py:_write_custom_endpoint` 合并已有 Provider 及 models，保留模型元数据；仅 make_default=true 才更新全局主模型。
- `hermes_cli/providers.py:resolve_user_provider` 从同一 Provider 读取接入地址、协议与凭据引用。

因此，同 Provider 保存多个模型、复用凭据、显式设置主备，符合已检查的 Hermes 源码机制。下述 LightVela 的展示标记属于产品扩展；目标实例的 Hermes 版本仍需在实现测试中验证，不能由本地源码推定所有实例均兼容。

| 方案 | 交互 | 取舍 |
| --- | --- | --- |
| A：组内简化表单（推荐） | 分组标题右侧“添加模型”，组内出现模型字段和添加/取消 | 位置明确、改动较小，可保留 Provider 上下文 |
| B：添加模型弹窗 | 分组入口打开小弹窗 | 长列表更好安排，但多一层弹窗与焦点切换 |

采用 A 作为待评审建议，不自动保存发现到的全部模型。

## 推荐交互

### 分组入口

1. 保留当前展开/收起方式与排序。在分组标题右侧增加带 Plus 图标的“添加模型”按钮。
2. 标题折叠按钮与添加按钮是并列元素，禁止嵌套 button。点击添加展开该组并显示末尾表单，不跳转到下方完整表单。
3. 同一时间只编辑一个分组。已有非空草稿时，切换组内添加入口需用项目 Dialog 确认放弃；点击“取消”直接放弃当前草稿。
4. 收起当前组时保留草稿；正在保存时禁止关闭或切换添加目标。重新读取实例或切换 Agent 时清空草稿，废弃过期请求结果。
5. 组内表单保持白底与分隔线，使用现有 Input、Select/可搜索组合框、Button、Dialog 和 Toast。桌面横排，移动端换行；展开下拉不改变左侧导航滚动位置。

### 模型来源与添加

| Provider 类型 | 模型字段 | 获取方式 |
| --- | --- | --- |
| 自定义 Provider | 可手填模型 ID，也可从发现结果中选择 | 主动点击“获取可用模型”，服务端复用当前 Provider 凭据 |
| 预置模型 API | 可搜索模型下拉框 | 沿用当前产品目录，不改成实时请求 Provider |
| Coding Plan | 模型下拉框或既有固定选项 | 沿用产品目录和套餐限制，不允许任意模型 ID |

- 表单仅包含“模型”、必要的获取按钮及“添加 / 取消”；不再次展示可编辑的名称、API Key、Base URL、协议。
- 每次添加一个明确选择的模型，允许重复此流程添加多个模型；发现结果仅用于选择，不整体写入。
- 默认行为固定为“仅添加”。成功后出现“已添加”行，不改变主模型或备用链；用户从该行设置主备。
- 已保存模型在下拉中标注“已添加”且不可重复提交；手填重复 ID 返回“该模型已添加”，不改变已有角色。
- 产品目录候选已经在组内出现时，允许通过添加将其保存为“已添加”；未保存的目录候选仍沿用现有直接设主备能力。
- 追加成功收起编辑表单、保持组展开并将新行放在该组已有保存行之后；不重新排列其他组。
- 取消、获取失败或保存失败均保留已有模型及角色。获取到空列表时自定义模型仍允许手填。
- 此流程保存配置不自动发起付费模型推理。获取目录成功、保存成功均不等同于连通性或推理成功。

### 主备角色展示

1. 删除模型行首 radio 及其仅用于页面选择的状态；直接对目标行操作。
2. “设为主模型”保持纯文字无对号。真实主模型行显示绿色“主模型”标签，操作文案建议改为禁用的“已是主模型”，Hover 使用项目 Tooltip。
3. 其他模型行显示“设为主模型”；备用模型显示“备用模型”和“取消备用”；已保存闲置模型显示“已添加”。
4. 分组折叠后继续展示“主模型：xxx / 备用模型：xxx”摘要，数据严格来自 snapshot.primary / fallbacks。
5. 保留当前初始全部折叠规则，不因为添加、发现或草稿选择自动更改主模型。当前主模型缺失或读取失败时不将组首行当作主模型。
6. 主模型仍需先切换才能删除；同 Provider 的其他模型可独立删除，不能清除兄弟模型或共享凭据。

## 技术方案

### 身份与凭据复用

新增两种职责明确的 debug/exec action，名称暂定 `probeConfiguredProvider`、`appendProviderModel`。

- 前端只提交目标 Agent、已保存模型的锚点身份（providerKey、modelId、baseUrl、routeBaseUrl）和新增模型 ID；不回传 API Key，也不把新端点作为请求目标。
- helper 每次读取当前配置，唯一解析 Provider 与有效路由，校验协议和凭据绑定。无法唯一解析时拒绝操作，不能凭显示名称或取组首凭据猜测。
- 同一界面分组若存在多个协议/凭据身份，增加组内连接选择或返回可解释的“不支持直接追加”状态；首版推荐阻止歧义操作并引导重新配置该服务商。
- 发现仅使用实例端 Hermes 的既有凭据解析机制；覆盖 env 引用、inline key、credential pool 和已有 key_cmd 机制。只存在 pool/key_cmd 的配置不得被误报为“未配置 Key”。不自建任意命令执行能力。
- endpoint、协议、extra_headers、request_overrides 等配置完整保留；发现接口需使用这些连接参数。已保存但当前适配器不支持的 transport 返回明确状态，保留自定义手填添加路径。
- 旧 Hermes 不支持目标 Provider schema 时返回可操作的升级提示；禁止回落到不确定的凭据来源。

### 追加与持久化

1. 复用 providers.<id>.models 的增量合并能力，保留已有模型元数据、Provider 设置及原凭据。
2. 追加操作保留现有 Provider 的 model/default_model；不调用 apply_primary、apply_fallback、remove_fallback。对于尚未规范化的历史 Provider，只在目标身份唯一可恢复时进行局部规范化。
3. 新 ID 不存在时追加；已存在且已保存时幂等返回，不改变角色或顺序。已存在但仅属于发现目录时，只提升选中项为显式保存。
4. 为区分动态发现目录与用户显式添加，推荐在 `providers.<id>.models.<modelId>` 元数据中增加 `lightvela_configured: true`。它只表达用户已保存该项，不参与 Hermes 主备判断；不创建另一份 configured_models 列表。
5. read_snapshot 在现有主备、历史配置与固定目录投影之外，投影被显式标记的模型；即使 discover_models=true，已添加模型仍可在刷新后显示。动态发现的其他条目不自动获得标记。
6. 现有 discover_models=false 的受管映射继续兼容。旧动态目录无标记条目保留原语义，不做无依据的全量迁移。新增路径、底部 add、目录候选 assign 应统一补充显式保存标记；确保旧 provider.model 在被替换前仍作为已保存模型保留。
7. 该元数据是建议的最小产品扩展：保留 discover_models 原值，避免为展示需求关闭整个 Provider 的发现能力。实施前验证 Hermes 读取与编辑是否保留此字段，未通过时需调整方案再实现，不能声称它是 Hermes 官方字段。
8. 保存使用“重新读取当前配置 → 合并目标 Provider → 保存 → 重读 → 验证 → 失败回滚”。验证包括：新旧模型均保留、主备不变、凭据与非目标配置不变。
9. 同实例内新增写操作需与现有模型写操作使用共同的短时互斥边界；网络发现不持有写锁。失败回滚必须在同一保护范围内，避免覆盖另一页面刚写入的配置。外部 Hermes 编辑若检测到基线变化，返回冲突并要求刷新。
10. 删除仅移除该模型条目及其标记，仍被其他模型/运行槽引用的 Provider 和凭据继续保留。

### 错误与异步状态

为新增 action 返回有限结构化错误码，由前端映射为本地化文案。超时或响应丢失后先重新读取确认状态，无法确认时提示“未能确认保存结果，请刷新后查看”，不将未知结果直接判为失败。

| 场景 | 建议提示或行为 |
| --- | --- |
| 成功获取零个模型 | 未获取到可用模型，可手动填写模型 ID |
| 明确 401 / 403 | 获取失败，请检查该服务商的 API Key 或访问权限 |
| 凭据缺失 | 该服务商未配置可用凭据，请在下方重新配置 |
| /models 不支持或响应结构不支持 | 该服务商暂不支持获取模型列表，请手动填写模型 ID |
| 网络超时 / 连接失败 | 获取模型超时，请稍后重试；仍保留手填能力 |
| Provider 删除 / 连接已变化 | 服务商配置已变化，请刷新后重试 |
| 身份不唯一 | 该服务商存在多份连接配置，请重新配置后添加模型 |
| 重复模型 | 该模型已添加 |
| Provider schema 不支持 | 当前智能体版本不支持此配置，请升级后重试 |
| 保存失败且已回滚 | 添加失败，原配置已保留 |
| 回滚失败 | 配置恢复失败，请刷新核对当前模型配置 |

Toast 沿用站内顶部居中样式，普通结果 3 秒消失；输入错误保留字段级提示。原始异常、上游请求体和凭据不进入 Toast、日志或返回快照。取消、换组、换 Agent 后的过期响应不能覆盖新草稿。

## 实施拆分与验收

建议分三步实施：先补齐 helper 追加/发现和契约测试，再添加组内表单与角色展示，最后完成多语言和双站浏览器验证。实际编码前将批准的范围录入当前执行计划。

预计业务改动范围：模型配置 panel、use-model-config、model-config-client、hermes-model-config-command、相关模型配置测试和必要 i18n 字典。若组内表单使面板继续膨胀，仅拆出本次表单组件。CI、SDK、其他页面与 Provider 新建身份生成策略不在范围内。

| 编号 | 场景 | 必须断言 |
| --- | --- | --- |
| T01 | 自定义 Provider A 已保存 m1，手填 m2 | 复用同一连接，无 Key 输入，m1/m2 刷新后都存在，主备不变 |
| T02 | A 获取目录并选择 m2 | 仅保存 m2，不批量保存目录，目录请求不返回凭据 |
| T03 | discover_models=true 时连续添加 m2/m3 | 三个已保存模型可见；无标记发现目录不冒充已保存 |
| T04 | 固定目录对象映射、数组、发现缓存、历史 configured_models/custom_providers | 按既有兼容规则读取；目标局部规范化不遗漏原模型或元数据 |
| T05 | 同名不同地址、同地址不同 Provider、组内凭据歧义 | 不跨身份复用，不产生隐式 endpoint 覆盖 |
| T06 | 重复 m1、重复提交、两个页面分别追加 m2/m3 | 幂等、保留角色，不丢失任何成功提交的模型 |
| T07 | 当前模型在其他折叠组 | 本组无主模型暗示，无 radio/按钮对号；主模型摘要仍准确 |
| T08 | 从 m1 切主到 m2、设置多个备用、取消备用 | 主模型唯一且不兼任备用，已添加列表和其他备用保持完整 |
| T09 | 删除 m2/删除最后一项/尝试删除主模型 | 兄弟模型和共享凭据不受影响；最后一项沿用清理规则；主模型阻止删除 |
| T10 | 空结果、401/403、404、超时、畸形响应 | 错误分场景；失败不清空原配置，自定义保留手填能力 |
| T11 | 保存失败、重读校验失败、回滚失败、响应丢失 | 原配置恢复或明确告知未知/恢复失败，不误报成功 |
| T12 | env/inline/pool/key_cmd、额外 headers、不同协议 | 按真实连接参数解析和请求，未支持能力有明确回退，凭据不泄漏 |
| T13 | 请求中切组、取消、切 Agent、Provider 被删除或改地址 | 旧响应不覆盖新草稿，保存前重新验证身份 |
| T14 | 预置 API/Coding Plan | 沿用产品目录/固定模型，无新增实时发现或手填绕过 |
| T15 | 国内/国际桌面 1280px、移动 390px，英文长按钮 | 不溢出、不遮挡、不改变侧栏位置；键盘和关闭焦点恢复正确 |
