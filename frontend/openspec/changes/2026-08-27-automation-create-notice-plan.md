# 自动任务创建成功通知 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `test-driven-development` before production code and `verification-before-completion` before claiming completion. The user explicitly selected inline execution; do not dispatch subagents. Do not commit, push, create an MR, or archive until the user reviews the verified diff.

**Goal:** 自动任务创建成功后，向该任务选中的每个通知目标即时发送一条本地化确认消息；投递失败不回滚任务，并在页面显示非阻塞警告。

**Architecture:** 复用 `hermes-cron-client.ts` 中已经按逗号拆分 `deliver` 的即时发送链路，把它提升为返回成功数和失败数的公共函数。创建表单只在 Cron 创建成功且 `deliver !== "local"` 时异步调用该函数，先关闭弹窗和刷新任务列表，再根据汇总结果调用父级错误 Toast；编辑、测试消息和测试运行保持原行为。

**Tech Stack:** React 19、TypeScript 5.9、Vitest 4、Testing Library、Hermes `send`、LightVela `useT()` 国际化。

## Global Constraints

- 发布范围为国内站与国际站同步，行为共用同一实现。
- 确认消息中文固定为 `LightVela 已添加新的自动任务。`，英文固定为 `LightVela has added a new automation.`。
- 只投递本次任务选中的目标；未选择通知通道时不发送。
- 一个目标失败不得阻断其他目标，也不得回滚或重新标记任务创建结果。
- 任一目标失败时显示 `自动任务已添加，但部分通知通道发送确认消息失败。`。
- 编辑、暂停、恢复、删除、测试消息、测试运行和场景任务入口不在本次范围。
- 不新增依赖、后端接口、设置项、埋点或自动重试。
