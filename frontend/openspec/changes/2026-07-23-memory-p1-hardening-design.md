# Agent 记忆页 P1 稳定性修复设计

## 文档状态

- 状态：设计已由用户确认，待文档复核后进入实施规划
- 规模：M（预计 6 至 8 个文件）
- 执行模式：single_agent
- 开发分支：`frontsandbox/memory-p1-hardening`
- 页面：`/agents/memory/`

## 背景与问题

Agent 记忆页目前通过 `BotRepository.execDebugCommand` 在目标 Agent 上读取和修改 Hermes 记忆文件及配置。代码审查确认有六类 P1 稳定性问题：

1. 读取命令固定使用 `$HOME/.hermes`，没有遵守 `HERMES_HOME`。
2. 使用正则读取 YAML，无法正确处理 Hermes 默认配置中的行尾注释等合法 YAML 语法。
3. 文件读取失败和 payload 类型错误会被静默转换为空内容或默认值，页面可能把故障显示成正常空态。
4. 读取、写配置和重启命令没有显式超时，底层请求可能无限等待。
5. 保存操作没有绑定 Agent 和请求序号；切换 Agent 后，旧保存链路可能覆盖新 Agent 的页面状态。两个限额卡片也可同时提交，造成并发写配置和重复重启。
6. 配置已经写入后，如果加载 SDK、获取重启命令、重启或重新读取失败，页面仍提示“调整失败”，无法区分“未保存”和“已保存但后续失败”。

## 目标

- 正确读取自定义 Hermes 根目录和合法 YAML 配置。
- 把真实读取错误、格式错误和契约错误显式反馈给页面。
- 为所有记忆页远程命令设置统一、可测试的超时。
- 保证旧 Agent 的异步结果不能修改当前 Agent 的 UI。
- 同一时间只允许一个记忆限额保存操作。
- 精确区分保存失败、完整成功和配置已保存后的部分成功。

## 非目标

- 不新增后端接口，继续使用现有 `debug/exec` 桥接。
- 不改 Hermes 的配置格式、记忆算法或 gateway 行为。
- 不重构整个 `agent-settings-page.tsx`。
- 不处理本轮审查中的 P2 埋点字段语义问题。
- 不新增第三方前端依赖，也不改变页面信息架构和视觉样式。

## 设计方案

### 1. 命令与 Hermes 根目录

保留现有单次远程命令读取 `MEMORY.md`、`USER.md` 和 `config.yaml` 的方式。Shell 先解析 Hermes 根目录：

```sh
HERMES_ROOT="${HERMES_HOME:-$HOME/.hermes}"
export HERMES_ROOT
```

Python 只从 `os.environ["HERMES_ROOT"]` 构造路径，确保文件读取与 Hermes runtime 使用同一根目录。命令选择 Hermes 自带虚拟环境中的 Python；该解释器不可用时才回退到系统 `python3`。

命令输出使用固定起止标记包裹 JSON，解析器只读取标记之间的内容，避免登录提示、调试日志或命令回显中的花括号干扰 JSON 解析。

### 2. YAML 与文件读取语义

配置必须通过 YAML safe-load 解析，并只读取顶层 `memory` 节点中的：

- `memory_char_limit`
- `user_char_limit`

语义约束如下：

- `config.yaml` 不存在：使用 Hermes 默认限额，并把 `usedFallbackLimits` 设为 `true`。
- 配置存在但 `memory` 节点或两个字段缺失：缺失字段各自使用默认值，并把 `usedFallbackLimits` 设为 `true`。
- 合法 YAML 的行尾注释、引号和空白：按 YAML 语义正常读取。
- YAML 无法解析、根节点或 `memory` 节点类型错误、限额字段类型/范围错误：命令失败，不伪装成默认值。
- `MEMORY.md` / `USER.md` 不存在：视为空内容。
- 文件存在但权限、编码或其他读取失败：命令失败，不转换为空字符串。

### 3. Payload 契约

前端解析器对核心字段执行严格校验：

- `memoryText`、`userText` 必须是字符串。
- 已用字符数和限额必须是有限整数；已用字符数不得小于 0，限额必须大于 0。
- `usedFallbackLimits` 必须是布尔值。

字段缺失或类型错误统一抛出可识别的 payload 错误，页面进入现有错误态。解析器不再为畸形 payload 静默补默认值。

### 4. 超时策略

记忆页的读取、配置写入和 gateway 重启统一传入显式 `timeoutMs`。首版使用 `120_000` 毫秒，作为导出常量供实现和测试共用。超时只终止当前 HTTP/命令等待，不改变 Hermes 配置回滚语义。

### 5. 保存操作的作用域与互斥

保存开始时捕获：

- 当前 `botId`
- 单调递增的 `saveRequestId`
- 当前保存目标（memory 或 user）

组件维护最新 Agent 和最新保存请求。每次异步阶段完成后，只有 `botId` 与 `saveRequestId` 仍匹配时，才允许写入 React state、toast 或页面错误。切换 Agent 或开始新一轮有效操作会使旧请求失效；旧请求可在远端自然结束，但不能污染新 Agent 的 UI。

保存链路中的重新读取必须显式读取最初捕获的 `botId`，不能调用依赖当前页面闭包的加载函数。

当任意一个限额正在保存时：

- 两张限额卡片的输入和提交按钮全部禁用。
- 仅实际提交的卡片显示保存中状态。
- 第二个保存请求不会启动，避免并发写配置和重复重启。

### 6. 保存结果状态机

保存链路划分为三个结果：

1. `failed`：配置命令尚未成功；保留原错误提示。
2. `success`：配置写入、gateway 重启和重新读取全部成功；显示成功提示并退出编辑态。
3. `partial`：配置命令已经成功，但后续加载 SDK、获取重启命令、重启或重新读取失败；不回滚配置，保留编辑态，并显示“配置已保存，但后续步骤失败”，附带刷新页面或手动重启的建议。

实现使用显式的“配置已写入”阶段标记或判别联合结果，避免用一层通用 `catch` 猜测状态。

## 代码组织

- `agent-memory.ts`：命令构造、固定 JSON 标记、Hermes 根目录、YAML/file 读取和严格 payload 解析；增加按指定 `botId` 拉取 snapshot 的可测试函数。
- 新增一个聚焦的保存编排模块：负责配置写入、重启、重新读取和 `failed/success/partial` 结果，不依赖 React。
- `agent-settings-page.tsx`：只负责请求序号、Agent 作用域、互斥 UI 和结果展示，不扩大页面级重构。
- 测试文件：分别覆盖命令/解析契约和保存竞态/部分成功行为。

## 测试策略

按 TDD 顺序先写失败测试，再做最小实现：

1. `HERMES_HOME` 自定义路径以及 `$HOME/.hermes` 回退。
2. YAML 行尾注释、字段缺失默认值、配置/文件读取错误。
3. payload 字段缺失、错误类型和非法数值。
4. read/config/restart 均传入 `120_000` 毫秒超时。
5. A Agent 保存期间切到 B，A 的完成或失败不修改 B 的状态。
6. 任意保存进行中时，另一张限额卡片无法再次提交。
7. 配置写入前失败返回 `failed`；写入后任一步失败返回 `partial`；全链路完成返回 `success`。

验证门禁：聚焦 Vitest、`pnpm check`、`pnpm i18n:check`、`git diff --check`，以及记忆页正常读取、编辑、保存和异常提示的本地可见验证。

## 风险与控制

| 风险 | 控制 |
| --- | --- |
| 远端 Python 环境缺少 YAML 库 | 优先使用 Hermes 自带虚拟环境 Python；依赖缺失时明确失败，不错误展示默认配置。 |
| 严格契约暴露历史脏数据 | 错误态明确呈现；不存在的文件仍保持合法空态，避免扩大用户影响。 |
| 保存完成后 Agent 已切换 | 所有 UI 写入同时校验 botId 和 requestId。 |
| 配置已写入但重启失败 | 返回 partial，不回滚，不宣称保存失败；给出恢复指引。 |
| 大型页面修改引发回归 | 保存编排下沉为独立纯模块，页面只做最小接线并用聚焦测试锁定行为。 |

## 验收标准

1. 自定义 `HERMES_HOME` 下的记忆文件和配置能被正确读取。
2. Hermes 默认配置中的 YAML 行尾注释不会触发错误默认值。
3. 文件权限/编码错误、非法 YAML 和非法 payload 会进入错误态。
4. 读取、写配置和重启都有 120 秒超时。
5. 切换 Agent 后，旧读取或保存结果不会覆盖当前 Agent。
6. 任意保存进行中时不能发起第二个限额保存。
7. 配置未写入时失败提示准确；配置已写入后的后续失败显示部分成功且不回滚。
8. 记忆与用户信息的正常读取、编辑和保存行为保持不变。
