# 首页登录态产品入口 Design

**Status:** 实现与验证完成，等待用户确认提交；不自动 commit、push 或创建 MR。

**Size:** S。公共首页头部的局部登录态入口调整，不改变认证、订阅、智能体创建或管理页行为。

## 背景

LightVela 国内站和国际站首页在登录态恢复完成后，顶部导航目前只显示语言切换和头像菜单。用户虽然可以从头像下拉中的“我的智能体伙伴”进入 `/agents`，但首页头部没有常驻、可直接发现的产品入口。

本需求在登录态首页增加一个紧邻头像的按钮，点击后直接进入智能体页面。按钮不使用“智能体管理”“控制台”等后台或技术化表述，而使用更轻量的产品语言。

## 目标

- 国内站和国际站首页在登录态显示常驻产品入口。
- 入口位于头像左侧，桌面端和移动端均可直接使用。
- 点击始终进入 `/agents`，不根据套餐、订阅状态或智能体数量改变目标。
- 各现有 locale 使用已确认或自然本地化的文案。
- 未登录首页及其他公共页面保持现状。

## 非目标

- 不修改首页 Hero、页尾 CTA 或未登录“免费试用”逻辑。
- 不修改头像菜单中的现有入口与文案。
- 不修改 `/agents` 的认证、订阅、空状态或创建流程。
- 不把该入口扩展到 About、Changelog、Docs、Subscribe 等其他公共页面。
- 不新增依赖，不调整公共头部结构或主导航项目。

## 方案选择

采用“首页显式开启 + 登录态动作区渲染”的方案：

1. 为 `PublicHeaderAuthIsland` 增加首页产品入口开关，默认关闭。
2. 仅 `PublicHomePage` 开启该开关，避免共享 Auth Island 让其他公共页面意外出现按钮。
3. 登录态桌面端和移动端均在 `UserAvatarMenu` 左侧渲染入口。
4. 使用原生 `<a href="/agents">` 进入产品壳，延续当前静态导出页面跨应用壳导航的可靠做法。

未采用的方案：

- 加入中间主导航：会混合公开站栏目与个人产品入口，并改变导航居中布局。
- 复用现有 `goToCreate`：该逻辑会按登录、订阅和智能体数量跳转不同目标，不符合“直达 `/agents`”。
- 仅保留头像下拉入口：可发现性不足，无法满足常驻按钮要求。

## 文案

| Locale | 文案 |
|---|---|
| `zh-CN` | 开始使用 |
| `zh-SG` | 开始使用 |
| `zh-Hant` | 開始使用 |
| `en-US` | Enter LightVela |
| `id-ID` | Masuk ke LightVela |
| `es` | Entrar a LightVela |
| `ja-JP` | LightVelaを開く |
| `ko-KR` | LightVela 열기 |

本地化按目标语言的自然产品表达处理，不要求逐字翻译中文。英文使用 `Enter LightVela`，强调进入产品体验，而不是首次注册或后台管理。

## 交互与视觉

- 仅在 `authReady === true` 且 `isAuthenticated === true`、并由首页开启入口时渲染。
- 桌面端使用现有头部主动作的黑色圆角按钮风格，高度与当前桌面 CTA 一致。
- 移动端使用同一视觉语义的紧凑按钮，高度与移动头部动作一致；按钮与头像保持现有 `gap-2` 间距。
- 按钮位于语言切换之后、头像之前；国内站没有语言切换时仍位于头像左侧。
- 链接语义使用 `<a>`，键盘聚焦、链接地址和默认浏览器行为可直接使用。
- 点击上报现有 `agent_enter_console_btn` 事件，并区分 `desktop` / `mobile` surface；上报不阻断导航。

## 状态与数据流

1. `PublicHomePage` 向 `PublicHeaderAuthIsland` 传入首页入口开关。
2. Auth Island 等待 Session 恢复；加载态继续显示现有骨架，不提前展示入口。
3. 未登录态继续展示现有免费试用和登录动作。
4. 登录态根据当前 locale 读取入口文案，渲染桌面和移动链接。
5. 用户点击后通过原生链接进入 `/agents`；后续页面状态由现有产品壳负责。

## 测试与验收

### 自动化

- 登录态 + 首页开关：桌面和移动入口均存在，文案正确，`href` 为 `/agents`。
- 登录态 + 开关关闭：不展示入口，保证其他公共页面不受影响。
- 未登录态 + 首页开关：不展示入口，现有免费试用和登录动作保持不变。
- 覆盖全部八个现有 locale 的按钮文案。
- 点击入口触发现有埋点，且不改变链接目标。
- 运行目标组件测试、`pnpm check`、`pnpm i18n:check` 和 `git diff --check`。

### 浏览器

- 国内站与国际站登录态首页各验证一次桌面布局。
- 在 390px 宽度验证移动端按钮与头像不重叠、不溢出。
- 点击后确认实际进入 `/agents`。
- 退出态确认顶部仍保持原有免费试用和登录入口。

## 风险控制

- 公共 Auth Island 被多个页面复用，因此入口必须由首页显式开启，默认关闭。
- 入口文案由 locale 显式映射；新增 locale 时 TypeScript 的 `Record<PublicSiteLocale, ...>` 继续强制补齐文案。
- 直接进入 `/agents` 不复用订阅判断；这是本需求明确行为，不代表绕过 `/agents` 内部现有守卫。

## 验证结论

- 目标测试完成 RED/GREEN：初始 12 个用例中 9 个按预期失败，实现后 12/12 通过；公共导航相关回归合计 24/24 通过。
- 全部八种 locale、首页范围开关、未登录回归、原生 `/agents` 链接和桌面埋点均有自动化覆盖。
- `pnpm i18n:check`、`pnpm check`、`pnpm build:cn`、`pnpm build:global` 通过；TypeScript diagnostics 为 207 current / 276 baseline / 0 new / 69 resolved。
- 真实登录态浏览器确认国内站“开始使用”和国际站“Enter LightVela”均位于头像左侧，桌面与 390px 下无横向溢出，点击进入 `/agents/`。
- 未为浏览器验收退出真实账号；未登录行为由自动化用例确认，原“免费试用”和登录动作保持不变。
