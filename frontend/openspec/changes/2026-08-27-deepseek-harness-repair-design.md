# DeepSeek Harness 修复操作设计

## 目标

在 DeepSeek Harness 已安装状态的运行卡片中增加“修复”按钮。用户确认后复用现有安装脚本重新安装 DSH 运行环境和 WebUI 插件环境，并沿用安装任务的进度、校验、切换及失败回滚机制。

## 交互

- “修复”按钮位于“重启”按钮右侧，使用次级按钮样式。
- 点击后显示确认弹窗，关闭弹窗或点击“取消”不触发远程命令。
- 弹窗标题：`修复 DeepSeek Harness`
- 弹窗正文：
  - `修复将重新安装 DeepSeek Harness 运行环境，并在完成后重启服务。修复期间 WebUI 暂时不可用。`
  - `模型配置、DSH 设置与存储数据将会被保留；WebUI 插件环境会重新安装，您自行安装的插件及相关自定义文件将被移除。`
- 弹窗按钮：`取消`、`修复`。
- 用户确认后关闭弹窗，运行卡片切换到现有进度布局；状态文案使用 `正在修复 DeepSeek Harness`。
- 修复期间禁止重复发起安装、重启或修复操作，模型配置卡片暂时隐藏。

## 执行与数据边界

- 修复调用 `DeepSeekHarnessCommandClient.startInstall("repair")`，由实例通过 `debug/exec` 下载并校验 COS 安装器。wrapper 先隔离完整旧 Web profile，只将 `cordis.patch.yml` 放入干净 profile，再执行安装器的 `install` 动作。
- 不新增 DeepSeek Harness 专用后端接口，也不新增安装器 action。
- 安装器继续保留 `$DSH_HOME` 下的模型凭据、DSH settings、storage 和原有 `web/cordis.patch.yml`。
- LightVela 管理的插件会重新安装；用户自行加入 `profiles/web` 的插件和其他自定义文件不会复制到新 profile。普通安装继续保留现有 profile 与额外插件。
- 修复成功后重新读取组合运行状态，并通过现有淡出淡入过渡返回已安装卡片。
- 修复失败时，安装器恢复旧 runtime 和 systemd unit，wrapper 恢复完整旧 Web profile 与原服务状态。前端随后重新读取实际运行状态；旧环境仍可用时保持已安装页面并展示修复失败原因。

## 任务恢复

- 本地持久化任务 ID 时同时记录操作类型 `install` 或 `repair`，以便页面刷新后恢复正确状态文案。
- 页面加载时若存在未完成任务，应先恢复任务轮询，再根据最终任务结果读取运行状态。
- 兼容旧版只保存任务 ID 的本地记录，旧记录按 `install` 处理。

## 错误处理

- 启动修复失败：保持已安装页面，展示 `DeepSeek Harness 修复启动失败，请稍后重试`。
- 任务失败且旧环境恢复成功：保持已安装页面，展示任务返回的失败原因。
- 任务失败且状态读取也失败：进入现有状态错误页面，展示可重试入口。
- 修复成功但 WebUI 尚未健康：显示真实的运行异常状态，不宣称修复成功。

## 测试

- 点击“修复”只打开弹窗，不调用 `startInstall()`。
- 点击“取消”、关闭按钮或按 Esc 不调用 `startInstall()`。
- 确认弹窗逐字展示已确认的两条正文。
- 点击确认后只调用一次 `startInstall()`，显示修复进度和正确状态文案。
- 修复完成后读取真实状态并恢复已安装卡片。
- 修复失败且安装器回滚成功时保持已安装页面并展示错误。
- 页面刷新后能够按持久化的 `repair` 类型恢复轮询。
- 现有首次安装、重启、WebUI 链接和模型配置行为保持通过。
