# 自动任务表单测试运行设计

## 背景

自动任务卡片已经支持“测试运行”：系统基于任务定义创建一次用完即焚的临时任务，在不推进原任务调度状态的前提下真实执行任务，并通过现有通知和 toast 反馈启动或投递结果。

新增和编辑弹窗目前只能保存表单。用户需要先保存、回到卡片再测试，无法在提交前验证任务说明、Skill 和通知方式是否符合预期。

## 目标

- 新增和编辑弹窗均提供“测试运行”按钮。
- 测试当前尚未保存的表单内容，而不是已保存版本。
- 测试不会创建正式任务、修改原任务或关闭弹窗。
- 复用任务卡片现有测试运行链路和反馈语义。

## 非目标

- 不改变正式任务的添加、编辑或调度逻辑。
- 不新增独立的测试运行后端协议。
- 不让调度时间、生效周期或多时间点脚本限制立即试跑。
- 不重构自动任务面板的其他状态和操作。

## 交互设计

“测试运行”作为次级操作放在弹窗底部操作区，与“取消”和“添加 / 保存”并列。按钮使用闪电图标和次级描边样式，避免被误解为保存操作。

按钮状态：

- 名称或任务说明为空时禁用。
- 正在添加、保存或测试运行时禁用，避免重复请求。
- 测试启动期间显示转圈；启动成功或失败后短暂显示结果态。

点击后弹窗保持打开。启动和后台执行反馈沿用任务卡片现有 toast：前置阶段成功后提示任务已在后台执行；投递失败或后台结果无法确认时继续显示对应提示。

## 技术设计

`HermesAgentAutomationsPanel` 继续作为测试运行状态和 toast 的唯一所有者。它把现有测试运行回调和当前运行状态传给 `AutomationFormModal`，避免弹窗复制一套异步编排。

`AutomationFormModal` 根据当前受控表单状态构造瞬时 `CronJob` 草稿：

- 新增模式使用稳定的表单测试标识作为临时任务来源 ID。
- 编辑模式保留原任务 ID，但名称、任务说明、Skill、上游任务和通知方式使用当前表单值。
- schedule 字段只用于满足领域类型，不参与立即试跑门禁。
- 不携带生效窗口脚本，确保试跑不被正式调度条件拦截。

瞬时草稿交给现有 `startCronTestRun` 流程。该流程继续创建一次性临时任务、等待后台执行并清理临时任务；表单不会调用正式的 create/edit 接口。若草稿选择了一个上游任务，临时任务通过现有 cron context 创建能力绑定该上游，确保试跑使用当前表单选择的上下文；未选择上游时保持现有普通临时任务路径。

## 错误处理

- 测试运行前置失败时恢复按钮状态，并显示现有“测试运行失败”提示。
- 后台执行或投递异常沿用卡片测试的提示，不阻塞用户继续编辑。
- 测试失败不关闭弹窗、不保存内容，也不改变原任务。

## 测试与验收

1. 新增弹窗输入内容后点击“测试运行”，测试回调收到当前名称、任务说明、Skill、上游任务和通知方式。
2. 编辑弹窗修改内容后点击“测试运行”，使用未保存值，并且不调用正式编辑接口。
3. 名称或任务说明为空、正在保存或正在测试时按钮禁用。
4. 测试启动时显示加载态，成功或失败后弹窗仍保持打开。
5. 国内站和国际站共享相同行为及对应文案。
