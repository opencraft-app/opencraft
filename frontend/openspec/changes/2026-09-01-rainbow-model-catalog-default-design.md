# 模型配置默认使用七彩石目录 Design

**Status:** 交互方案已确认，等待书面规格验收后进入实施计划。

## 背景

当前模型配置页仍会通过 `useModelProviders` 获取七彩石模型供应商配置，并由产品适配层把供应商下的模型转换为 `catalogModels`。但配置面板初始化时会把模型选项置空，用户必须先填写 API Key 并点击“获取可用模型”，才能选择模型。

本次调整重新把七彩石模型目录作为默认展示内容，同时保留非腾讯系供应商的实时模型发现能力。实时发现成功后，最新结果作为当前唯一模型列表，不再与七彩石目录合并或用目录补空。

## 目标

- 进入模型配置页或切换预置供应商时，直接展示该供应商的七彩石模型列表。
- 默认选中七彩石列表第一项。
- 非腾讯系供应商及自定义供应商保留“获取可用模型”按钮。
- 点击“获取可用模型”成功后，用最新返回结果完全替换当前模型列表，并默认选中第一项。
- 腾讯系供应商不展示“获取可用模型”按钮。

## 供应商范围

“腾讯系供应商”按供应商 `value` 判断：

- `value === "tokenhub"`；
- 或 `value` 以 `tencent_` 开头。

上述规则覆盖普通 `tokenhub` 以及所有现有和后续新增的 `tencent_*` 套餐，避免维护易遗漏的固定枚举。

除腾讯系以外的预置供应商，以及用户创建的自定义供应商，均支持实时获取可用模型。

## 状态与交互

### 初始展示

| 供应商类型 | 初始模型列表 | 初始选择 | “获取可用模型”按钮 |
| --- | --- | --- | --- |
| 腾讯系预置供应商 | 七彩石 `catalogModels` | 第一项 | 隐藏 |
| 其他预置供应商 | 七彩石 `catalogModels` | 第一项 | 展示 |
| 自定义供应商 | 空列表 | 无 | 展示 |

如果七彩石没有返回模型，模型列表保持为空，不虚构默认项。腾讯系仍按要求隐藏实时获取按钮。

### 重置时机

下列操作会使当前实时结果失效，并重新载入当前供应商的七彩石目录、选中第一项：

- 切换供应商；
- 切换供应商分类；
- 修改 API Key；
- 成功添加模型后继续配置下一项。

自定义供应商没有七彩石目录，因此发生上述重置时回到空列表和未选择状态。

### 实时获取

仅在支持实时获取的供应商中展示并启用现有“获取可用模型”按钮。

- 请求进行中：保留当前模型列表和选择，按钮继续使用现有加载态。
- 成功且结果非空：用结果完整替换当前列表，并选中第一项。
- 成功但结果为空：将当前列表替换为空并清除选择，不回退七彩石目录。
- 请求失败：保留请求前的模型列表和选择，并使用现有错误提示反馈失败。
- 再次请求成功：再次完整替换上一轮结果，不做追加、合并或去重拼接。

现有请求版本控制和供应商指纹校验继续生效，过期响应不得覆盖用户切换后的状态。

## 实现边界

- 在产品供应商适配结果中增加独立的“是否支持实时刷新模型”能力字段。
- 该字段只控制模型配置面板是否展示实时获取入口，不改变现有 `discoveryStrategy`、连接检测策略或 Hermes 命令参数。
- 面板以当前供应商的 `catalogModels` 生成默认列表，并集中处理“恢复目录并选择第一项”的状态重置。
- 继续复用现有 Hermes `probe_api_models` 能力获取实时列表。
- 不改变 API Key 输入、模型状态检测、主模型/备用模型用途、添加模型和配置持久化协议。
- 不新增或修改用户可见文案，因此不涉及翻译资源变更。

## 测试与验证

- 适配层测试：验证 `tokenhub`、任意 `tencent_*` 不支持实时刷新，其他预置供应商和自定义供应商支持。
- 面板测试：验证七彩石目录默认展示并选择第一项。
- 面板测试：验证腾讯系隐藏按钮，其他供应商和自定义供应商保留按钮。
- 面板测试：验证实时成功结果完整替换目录并选择第一项，空结果清空列表，重复获取覆盖上一轮结果。
- 面板测试：验证实时获取失败时保留原列表和选择。
- 面板测试：验证切换供应商、分类、修改 API Key 及成功添加后恢复七彩石默认列表。
- 运行相关 Vitest、`pnpm check` 与 `git diff --check`。

## 非目标

- 不修改七彩石接口、数据结构、缓存策略或供应商排序。
- 不把七彩石目录与实时获取结果合并。
- 不为腾讯系增加其他刷新入口。
- 不调整 Hermes 后端的模型探测或配置保存逻辑。
