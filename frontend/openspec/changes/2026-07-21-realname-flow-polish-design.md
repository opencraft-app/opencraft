# 实名认证流程体验优化设计

日期：2026-07-21  
状态：待用户书面确认  
规模：M（重构现有多阶段弹窗的结构、交互与可访问性，不改变接口）

## 1. 目标

在不改变现有黑白灰配色、认证步骤、后端接口和业务判定的前提下，把实名认证从传统分段表单改造成克制、连续、稳定的产品化向导。

成功标准：

- 身份信息、人脸核身、手机验证在同一稳定弹窗壳体内连续推进。
- 用户始终能识别当前步骤、已完成步骤和剩余步骤。
- 桌面端减少大按钮、硬分割线、固定长连线和多层圆角卡片造成的笨重感。
- 移动端不横向溢出，刷脸阶段优先展示直接打开核身页面的操作。
- 不改变实名认证 API、轮询策略、手机号是否必填的判断、实名成功真源或隐私边界。

## 2. 方案选择

### 采用：稳定壳体 + 连续步骤画布

弹窗的标题、进度区和底部操作区保持稳定，中间内容按阶段切换。阶段切换只使用短暂的透明度与纵向位移动效，使用户感知到流程推进，但不造成弹窗跳动。

### 未采用方案

1. **左侧步骤导航 + 右侧内容**：桌面端专业感较强，但三步流程不足以支撑双栏结构，移动端还需维护第二套布局。
2. **弱化进度的极简逐页表单**：界面最简洁，但用户无法提前知道还需人脸和手机号验证，可能降低完成率。

## 3. 信息架构

弹窗固定分为三层：

1. **流程头部**
   - 标题与一句当前流程说明。
   - 自适应步骤轨道，连接线使用弹性布局，不再固定为 96px。
   - 已完成步骤显示勾选，当前步骤强调，后续步骤弱化。
2. **阶段画布**
   - 只渲染当前阶段的核心任务。
   - 身份信息和手机验证阶段按实际内容自然撑高，不设置固定最小高度；二维码、人脸等待和同步状态自身保留必要高度。
   - 阶段变化时不做高度动画。
   - 表单错误固定展示在阶段底部预留槽；等待和过期状态贴近对应操作展示。
3. **操作区**
   - 桌面端主按钮使用适中宽度并右对齐，移动端占满宽度。
   - 左侧展示简短安全说明；加载时按钮宽度和位置不变。
   - 后端自动同步阶段没有无意义的空白按钮区。

## 4. 分阶段设计

### 4.1 身份信息

- “证件类型：身份证”改为静态信息行，不再伪装成不可操作的下拉框。
- 姓名和身份证号使用统一输入组件外观、清晰的键盘焦点和自动完成属性。
- 姓名、身份证格式和两者不匹配错误统一显示在底部操作栏的反馈区域；输入框仍通过错误描边和 `aria-describedby` 指向该提示。
- 隐私协议保持在提交动作之前，链接可独立点击，不触发复选框的意外切换。

### 4.2 人脸核身

- 桌面端取消“大灰色卡片套二维码白卡”的嵌套结构。
- 使用一个简洁内容面：二维码作为主要视觉对象，旁侧或下方展示“扫码—完成刷脸—返回等待”的短说明和实时状态。
- 有效期使用次级文本展示；等待、已过期、未通过状态占用同一位置，避免布局突然变化。
- 移动端不展示二维码，直接提供“打开刷脸页面”操作，并说明完成后返回当前页面。
- 轮询和页面重新可见时的状态刷新逻辑保持不变。

### 4.3 手机验证

- 手机号与验证码组成一个紧凑表单组。
- “获取验证码”与手机号输入框保持同一高度和视觉基线；发送中、倒计时和不可用原因就地显示。
- 手机号占用、手机号格式、验证码不存在、过期或错误统一显示在底部操作栏的反馈区域；关联输入框保留错误描边和语义关联。
- 已绑定手机号继续只读展示，新用户仍可输入中国大陆手机号。

### 4.4 同步、失败与完成

- Shadow 同步阶段使用居中的轻量状态区，持续显示系统正在处理的事实。
- 同步失败保留现有重试能力；FaceID 供应商失败或过期仍回到重新刷脸，不混淆为 LightVela 同步失败。
- 成功后继续以刷新后的 `user.realnameVerified` 为唯一完成真源，不新增本地成功副本。

## 5. 动效与响应式

- 弹窗进入和退出、阶段内容切换只动画 `opacity` 和 `transform`。
- 交互反馈不超过 200ms，默认使用 `ease-out`；尊重 `prefers-reduced-motion`。
- 不动画宽度、高度、padding、背景模糊等高成本属性。
- 弹窗设置视口内最大高度和内部滚动区；移动端保留安全边距。
- 内容切换时将焦点移动到当前阶段标题或首个可操作字段，避免键盘用户迷失。

## 6. 可访问性

- 使用项目现有 Radix Dialog primitive，提供 `role="dialog"`、标题关联、焦点锁定和关闭后的焦点恢复。
- 遮罩点击不关闭；支持 Esc 和右上角关闭按钮。
- 图标按钮提供可访问名称，装饰图标使用 `aria-hidden`。
- 输入框使用显式 `label`、`aria-invalid` 和 `aria-describedby` 关联错误。
- 轮询和同步状态使用 `role="status"` / `aria-live="polite"`，避免重复打断屏幕阅读器。
- 禁用按钮附近提供可理解的条件，不只依赖灰色表达不可用。

## 7. 组件边界

为降低 `account-page.tsx` 继续膨胀的风险，实名认证视图从页面中抽为聚焦组件：

- `realname-verification-modal.tsx`：Dialog 壳体、阶段编排和动作区。
- `realname-stepper.tsx`：纯展示步骤轨道。
- 现有 API 调用、轮询和状态判断优先随弹窗组件迁移，不改变 Repository 接口。

如果迁移会显著扩大回归面，则首轮只抽取步骤轨道和阶段视图，保留异步控制器在原文件；实现计划以测试可控和最小风险为准。

## 8. 错误与边界

- 保持现有后端错误码到中文文案的映射，不暴露原始 code 或堆栈。
- 输入相关错误采用无容器的行内校验：输入框仅增加轻微错误描边，底部操作栏左侧显示小型提示图标、红色短标题和灰色解决建议；不新增背景、边框、圆角、阴影或嵌套卡片。
- 底部操作栏左侧始终是有内容的反馈区域：无错误时显示安全说明，有错误时在原位替换为错误提示，不保留空白错误槽。
- 反馈区域保持稳定的最小高度，错误出现或消失时不改变字段、协议、主按钮或弹窗的位置；错误内容不使用高度动画。
- `phone_in_use` 展示标题“该手机号暂不可使用”，说明“该手机号已绑定其他 LightVela 账号，请更换手机号或联系管理员。”；`realname_mismatch` 展示标题“身份信息未通过核验”，说明“请确认姓名与身份证上的信息完全一致后重试。”
- 技术错误码完全隐藏；未能归类到字段的网络、服务和同步错误在当前阶段内容底部使用同款无容器提示，不使用裸露的整行红字。
- 用户修改与错误相关的字段时清除该错误；其他字段变化不应误清除无关错误。
- 恢复中的 pending attempt、FaceID 过期、FaceID 未通过、手机号验证码错误、Shadow pending/failed 均需保留现有行为。
- 用户关闭后重新打开时继续从后端 attempt 状态恢复，不在浏览器存储姓名、身份证号或核身地址。
- 已绑定手机号用户展示两步；未绑定手机号用户展示三步，步骤轨道在首次渲染时即稳定。

- 先补组件测试，再重构实现。

- 新增以下断言：
  - Dialog 具备可访问名称、焦点锁定和 Esc 行为，遮罩点击不关闭。

  - 身份证类型不再渲染为伪下拉控件。

  - Shadow 自动同步阶段不渲染空白操作栏。
  - 减少动态效果时阶段切换无非必要动画。

## 10. 明确排除

- 不修改现有配色、品牌色、后端接口、错误码或轮询频率。
- 不改变实名准入规则、手机号验证开关或国际站行为。
- 不新增 UI/动画依赖，不修改其他账号弹窗。
- 不在本次补做身份证 ISO 7064 校验位算法。
