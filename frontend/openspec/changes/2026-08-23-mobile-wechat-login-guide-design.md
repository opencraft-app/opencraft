# 移动端微信登录引导设计

## 目标

普通移动浏览器点击微信登录后，不再只显示“请在微信中打开”的错误提示，而是提供可执行的下一步：复制微信 OAuth 登录链接，并提示用户前往微信粘贴打开。

## 交互

- 微信内置浏览器继续直接使用 `official_account` 模式跳转。
- 桌面浏览器继续使用 `website` 模式跳转。
- 普通移动浏览器打开国内站登录弹窗时，默认直接展示微信图标、`复制链接，前往「微信」打开` 和 `复制链接` 按钮，不再要求先点击一次微信登录按钮；从其他登录方式切回微信时也直接恢复该引导。
- 复制时优先使用 Clipboard API；权限拒绝、文档失焦或 API 不可用时降级使用 `document.execCommand("copy")`；两种方式都失败时展示可选中、可长按复制的原始链接。
- 复制成功后就近显示 `已复制，请打开微信粘贴访问`；两种复制方式都失败时显示 `复制失败，请长按复制下方链接`，并通过 live region 向辅助技术播报。
- 国内站登录弹窗仍以协议勾选作为复制动作门禁。引导默认可见；未勾选或进入引导后取消勾选时，复制按钮复用现有待确认样式并设置 `aria-disabled`，点击仍展示协议提示且不写入剪贴板。
- 登录方式切换、弹窗关闭或重新打开时清除引导和复制状态。弹窗首次直接展示引导时聚焦复制按钮；从手机或 QQ 切回微信时不再次抢焦点。
- 复制按钮复用弹窗主按钮的胶囊圆角、`text-sm` 和 `font-medium`；引导提示同样使用 `text-sm font-medium`，避免形成独立字号层级。
- 标题容器显式承担底部间距，内容区从正常文档流开始，视觉距离保持不变并符合 `DESIGN.md` 的 Modal Layout 约定。

## 链接与边界

- 复制 `AuthRepository.getOAuthStartUrl("wechat", { wechatMode: "official_account" })` 返回的 URL；切换账号模式同时保留 `switchAccount: true`。
- Repository 继续负责附加当前页面的 `return_to`，本次不修改后端接口或 OAuth 回跳校验。
- `/auth/sign-in` 使用同一引导组件和复制降级逻辑；该页面同时陈列多种登录方式，因此保留用户点击“使用微信登录”后再展示引导的时机，且没有协议门禁。弹窗与独立页的引导内容一致，展示时机有意不同。
- 复制成功时在当前浏览器上报微信 `copy_link` 事件。由于用户会转到微信浏览器继续登录，`sessionStorage` 无法跨浏览器传递，本次不把复制动作记录为可跨浏览器归因的登录方式。
- 不尝试 `weixin://` scheme，不增加依赖，不修改桌面和微信内现有跳转。

## 验收

- 普通移动浏览器打开登录弹窗即展示引导且不重定向。
- 复制内容是 `official_account` 启动 URL，成功和失败状态均可见。
- 弹窗协议门禁、微信内跳转、桌面跳转和 QQ/手机登录回归通过。
- 390 x 844 移动端页面无横向溢出、遮挡或不可点击控件。
