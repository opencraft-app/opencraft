# USER.md 与 MEMORY.md 为什么不能合并？

> **LightVela 是什么：** LightVela 是一个云端个人 AI Agent 平台，帮助用户运行具备长期记忆、Skills、自动化任务和多渠道接入能力的 Agent。[访问 LightVela](https://lightvela.ai/?from=social_techpedia)

Hermes Agent 的两份长期记忆笔记加起来只有约 **1,300 tokens**——放在动辄十万上下文的时代，这个空间过分节制。更让人意外的是：它还坚持把这 1,300 tokens **拆成两份文件**，而不是合成一份。

原因是三条硬约束：**容量互不挤压、加载语义不同、更新语义不同**。合成一份看起来更简单，实际用起来更糟。

## 两份笔记分别装什么

**用户画像**（约 500 tokens）是关于"你"的稳定描述：姓名、职业、沟通风格、常用技术栈、作息与禁忌、长期目标。它的特征是**稳定**（几天甚至几周才更新一次）、**结构化**（分节、字段化）、**每次会话必载**。

**事实档案**（约 800 tokens）存的是你和 Agent"一起干过什么"：某个项目跑在哪个端口、上周把首屏改成了动态渐变、和 A 团队定了 Q4 做 X、这个 API 走内部 SDK 而非公开接口。它的特征是**动态**（几乎每次实质会话都写入 1-2 条）、**条目式**（一条条追加）、目标条目数 8–15 条。

一句话区分：**画像随"你本人"变化才改，档案随"每一天的对话"增长。**

## 为什么不能合并？三条硬约束

### 约束 1：容量各自独立，不互相挤压

500 + 800 合并成一份 1,300 tokens 的笔记后，会立刻遇到一个荒谬的决策：**当档案快满时，Agent 是否要为了"再记一条事件"而删掉一条"用户是谁"的画像？**

答案显然不该——但一旦合并，这个决策就必须做，而且**每次记录都要做一次**。分开之后，两个池子各自演化：档案满了只挤自己，不会污染画像。

### 约束 2：加载语义不同

两份都是每次会话必载，但它们在系统提示里扮演的角色完全不同：

- 画像回答的是"**你面对的是谁**"，用于定调：语气、结论粒度、技术栈假设。
- 档案回答的是"**你们一起做过什么**"，用于提供事实抓手。

合并后两段内容会**互相稀释**——Agent 无法快速判断"这句话是我要遵循的沟通风格，还是我要引用的过往事实"。

### 约束 3：更新语义不同

- 画像里的偏好字段以"**覆盖旧值**"为主：你说"以后别再总结了"，直接覆盖对应那行。
- 档案以"**追加 + 按需整合**"为主：事件是时间序列，历史不能随意抹掉；容量满了则触发主动整合。

合并后，"新增 / 替换 / 删除"三种操作要在同一个文件上并存，实现复杂度和你的心智负担会**同时变糟**。

## 一个具体的例子

假设你告诉 Agent：

> "我叫 Jasmin，是一名前端工程师，喜欢结论先行的沟通风格。最近在做 agent-demo 项目（一个 AI Agent 应用）的国际站，用 Next.js。上周我们把首屏改成了动态渐变。"

一个训练良好的 Agent 会这样拆：

**进画像**：

```md
## Identity
- Name: Jasmin
- Role: 前端工程师

## Preferences
- 沟通风格：结论先行
- 常用技术栈：Next.js
```

**进档案**：

```md
- [2026-07-30] agent-demo 项目：国际站首屏改为动态渐变。
- 相关项目：agent-demo / 国际站
```

区别很清楚：**"你是什么样的人"进画像，"我们一起做了什么"进档案。** 前者只会随你换工作、换团队才改；后者每天都在长。**分开写，才能各自演化。**

## 还有一份"不该记什么"的黑名单

Agent 也不是什么都往画像里塞。它有一份跳过清单：

1. **一次性情绪**："今天头有点疼"——不是稳定属性。
2. **临时任务参数**："这次帮我把标题改成 X"——用完即弃。
3. **模糊态度**："我大概比较喜欢简洁一点"——不够可复用。
4. **能从上下文实时推断的信息**——没必要落盘。
5. **未经你显式确认的敏感信息**（邮箱、密码、地址）——涉隐私默认不写。

有了这份黑名单，画像才能维持"500 tokens 且高质量"的密度。

## 这对产品意味着什么

对 AI Agent 产品而言，这种分层不只是工程细节，它决定三件事：

1. **能不能给你看"它对你的印象"**——需要一份稳定、可读、可编辑的画像。
2. **能不能长期不失忆**——需要一份可增长、可召回的事实档案。
3. **成本能不能被约束**——分层加载才能既记得你是谁，又不烧掉整个上下文。
