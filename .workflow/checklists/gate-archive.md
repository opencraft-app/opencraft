# Gate: 归档阶段门禁

> 验证阶段通过后，进入归档阶段。本 checklist 确认本次需求已经完整交付且痕迹清晰。
> 全部通过后，可以关闭本次需求 / 提 MR / 写发布说明。

---

## 一、产物完整性（必须）

- [ ] `openspec/plan.md` 中所有任务已勾选完成 `- [x]`
- [ ] 涉及的 spec 已更新或新增到 `openspec/specs/`
- [ ] 不在范围内的"待办事项"已记录到 `openspec/changes/` 或 issue
- [ ] 临时调试文件 / 截图 / 草稿已清理或归档
- [ ] `openspec/current_state.md` 未写入本次需求历史、上一个需求摘要或当前会话状态；历史事实以 `openspec/changes/*.md` 为准
- [ ] 如存在旧版「## 当前进行中」「历史归档」「上一个需求」等段落，已移除或迁移到本次归档单文件
- [ ] 已评估本次变更是否影响稳定架构 / 模块索引；如影响，`openspec/current_state.md` 已做段落级最小更新；否则保持不变
- [ ] `openspec/plan.md` / `proposal.md` / `spec.md` 已重置为带「上一需求归档于 YYYY-MM-DD：{需求名}」指纹的占位语（grep "上一需求归档于" 命中 3 次）
- [ ] 如存在 `.workflow/runtime/verification-ledger.md`，已从中提炼验证摘要；未用 ledger 替代真实验证结果
- [ ] 已执行本地 AI 用量审计：`metadata.localUsageAudit` 有结果，或明确降级为 `null` 且不阻塞归档

---

## 二、变更归档（必须）

- [ ] `openspec/changes/` 下已创建本次变更的描述文件（含范围 / 影响 / 关键决策）
- [ ] 变更描述包含：变更类型 / 影响模块 / 兼容性说明
- [ ] 涉及破坏性变更的，已在 CHANGELOG 中标注 BREAKING

---

## 三、CHANGELOG（按需）

> 工具仓库 / 库类项目必须；业务项目按需。

- [ ] CHANGELOG 新增本次变更条目
- [ ] 变更条目包含：版本号 / 日期 / 变更类型（feat/fix/chore）/ 变更内容
- [ ] 含「💡 设计思考」段落（可选但推荐）：为什么这么改，踩坑经验

---

## 四、TAPD / 工单（如启用）

- [ ] TAPD 状态已流转到下一阶段（开发完成 / 待测试 / 已上线）
- [ ] TAPD 评论已发布（含产物链接、自验结论）
- [ ] 关联的 bug / story / task 已正确关联到本次提交

---

## 五、MR / Code Review（必须）

- [ ] MR 已创建，目标分支正确
- [ ] MR 描述清晰说明了：动机 / 方案 / 测试范围 / 风险
- [ ] 已指定 Reviewer
- [ ] CI 全绿（lint / type-check / 单测 / E2E P0）

---

## 六、收尾确认（必须）

- [ ] 本地工作区干净（没有遗漏未提交的相关文件）
- [ ] 远程分支已推送
- [ ] 已与用户确认本次交付符合预期

---

## 门禁结论

- [ ] **通过**：本次需求归档完成
- [ ] **打回**：存在交付缺漏，需补充
- [ ] **有条件通过**：列出后续跟进项（如"待 MR Approve 后合并"）
