# Codesign 文档约定

本目录用于沉淀**可复用的操作手册、权限设计、平台接入记录和发布流程**。

目标：

- 让后续同学或 agent 能复用已经验证过的流程
- 把“为什么这样设计”写清楚，而不只记录命令
- 在不泄露敏感信息的前提下，保留足够的审计与复盘线索

## 内容边界

本目录适合放：

- 发布流程说明
- 权限模型设计
- 子账号 / 策略 / 项目 / deployment 创建记录
- 实际踩坑与排障总结
- 面向操作者的使用说明

本目录不适合放：

- 临时实验草稿
- 与当前平台接入无关的产品讨论
- 未验证、不可执行的大段猜测性方案

## 安全要求

严禁把以下内容提交到 Git：

- 主账号或子账号密码
- CAM AccessKey 的 `SecretId` / `SecretKey`
- EdgeOne Pages API Token 明文
- 带鉴权 query 的临时预览链接
- kubeconfig 明文
- cookie / session / 本地登录态
- 任何可直接复用的生产敏感凭据

允许写入仓库的内容包括：

- 用户名
- UIN / UID
- ProjectId / PolicyId / Deployment ID
- 策略 JSON
- 命令、步骤、结论、风险说明

原则：

- **保留可审计元数据**
- **不保留可直接登录或调用的秘密**

## 写作约定

更新本目录文档时，优先写清四件事：

1. 做了什么
2. 为什么这么做
3. 实际结果是什么
4. 哪些地方还需要人工或后续步骤

如果一个流程中有“已验证”和“未闭环”两部分，必须明确区分，不要混写成“全部已完成”。

## 文档组织

建议保持两类文档分离：

- `README.md`
  - 目录入口和文档导航
- `*-operator.md`
  - 面向执行者的使用说明
- `*-provisioning.md`
  - 面向维护者的创建记录、权限设计、资源清单

如果后续要继续创建更多受限子账号，优先：

- 沿用现有 provisioning 文档结构
- 明确记录新对象的用途、边界、策略和实际创建结果

## 本地状态

本目录文档可以引用本地状态文件的路径或名字，但不要提交这些文件本身。

例如：

- `frontend/.edgeone/project.json`
- `~/.edgeone/*`

它们属于本地状态，只能在文档里说明用途，不能纳入仓库。
