# Reasoning 能力与请求契约

## 不变量

- 未声明可配置 reasoning 能力：无默认档位，不发送 effort 参数；不据模型名称推断。
- 默认档位只在模型支持的集合内有效；允许支持集合非空但不声明默认值。
- none/off 是模型可声明的真实值，不是通用的“缺省”标记。
- 展示、选择恢复及请求编译使用 composer-core 的同一能力归一化/选择函数。

## 边界

OpenCraft 的非生成 model/list 结果类型允许 defaultReasoningEffort 为 null，不修改上游生成文件。DSH 目录不再补 none。读取旧的必填字符串协议时，空支持集合归一化为无能力；非空集合中非法默认值报错，能力查询不发布不完整或非法结果。

模型切换/缓存恢复只保留目标模型支持的选择，否则使用它声明的默认值或不设置，不从全局档位表自动降档，也不选择列表第一档。Composer 的显示值和编译结果由同一规则派生，原始不可变提交意图不篡改。

发送前捕获的提交意图使用界面实际派生的模型和档位，而不是直接转发旧缓存；以新对象承载规范化选择，不改写旧意图。能力查询失败是明确的编译前失败，不能归类为“消息可能已发送”。

实际提交前，Host 命令端口读取选中模型（已有会话可取当前执行模型）的最新目录能力，再编译请求。不另建缓存；菜单展示仍消费联合能力查询。选中模型失效或无法确定模型却指定档位时中止，不猜测。steer/queue 不接受这些覆盖项，沿用既有命令边界。

编译器收到明确能力后，不会发送不适用的旧参数；明确支持 none 时仍发送 none。直接调用引擎并传非法参数仍由引擎拒绝，不添加“删除所有 none”或 DeepSeek 名称分支。DSH 默认模型投影还必须 unset 已不再指定的 reasoningEffort，防止旧引擎覆盖残留。

## 验证

reasoning-capability.test.ts 覆盖无能力、合法 none、非法默认、无默认和切换残留；smoke-reasoning-contract.ts 使用隔离产品目录、真实 Workbench 编译器与 DSH、仅本地 HTTP 模型端点，验证旧 none 不进入真实请求。
