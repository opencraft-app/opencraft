# Server collaboration spaces

A Server is a collaboration space inside one deployment, independent of engine
`serverId`, Host, Hub, and human identity. `myself` is the default local space;
creating another Server does not start another service process.

The user specified a bottom-most left-edge drawer, closed by default. It is not
a permanent `myself` row or a replacement panel inside the existing Sidebar.
The complete page travels right to reveal a stationary, recessed Server drawer
with a shared shadow. Pointer drag, touch, cancellation, release and reduced
motion consume the existing Shell gesture/motion owner. Server selection is the
primary destination; members, creation and invitation are nested management
views. Reuse shared Navigation, Button, input and Radix focus primitives.

Shell owns physical viewport, gesture arbitration, input exclusion, portals and
return focus. Feature state owns membership operations and form drafts. Native
credentials remain at their existing execution owner. Server selection does not
rebuild Chat or replace its saved drafts. The stationary sidebar chrome follows
whole-page displacement while remaining independent of ordinary sidebar motion.

Core storage owns spaces, member roles, expiring invitation digests, and explicit
engine/Thread-to-space assignments. Existing human Actors remain the identity
authority. Space membership gates reads and subscription delivery; private
conversation policy remains an additional restriction. Creation captures its
space before asynchronous work and commits assignment before receipt delivery.
Only Native-proven older history can be adopted into the default space.

Validation: see the thread's Server drawer verification artifact for the actual
wide/narrow, pointer/touch, theme, motion and failure sequences reviewed. Core
coverage includes membership isolation, invitation expiry/replay, revocation,
Worker lock waits, restart recovery and previous-schema upgrade/checksum refusal.
The implemented authentication and deployment boundaries are in
[Server spaces](../../docs/server-spaces.md).

## Edge discovery refinement

The Shell reserves an extra leading gutter in sidebar content, leaving the
footer geometry unchanged. A shared `edge` Button size presents a visible
attached 28×48px handle, with the existing input-capability minimum expanding
its touch hit area. The recessed drawer is 280px wide and consumes paired
neutral underlay colors from the theme owner. It stays closed by default.
Reviewed the actual Settings route in light, dark and Longing themes at
1300×900, plus touch input at 390×844: the handle no longer collides with
navigation labels, and the gray underlay reads below the moving page.
