# Personal machine enrollment

Task: generate one Bash command in the local-owner Workbench, run it on Linux or
macOS, and use that machine's existing Agents and native histories in myself.
The current scope is the trusted local owner. Headless multi-user deployments
must not enable this service without verified Human/owner admission.

Use the existing onboarding sheet (Settings/object collection pattern) for
machine list and enrollment. Shared Settings inputs, Buttons and identity icons
own controls. Generate command is the primary action; choose Agents and revoke
are quiet scoped actions. The onboarding sheet owns width/scrolling. Long
commands wrap within the existing bounded content, never expanding the viewport.
Cold/unavailable detection must not declare an unsupported Host ready. Cached
machine rows survive transient reads; online status and runtime readiness remain
separate. Import busy state prevents machine switching/closing during commit.

Core owns local Actor-bound machine identity and credentials in an asynchronous
Worker. Only hashed pairing/daemon credentials persist in its private registry.
Pairing is 15-minute, one-machine and idempotent only for the same durable remote
credential and native machine identity. Revocation commits before retiring every
active relay stream. Storage failure closes admission and existing channels.

Reuse Relay control/data framing, relayDuplex, connectRelay, LocalIngress and the
standard Local Agent Host. The companion opens no public remote listener; its
relay streams enter the private ingress in process. Credentials, native sessions
and cwd stay remote. A disconnect retires the attachment, not native Agent work.
The source installer is an exact SHA-256 archive generated by the trusted local
build; no uncommitted installation is represented as a public release. Bash
supports Linux/macOS x64/arm64, pins Node 26.7.0 privately if needed, and reuses the
existing npm, DSH preparation and bridge build. A reachable HTTPS installation
address is required; a browser-login-only share is insufficient.

systemd user service is used when available. Other systems use an explicitly
reported detached process (no reboot-start claim). Local --status and --stop use
an owner-only Unix socket. Existing CLI credentials are not installed/copied.
