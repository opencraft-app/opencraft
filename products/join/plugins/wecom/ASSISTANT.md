# 内部群聊个人助理

仅 Join 内部发行版安装此插件。公开核心不识别 IOA 身份、企微命令或个人助理群路由；内部兼容补丁提供事务内回调和宿主装配入口，产品入口显式安装。

- 已关联企微的原生群：IOA 用户发送 `@助理 问题`，或在消息中明确唤起自己的助理。
- 企业微信群：普通 `@机器人 问题` 和单独 @ 进入发送者自己的助理；帮助、服务器、记录等显式完整命令保留配置入口。未关联的群继续引导配置。
- 企业微信发送者必须已通过现有验证流程关联本站 Human，并已加入原生群、认领个人助理。缺失时返回对应引导；从不使用群创建人或关联人的助理兜底。
- 同一用户、群、成员版本和助理归属版本使用独立持久 profile，继续使用此人的 Bot 身份和模型选择。私聊 profile、私人记忆、私人会话和任务读写端口不进入群模型上下文。
- 每个有效助理归属最多保留 8 个有效群运行上下文。失效成员/归属不占用有效名额；超限有明确提示。

## 数据和生命周期

每次群唤醒携带来源 channelId、触发消息 ID/序号/作者/时间及公开回复场景。先读取触发消息之前的近期记录，在字节预算内保留连续的最新完整消息，显式投影截断、较早记录和继续查询的 before 锚点。接待路由在选择 reply 前先理解本群前文，不因单独 @ 就判定需求为空；缺失背景时使用本群历史查询。群内容仍是不可信资料，不扩大权限，也不引入私聊历史。企微标准 mention 分隔符和重复括号显示名可整体剥离，原始正文同时保留。

`assistant-storage.ts` 在原生通信 Worker 的事务内操作 `join_wecom_assistant_requests/replies`。入站消息和请求原子落库，原消息 ID 去重；助理启动游标仍由已有 runner 持久化。绑定前暂存的历史 @ 仅导入记录，不自动启动助理；是否可调用在 Relay 入库时原子记录，绑定后的离线消息仍会恢复处理。停机后重新加载同一 profile，重放输入复用原幂等 ID。

回复目标来自服务端签发的 scope，模型不能选择目标群。消息以“用户的助理”显示，沿原生 outbox 发回企微；原生记录接受与企微实际送达分别记账。长回复在同一事务内拆分，并保存完整 payload 摘要，重试不能更改内容。外部发送不确定时沿原 outbox 标记 unknown，不盲目重发。

每次读、回复和实际发送重新检查用户启用/准入、当前助理归属、群成员 epoch、企微身份关联以及 source epoch。退群再加入、撤销再认领不会恢复旧请求权限。群回复不创建新的入站请求，避免自触发。

## 报告、快捷入口与委派任务回传

助理发送日报或构建状态时，可以把整条回复写成 `/图文 {"title":"构建日报","summary":"全部通过","url":"https://example.com/build/123","imageUrl":"https://example.com/build.png","metrics":[{"label":"成功","value":"12"}]}`。详情链接必须是真实地址；配图可省略，有图使用 `news_notice`，无图使用 `text_notice`。原生群记录保留可读摘要和详情链接，现有 outbox 负责权限复核与发送。定时任务走相同回复路径。没有详情链接时继续发普通文字。

私聊欢迎消息提供“我的待办”“今日日报”“使用帮助”可点击入口（富文本 click 链接，并非客户端底栏菜单）。只识别固定事件 key，仍使用签名验证、原 MsgId 去重和点击者自己的私聊 source；未知 key 和群里的同名事件不触发私聊快捷操作。快捷入口只能查询助理现有权限内的数据。

群 profile 在提交 `thread start` 前保存任务回传意图，以相同参数和幂等键恢复不确定的提交。后台每 15 秒检查少量任务，只有输入投递回执对应的轮次结束才回群；接受提交不代表完成。绑定仅适用于本 scope 创建的任务及其显式跟进，不接管其他私聊会话。发送前重新检查 scope 授权，冻结正文并复用原生回复 ID，避免重启或确认丢失产生重复消息。后续私人轮次不复制进原群，失败和主动停止也会报告。长结果保留部分正文和任务会话引用，未分页取得的内容明确标记为部分结果。

出站文件上限为 20 MiB。助理私有 IPC 使用 384 KiB 分块，逐块检查 scope，拒绝不连续写入或改变已有字节；最后一块才建立原生 outbox 消息。Relay 仅对已认证的 file-send 接口提高 JSON 大小限制（包含 base64 开销），原回调大小不变。中断上传暂存一天，保持同键重试；外部发送结果未知时仍遵守既有 outbox 不盲重发规则。

`assistant-install.mjs` 仅由 Join gateway 安装。通信 Worker 接收安装时固定的模块 URL；没有客户端可选模块入口。独立助理进程由内部 `assistant-server.mjs` 安装群运行扩展，保留现有私聊进程、附件接收与活动观察。

## 装配和验证

构建必须包含 gateway、orchestration-runtime-worker、assistant-server、assistant-extension 和新 server schema 迁移。迁移进入内部兼容补丁，不能仅替换一个网关文件。发布前备份当前数据库和所有受影响运行配置。

聚焦验证：`npm run test:wecom --workspace @join/opencraft-distribution`、Relay 的 `wecom-*.test.ts`、个人助理宿主/运行器回归、类型和边界检查、正式 Join gateway 构建。真实企微账号和模型联调另行记录，合成测试不代表已上线。

### 转发附件、任务文件与私聊卡片

转发/混排会保留最多16个嵌套图片、文件和语音引用（深度3、扫描200项）。
文件转为资料编号，PNG/JPEG图片（单张2MiB以内）进入本群助理的附件上下文；语音使用既有识别服务。
下载总预算40MiB，失败明确标注，不把转发记录中的发送者当成请求权限主体。
所有文件（包括 PDF、Word、Excel、PPT、CSV、纯文本、代码、压缩包及未知格式）统一只保留原件和可信元数据。不在接入层内置解析器、提取/截断正文、生成文本切片或向群助理注入文档正文；旧版文本切片也不再读取。如何读取、分析、转换和生成交付物由 agent 根据任务自主选工具，不按扩展名硬编码业务流程。需要文件工具时，通过既有 `thread_command` 使用主人的完整 OpenCraft 会话处理原文件。资料查询只返回路径、名称、字节数、下载状态，不提供正文分页。图片预览仅做协议尺寸/格式适配，不承担 OCR 或内容分析。

### 资料来源与可靠重放

资料编号不是访问凭据：下载端持久记录真实 source，群助理每次通过自己的有效 scope 获取服务端 source，再据此物化和读取。跨群粘贴编号、未标记来源的旧材料副本均不能授权，旧副本也不能进入图片上下文。旧全局缓存仅在原生外部消息记录中的编号与 source、提供方 MsgId（含嵌套位置）重新计算出的 HMAC 相符时补齐来源；不以用户正文中的任意编号认领资料。无法验证的旧资料需在本群重新发送。

网关在原生入库前原子写入并 fsync 私有接收日志，固定原始消息指纹、首次派生文本及文件下载意图。原生入库确认也先于 Relay ACK 持久化；ACK 丢失、网关退出或重启不会遗失下载任务。文件短暂失败按退避自动恢复并刷新旧失败说明；404/410、超过大小限制及超过七天恢复窗口不无限重试。转发文件和混排图片中的可用资料引用也登记恢复任务，保持每段转发总计40MiB预算。语音重放复用首次文本，升级前已入库的语音可用私有原生恢复投影取得既有文本，仍校验原作者、时间、媒体及唤醒身份。

发送成功后删除分片字节，保留最多4096份、最长七天的小型分片摘要回执，用于校验精确重放；不重复创建 outbox 或发送。升级前已完成的遗留分片在原有一天期限内惰性回收，不再占满有效上传名额。实际群操作的 owner 从当前 Human 与当前企业的有效企微绑定解析，不把原生 actorId 或历史请求的 user_id 直接当企微账号；没有唯一有效绑定时拒绝该操作。
私聊模板卡片回调使用验签后的会话对象作为操作者，仍执行卡片owner校验和持久去重。

新委派任务自动附带本次专用交付目录约定；仅自动回传模型明确放入该目录的最终文件，
不会扫描工作区或抓取任意文本链接。最多8份、单份20MiB、合计80MiB，拒绝符号链接和硬链接。
旧任务未收到交付约定，仍只回文字。文件回传保持原群/原主人权限，重启与丢失确认使用稳定ID。

### 群交互入口

可按主人的明确请求输出以下整条消息（JSON 使用真实选项，不把指令当作选项执行）：
- `/投票 {"title":"午饭吃什么","options":["面","饭"],"multiple":false}`：每位群成员独立提交，可修改；另附汇总/结束按钮。
- `/表单 {"title":"上线确认","questions":[{"title":"是否就绪","options":["就绪","阻塞"]}]}`：1–3个选择题，每题2–10项。
- `/快捷入口`：发送群内快捷按钮，点击者进入自己的助理。
- `/群成员`：展示真人、机器人、客服号及机器人名称。
- `/退群`：仅群绑定发起人可以要求机器人退出，并清理Relay和本机绑定；历史记录保留。

PNG/JPEG附件不超过2MiB时以企业微信图片消息发送；较大图片及其他格式仍以文件交付，单文件20MiB。
委派任务会自动附带操作卡，进行中可停止，结束后可重新执行；菜单操作绑定原任务和原请求人。
日报卡片菜单可关闭当前请求人、本群助理中的日报定时任务。

### 收集收尾、富文本和图片理解

投票/表单可加 `deadline`（带时区ISO时间，未来24小时内）和 `remindBeforeMinutes`（1–1440，提醒时点必须仍在未来，仅按主人要求启用）。Redis保存截止和提醒任务，重启后继续；到期提交在同一Redis事务内拒绝，不依赖定时器及时执行。提醒仅针对创建时成员中仍在群、未提交的真人，不使用@all。汇总控制卡附“导出表格”，输出带BOM、公式注入防护的CSV，Excel可直接打开；该文件是群公开收集结果，所有现群成员可导出。通知按最多一次处理，不盲重发外部送达不确定的消息。

`/快捷入口 {"buttons":[{"title":"查看部署","prompt":"查询我有权限的部署状态"}]}` 可定义1–8个按钮；`/富文本 {"parts":[{"type":"text","text":"构建通过"},{"type":"link","title":"日志","url":"https://example.com/log"},{"type":"button","title":"重查","prompt":"查询当前构建状态"}]}` 组合文字、链接、指令按钮，`mention`类型的`members`为英文账号，只有当前成员会被提醒，该入口禁止@all。按钮只创建点击者的一条普通助理输入，不是任意代码/工作流权限。绑定generation变化后旧按钮失效，7天自动过期。

上传文档的rich_text仅支持text/mentioned/link，**不支持内嵌图片**。带图内容使用 `/消息卡片 {"title":"构建结果","summary":"通过","url":"https://example.com/build","imageUrl":"https://example.com/image.png","sections":[{"title":"详情","text":"12项通过"}],"links":[{"title":"日志","url":"https://example.com/log"}],"buttons":[{"title":"重新查询","prompt":"查询我的构建状态"}]}`，最多4段、3链接、2个右上角菜单按钮；详情链接不可虚构。图片显示于同一图文卡片，不声称支持任意位置的图片穿插。

较大栅格图自动限尺寸压缩为2MiB以内JPEG后走原生图片，失败保留原文件交付；不覆盖原始字节。动态图和自定义表情取首帧供助理理解，限定2400万像素和输入字节；表情仅从文档所示腾讯CDN白名单HTTPS下载，拒绝跳转、凭据、端口和任意地址。

外部企业SenderCorpId与账号共同构成独立归档身份，转发记录也保留企业标记，不映射成本企业员工、不唤起本企业同名账号的助理；当前API单聊只接受userid，无法安全区分跨企业同名私聊，因此外企私聊不绑定、不执行。跨企业助理授权需要另行设计，不以同名猜测。

### 历史原件和任务交付恢复

资料读取按本群服务端 source 按需物化元数据，再次校验权限后返回原件路径；不依赖近期消息缓存，不提取正文。群消息准入和任务回传分别轮询，每个 scope 只允许一份准入作业和一份回传作业，单类最多8份并行；慢文件不阻塞其他群，关闭/撤销会取消在途等待。

任务完成时，将明确交付目录中的合规文件保存为独立持久字节快照，提交清单后才发送。重启重试不再读取可能被 agent 修改或删除的交付原目录。单个暂时发送失败不会挡住后续文件；旧任务文件或快照永久不可用会单独提示并继续交付其他文件，不伪造原件。任务执行结束与交付状态分开，交付失败不阻止重跑，失败/上限/停止卡片与真实执行状态一致。原生 outbox 送达不确定语义、稳定消息ID和每次权限复核保持不变。

空附件不会构造假内容或触发内部空指针异常，而是明确提示暂不支持发送空文件；同行文字和其他有效附件仍正常发送。批量交付额度只统计实际接受的文件。

### 统一管家 CLI

管家 `thread_command` 接受 `argv:["wecom","capabilities"]` 及托管企微命令，仍走原 Bot 身份和 Worker 事务。本群运行时只允许当前 source/scope，不接收模型选定的 actor/token；私聊管家的入口只能列出其本人的有效会话。完整 agent 交办任务自动带本会话独立 CLI 的绝对路径，launcher 和 socket 位于 Gateway/Hands 共用 execution 目录；不下发企微总密钥，不另建公网 API。私有凭据不进入提示词，只作为本机 capability 保存在私有 binding 文件。

`capabilities` 区分可直接调用、自动协议处理及运维专用能力。读/收发、群操作、托管图文/按钮/投票/表单、任务控制使用原有 owner；卡片回调/成员核验/身份转换等即时协议工作由原 Relay 处理。原始运维 CLI 的 JSON 文件参数已修正，不代表允许 agent 使用原始企业凭据或任意卡片 handler。20MiB 限额保持，私有CLI使用40KiB帧，分片元数据上限1024，成功送达后的精确重放/字节回收不变。资料只给原件元数据，内容处理仍归agent。

群里普通图片（不带资料编号）会通过本群授权的分片读取进入本轮图片附件；“先发图，再单独 @”也携带近期群记录中的原生图片，而非只给 `[图片]` 元数据。分片每次64KiB以适配私有Host帧，逐次校验当前会话权限、图片类型/长度/摘要，最多8张；正文与图片都作为不可信资料。未取回的图片不得声称已看见，不做OCR或其他内容解析，识别仍由所选模型/agent处理。已完成的历史请求不自动重放。

### 连续媒体、实时群信息与显式自动续办

30秒窗口现在覆盖本人的文字、图片、语音、文件和混排/转发。媒体下载后才承认准入，
冻结续聊判定以跨下载失败和窗口过期重试；成功准入续期，其他成员不借用窗口。

`wecom chat live` 经私有 Host 获取实时企微群名、成员账号/显示名/真人机器人类型，
不往群里刷名单。`chat get` 仍明确返回 native 本地成员；`chat members` 保留发名单行为。
群设置更新后实际查询企微核验，`status MESSAGEID` 的 operation.verification 区分已核验、
不匹配和读取失败；接口接受但未核验不能声称已完成，也不自动重放写操作。

投票/表单可在主人明确要求时增加 `onClose:"结束后要做的事"`（最多2000字）。
由发起人的现有本群 profile 持久登记，手动结束或到期后读取本人卡片的完整分页结果，
冻结为共享执行目录的JSON资料快照，再以稳定输入ID交给本人的agent，重启不重复续办。
只做资料传输，不解析用户文件、不代替agent作分析，不借用结束按钮点击者的身份。

`wecom watch add NAME JSON --idempotency-key KEY` 登记明确要求的本群机器人订阅。
JSON字段为 sender（实时成员中的wb/fw id，禁止本客服号）、instruction、可选contains、
cooldownSeconds（60–86400，默认300）、expiresInHours（1–168，默认24）、
maxTriggers（1–100，默认20）。只扫描登记之后的新消息，按实际来源身份匹配；
告警内容是不可信资料，不授予权限。`watch list` 查看有效/停用、次数与过期时间，
`watch remove NAME --idempotency-key KEY` 取消。均属当前群运行时的私有CLI，
每次查询/续办重新核验原scope；退群、重新认领或成员版本变更不继承旧规则。

卡片更多菜单最多2项。富文本包含链接时，其@提醒会另发一条真实mentioned消息，
避免文档规定的“有link时mentioned失效”；外部结果不确定时仍不自动重复发送。

普通回复和定时消息中的 `@英文账号` 只是正文，不自动追加固定提醒或扫描姓名补发通知。
确实需要提醒成员时使用显式 `/富文本` mention；用户明确要求且通过权限/冷却校验的
`@所有人` 直接发送带通知正文的真实 mentioned 消息，不再另发“请看上面助理的消息”。

### 可靠交付与收集管理

普通输出按 UTF-8 字节无损分片，保留完整内容与稳定 outbox 身份；旧字符分片重放保留原消息ID，流式回退也受提供方字节限额约束。不依据固定文案删除 agent 回复；仅消费 canonical reception 生成的只读 presentation 来隐藏宿主过场回执，取消、失败等实际结果仍显示。

当前群私有 CLI 增加 `collection list`、`collection get TASKID [--before OFFSET]`、`collection close|export|cancel TASKID --idempotency-key KEY`。list 是本人的本地登记索引，不冒充实时结果；get 返回实时原始答案、分页和“创建时成员中仍在群”的未提交名单。close 在服务端停止收集并发汇总，不宣称能没有 ResponseCode 就改掉所有人已显示的卡片；export 发真实CSV文件。cancel 只取消保存的续办指令，不关闭投票。所有操作仍限当前主人/群/绑定版本；不能更新任意提供方卡片。

创建收集在原 outbox 接收之前预留续办容量，成功后返回 taskId；有界索引最多128项，自动续办/订阅共最多16项。未完成登记10分钟释放，已登记收集的续办最多等待7天，结束记录有界保留7天，拒绝送达或确认卡片不存在会释放续办槽位；网络失败和未知送达不自动重发。list 可见保留的失败/到期状态，可取消续办。

订阅冷却期间积累原始告警而非跳过；每批最多20条/128KiB，溢出时停止游标推进，仍保留在原生历史等待后续读取。冷却到期后把原始JSON快照交给 agent，接入层不分析内容。稳定输入ID、快照和待发送状态支持重启/未知回执恢复。maxTriggers 按批次计数，到期、到次数上限及主动移除都停止触发；list 显示缓冲条数和已处理消息数。

`wecom send file PATH` 强制原文件、原始字节；`send image PATH` 明确请求图片消息，不能转换时明确拒绝，不冒充已发图片；普通助理附件保留 auto。发送意图随上传块、幂等载荷和成功回执一起冻结，同键更换 file/image 会拒绝。

### 统一群同步

原生群是本体，企微是可选外部连接。原生改名/增删成员立即生效，同一事务记录向外同步操作；
企微失败不撤销本地成功，也不影响本地群使用。助理继续使用 `chat rename/add/remove`，不需要选择同步命令；操作按原生群主权限校验。
普通操作返回 receiptId，用原有 `status RECEIPT` 查结果。local.applied 仅代表本群已生效，
只有 wecom.confirmed 才代表此次修改已在企微核实；pending 时后台继续处理，不要求用户重试。
needs_attention 时说明具体未完成的事项，unconfirmed 时明确无法确认，禁止换 key 盲目重发。
不要向群里解释队列、代次、观察票据等内部状态，也不要自动补发“请看上面的消息”。
默认首次观测保留原生状态；接入现有企微群要导入其标题/成员时配置 `initial:external`。
成员自动导入沿用完整历史权限，需要配置 `historyAccess:full`。未知身份不会自动注册/授权。
`chat add/remove USER` 的 USER 仍是 RTX，通过已登记身份解析；不按显示名猜人、不自动建账号。
已配置连接的字段即使仅入站或关闭，也只做本群修改，不偷偷改走企微直写。
未配置统一连接的历史绑定保持原企微操作语义，不自动开启成员导入。
连接配置和诊断保留在维护 CLI，细节见 `GROUP-SYNC.md`，无需向普通用户介绍。

### 合并转发聊天记录的展示与原件

转发记录另存结构化原件，保留发送人快照、时间、消息次序、嵌套关系及附件位置；
接入层只做协议解码，不自动总结、不解析文档。OpenCraft 时间线展示聊天记录卡片，
点开阅读原文；旧版纯文本存档明确标注，无法恢复的结构与图片不会凭空还原。
原始 JSON 同样通过资料编号交给 agent，长预览不代替原件。记录最多 2 MiB、
1000 条消息、5 层嵌套，超限明确标注部分接收；附件沿用最多16项、单项20 MiB、
总下载40 MiB的边界。目录昵称是展示快照，不是权限主体。

界面读取附件先验证当前原生会话成员权限，再从已保存记录按位置解析资料编号，
核对原始来源后分块读取。浏览器不能传任意文件路径或 URL，离群后禁止继续读取；
图片仅允许已验证的安全光栅格式，不执行转发文字里的 HTML、Markdown 或链接。

### 任务真实状态与历史图片按需读取

委派提交回执包含当前会话的 `taskKey`；`wecom task list [--before OFFSET] [--limit N]`
提供本地跟踪索引，`task get TASKKEY` 读取平台真实状态，不输出私有提交参数。
状态卡区分已提交排队、已观察到执行以及最终结果；查看进度按钮使用同一 owner/scope。
停止会消费底层 `stopped/turnId` 回执，已经完成的任务不会被标成停止，停止请求也不承诺撤回外部效果。

历史翻页只返回图片元数据时，Agent 可调用 `wecom image get MESSAGEID`，经当前 scope
逐块授权读取原生图片，并在共享 execution 目录取得 PNG/JPEG 原字节路径（每图2MiB，
每 scope 最多16份，下次读取时清理超过一天的旧缓存）。该路径供完整 Agent 看图；不把元数据冒充视觉输入，
不加OCR，不改变文件分析由Agent自主选择工具的原则。群操作优先使用 CLI 和 status 回查，
旧文本斜杠指令仅保持兼容。


### 运行中补充

管家可先查委派任务状态，再用 thread tell 的 delivery=steer 和精确 expectedTurnId
给原运行轮次补充要求。群端只接受本群任务回执对应的轮次，不为补充另建任务、
导出目录或结果回传绑定，也不追加一份交付约定覆盖原任务。原任务仍只回传一次最终结果。
群授权和任务授权分别复核；过期轮次、接管、停止、等待输入不会自动降级排队。
输入 accepted 不代表已注入，injected 也不代表任务已完成；重试沿用原参数与幂等键。


## 统一的出站展示模型

复用现有出站 envelope 的 `text/author/mentions/replyTo`，新增可选 `presentation`：
`{version:1,sender:{id,role,displayName},format:'text'|'markdown'}`。角色和格式由原生
消息 owner 在授权后的 claim 事务投影，ChannelSync 原样传到 transport，不新增平行消息库。
Join 根据 `join_wecom_assistant_replies` 的真实行识别助理输出；人类即使叫“某人的助理”
仍是 human/text，系统通知是 system/text。展示角色绝不替代发送者、成员关系、代办权限校验。

Relay 仅接收已认证 Gateway 的展示投影；完整 origin 的 ID/名称始终由认证 server 覆盖，
不使用请求体的 origin/serverId/serverName。普通、助理、富文本 @、图片说明共用一份署名：
可信服务器名称优先，否则只展示短 Hub ID，完整 ID 不变。Markdown 只决定编码，不决定身份。
`format` 为 Markdown 的消息，在可用回复锚点且开启流式能力时优先 stream，明确拒绝后
改用普通 Markdown；未知结果不换通道重发。真实 @ 仍走 rich_text，偏移按原始正文计算。

旧 Gateway 没有 presentation 时，兼容层只认原生 owner 分配的 `wecom-assistant:` 加 64位
哈希的消息 ID；不按名称、正文或 replyTo 猜类型。其他旧消息保留 text，角色记为 unknown。
声明了 v1 却缺失/矛盾的字段会拒绝，不退回名称推断。新旧 Gateway/Relay 可按先 Relay、后
Gateway 的顺序更新；没有数据库 schema 或历史消息重写。

普通 Markdown 每条 4096 UTF-8 字节，包含重复署名。复用固定版本 marked 保留完整区块，
纯文本长段落按 Unicode 码点拆分；不可安全拆分的区块和跨段引用整体作为 `聊天消息.md`
附件保留，不截断内容。部分发送后的失败不得当作整条可重试。

详细模型与兼容边界见 docs/internal-distribution/wecom-outbound-presentation.md。
