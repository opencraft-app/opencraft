# Proj Overview

Join Application 中的 LightVela 项目视图，遵循用户提供的 v6 布局。它汇总真实 Tasks 与可访问会话，不拥有执行、审批或任务写入权。

## 来源和口径

- `catalog.ts`：三个目标与建设方向由用户提供的《LightVela必赢之战Review(3)》整理；147 项现有看板标题经主题梳理形成固定 ID 归类。分类是展示整理，不是业务已批准的目标关系。新 ID 进入待归类，不做运行时关键词猜测。没有对应事项的规划方向仍可见，不伪造卡片。
- 产品数据为 2026/10/27 汇报快照：现有用户 61,463、人工日活 7,908（截至 10/26）、D7 7.7%（09/27—10/19 首现队列）。国内/国际并列，不作跨站去重、不补造趋势。用户侧 Token 尚无该附件数据，展示缺失。工作筛选不改变历史产品指标。
- 事项读 `opencraft/tasks/list`；不包括归档、回收站。真实身份下的会话 `thread/read` 状态有执行优先级；明确 wait flag 或完整 Tasks 生命周期中的有效交接表示等待。没有关联会话为未跟进。idle、failed、unknown 与完成/取消单列，不能误标成运行或等待。
- 等待只取完整可读当前生命周期的结构化交接和业务状态变化，截取所选周期；普通更新不重置起点。无负责人不计时，未知不是 0；历史等待按事项汇总，本版不把历史时长重新归责现负责人。未记录原生 wait flag 的开始时间时只显示状态，时长未知。
- 待办读取关联会话最近三轮、每轮最多 50 条记录中的最新可解析计划复选清单（摘要接口不含计划，因此使用有限条目分页）。不从阶段、描述、验收标准或自由文字估算待办完成。没有全量可读计划时显示已完成事项数/事项数，不能冒称待办进度；有计划时按事项均值汇总并显示覆盖率。只读复选框不改变原会话待办。
- Token 来自已授权 `opencraft/token-usage/query` 团队账本，按北京时间自然日、近 7/30 天查询，分页须同一 revision；不降级个人用量伪装团队。完整读取前不发布总额。按当前全量关联事项数均摊，再做筛选及目标汇总，取消事项不纳入汇总。未采集、拒绝或缺失保持未知；不补造 0。
- 参与人由既有 Tencent OA accepted-message 投影提供；我的视角包含本人负责或参与的事项。负责人用目录 ID 精确匹配当前身份 handle，不从名字猜。投入栏显示负责人去重数和 Token；缺少完整活跃日不计算人·天。
- 四请求并发上限；原生会话只读元数据和有限最近轮次，不全量水合会话。界面关闭、账号/Host 代次变化时取消旧读取。数据仅保存在当前账号作用域视图内，后台刷新保留可用列表，刷新失败通过宿主 notice；冷加载用骨架。统计周期切换重新读取相应数据，不挪用旧 Token。

## 交互与视觉

沿用原型的产品指标、目标→方向→事项树、第二列进度状态和右侧详情。树与抽屉采用同一投影。详情只读待办、判断项与原会话入口，Description/验收标准可展开，保留既有上下文。原生 `openConversation` 负责导航，不创建新模拟会话或直接拼接地址。基础按钮、字体、主题和 Radix Dialog 行为复用现有 owner；目录控制栏适配实际容器宽度。

## 验证

`npm exec -- tsc --noEmit -p tsconfig.json`（products/join）、`npm exec -- tsx --test tests/proj-overview.test.ts`。浏览器：`node --import tsx products/join/scripts/smoke-proj-overview.ts`（装配源码根目录）；真实 Workbench Shell + 合成服务边界，桌面/触控与明暗，验证入口、状态列、待办、抽屉、跳转、筛选和横向溢出。真实登录与生产会话状态以部署后核验为准。
