# Join 产品装配

本目录拥有本机已接通的企业身份插件、企业微信桥接和正式 Web/Gateway 装配。
核心拥有授权、会话、IM 时间线和 Gateway 生命周期；产品只注入企业能力。

- `web.ts` / `vite.config.mjs`：在核心扩展之外加入企业身份 UI 和 locale。
- `identity.mjs`：复用当前 Hub 验证的企业身份及参与人元数据。
- `gateway.mjs`：通过核心 `startContainerGateway` 注入身份与可选企业微信 transport。
- `plugins/tencentoa/`：迁入的企业插件源码；依赖与核心 workspace 共用根 lockfile。
- `plugins/wecom/`：已部署的企业微信 transport，运行凭据由私有配置加载。

企业微信回调属于接入适配，不能建立第二套主体授权或 IM 消息真源。
不提交真实身份断言、员工数据、访问凭据、运行配置、数据库、构建输出或 node_modules。
安装、同步与发布语义见 [内部发行版](../../docs/internal-distribution/README.md)。

## 原生群关联企业微信群

创建关联群首先原子写入原生群和创建意图。Worker 在调用 Relay 前固定创建请求；
超时、重启和群主显式重试都复用同一个原生群 ID 和请求，不将重试当作新群。
Relay 首批接收最多 49 位受邀成员，这不是原生群的容量：其余已选成员保留为
待交付意图，关联成功后通过现有授权、幂等和回读确认的成员同步队列逐个加入。
创建期间发生的更名、加人和移人以固定请求为基线补偿，不覆盖外部新增成员。
未解析身份仍由受验证的 OA/RTX 目录链路补齐，不能用显示名称绑定身份。

群同步状态接口在尚未取得企微 source 时也返回排队、创建中或失败状态；复用
既有页面的状态及重试控件。只有原生群主能重试，重复请求不能重置活跃尝试或
覆盖更新的失败；成员仅能查看脱敏状态。原生群本身不因企微暂时不可用而消失。

### 已有企业微信群接入

Join 的完整消息桥接目标会对当前有效的普通群关联初始化双向群名/成员同步，
与从 OpenCraft 发起的建群保持一致；首次按企微名单导入已验证成员。
启动时也补齐原先未配置或仅检查的群，无需重新拉入客服号。私聊、断开的关联、
已显式暂停或另行配置的群不被自动改写。初始化必须经过当前 Relay 授权回读、
source epoch、原生群主身份及企微在群状态检查；目录关联不授予登录准入。

初始化会从原生成功写入的幂等凭证恢复仅观察期间的本地更名、加人和移人，
仍通过原有同步队列交付并回读确认。不能将首次仅有群主的原生名单当作移人命令，
也不全量覆盖外部名单。消息接入与群成员/群名同步统一走已有授权 owner。
