# 按能力分开的验收场景

继承[脚本规则](../AGENTS.md)。本目录只拥有验收步骤、断言和证据；产品状态通过本地协议交给原owner，不直接写业务库或调用服务。

- memory.mjs：显式更正/遗忘、自动学习原用户锚点；不把保存成功当语义准确。
- work.mjs：资料、提问/重启、修订/取消、结果回主助理与运行观察。
- automations.mjs：有限安排、明确秒数的自然语言配置、本地事件去重与结果通知；不冒充远程事件或日历理解。
- skills.mjs：安装/启用的操作者步骤、实际加载固定版本和来源依据；显式技能请求不等于自主选择能力。
- context.mjs：临时runner生命周期、带场景前缀的请求ID、等待/采证/关闭；业务状态不存于这里。
- catalog.mjs：有限场景目录与选择校验。失败后停止后续场景并标记not_run；可单选场景在全新profile独立复现。

personal-scenario.mjs只编排。passed指自动断言，quality始终unverified并保留人工核对项；fixture与真实模型模式分开。无人关注长周期、敏感介入、语义通知等未运行覆盖须显式列出，不能用这四个场景宣称全能力验收完成。

新增场景须能通过公开协议独立运行，并清楚记录原输入、检查与限制；只在出现实际需要时增加共用helper。验证：test/module-boundaries.test.mjs及demo:personal；真实请求需显式授权模型连接。
