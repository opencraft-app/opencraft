# 虚拟管家三轮复测：通过率不能替代稳定性

后续新增字段诊断与同配置复测见 [协议失败定位](BUTLER-PROTOCOL-DIAGNOSIS-20261110.md)；本文保留当时证据与结论。

同一套六个场景连续三轮，共 18 次，**14 次自动检查通过、4 次失败（77.8%）**。三轮分别为 4/6、5/6、5/6；全部运行，无整题截止或硬超时，但有一次内部模型请求触发 60 秒超时后恢复。此前单轮 6/6 的结果保留，不再以它证明系统稳定。

这是同六题的重复观测，不是 18 道独立新题，也不是通用管家可靠性估计。实际测试范围和输入见 [协议](BUTLER-SUITE.md)，此前结果见 [首轮](BUTLER-RESULTS-20261110.md)。

四次整题失败均为 `Codex structured output failed after one protocol correction`：

- 第1、2轮的并行题：第一项工作已正确进入等待；创建第二项独立工作时接待命令未通过结构化协议校验，因此第二项没有创建。
- 第1轮 Goal 题：初始创建目标提议未通过协议校验。
- 第3轮记忆题：第一条“记住我在上海”就未能通过接待协议校验，没有推进到更正/遗忘。不能将这次失败归为 Markdown 存储、检索或忘记能力本身失败。

前两次并行题没有进入后续并行执行阶段，因此不能据此判定 Work 并发调度失败。四次均显式报告输入未处理成功，没有用成功文案掩盖未提交动作。

## 通过场景里的内部失败

只看最终 14/18 会低估不稳定程度。持久事件和 OTel 日志还显示：

- 总共 **15 条 `codex.schema_rejected`**，分布在 9 个场景。它们是协议解码尝试被拒，不是 15 个独立业务失败；包含上述四次整题失败和被纠正恢复的尝试。
- 第2、3轮 Goal 的验收决策各出现一次 `Every criterion needs an explicit evidence assessment`。宿主拒绝不完整验收证据，后续生产重试成功。
- 第3轮 Goal 的前置报告复核还先遇到结构化失败，再遇到一次 **60 秒模型超时**，随后才接受结果、释放后续工作。整题用时 **225.7 秒**，接近固定 240 秒截止。第2轮为 123.9 秒；初次单轮约76秒。
- 14 个最终通过的场景中，6 个观察到上述协议/验收/截止问题后恢复；这不是“14 个一次成功”。各层记录会指向同一次失败，不能将这些数字相加作为失败总数。

因此当前结论是：**核心持久状态和防误操作约束在已走到的路径上成立，但自然语言到合法命令的稳定性不足，部分成功依赖重试且存在长尾。暂不支持放心无人值守的结论。**

## 根因能确认到哪里

`CodexStructuredHarness` 在 [structured-harness.mjs](../src/adapters/codex/structured-harness.mjs) 中捕获 `decodeOutput` 的所有异常，只记录角色和 attempt；纠正输入也是通用的“JSON 或 schema 不符合”提示。最终失败后删除临时原生目录。当前证据只能确认解码/契约拒绝，**不能区分 JSON 语法、缺失字段、跨分支字段、错误枚举，或提供方的约束生成兼容问题**，也不能直接归咎于 Codex 或模型智力。

本轮未修改生产逻辑或增加重试。建议后续先保留受控的校验错误码/字段路径和脱敏失败样本，再针对失败样本复现和精简协议。目标验收必须继续严格检查证据，不能为了提高通过率跳过校验。
