## 接入必须保留的语义

1. **LoCoMo 是两名人类的对话。** 当前 `assistant-session.mjs` 只区分 user/assistant，且学习主要接受用户证据。将 speaker B 标成 assistant 会丢失事实或误判来源；将两人都当成当前 owner 也会污染个人画像。需明确“读取旁观对话”的资料输入路径，保留 speaker 与原始消息引用，再做文本投影。`qa/evidence/event_summary` 不给被测助理，图像未释放不能假装测了视觉。
2. **公开长上下文不是未来信息通行证。** 按上游规定给到查询时间的历史；画像标签、答案、题型、证据定位留在判卷进程。LongMemEval 的原始未来会话按原协议报告；另设因果严格组，不能悄悄过滤后仍报同一基准成绩。
3. **更正与遗忘分开。** 更新当前偏好不等于删除原文；活跃事实删除、防止再次学习、回答中不披露、物理擦除是四种不同契约。目前保留原历史/摘要，最后一项未实现。自然语言“忘记”应明确产品承诺后评分，不能只见墓碑就算全通过。
4. **问答和行动用各自真实入口。** 静态 QA 继续复用原 History/MemoryLearning/Context/Reception；委托走 LocalRunner 与真实执行链。BFCL 外部工具尚无受控动态注册桥接，不能在评测器里代替助理完成工具操作，再宣称产品端到端成功。
5. **先记一次、多问几题需要隔离。** LoCoMo/PersonaMem/MAB 可按同一历史准备后复用，节省成本；每个独立问题从同一完整快照恢复，或证明查询不会反写。快照包括记忆文件、SQLite、摘要与相关引擎状态。正式多轮任务则按协议保留状态，不重置。不能并发共享可写 profile/原生线程。

## 用 OTel 回答“为什么慢”

当前已有 `evaluation.replay`、`memory.prepare`、`context.prepare`、`gen_ai.operation`、`codex.startup`、`codex.version_check`、`codex.rpc`、`codex.turn`，以及 `.started/.finished` 日志。[本地遥测说明](../docs/local-telemetry.md)

下一轮性能报告以 case 元数据关联其独立 profile 的 traces，拆出准备阶段、模型等待、原生启动和最终问答；冷启动与同一运行中的后续调用分组。跨度父子会重叠，不能把全部 duration 相加当成墙钟；远端排队/网络/推理暂不能细拆。强杀留下的 started/未结束 span 标为不完整，不能推断为零耗时。

当前只有本地 trace/log，已有单 run 聚合器，**尚无统一跨 suite 聚合器或 OTel metrics**。先用固定小样本取得时间分解，再决定是否做进程池/学习合并。评测串行逐轮学习与产品默认后台合并要分别测；改变回放协议需要新 track，不能用缩减学习量的成绩替换旧协议。

## 第一批推进顺序

1. **P0 接线与可靠性**：保持现有离线测试；补全 Codex 主助理委托、自然语言更正/遗忘和范围隔离的小型真模型验收。测试用合成资料、私有 profile、当地模拟工具，验证持久收据而非仅看回答。未通过项保留为未通过。
2. **P0 长历史与性能**：扩展 S 的配对选题/判卷；在排除旧 70 题及早期 pilot 的集合中按七层固定选 **14 题（每层 2 题）**作为接线和成本 pilot。同一批题采 OTel、索引/问答与有效答案率；不因耗时或答错换题。
3. **P1 泛化**：通过 pilot 后扩展 S；新增 LoCoMo 文本、PersonaMem v1 32k、MAB 的 AR/CR。分别按会话/用户/历史固定样本，先少量整段输入，不按答案挑短历史。v2 文本/模态协议核对后再加入。
4. **P2 行动与压力**：将 MemoryArena 作为经验驱动行动目标；BFCL 作工具诊断，τ 文本域作协商/规则执行，AgentDojo 作配对攻击实验；M 作规模压力。需要各自的环境桥接，当前不承诺可直接运行。
5. **P3 网页经验**：具备轨迹、图片和受控资料入口后，再接 LongMemEval-V2；不能把图像丢弃后报官方多模态分数。
