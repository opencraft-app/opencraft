# 记忆契约修正与固定样本复测

2026-11-09。按用户要求统一提炼/复核标准、精简模型输入、补齐检索契约后复测。实现边界见[模型与查询契约](../docs/memory-model-contract.md)。本轮仍在独立实验目录，未部署 Join，没有数据库迁移。

## 实现

- 提炼和复核共用“有用户证据且对未来交互有用”的标准，区分 profile 与有时效的 log；不再将永久性作为所有日志的必要条件。任务中的用户明确自述可学习，资料正文和助手文字不能独立证明个人事实。
- 将完整宿主快照与模型载荷分开，模型仅见一种事实表示、带用户可引用 ID 的成对对话和最小 scope/项目/共享背景。宿主 CAS、权限、来源、显式保护和墓碑保留。
- memory.search 默认旧连续短语模式，新增显式 terms 全部词匹配；搜索结果带文档读取参数及事实内部的匹配 offset。授权文件目录支持稳定 cursor，文件读取沿原分页与权限检查。目录只列索引中有事实的文档，空文件可能不列出。
- 主聊和组件 reader 共用查询说明及限制；新工作捕获文件目录工具，旧 Delegation 不自动扩权。没有增加 Shell、向量库或新记忆 owner。

仍保留原独立布尔复核、整批提交、三次尝试、原90秒尝试截止和12轮合并。本轮未实现逐项复核，也不按这六题的 gold 定向提炼。

## 冻结与比较范围

reader 保持 DeepSeek Flash 1017，后台保持 hy4 / reasoningEffort=none，Harness 保持原 Codex 二进制。PersonaMem 仍为同一已知历史、同一六题、同一因果前缀、原官方严格选项评分；更正场景解析后的冻结输入复用上一轮。新建隔离 profile，旧结果不覆盖，没有为分数重跑失败题。

## 剩余问题：从未写入转向读侧选择与使用

公开历史的40条当前事实，在原初始注入预算下仅有8条profile+9条recent进入上下文，truncated=true，另23条未注入。图像小说的“开始喜欢”和“后来停读”两段现在均已存在于log，但初始上下文只含较新的停读信息；更中间的83源索引暂停阶段仍在72拒绝批次中。

本轮六道记忆题的reader均直接答题，**没有执行一次 memory.search、memory.files.list 或 memory.file.read**。因此工具接线和权限在真实原生loopback及存储回归中已验证，却没有证明真模型在长历史裁剪时会主动补查。当前不以开放原文或无限扩大初始注入掩盖该问题。

这不是将历史log简单判为相互矛盾：不同时间的状态可以都真实，但目前没有强制把阶段关系/转变理由组成可追溯链，读取方需要主动查看缺失部分。下一步应单独验收裁剪情况下的检索决策、按事实与来源追读以及演变重建；仍保留重要事实写入准确性与整批否决的检查。
