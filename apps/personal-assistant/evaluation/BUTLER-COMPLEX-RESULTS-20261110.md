## 新增验收的价值

- 多父依赖必须全部就绪，不能一个父任务完成就启动汇合；汇合后的摘要也必须用真实日期和人数。
- 急事完成时旧目标仍保持暂停；修改任务不能隐式恢复所属目标；恢复后使用新要求。
- 连续改版只保留最终有效契约和交付，迟到回答及过期修改均被拒绝，旧快照不重写。
- 菱形依赖两条分支都失效；单独重做一条不能放行最终工作，最终边也需显式采用新版本。
- 已验收目标必须明确重开才能续办；旧结果仍保留但不能验收新执行，兄弟工作不重跑。

产物判卷新增绑定：只从当前有效 Execution 的公开发布回执定位文件并核验 SHA256；历史文件里碰巧有正确关键词不能过。日期等使用用户明确要求的唯一字段行，允许正文说明旧值作废；不是通用语义评分，也不更改旧题规则。用例与边界见 [协议](BUTLER-SUITE.md) 和 [实现](butler-complex-cases.mjs)。

## 实际暴露的三个问题

### 1. 两项独立工作被合并成一个 Work

用户明确说“创建两项独立工作，不需要长期目标”，分别给出 TRAINING-ALPHA 和 TRAINING-BETA。主助理却返回 `delegate`，在一个 goal/completion 中塞入两套要求，只创建一个 Work。不是字段解析失败、没有配额，也不是目标调度问题；这是规划阶段的工作粒度错误。后续不能按原设计分别回答、追加要求和取消，因此第一项断言就停止了本题。

不能为继续跑完而由评测器替它拆成两项，也不能说本轮已测出“答案串线”；交错回答步骤根本未到达。[原输入、决策与最终状态](runs/butler-complex-20261110-v1/crossed-answers.json)。

[接待提示词](../src/adapters/models/reception-model.mjs)同时规定“单个有界工作的步骤用一个 delegate”和“明确独立请求使用 batch”；[原生路由](../src/adapters/codex/structured-harness.mjs)也有类似边界。本轮选择说明两者区分仍不稳定，但没有消融实验，不能断言某一句提示就是唯一原因。下一修复应针对独立工作粒度的路由与契约，而非增加 JSON 重试或无限延长超时。

### 2. 已恢复执行，产物仍说“保持暂停”

interrupt-replan 的自动生命周期检查通过：旧目标暂停、急事完成、改版未解除暂停、显式恢复成功。可 WEEKEND 笔记仍写“所属目标（周末读书会）继续保持暂停，稍后再恢复执行”。这与产生该笔记时已经恢复的事实矛盾。

只读检查该执行快照：`request.latest` 仍为更早的“改日期并继续保持暂停”输入，快照没有显式当前 Goal 状态投影；后来的 goal.resume 已结算。证据支持“历史要求与当前生命周期事实没有清楚区分”的诊断，不能据此宣称执行调度失效。应保留历史请求不变，同时让执行/报告复核读取当前权威状态，避免把历史控制语句写成现状。[诊断与原文](runs/butler-complex-20261110-v1/failure-analysis.json)。

这是人工复核发现的语义问题，未纳入本轮预先固定断言；自动 passed 保留，不改报整题语义通过。

### 3. 未确认的假设变成了确定表述

natural-plan-join 的日期与人数正确，但 runbook 把“活动形式：线下读书会”写成确定信息。用户只确认了日期和人数，上游也明确线上/线下尚未确定。模型可以给建议方案，但应标出假设，而不是默认为已确认事实。本地没有发生任何外部订场操作，问题在产物事实表述。

另有呈现问题：第三题中文请求得到英文笔记，多处产物携带内部 ID/临时路径/哈希。没有把这些追加为自动失败，但不能因为状态断言通过就称交付体验已成熟。逐题有限复核见 [artifact-review](runs/butler-complex-20261110-v1/artifact-review.json)。

## 结论与下一步

复杂组合下，多版本、依赖、暂停恢复和重新验收的协调机制继续通过；主助理的任务拆分和状态/假设表述仍有明确缺口。modelQualityScore 仍为 null，5/6 仅表示预声明自动检查结果。

优先修复“独立工作被合并”，以及“当前生命周期事实与旧请求分离”的上下文契约，再用新 run 重测这两题及未到达的交错回答流程。后续增加受控外部工具的部分成功/超时、跨天恢复与自然语言优先级冲突；当前题库没有验证这些能力。
