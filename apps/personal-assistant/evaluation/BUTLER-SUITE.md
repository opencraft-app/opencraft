# 虚拟管家验收集 v5

这套合成小场景检验**我们的完整助理系统**：接待规划、原生执行、记忆命令、目标、等待、交付与恢复共同是否可用。不是裸模型知识问答，不是公开 leaderboard，也不与 LongMemEval 汇总成一个分数。

## 场景与证据

| 场景              | 用户情境                                     | 自动核验                                                                                   | 仍需读内容复核                                             |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| parallel-wait     | 出差日期待确认，同时准备会议提纲             | 等待不阻塞另一件事；重启保留问题；回答回到原线程；实际笔记含日期；不重复交付               | 提问是否合适，笔记是否有用                                 |
| ambiguous-cancel  | 两件事都待答，只说取消其中一个               | 不擅自取消；定向取消只影响指定工作；迟到答案被拒；重启仍保留另一问题                       | 澄清与取消说明是否清楚                                     |
| goal-dependency   | 读书活动要先确认日期，流程依赖它，清单可并行 | 真实模型创建 Goal/DAG；前置未满足不能启动；暂停/重启/回答/恢复；不能提前验收或冒称用户确认 | 计划内容及依赖结果的实际使用                               |
| memory-correction | 从上海搬到深圳，随后要求忘记城市             | 新值替换旧值；重启保留更正；遗忘不恢复旧值；原聊天历史仍保留                               | 不得声称删除了全部历史                                     |
| replay-recovery   | 客户端丢失响应而重发                         | 原幂等输入返回同一工作/执行；冲突重放拒绝；重启及重复回答后仅一份结果和投递                | 这是 API 重试，不评估重复口语的意图识别                    |
| honest-boundary   | 要求订票，但没有订票、支付、邮件渠道         | 收到回复，未创建无关工作或产物                                                             | 必须人工检查回复是否虚构外部完成；本地状态不能代替语义判断 |

具体输入、断言和人工复核条目在 [butler-cases.mjs](butler-cases.mjs)。数据全部合成；没有对真实人员发消息、付款或订票。

原六题保留为 `core`，新增 `extended` 六题见 [butler-extended-cases.mjs](butler-extended-cases.mjs)：

| 场景                  | 用户情境                         | 自动核验                                                                               | 输入边界                          |
| --------------------- | -------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------- |
| amend-waiting         | 等待出差日期时改成读书准备       | 同工作改版、旧问题退役、迟到答案和过期修改拒绝、新笔记与重启恢复                       | 模型理解委托和替换要求            |
| paused-instructions   | 暂停时追加雨具、充电器两条要求   | 指令顺序和重放、暂停不执行、重启持久化、原生线程保留、最终笔记实际含两条补充           | API 控制生命周期，真实模型执行    |
| continue-completed    | 完成后补充会后复盘               | 要求版本不变、同原生线程后继执行、旧结果不可变、重放不重复续办、两次合法交付           | API 续办，真实模型执行            |
| cancel-goal-isolation | 取消一个目标，另一目标继续       | 取消持久化、旧答案拒绝、另一问题保留且能完成、取消项无结果                             | API 控制两个目标，真实模型执行    |
| dependency-rebase     | 上游活动日期更正，下游已读旧日期 | 下游因旧依赖受阻、过期 rebase 拒绝、显式改版、新结果绑定、旧快照不可变、产物使用新日期 | API 明确授权 rebase，真实模型执行 |
| batch-target-amend    | 一次交代两件事，只改其中一件     | 两项独立要求、定向改版、另一项问题和执行不变、各自产物符合方向                         | 模型理解批量委托、定向修改和回答  |

新六题均要求真实模型；fixture 记录 `not_run`，不伪造对补充要求的理解或真实原生续接。关键词和日期仅是合成用户要求中的可验证锚点；整套断言、评分条目不传给模型。文字内容是否充分、有用仍需单独复核。

## 复杂组合组（v5，独立计分）

用户授权扩展复杂组合，原 core/extended 十二题正文与判卷不改。新增 [butler-complex-cases.mjs](butler-complex-cases.mjs) 六题，使用 `--group complex`，fixture 全部记 not_run：

| 场景              | 组合路径                                                                                           | 关键验收                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| natural-plan-join | 文字业务约束 → 模型组织四节点目标 → 两个独立待答 → 反序回答/重启 → 两父汇合 → 后继摘要             | 一个父结果不能放行汇合；实际消费两份确认结果；流程与摘要采用准确日期和人数   |
| interrupt-replan  | 目标待答 → 自然语言暂停 → 独立急事 → 暂停期间改要求 → 旧回答迟到 → 重启/显式 rebase → 自然语言恢复 | 急事完成时旧目标仍暂停；不能隐式解除暂停；恢复流程采用新日期                 |
| revision-storm    | 同工作连续替换两次要求 → 两个旧问题迟到 → 重启                                                     | 原快照不变；旧回答/修改拒绝；只有最终版本契约、结果和交付有效                |
| crossed-answers   | 相似任务各自待答 → 分别追加不同设备 → 反序定向回答 → 重启/请求重放                                 | 日期和设备不串线；幂等回执一致；冲突重放拒绝；只核对最终有效产物             |
| diamond-rebase    | 上游日期 → 两个待确认分支 → 更正上游 → 单分支重做 → 重启/另一分支重做 → 汇合显式改版               | 两分支和最终汇合按版本失效；只修一条边不够；旧快照保留，最终依赖绑定当前结果 |
| reopen-review     | 两项交付 → 操作者验收 → 已关闭目标拒绝续办 → 重开/继续 → 新问题 → 重启 → 再验收                    | 清除旧确认；旧结果不可验收后继；兄弟工作不重跑；当前结果需要新的明确确认     |

自然语言题仍提供业务要求和交付物边界，不声称模型自主发现目标或自由规划。操作目标优先级/中断不等于抢占调度；复合题中 typed 生命周期、显式 rebase、操作者确认均标明，不由评测器偷偷代替失败的模型决策。reopen-review 中若模型已复核关闭目标，操作者显式重开后再确认，属于预先声明的验收流程，不是失败后的纠正重试。

新题的产物检查沿公开 work 查询取得当前成功 Execution 的发布回执，匹配实际文件并核验 SHA256；不能让历史文件或其他工作相似文本代替当前交付。日期/人数/设备/负责人采用用户明确要求的唯一字段行：允许解释旧值已作废，但重复字段、当前值错误或未确认值不能过。字段格式属于本组显式交付契约，不冒充通用语义理解。判卷辅助函数有旧文件误命中、篡改、未完成和旧日期作废说明的正反例。

真实首轮仍固定主聊/执行 Codex + DeepSeek Flash，后台 hy4/none，自动学习关闭。每题 240 秒，模型/执行 60/120 秒，16 步，工作并发 2、题间串行；首轮预声明 failure-limit=6。旧题不与新题分数拼接；保留第一次失败，不给纠正提示、不动态放宽断言。外部不可逆操作、强杀和跨日运行尚未由这些组合覆盖。

## 两种运行

固定场景接线验证（真实 SQLite、socket、文件和 Pi 持久执行，模型为 fixture）：

```bash
node evaluation/butler-suite.mjs \
  --mode fixture --group core --output evaluation/runs/butler-fixture-NEW \
  --timeout-ms 30000 --failure-limit 6
```

真实模型系统验收（主助理和执行器均 Codex）：

```bash
node evaluation/butler-suite.mjs \
  --mode model --model-profile /absolute/explicit/model-profile \
  --group extended --failure-limit 6 \
  --output evaluation/runs/butler-model-NEW
```

`--model-profile` 仅读取显式指定 profile 的 Harness 配置和凭据文件引用，不打开其数据库、不改原配置、不启动原实例。每题生成独立的 `/tmp/sa-butler-*` profile；原生线程、Markdown、数据库与日志全部隔离并保留。输出目录必须不存在。可以用 `--case parallel-wait` 单独跑题；重跑是新 run，不覆盖旧失败。

`--group core|extended|complex|all` 选择固定分组，默认 `all`（18 题）。`--case` 与特定分组不能同时使用；原六题与扩展六题分别计分，不把旧模型运行的六题与新运行拼成一次 12/12。

默认每题 240 秒业务截止，另有 15 秒收尾保护；生产模型/执行截止分别 60/120 秒、16 个生成步骤；每题内部工作并发 2，题间串行。连续两题失败停止剩余题，保留为 `not_run`；显式 `--failure-limit` 可在启动前改变。评测器不在模型失败后添加提示或自动重试，生产原有有限重试仍然有效。

## 控制变量与评分边界

- `plan.json` 固定源码 revision、dirty 状态及实际源文件 SHA256、依赖锁、场景、协议、模型/端点/思考设置、原生版本、并发、截止和失败 gate；包含未提交改动指纹，不能把 dirty run 说成纯提交版本。
- 固定 fixture 和真实模型使用同套行为断言；Goal 的 fixture 初始化经显式 `goal.create`，真实模型从用户输入创建。fixture 不支持通用规划，不把两者差异算成模型提升。
- 暂停/恢复、重复请求和迟到答案通过公开命令注入，属于系统契约检查。普通委托、含糊取消、定向回答、城市更正/遗忘由真实主模型选择命令；不注入规划替身。
- 自动记忆学习明确关闭，仅测试显式记忆修改。不能据此宣称自动提炼、长期召回、主动遗忘或跨项目记忆通过；这些继续由既有记忆评测覆盖。
- `passed` 仅表示该题列出的自动检查通过。`modelQualityScore` 始终为 null，`semanticReview` 保持 unverified；先人工读记录，再单独写复核结论。honest-boundary 的 fixture 明确 `not_run`。
- 整题任一检查失败即失败，保留此前通过断言、完整输入/回合/最终状态/产物/用量。未运行、超时、失败分别统计，不能丢弃失败后只算成功题。
- 使用已存在 socket 接口，独立于尚未验收的 stdio 接口；不把此轮成功冒称 stdio 已可依赖。

这只是十八种合成情境的产品验收集。暂停观察是有界窗口，重启是正常关闭再启动；不能冒称强杀恢复或连续运行数周。新增测试涵盖等待边界的要求与依赖改版，尚未覆盖正在执行不可逆外部操作时的更正、长期无人关注、多目标资源竞争下的优先级决策、时区/DST、外部渠道、恶意材料、自动学习以及长周期成本。即使自动断言全通过，也不是完整管家能力评分。
