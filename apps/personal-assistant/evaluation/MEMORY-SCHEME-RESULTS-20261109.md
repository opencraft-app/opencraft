# Grokbot 派生记忆方案：组件实测

评测对象是我们的记忆方案，固定 `deepseek-v4.1-flash-1017` + Codex 0.162.1 和同一个 reader。结果不能解释为模型榜单，亦不是官方 Grokbot 产品对比。规则见[协议](MEMORY-SCHEME.md)，原来源见[非官方源码对齐](../docs/grok-memory-parity.md)。

本轮两组运行后均已退出。没有修改生产记忆算法、提示词、数据库结构或 Join 部署；新增的是隔离评测入口、对照、诊断和文档。

## 结论

短的受控场景证明记忆链路能实际写入、区分用户与助手、用更正后的事实及其理由回答；长历史下仍存在明显的提炼/复核重试成本和未成功学习的批次。当前不能宣称公开长历史准确率或性价比已达标。

## 随机事实与更正：真实记忆发挥作用

全新随机地点标识、随机偏好位置与时间组合在调用前固定，8 条原始消息、4 个用户 exchange、6 个问题。历史中另有一条助手虚构的不同地点；它不构成用户证据。前两题只看更正前的前缀，之后四题只看更正后的前缀，题目和回答不回写学习任务。

| 路径                      | 正确/计划 | 有效回答 | 范围                                                    |
| ------------------------- | --------- | -------- | ------------------------------------------------------- |
| 原记忆提炼/复核/文件/读取 | **6/6**   | 6/6      | 两项原始事实、用户/助手归属、更正后的两值、两个更正理由 |
| 完整历史，同 reader       | **6/6**   | 6/6      | 同一因果前缀                                            |
| 无历史，同 reader         | **1/6**   | 5/6      | 4 个返回答案计错，1 次未通过 reader 答案/能力契约       |

无历史另有一条回答明确表示不知道，按既定选项评分计错；上述数字衡量获得正确个人信息的能力，不能将不知情的拒答描述成记忆系统故障。

原生学习两批均首次提交，2 个源任务 committed、2 个合并任务 merged；更正后剩 2 条活跃事实。所有已提交来源 ID 都能对应 canonical 用户消息。准备约 **12.96 秒**，不包含虚拟推进的静默等待；不是手机或服务的实时可见延迟。

| 实测已知 token               |       数量 |
| ---------------------------- | ---------: |
| 记忆学习一次性开销，4 个调用 |      9,095 |
| 记忆路径的 6 次问答          |     57,582 |
| 记忆路径合计                 | **66,677** |
| 完整历史 6 次问答            | **53,230** |

这段历史很短，记忆路径已知 token 比完整历史约多 **25.3%**，尚未取得压缩收益。模型、schema 和事实元数据均有开销；不能因命中率高就假定便宜。这里没有未知 token 调用，但仍无实际账单/单价。整个三路探针约 79 秒；不同路的调用分别计费，准备不重复摊到每题。

这是一个独立历史的因果接线探针，不能把 6 道相关题当作总体 100% 质量。没有测试遗忘、语义防复活、所有历史擦除、多 human 授权或更正后回溯完整旧偏好轨迹。

## 接下来优先处理的记忆问题

1. **引用约束**：减少提议中无效 evidence/fact ID 导致的整批重试；继续保留原 owner 校验，不能放宽来源规则换取通过。
2. **复核与重试效率**：区分结构错误、语义否决、整体尝试截止和服务错误，核对可持久恢复的复核边界；不要把所有失败重走提炼或增加无界重试。
3. **批次收益与损失**：记录批次覆盖、未成功学习的来源和长期保真度，在独立未见历史上同时衡量成本及质量，再决定是否改默认批次/调度。
4. **再扩大公开样本**：先让既定工作负载可完成，之后增加独立 persona；短探针不替代长历史和遗忘验收。

本轮未为追求这 6 题得分调整记忆算法或生产提示词。

## 评测入口后续修正与验证

真实运行结束后，修正了评测自己的两个问题：对照与记忆各用独立 profile/进程/截止，防止慢学习吞掉对照时间；共享截止中断单列为 censored。reader 契约失败补充具体决策类型，准备完成时也单独记 checkpoint。三路的共同 reader 指令和生产记忆实现未改变。

当前新调度已通过离线验证，**没有重新付费跑上述公开样本**；两组实测都属于其原计划/冻结源码，不能称为当前修正版的完整真模型复验。
