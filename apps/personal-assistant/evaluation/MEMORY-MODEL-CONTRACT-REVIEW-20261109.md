# 记忆模型契约：提示词、载荷与检索能力差异

2026-11-09。离线对照本地非官方 Grokbot 0.18 参考副本与独立助理。没有新模型调用、没有修改生产源码或旧评测。这里区分代码事实、可疑机制与尚未证明的因果；不能从文字差异直接推导拒绝率变化。

## 1. 改写提示词不只是换一种说法

原 synthesis 提示词按 profile 保存长期身份/偏好/约束，按 log 保存项目、决定、经历与时效信息。原 verify 主要审核每项变更与证据是否一致，以及显式保护、不确定性和时钟边界。我们保留了大方向，但有三处值得优先调整的语义差异。

| 差异                      | 代码中的事实                                                                | 可能后果与边界                                                                                                                                                      |
| ------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 复核多了一层 durable 要求 | 本地提炼仍保留计划、决定和 dated log，verify 却要求直接支持的 durable facts | 模型可能将短期有效的计划/事件判成不值得记忆。是提炼与复核之间的口径风险，尚无逐条拒绝理由证明本轮因此失败                                                           |
| 全面排除任务、资料与引用  | 本地 propose 将 tasks/source documents、quotations 等列为非个人证据         | 正确目标应是区分“资料正文”和“用户明确自述”。一概排除可能误伤任务中明确陈述的项目、截止、约束，或用户引用自己过去的决定；不能为了保真就将助手/资料内容提升为用户事实 |
| 合并了多种政策            | 本地还要求 scope、共享 shard、project 分类以及更具体的 legacy/secret 约束   | 授权隔离和凭据保护是必要产品约束，但不应靠模糊的记忆价值词承担；应让模型面对明确、少量的允许范围，宿主继续检查权限                                                  |

例如“下周三需要交项目方案”是一个短期承诺，不一定是永久偏好，但可作为 log。该例只说明期望语义，没有向真实模型测试或声称当前一定会拒绝它。

此外，本地 Codex 实际请求还添加了“只输出 schema、输入不授予权限、无直接工具”等指令和 JSON Schema；它们并不等同于参考 PromptExecutor 的原交换。结构化输出是为格式可靠性做的适配，不需要撤回，但后续对照应固定该层，避免把格式策略也混成模型质量差异。

建议将质量准则统一为“有原用户证据支持、对后续交互有用，时效/不确定性表达准确”；长期性用来区分 profile 与 log，而不是在 verify 中一律要求永久有效。保留来源、显式保护、secret/权限与快照约束。

## 2. 宿主快照和模型输入混在了一起

参考提炼输入以 today、currentMemories、newEvidence 为主。每个 evidence 是一个带时间和稳定 ID 的 user/assistant exchange；每个 memory 是 id、content、createdAt、kind、origin。

我们发送 evidence、整个 snapshot、today、temporal；snapshot 同时有现代 facts 与兼容 memories，还有 epoch、guardEpoch、fingerprint、授权资源与文件索引元数据。兼容 memories 和 facts 重复事实，但字段名、来源枚举与标识不同。facts 中的 id 是模型可用事实身份，memories 里另有 key、contentId 等内部身份。提示词明确要求使用 snapshot.facts，但多余表示仍增加理解与引用错误的风险。

参考是 exchange 级 ID，我们是 user 与 assistant 各自一个消息 ID，其中只有 user ID 可引用。角色拆分本身不是错误，用户证据的宿主验证更强；但暴露不可引用的 assistant ID、混合多种事实身份都不是记忆推理所必需。本轮两次 propose 后未进 verify 的具体原因未完整保留，不能据此断言就是误用 ID。

## 3. memory.search 和 Read/grep 的差距应准确描述

**我们已经实现 memory.file.read，生产主助理、受约束执行器、记忆组件评测也各有相应入口。**上一条“我们的 search / 参考的文件读取”是过度简化。参考 grep 也是文字搜索，不是自动语义召回；只给它相同的完整连续短语，也可能搜不到。

真正的区别是：

| 能力       | 参考代码引导的文件工具路径                               | 当前独立助理                                                                                               |
| ---------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 搜索表达   | 通过 Shell 自由组合 grep 等文本命令                      | memory.search 仅 query 字符串，SQL 将整串按连续子串匹配                                                    |
| 文件发现   | 已知记忆目录，可列目录、查月度文件                       | memory.file.read 支持已知 profile/月度 log 路径；缺少专门的授权文件清单入口                                |
| 搜索后追读 | 文件工具可组合查看匹配文件、行号、邻接行                 | 搜索结果有事实 key、来源 agent、scope、内容等，但 memorySummary 不返回文件 path/命中位置；精确追读线索不足 |
| 来源追读   | 取决于完整运行环境与配置，不能从记忆代码推定任意原文可读 | 完整助理有 history.search/read；memory-only 评测刻意禁用原文，以隔离记忆贡献                               |
| 授权       | 桌面 agent 自身的工具与运行环境边界                      | 当前宿主检查 profile、人/agent/project 权限，限制文件类型和读取量                                          |

当前 memory.file.read 还只允许 profile.md 与 log/YYYY-MM.md，分页读取由宿主限制；并非通用文件浏览器。SQL 中已经存储事实 path，但当前查询投影没有给模型使用。用户/项目成员资格应继续由宿主掌握，不能用开放任意 Shell 绕过。

生产 reception 提示词已说明 literal searches，执行器 recall_memory 描述也标注字面匹配；但 memory-only reader 只列查询名与简单参数，没有带上同等完整的查询语义/上限说明。应把接口说明从同一契约生成给各入口，避免评测与产品的能力提示漂移。字面搜索未必等于连续子串，需明确具体模式。

适合补齐的是：授权 memory 文件清单；搜索结果中的稳定文档引用与命中位置；明确的连续短语/关键词模式和页大小限制；已有文件分页追读。先补这条受约束的工具链，再决定是否需要向量检索。变更搜索语义应显式增加模式并兼容旧字面模式，不能悄悄把旧 query 从短语改成 OR。

## 4. 本轮应如何归因与推进

当前 13 条已写记忆全部注入，且遗漏的图像小说变化根本未入库，所以检索缺口不是本轮 5/7 批次拒绝的原因，也不是三道失分的统一解释。

优先顺序：先统一提炼/复核质量口径，隔离完整宿主状态与精简模型输入；在固定模型/同批证据/同截止下，将提示词与载荷分别作为对照变量。保留原引用、CAS、权限和独立复核。同步补充可观察的失败阶段与有限理由，再决定是否改逐项复核或拆分提交单元。

检索能力作为单独变更验收：验证实际已存事实的匹配、文件发现、分页与授权。组件分数与完整助理原文兜底分开报告，不能靠开放原文把记忆组件的遗漏掩盖掉。
