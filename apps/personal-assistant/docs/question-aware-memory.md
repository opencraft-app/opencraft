# 问题驱动的最小召回修正

2026-11-09。仅修改读取链路，不改提炼、独立复核、事实/墓碑、文件权威或数据库schema。用户要求独立提交并与原实现配对复测。

原ReceptionQueries.seed不接收问题，只注入画像与近期日志；旧日志即使已保存也可能没进入输入，后续搜索又取决于模型主动选择。

当前普通用户上下文把当前原消息传入seed。原SELECT-only recall端口在相同授权view中按词面重合数挑选最多12条事实；查询最多6000字符、24个去重非功能词，以Intl.Segmenter处理Unicode词边界，同分按更新时间与key排序。没有embedding、语义理解、查询模型或第二份索引；词形变化、同义表达和隐含关联仍可能漏召回。

原prompt API与执行快照不改；接待输入将profile/recent/recall按key去重，保留来源/文档引用、项目成员元信息及“不完整”标记。摘要目录只提供元信息，事实正文只出现一次。原总字节限制仍有效，必要时裁剪并明确truncated。

显式memory.search继续默认literal或全词AND匹配。零命中只附缩词重试建议；是否重试由有界查询循环决定，不能把空结果静默换成另一种匹配语义。

配对评测在每个原始因果前缀上学习一次，两路读取相同已学习事实：reference直接加载基线提交的原Queries、ReadModel与readerInput；候选加载本次实现。共同reader、后台、题目、源材料、指令与读取预算固定，交替先后次序。问题与选项不进入学习；自动召回仅使用当前问题，不使用选项或gold。保存初始read-view，既比较答案，也核对相关事实是否进入输入。

这是一组读取改动的合并消融。已看过的17题/3人物只作回归，不能宣称盲测泛化、单项因果收益或腾讯两方案重新排名。

自动初始召回沿用原prompt选出的最多3个项目；其余已加入项目只在元信息列出，后续显式查询仍可按原grant读取。画像最多50条、近期最多30条，合并去重和裁剪均保留不完整标记。
