# 产品目标：可日常使用的本地个人工作助理

2026-11-02，用户要求「继续实现，脱离原型，但是目标是什么呢？」。本文件将已有方向收敛为可验收的首版目标，状态随真实证据更新。提出人身份未确认。

## 首版服务的人和工作

服务一个明确的本地用户，处理其指定资料和项目中的个人工作：整理信息、形成可追溯结果、持续跟进，以及保存本人明确要求记住的偏好。用户通过稳定入口交代、追问、更正和取消；后台运行与页面无关。

首版是无界面 CLI + 常驻 runner。同一内核后续可装配进 OpenCraft；当前独立数据适配不作为新增平台权威直接上线。

## 三条产品闭环

| 场景           | 用户交代的工作                                                  | 可用标准                                                                                            |
| -------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 资料整理与更正 | 整理指定项目的本周进展、依据和待跟进事项；过程中缩小范围        | 真正读取资料，结果有来源；更正进入同一事项；能查询、取消；结果回原入口                              |
| 信息不足时协作 | 先确认整理范围，再继续做                                        | 问题持久保存；等待时释放执行资源；重启后仍可回答；同一回答不重复推进，过期回答不能恢复新方向        |
| 按安排持续跟进 | 定时检查项目变化；明确何时通知、暂停和停止；偏好可显式保存/更正 | 安排和每次运行分开；关闭客户端仍能运行；结果/阻塞可查，暂停后不继续；记忆的真实回执和后续使用可验证 |

## 退出原型阶段的证据

1. 同一个已明确授权的真实模型连接跑通以上场景，不能用 fixture 替代语言理解和内容质量。
2. 用真实本地资料连续完成多轮工作，保留源文件、运行记录、产物和用户可见对话；结果能用于实际工作。
3. 崩溃、重启、重复输入、修改、取消、等待和投递失败均有可追溯恢复证据。已发生的动作与未知状态照实呈现。
4. 一个新 profile 按文档即可配置、启动、诊断和停止，不依赖原开发进程、隐藏工作区或共享凭据。
5. 领域对象、写入 owner、资源权限和原生执行归属保持清晰，并有迁移与回归证据。

这些是产品验收标准，不是新增人工审批或部署门槛。当前 Join 的交付规则不在本目录修改。

## 范围边界

首版保持单用户、单机、明确资料根和有限工具。多 Bot 社交/协调、任意桌面控制、完整工作台 UI、跨机同步及 Temporal 部署不作为前置。执行引擎仍优先 Pi，原生 checkpoint 和工具任务只由 Pi 持有。

0.10.0已收窄Pi/工具对应用对象的依赖，并将个人验收按工作、记忆、自动化、技能拆成可单选场景，详见[0015记录](iterations/0015-module-boundaries.md)。这些改动提高定位与独立验证能力，不代替真实服务质量、敏感认证、长期无人值守或实际业务连接验收。

0.11.0按用户要求先吸收持续安排和长期上下文能力，不以真实模型验收为开发前置。已实现的日历/once/条件盯办、项目/档案/近期召回与原文检索见[持续助理说明](long-running-assistant.md)；可直接用CLI验证配置，整体产品仍development，语义条件、分类和召回质量分别待验收。
