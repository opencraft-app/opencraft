# 第八轮：自动证据记忆

每次接待成功提交，在同一事务内将原用户消息和实际回复的ID/文本保存为memory_learning任务。后台独立提议、程序检查、第二次模型复核，再调用原MemoryService批量写入。主接待没有等待学习模型，不获得学习队列或记忆库写入权。

MemoryLearningService独占任务，MemoryService独占记忆值和memory_provenance；两者通过snapshot/epoch/apply窄接口协作。runtime的MemoryLearningCoordinator只有临时请求和取消信号。MemoryLearningModel仅接收序列化数据，生产路径进行两次独立模型调用；fixture只识别一个测试偏好，不能证明语义质量。

每项变更必须引用该任务原用户消息ID；助手文本不能作为事实依据。最多8项，key160字符、value2000字符。默认只允许创建或更新automatic来源记忆，用户显式记忆、所有旧来源不明记忆、遗忘墓碑不被自动改写。记录证据ID，原文保留在任务与原主历史。快照epoch变化丢弃整批旧提议，保留原证据并基于新快照有界重做，最多3轮尝试后仍冲突标为stale；提议/复核期间的新用户更正不会被覆盖。

提议先持久化，重启从复核继续；复核必须返回布尔true，字符串true不算通过。无变化无需复核。批量值、provenance、epoch和任务完成同事务提交；中途错误整批回滚。模型错误退避最多3次，保留原提议，不无限重试。大于128000 UTF-8字节的证据加快照标为skipped，不截断后冒充完整推断。

当前保守地不自动删除记忆；用户仍可显式forget。墓碑保护按key生效，不宣称能阻止模型在别的key下语义近似复述；真实模型事实提炼和独立复核质量仍需验收。没有借用模型凭据、调用外部服务或修改Join。

schema6→7新增memory_learning和memory_provenance，不重写旧记忆；旧条目视为explicit。memory-learning.test.mjs覆盖自动交互入口、引用校验、复核拒绝、显式/遗忘保护、自动更正、较新记忆冲突、提议重启恢复、批量故障回滚和持久重试上限。

自动更新推进全局epoch供学习CAS和未来快照使用；用户显式变更另推进屏障。新工作只因显式更正/遗忘阻止旧快照发布，避免自动提炼导致正常工作无端失败；旧快照沿原全局检查。
