# 第三轮：把个人工作闭环作为产品目标

日期：2026-11-02；提出人身份未确认。用户原话：「继续实现，脱离原型，但是目标是什么呢？」。本轮继续独立目录，不集成/部署 Join，不使用共享凭据。

目标见 [product.md](../product.md)：单个本地用户可日常使用的个人工作助理，处理指定项目资料、持续事项、必要问答及显式偏好。既有 Pi 执行保持不变；没有引入多 Bot 管理或 UI 作为前置。

## 实现

- Interaction 绑定原 work/revision/execution/callId；InteractionLedger 是唯一写入 owner，InteractionService 协调提问、回答和拒绝的事务。
- 提问先持久提交，再由 Pi adapter 挂起原工具执行；等待不持有 Harness 或工作槽。答复重新调度原执行，使用同一 native Submission。
- 更正/取消退役旧问题；过期/第二次回答被拒绝。多个问题需全部回答才能继续，拒绝使该版本待答问题退役并阻塞工作。等待期间不执行其他工具动作。
- 问题返回关联主聊天，接待可提交 answer/reject；会话外问题不可被模型建议操作。直接 submit 工作仍经 CLI 查问题。
- 接待可建议显式 remember/forget，经 MemoryService CAS；墓碑保留版本、删除正文退出当前召回，遗忘后重新记住使用正确版本。
- schema2→3 保留既有工作、输入和委托；旧 grant 不自动获得 ask_user。schema1 仍可顺序升级。
- 离线 doctor 检查显式配置和目录，只暴露当前进程 API key 是否存在。真实验收入口 accept:real 拒绝 fixture，创建全新 profile/合成资料，记录失败与自动证据，不自动宣布产品质量通过。

## 验证和限制

完整证据在根 VALIDATION.md 第三轮。初次新测试误读 runtime 字段，随后测试的错误文案匹配不准，以及探针使用了固定目录不存在的模型 ID；对应失败日志保留。原生问答挂起/回答、重启、修改/取消、拒绝、崩溃窗口、主会话和显式记忆已加入集成回归。

真实模型的意图/问题/产物质量、完整 token/费用/执行步数预算、长期运行、认证/接管、来源订阅、自动记忆和平台 owner 适配仍未验收或实现。当前状态为 development。fixture 场景通过只证明已测机制；真实验收脚本存在也不等于已经运行。
