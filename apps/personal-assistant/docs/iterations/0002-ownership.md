# 第二轮：领域、所有权与主会话

提出人：当前会话用户，身份未确认。日期：2026-11-02。需求原话：「开搞，而且重要的是你得建模 文件夹和类 所有权边界。我会让你逐步丰满」。

本轮保持独立目录；未集成/部署 Join，未使用真实模型或第三方服务凭据。

## 交付内容

1. 将平铺 Store/Runner 拆成领域、应用、port、适配器、接口和本机运行装配。具体类与状态所有权见 [architecture.md](../architecture.md)。
2. 为工作、助理/委托、会话/决策、记忆和安排落实领域行为。工作目标当前仍为文本，默认完成标准是本地交付；没有伪装成完整通用工作规划器。
3. 将执行绑定和结果/投递的修改收敛到 ExecutionLedger/OutcomeLedger，业务协调经服务调用，不互相直接修改 repository。输入和主历史也有明确唯一写入入口。
4. 加入稳定主聊天、持久 reception turn、事务外模型建议与事务内命令提交；普通聊天不建事项，已有事项的修改/取消核验会话关系及目标版本。
5. 主接待 Coordinator 与后台工作槽分开；最终结果以稳定 Delivery ID 回到原聊天。
6. 通过显式 workspace 绑定读取真实本地资料，限制相对路径、格式、大小和链接；产物保留来源路径及哈希。原委托保存资源 binding，配置变化不会扩大旧授权。
7. schema v1 → v2 保留第一轮输入、工作和记忆。第一轮导入路径保留无状态兼容 facade。
