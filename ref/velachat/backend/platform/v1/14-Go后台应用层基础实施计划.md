# Go 后台应用层基础实施计划

状态：待用户批准实施  
日期：2026-07-30  
依据：`13-Go后台应用层架构设计.md`

## 1. 本切片目标

本切片建立可运行、可生成、可黑盒测试的 Go HTTP/Application 基础：

```text
OpenAPI 3.0.3
→ oapi-codegen strict std-http
→ net/http ServeMux
→ 统一认证/校验/错误中间件
→ Application/Port 边界
```

交付：

- 把现有 OpenAPI 3.1 无语义变化迁移为 3.0.3；
- 固定 oapi-codegen 和 request validator 版本；
- 生成 DTO、strict interface 和 ServeMux 路由；
- 建立 HTTP Server、requestId、错误、缓存和 graceful shutdown；
- 建立 CredentialCandidate/AuthState/CurrentPrincipal 门禁；
- 建立 Clock、IDGenerator、Authenticator、RateLimiter 等 Port；
- 为 59 个 operation 建立编译覆盖和协议测试框架；
- SQLite 下只允许 API/Worker/Scheduler 单进程组合；
- 为下一个 Auth/Server 纵向切片提供稳定接入点。

本切片不实现：

- register/login/refresh 的真实业务；
- Server、Channel、Agent、Computer、Task、Reminder 用例；
- Ent Repository；
- JWT、PasswordHasher、UserSig 的生产适配器；
- 腾讯 IM/TAT、Redis 真实调用；
- Worker/Scheduler 业务循环。

未实现的业务 operation 不对外启动生产监听。测试使用生成接口的受控占位实现验证
传输层；不能把 501 占位当作可发布业务。

## 3. TDD 规则

除生成代码和配置文件外，严格执行：

```text
写一个失败测试
→ 运行并确认按预期失败
→ 写最小生产代码
→ 运行并通过
→ 小步重构
```

每个任务必须保存 RED 和 GREEN 使用的命令及结果。禁止先写一批生产代码再补测试。

生成代码的门禁是：

```text
源 OpenAPI 校验通过
→ 运行锁定生成器
→ 生成包编译
→ 生成结果重复执行无漂移
```


验证：

```text

operationId 仍全局唯一

```

该任务只转换协议表达，不增加或删除业务 endpoint。

## 6. 任务 3：内层 Port

新建：

```text
internal/ports/clock/clock.go
internal/ports/id/generator.go
internal/ports/authn/authenticator.go
internal/ports/ratelimit/limiter.go
internal/ports/token/signer.go
```

定义最小接口：

```text
Clock.Now
IDGenerator.New
Authenticator.Authenticate
RateLimiter.Allow
TokenSigner.Sign/Verify
```

规则：

- Application 不直接调用 `time.Now()`、`id.New()` 或 Redis；
- RateLimitSubject 是 IP/LoginHash/AccountID/AgentID typed union；
- Candidate 与 CurrentPrincipal 类型分离；
- Port 不引用 `net/http`、OpenAPI DTO、Ent 或腾讯 SDK；
- Fake 实现只放 `_test.go` 或专用 internal test package。

RED：

- 非法 RateLimitSubject 无法构造；
- CredentialCandidate 不能作为 CurrentPrincipal 使用；
- Fake Clock/ID 能稳定驱动测试。

GREEN：

- 只实现接口、值对象和必要构造校验；
- 系统 Clock/ID adapter 复用数据库会话已有 `clock`/`id` 包。

## 8. 任务 5：CredentialCandidate 与认证门禁

新建：

```text

internal/app/authn/service_test.go
internal/transport/http/auth_state.go

```

RED：

- Human、Runtime、AgentCredential scheme 精确隔离；
- Human JWT 不能通过 RuntimeBearer；
- Candidate 未经 Authenticator 不能读取 CurrentPrincipal；
- revoked/currentness error 不能进入 Handler；

GREEN：

- validator authentication hook 调用 `authn.Service`；
- 成功后写入 CurrentPrincipal；
- strict Handler 只能通过 typed accessor 取得 Principal；
- AuthState 不跨请求复用。

本任务使用 Fake Authenticator，不实现 JWT 或数据库 session 查询。

## 9. 任务 6：OpenAPI validator 与三类错误出口

新建：

```text
internal/transport/http/validator.go
internal/transport/http/validator_test.go
internal/transport/http/strict_errors.go
internal/transport/http/strict_errors_test.go
```

RED：

- 未知 path → 404/route_not_found；
- 已知 path + 错误 method → 405/method_not_allowed + 正确 `Allow`；
- 非法 UUID/path/query/header/body → 400 或 422 的统一 ErrorEnvelope；
- security failure → 401 ErrorEnvelope；
- std-http bind error 不返回纯文本；
- strict handler 未知 error → 500/internal_error；
- malformed handler response 不泄露内部错误。

GREEN：

- 配置 `ErrorHandlerWithOpts`；
- method mismatch 显式从 OpenAPI 路由表计算 Allow；
- 配置 std-http ErrorHandlerFunc；
- 配置 strict Request/Response error handlers；
- 三类路径共用 error encoder。

## 10. 任务 7：HTTP Server 与安全 Middleware

新建：

```text
internal/transport/http/server.go
internal/transport/http/server_test.go
internal/transport/http/middleware.go
internal/transport/http/middleware_test.go
```

RED：

- requestId 生成并进入 response/error/log context；
- panic 被恢复为统一 500；
- body 超限被拒绝；
- JSON endpoint 拒绝错误 Content-Type；
- CORS 只允许显式 origin/method/header；
- 可信代理配置不会信任任意 X-Forwarded-For；
- 敏感 response 强制 no-store；
- timeout/cancel 传播到 strict Handler；
- 不使用默认 `http.DefaultServeMux`。

GREEN：

- 显式构建 `http.Server`；
- 配置 ReadHeader/Read/Write/Idle timeout 和 MaxHeaderBytes；
- 全部 middleware 使用 `func(http.Handler) http.Handler`；
- 不在 middleware 做 Server 角色授权。

## 12. 任务 9：59 operation 传输契约框架

新建：

```text
internal/transport/http/contract_test.go
internal/transport/http/testserver_test.go
```

目标：

- `_test.go` 中的 ContractHarness 编译期满足 generated StrictServerInterface；
- Harness 为每个 operation 返回最小、合法、无 Secret 的 canned response；
- Harness 只用于验证生成路由、middleware 和 OpenAPI contract，不进入生产二进制；
- 本切片不建立返回 501 的生产 Adapter，也不发布空业务；
- contract test 对每个 operation 的实际 response 执行 OpenAPI response validation；
- DTO 测试确保内部 Entity/Secret 字段不会序列化。

生产 Adapter 从下一纵向切片开始，按 Auth、Server、Agent 等领域分文件逐个实现；
每个方法只做 DTO mapping 和 Application 调用。

验收：

```text

59/59 operation 有 contract case
所有 success/error response 通过 OpenAPI validation
```

## 13. 任务 10：SQLite 组合运行时

新建：

```text

internal/runtime/roles_test.go
internal/runtime/supervisor.go
internal/runtime/supervisor_test.go
```

RED：

- SQLite 缺少 api/worker/scheduler 任一角色时拒绝启动；
- SQLite 不能启动独立 worker/scheduler；
- 三角色只共享一个 Database Handle；
- readiness false 后三个角色同时停止 intake；

- TDSQL 模式允许独立角色配置，但本切片不连接 TDSQL。

GREEN：

- 实现角色配置和通用 supervisor；
- Worker/Scheduler 使用 Fake loop；
- 不提前实现业务消费。

## 15. 完成条件

- 标准 ServeMux 可以通过 `httptest` 承载全部 OpenAPI route；
- 所有请求/响应/错误都受 OpenAPI 与统一 encoder 控制；
- Candidate 不能绕过 currentness 门禁；
- SQLite 进程角色约束可执行；
- Application/Port 不依赖 HTTP、Ent 或腾讯 SDK；
- 生产监听仍由功能开关关闭，直到至少一个真实业务闭环完成；
