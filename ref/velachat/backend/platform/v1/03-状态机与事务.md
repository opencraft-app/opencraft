# 状态机与事务

## 1. 状态机

### 1.1 IM 资源

```text
provisioning → ready
provisioning → error
error → provisioning
```

Account、Server、Member、Agent、Channel 的平台事实先提交，腾讯 IM 资源通过
TencentOperation 异步收敛。

### 1.2 Computer

```text
provisioning → active → removed
```

```text
tatAgentState: unknown ↔ online ↔ offline
                         ↘ error
```

外部纳管 Computer 在取得 `rins-*` 前保持 provisioning。removed 是业务终态，但不
自动删除或关机用户的真实服务器。

### 1.3 Agent Runtime

```text
desiredState:  stopped | running
observedState: unknown | deploying | stopped | starting | running | stopping | error
```

desired 与 observed 分离。平台 API 修改 desiredState，TAT 操作更新最近 observed；
UI 必须明确显示“期望状态”和“最近观测状态”，不能把一次命令受理当作已运行。

### 1.4 TencentOperation

```text
pending → running → succeeded
                 ↘ retry_wait → running
                 ↘ failed
                 ↘ uncertain
pending/running/retry_wait → superseded
```

只有可安全重试的操作进入 retry_wait。返回结果未知且无法查询确认时进入 uncertain，
不能伪造成功。

### 1.5 Member 与业务对象

```text
Member: active → removed
Reminder: active ↔ paused
          active/paused → canceled
          once 到期 → completed
Occurrence: due → acknowledged | canceled
```

## 2. 创建 Account

Account 注册是允许的低频 TDSQL 2PC：

1. 标准化登录名并计算 loginHash；
2. 在 loginHash 分片预留 AccountLoginIdentity；
3. 生成 accountId，在 accountId 分片创建 Account；
4. 同 accountId 分片创建 `im.identity.ensure` TencentOperation 和 Outbox；
5. 2PC 提交后登录身份进入 active。

腾讯导入账号成功后 Account 进入 ready。只有 ready 才可签发 Human UserSig。
事务内不调用腾讯云 API。

## 3. 创建 Server

Server 创建是允许的低频 TDSQL 2PC：

1. 校验 Account IM identity ready；
2. 在 slug 分片预留 ServerSlugRegistry；
3. 在 serverId 分片创建 Server 与稳定 Community GroupId；
4. 创建 Owner Human Member，复用 Account.imUserId；
5. 创建 `#全员` Channel；
6. 创建 Community/membership TencentOperation 与 Outbox；
7. 2PC 提交后 slug registry 进入 active。

Community 和 Owner membership 都 ready 后，Server 才进入 ready。

## 4. 邀请、加入和离开

接受邀请前先按 accountId 点查 Account IM identity；随后只在 serverId 分片锁定
Invite 和 Server：

1. 从 Invite Token 解析 serverId 路由并校验完整哈希、期限和次数；
2. 幂等创建 Human Member；
3. 创建 Community membership 操作；
4. 更新 Invite 次数并写 Outbox。

以上权威写入全部位于 serverId 分片。AccountServerMembership 由 Outbox 异步投影，
不参加 Member 事务。

离开或移除时：

1. Owner 不可直接退出；
2. Member 进入 removed；
3. 非系统 Channel membership 进入 leaving；
4. 异步移除 Topic 与 Community membership。

不删除 Account、全局 UserID、C2C 历史或其他 Server membership。

## 5. 创建 Agent

事务：

1. 校验 Server 和可选 Computer；
2. 创建 `Member(kind=agent)`；
3. 创建同 ID Agent，生成稳定 `a_` UserID；
4. 创建 `im.identity.ensure` 与 Community membership 操作；
5. 写 Outbox。

Agent identity 和 Community membership ready 后才能部署 Runtime。创建 Agent 不会
立即把 Runtime 启动。

删除 Agent 时：

- Member 进入 removed；
- desiredState=`stopped`；
- 当前 Runtime credential 全部 revoked；
- Reminder canceled；
- 创建 TAT stop 与 IM membership remove 操作；
- 腾讯 IM UserID 保留但不再签发 UserSig。

## 6. Computer 接入

### 6.1 腾讯云原生实例

Owner/Admin 提交 `tatRegion + tatInstanceId`。Computer 首次绑定是允许的低频
TDSQL 2PC：

1. 在 bindingHash 分片预留 TATInstanceBinding；
2. 在 serverId 分片创建 active Computer；
3. 2PC 提交；
4. Worker 调用 TAT 查询系统、Agent 在线状态并更新观测字段。

### 6.2 外部托管实例

1. 后台按部署策略选择托管 TAT 地域（v1 默认北京），在 serverId 分片创建
   provisioning Computer；客户端不提交地域；
2. 后台调用 TAT CreateRegisterCode，限制一次注册、短有效期和出口网段；
3. 返回一次性结构化注册材料；
4. Worker 查询新 `rins-*` 并计算 bindingHash；
5. 使用 2PC 预留 TATInstanceBinding 并绑定 Computer.tatInstanceId；
6. 校验 OS 为 Linux/Windows，或目标为批准的 macOS managed Canary，并确认
   TAT Agent 在线；
7. Computer 进入 active。

注册码材料只显示一次，不进入日志或幂等响应缓存。过期未注册可重新生成，但同一
Computer 同时只能有一个有效注册过程。

移除 Computer 前必须没有 active Agent 绑定。移除仅解除平台关系和停止对应
Runtime，不调用云服务器销毁 API。删除事务在 serverId 与 bindingHash 分片内同步将
TATInstanceBinding 从 `active` 置为 `retired`、清空 Computer 当前 `tatInstanceId`，再将
Computer 置为 `removed`；任一步失败整体回滚。

同一用户在同一 Server 重新安装时，客户端只读取得本机 TAT region/instanceId，并同时
证明旧 Computer credential 与新 Computer enrollment token。后台签发五分钟、绑定双方
revision/token hash/release hash 的 replacement grant；claim 事务将 retired binding 原子
改为新 Computer 的 active binding。旧 Computer 永久保持 removed。active binding、跨
Server、版本不一致、purged identity 均拒绝，且不触发 TAT 重新注册。

创建 Agent 时必须同时指定同 Server、已纳管且 `lifecycleState=active` 的 Computer。
绑定事务不要求 Computer 瞬时在线；创建后的 Agent 保持 `stopped/unknown`，不会自动部署。
Agent 仅能在停止态迁移到另一台符合条件的 Computer，任何更新都不能清空绑定。

## 7. Agent credential 与 Runtime Session

部署或轮换时生成高熵 Runtime credential：

1. 创建 `staged` credential，数据库只保存强哈希与 version；
2. 必要时先停止 Runtime，旧 active credential 仍有效；
3. 通过固定 TAT 模板把新 credential 写入 versioned 权限受限文件；
4. TAT 明确确认安装版本后，事务切换 Agent.credentialVersion；
5. 新版本进入 active，旧版本进入 revoked；
6. 再启动 Runtime，并清理旧 credential 文件。

安装结果 uncertain 时 Runtime 保持停止，Worker 先用不含 Secret 的版本探测确认，
不得同时撤销旧版本和猜测新版本已生效。

Computer 为当前 Agent launch 调用 `/v1/computer/agents/{agentId}/launches` 或其
`/{launchId}/session` 刷新端点：

1. 从 credential 前缀解析 serverId/agentId/version 路由；
2. 在 serverId 分片按 secret hash 定位 credential；
3. 校验 Agent/Member/Computer 当前性和 version；
4. 签发短期平台 Access Token；
5. 签发同一 Agent UserID 的短期 UserSig；
6. 返回 Server、Channel、reply policy 和 Runtime 配置；
7. 更新 credential.lastUsedAt。

UserSig 或平台 Token 到期前，Runtime 使用同一当前 credential 重新换取。credential
一旦 revoked，后续换取立即失败。

## 8. 部署与生命周期

后台不为单个 Agent 创建 TAT 操作。deploy/start/stop/restart 只修改 Agent 期望状态，
递增所属 Computer 的 `assignment_revision`，并同步返回已完成的 platform operation。

Computer daemon 长轮询 Assignment：

1. 读取完整 Agent 配置与当前 credential version；
2. 在本机启动、停止或替换对应 RuntimeActor；
3. Agent 自行用短期凭据直连腾讯云 IM；
4. daemon 以 assignment epoch、generation、attempt、launchId 回报观测；
5. 后台只接受当前 launch 的递增 observation，旧输出不会覆盖新状态。

TAT 只管理 Computer 注册、在线探测和 PTY，不参与单个 Agent 生命周期。

## 9. PTY Session

`POST .../terminal-sessions` 是同步短事务：

1. 校验 Human 为 Server Owner/Admin；
2. 校验 Computer active、TAT Agent online；
3. 后台调用腾讯云 TAT `StartSession`；
4. 把短期 session connection 信息直接返回浏览器；
5. 只保存调用者、Computer、开始时间和腾讯 requestId 等脱敏审计。

浏览器直接连接腾讯云 TAT WebSocket。平台不代理字节流，不保存终端输入输出，也不
定义自己的 WebSocket/AsyncAPI。

PTY 断开不改变常驻 Runtime 的 desiredState。

## 10. 聊天路径

Human 或 Agent 使用腾讯 IM SDK 直接发送消息，平台没有对应事务：

```text
Human IM SDK → 腾讯云 IM → Agent IM SDK
Agent IM SDK → 腾讯云 IM → Human/Channel
```

Agent Runtime 按 replyPolicy 处理 C2C 与群 @。聊天离线补偿、顺序、历史和重试由
腾讯云 IM SDK 负责，平台不创建 Invocation、Delivery、ACK 或消息回执。

## 11. Task

创建、指派或修改 Task 时：

1. 锁定 Task 和目标 Member；
2. owner 改变则 `assignmentRevision+1`；
3. 提交 Task 事实；
4. 若 owner 是 Agent，写 `im.agent.notify` Outbox；
5. Worker 发送只含 taskId、assignmentRevision 的 IM CustomElem。

Agent 更新 Task 时必须满足：

```text
Task.ownerMemberId == 当前 Agent.id
X-Resource-Revision == Task.revision
请求幂等键未发生载荷漂移
```

Human 不执行 `claim`。Human 的状态写入只表达控制面动作：验收通过、退回修改、
关闭或重新打开；`todo → in_progress` 的首次执行确认由 Agent Runtime 完成。

通知失败不回滚 Task。Runtime 登录或重连后通过 HTTP 查询自己当前 Task，因此通知
不是正确性依赖。

## 12. Reminder

Scheduler 使用数据库锁领取到期 Reminder：

1. 以 `(reminderId, scheduledFireAt)` 幂等创建 occurrence(due)；
2. once 进入 completed，cron 推进到下一个未来时间；
3. 写 Agent 通知 Outbox；
4. Agent 通过 HTTP 拉取 due occurrence；
5. Agent 处理后幂等确认 acknowledged。

通知失败可重试；即使没有通知，due occurrence 仍会被 Agent 的周期对账发现。v1
不无限补建停机期间的 cron 历史，只创建当前调度策略指定的下一次 occurrence。

正常 Scheduler 由 Redis 时间轮携带 serverId/reminderId 唤醒，按 serverId 点查。
Redis 丢失时使用低频 TDSQL 全 set 恢复扫描，不把广播扫描作为常规调度循环。

## 13. 幂等、锁和失败

- 所有非 Secret HTTP 写操作使用 `Idempotency-Key`；
- 更新使用 revision/`X-Resource-Revision`；
- Server idempotency/Outbox/TencentOperation 使用 partitionKey=serverId；
- Account idempotency/Outbox/TencentOperation 使用 partitionKey=accountId；
- 同一 Agent 的 TAT lifecycle 操作串行；
- 腾讯资源操作执行前回读当前业务 revision；
- Outbox 只携带 aggregate ID，不携带消息正文或 Secret；
- Worker 使用短租约、指数退避和稳定幂等键；
- uncertain 只能通过腾讯查询或人工确认收敛；
- IM/TAT 暂时不可用不改变已经提交的 Task/Reminder 事实；
- 普通聊天正确性不依赖平台数据库；
- 除 Account 登录身份、Server slug、Computer TAT 绑定三个 registry 生命周期外，
  业务事务不得跨 shardkey；
- TDSQL 事务内禁止调用腾讯云、Redis 或其他外部网络。
