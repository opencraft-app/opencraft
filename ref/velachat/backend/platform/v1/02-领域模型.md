# 领域模型

## 1. 总览

```text
LoginIdentity ──> Account ──1:1── Human IM UserID
   │
   ├── AccountServerMembership（只读投影）
   └── Human Member ──> Server ──1:1── Community
                            ├── Channel ──> Topic
                            ├── Agent Member ──1:1── Agent
                            │                    ├── Agent IM UserID
                            │                    └── Computer
                            ├── Computer ──> TAT Instance
                            ├── Task
                            └── Reminder ──> ReminderOccurrence
```

腾讯云 IM 拥有聊天数据；腾讯云 TAT 提供机器执行通道；平台拥有业务对象和映射。
Server 域按 serverId Group-Shard，Account 域按 accountId Group-Shard。

## 2. Account

```text
Account
id
email
displayName
passwordHash
tokenVersion
imUserId
imState = provisioning | ready | error
revision
```

- 一个 Account 只有一个全局 Human IM UserID；
- `imUserId` 使用 `u_` 前缀，创建后不变；
- Account 离开某个 Server 不影响其他 Server 和网络级 C2C；
- 只有 `imState=ready` 才签发 Human UserSig。

### 2.1 AccountLoginIdentity

```text
AccountLoginIdentity
id
loginHash
kind = email | phone | oauth
normalizedLogin
accountId
state = active | retired
```

登录名按 loginHash 分片并保证全局唯一。先解析 accountId，再点查 Account。Account
行中的 email 只是显示快照。

### 2.2 AccountServerMembership

```text
AccountServerMembership
id
accountId
serverId
memberId
role/status
serverName/serverSlug snapshot
serverRevision
```

它是“我的 Server”列表投影，不授予权限。真正授权仍由 Server 分片内 Member 决定。

## 3. Server

```text
Server
id
slug
name
ownerMemberId
imGroupId
imState = provisioning | ready | error
revision
```

一个 Server 映射一个启用 Topic 的 Community。v1 使用部署级唯一 SDKAppID，因此
Server 不保存 Provider App 分片字段。

### 3.1 ServerSlugRegistry

```text
ServerSlugRegistry
id
slug
serverId
state = reserved | active | retired
```

Server 按 ID 分片；全局 slug 唯一和 `/s/{slug}` 路由由独立 registry 保证。

## 4. Member

```text
Member
id
serverId
kind = human | agent
accountId?
role = owner | admin | member
displayName
handle
status = active | removed
imState = provisioning | ready | error
revision
```

- Human 必须关联 Account，并复用 Account.imUserId；
- Agent 不关联 Account，其 IM 身份来自 Agent；
- Human 同一 Account 在同一 Server 最多一个 Member；
- Agent.id 与对应 Agent Member.id 相同；
- removed 是 v1 终态；
- Member 是平台授权事实，腾讯 membership 是传输投影。

## 5. Agent

```text
Agent
id
serverId
imUserId
computerId
runtimeKind
runtimeModel?
replyPolicy = mention_and_dm | all_channel_messages | dm_only
desiredState = stopped | running
observedState = unknown | deploying | stopped | starting | running | stopping | error
credentialVersion
imState = provisioning | ready | error
lastObservedAt?
lastErrorCode?
revision
```

- Agent 是腾讯普通 UserID，使用 `a_` 前缀；
- 每个活跃 Agent 从创建开始必须绑定同 Server、已纳管且生命周期为 active 的
  Computer；Computer 可暂时离线，但不能解除绑定；
- Agent 处于停止态时可以迁移到另一台符合条件的 Computer；删除后的历史墓碑允许保留
  旧绑定，无法可靠回填的旧墓碑允许为空；
- Agent Runtime 可获得短期 UserSig，直接连接 IM；
- `replyPolicy` 是 Runtime 输入过滤规则，不改变腾讯消息可见性；
- `desiredState` 是平台希望达到的状态，`observedState` 来自最近一次 TAT/IM 观测；
- Runtime 的安装位置和服务模板由平台版本决定，API 不接受任意 shell/env/path。

### 5.1 AgentRuntimeCredential

```text
AgentRuntimeCredential
id
serverId
agentId
version
secretHash
state = staged | active | revoked
lastUsedAt?
createdAt
revokedAt?
```

新 credential 先以 staged 写库，经 TAT 确认原子安装后才切为 active；旧版本随后
revoked。长期 credential 只写入目标 Computer 的权限受限文件，用来换取短期平台
Token 和 UserSig。数据库只保存强哈希。Agent.credentialVersion 只指向 active
版本。

## 6. Computer

```text
Computer
id
serverId
name
tatRegion
tatInstanceId?
tatInstanceKind = cvm | lighthouse | managed
osType = linux | windows | macos
lifecycleState = provisioning | active | removed
tatAgentState = unknown | online | offline | error
registrationExpiresAt?
lastObservedAt?
revision
```

- `managed` 对应 `rins-*` 托管实例；
- `macos` 仅允许 `managed`，以当前登录用户模式运行；
- 原生和托管实例的 RunCommand、状态查询和 StartSession 语义完全一致；
- 外部纳管过程中 `tatInstanceId` 可以暂为空，注册成功后固定；
- 一个 TAT 实例在平台中只能绑定一次；
- Computer 只持有自身作用域的短期平台会话与可轮换运行凭证；它不持有 Human 或 Agent
  Runtime 身份，不建立自研平台长连接，也没有 IM 身份。

### 6.1 TATInstanceBinding

```text
TATInstanceBinding
id
bindingHash
tatRegion
tatInstanceId
serverId
computerId
state = reserved | active | retired | purged
```

Computer 按 serverId 分片；本 registry 按 region+instance 哈希分片，保证同一 TAT
实例不能跨 Server 重复占用。解除纳管时 `active → retired` 并清空旧 Computer 的当前
TAT 引用；同一机器经旧 credential 与新 enrollment 双重证明后，可把同一行重新认领为
`active` 并更新 owner。管理员确认腾讯侧 identity 已销毁后只能置为 `purged`。
`retired/purged` 均为永久防重墓碑，不物理删除。

## 7. Channel

```text
Channel
id
serverId
name
visibility = public | private
systemKey = all | null
imGroupId
imTopicId?
imState = provisioning | ready | error
revision
```

- `systemKey=all` 使用 Community 根会话，`imTopicId=null`；
- 其他 Channel 一律映射 Private Topic，以获得独立成员；
- Public Channel 对 Server 成员可发现并允许主动加入，但不自动继承 Server 成员；
- Private Channel 只对已加入成员和 Server 管理员可见，由管理员添加成员；
- visibility 创建后不可修改；
- v1 不在平台持久化 DM。

### 7.1 ChannelMembership

```text
ChannelMembership
id
serverId
channelId
memberId
state = joining | active | leaving | left
imState = provisioning | ready | error
membershipVersion
```

`#全员` membership 随 Server Member 派生，不能单独退出。普通 Public Channel 的成员
可以主动加入或退出；普通 Private Channel 只能由管理员添加，但成员可以退出自己。

## 8. IMMessageRef

平台业务对象可选择引用一条腾讯消息，但不复制其内容：

```text
IMMessageRef
kind = c2c | group
messageId
groupId?
topicId?
senderUserId?
```

引用用于跳转和诊断，不授予权限，也不是平台聊天数据库。

## 9. Task

```text
Task
id
serverId
number
title
description?
status = todo | in_progress | in_review | done | closed
ownerMemberId?
assignmentRevision
createdByMemberId
updatedByMemberId
sourceMessageRef?
revision
```

owner 每次改变都递增 `assignmentRevision`。Human 通过控制面创建、指派和验收，
不成为 Task 的执行者；Agent 只能领取和更新仍由自己负责且 revision 匹配的 Task。
指派通知只是唤醒信号，Task 行才是事实。

## 10. Reminder

```text
Reminder
id
serverId
agentId
createdByMemberId
scheduleKind = once | cron
schedule
timezone
text
status = active | paused | completed | canceled
nextFireAt?
revision
```

```text
ReminderOccurrence
id
serverId
reminderId
agentId
scheduledFireAt
state = due | acknowledged | canceled
acknowledgedAt?
resultCode?
textSnapshot
```

每个计划时间最多一个 occurrence。Agent 通过 HTTP 查询未确认 occurrence，因此 IM
通知可以重复或丢失。

## 11. TencentOperation

所有腾讯云异步副作用使用一个具体而非多云抽象的操作对象：

```text
TencentOperation
id
partitionKey
serverId?
service = im | tat
kind
resourceType
resourceId
idempotencyKey
desiredRevision?
state = pending | running | retry_wait | succeeded | failed | uncertain | superseded
attempts
nextAttemptAt?
errorCode?
result?
```

IM 操作包括身份、Community、Topic、membership 和业务通知；TAT 操作包括外部注册
对账、deploy/start/stop/restart/probe。Worker 每次执行前回读业务对象和 revision，
旧操作进入 superseded。

`StartSession` 是短期交互授权，成功结果直接返回调用者且只记录脱敏审计，不作为
可重试后台操作。

## 12. 支撑对象

- `IdempotencyRecord`：按 partitionKey 分片，保存 HTTP 写命令的稳定结果；
- `OutboxEvent`：按 partitionKey 与事实共置，只携带 ID 和路由；
- 腾讯云管理员凭证是部署配置，不是领域对象；
- 腾讯云普通配额是运维配置，不是数据库实体。

## 13. 不变量

1. 一个 Account 一个 Human IM UserID，可加入多个 Server。
2. 一个 Agent 一个普通 IM UserID，只属于一个 Server。
3. Human 和 Agent 都直接连接腾讯云 IM。
4. 一个 Server 一个 Community，一个 Channel 最多一个 Topic。
5. Computer 必须是 Linux/Windows TAT 原生或托管实例，或批准的 macOS managed
   Canary。
6. 原生与托管 Computer 使用相同执行接口。
7. Computer 不连接平台 WebSocket。
8. 聊天消息不进入平台数据库。
9. Task/Reminder 通知不构成业务事实。
10. Agent Runtime 不能获得腾讯云管理员凭证。
11. Server 热路径显式携带 serverId；Account 热路径携带 accountId。
12. TDSQL 不使用外键；复合主键和事务层保证跨表归属。
13. 主键和所有唯一索引必须包含对应 shardkey。
14. v1 不存在 Provider、物理 Shard 目录、Invocation、Delivery 或 Activity。
