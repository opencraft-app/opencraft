# 平台后台与数据库联合评估

## 1. 总体结论

现有 v1 设计可以实施，而且后台复杂度已经显著降低：

```text
Human / Agent ──直连── 腾讯云 IM
Web / Runtime ──HTTP── Go 平台后台 ──业务事实── 数据库
                                  ├──资源编排── 腾讯云 IM REST
                                  └──机器执行── 腾讯云 TAT
```

Go 后台不承担聊天消息、未读、附件、Computer 长连接、Agent 投递和 PTY 字节流。
它真正要做的是身份、授权、业务状态机、可靠腾讯云副作用和短期凭证签发。

20 张业务表总体足够。当前不需要增加消息表、Activity 表、Terminal Session 表或
Provider 抽象表。

## 3. 应用层边界

Handler 只负责：

- 解析和校验 HTTP；
- 读取认证主体；
- 调用一个应用服务方法；
- 将稳定应用错误映射为 HTTP。

应用服务负责：

- 权限和跨对象不变量；
- 选择 accountId/serverId partition key；
- 幂等、revision 和事务；
- 写业务事实、Operation 与 Outbox；
- 返回公共 DTO。

Repository 负责：

- 强制所有 Server/Account 查询携带 route key；
- 在一个 partition transaction 中提供一致读写；
- 实现锁、唯一冲突映射和游标；
- 隐藏 Ent Client、SQLite/TDSQL 差异。

腾讯云 Adapter 负责：

- 腾讯请求/响应转换；
- 腾讯错误归一化；
- Secret、签名与日志脱敏；
- 请求超时、查询和安全重试；
- 不自行决定业务状态。

## 4. 两项联合阻塞

### 4.1 托管 TAT 注册关联

现有 Computer 只有 `registrationExpiresAt`，不足以把一次注册流程可靠关联到最终
`rins-*`。需要数据库会话在 `computers` 中容纳：

```text
registration_generation
registration_reference NULL
registration_expires_at NULL
```

`registration_reference` 只保存腾讯返回的非 Secret 标识；注册码、脚本和 Token
永不入库。每次重新生成递增 generation，Worker 只允许当前 generation 完成绑定。

如果腾讯 API 最终证明没有可持久引用标识，则必须把“注册码创建和实例发现”的实际
可查询字段重新定义清楚，不能用时间窗口猜测实例归属。

### 4.2 原生 Computer 创建顺序

冻结为：

1. 在数据库事务外调用 TAT Describe，校验实例存在、OS 支持和 TAT online；
2. 生成 Computer ID 和 bindingHash；
3. 进入受控事务，预留 TATInstanceBinding 并创建 active Computer；
4. 提交后创建后续 probe/reconcile 唤醒。

这样 `POST /computers` 返回 201 时语义明确：平台绑定已经建立，最近观测仍可由
后续 probe 更新。腾讯只读调用失败时不产生半成品 Computer。

## 5. 实施前应修正但不阻塞数据层的事项

1. 幂等规则按三类冻结：
   - 普通命令：Idempotency-Key + 稳定响应缓存；
   - 天然幂等命令：重复调用返回同一终态；
   - 一次性 Secret：不缓存响应，每次创建新会话或按 generation 明确轮换。
2. `revokeInvite` 补 Idempotency-Key，或明确为重复撤销始终 204。
3. Runtime 每次 Session 续签重新取配置，并定时调用 `/runtime/me`；不新增推送连接。
4. Runtime 的 Task 对账 cursor 是服务端不透明字符串，只能原样续用。
5. PTY“审计”在 v1 定义为外部结构化安全日志，不宣称数据库可查询审计。
6. Operation 示例统一改为 UUIDv7，不再使用 `op_` 资源前缀。
7. Refresh Token reuse：已使用 token 再次出现时撤销同一 family，并递增必要的
   Account token version。

## 6. 推荐后台工程结构

```text
cmd/chatserver/
internal/
  app/
    auth/
    server/
    channel/
    agent/
    computer/
    task/
    reminder/
    operation/
  transport/http/
  domain/
  ports/
    repository/
    tencentim/
    tencenttat/
    token/
    clock/
  adapters/
    persistence/ent/
    tencent/im/
    tencent/tat/
    redis/
  worker/
  scheduler/
  observability/
```

数据库会话交付的 Ent Client 只允许进入 `adapters/persistence/ent/`。`internal/app`
和 `transport/http` 不导入 Ent 包。

## 7. 可并行实施顺序

### 平台后台会话现在可做

1. 稳定错误、认证主体、Clock/ID/Token 等基础端口；
2. OpenAPI HTTP Router、请求校验和统一错误响应；
3. 应用服务接口与内存 Fake Repository；
4. 腾讯 IM/TAT Adapter 接口及 Fake Server；
5. Auth、Server、Runtime Session 的应用层测试；
6. Operation Worker 的状态机和重试策略测试。

### 数据库会话继续做

1. 20 个 Ent Schema；
2. SQLite migration 和 schema audit；
3. transaction/partition 基础设施；
4. Repository 所需的带 route key 查询能力；
5. 托管注册字段联合决定后的 Schema 调整。

### 汇合点

数据库层提供 Repository 实现后，把内存 Fake 替换为 Ent Adapter，先完成：

```text
register/login
→ create Server
→ IM provisioning
→ Human IM Session
```

随后完成 Computer/TAT、Agent Runtime、Task/Reminder。这个顺序能最早验证真实腾讯
云闭环，同时不会把后台实现绑死在数据库生成代码上。

## 8. 验收门槛

- Handler、应用服务和 Ent Adapter 分层依赖单向；
- 所有 Server/Account 数据访问都显式携带 route key；
- 数据库事务内没有腾讯云、Redis 或文件调用；
- 一次性 Secret 不进日志、Outbox、Operation snapshot 或幂等响应；
- 外部调用超时不会被伪装成成功；
- Runtime Token 不可跨 Agent/Server；
- 普通消息正文不进入平台后台；
- OpenAPI lint、fixture 校验、单元测试和 race test 通过。
